## 1. 課程定位與分類問題的本質

### 1.1 現實世界中的文件分類（母頁）

- **新聞網站**：自動標記文章為「政治」、「體育」、「娛樂」。
- **垃圾郵件過濾**：判斷一封郵件是否為 spam。
- **網頁目錄**：Yahoo 曾經用人工和系統將數百萬網站分類到目錄樹中。
- **醫學文獻數據庫**：PubMed 將醫學論文自動標記為不同的研究領域。
- **專利申請**：自動判斷專利屬於哪個技術類別。
- **商品推薦**：根據商品描述分類到不同的產品類別。

### 1.2 分類的核心問題（Part 1）

> **我們要解決什麼問題？** 給定一份新的文件，**自動判斷它屬於哪個預定義的類別**。

換個角度說：

- 我們有一些已經被人工標記的文件（訓練資料）。
- 我們要學習文件和類別之間的對應關係。
- 最後對全新的、沒見過的文件進行分類。

### 1.3 分類問題的四種類別型態（母頁總結 Lecture 3-1 回顧）

核心概念鏈：

$$
\text{文字分類問題} \rightarrow \text{類別定義} \rightarrow \text{算法選擇} \rightarrow \text{評估指標}
$$

文字分類的本質＝把文件映射到類別空間。類別可能是：

| 型態 | 例子 |
|---|---|
| 二元 | 垃圾／非垃圾 |
| 多元 | 新聞類別 |
| 多標籤 | 藥物副作用 |
| 階層式 | 動物 → 哺乳動物 → 犬科 |

**這回答什麼行銷/商業問題**（材料依據：母頁應用清單 + Part 1 應用場景章）：一個商業標的到底是「是/否」型（會不會流失、是不是詐騙評論）、「單選」型（歸到哪個商品類別）、「多選」型（一則新聞同時是政治+經濟+能源）、還是「樹狀」型（Electronics > Computers > Laptops）。這一步決定後面所有指標與模型的形式。

## 2. 學習範式與演算法史

### 2.1 三種學習範式

#### Supervised Learning（監督式學習）

- 正式定義：訓練階段有一組帶標籤的資料集。【原文此處公式區塊為空】
  - 其中 $x_i$ 是輸入（如文件），$y_i$ 是對應的標籤（如類別）。
  - 機器學習模型的目標是學習一個函數 $f: X \to Y$，使得對於新的未見過的 $x$，都能預測對應的 $y$。
- 白話：就像有一位「老師」一開始就告訴你答案。你根據這些帶答案的例題不斷練習，最後學會了解題的方法。在文本分類中，老師就是那些被人類標記過的文件集合。
- 典型應用：垃圾郵件過濾、情感分析、主題分類。

#### Unsupervised Learning（非監督式學習）

- 正式定義：訓練資料集 $D = \{x_1, x_2, \ldots, x_n\}$ 中沒有標籤 $y$ 的資訊。模型要從資料的內在結構中發現規律，通常目標是將資料分組（clustering）或降維（dimensionality reduction）。
- 白話：沒有老師。看到一堆雜亂的書，你可能自己決定按「大小」、「顏色」、「厚度」等方式分組，但沒人告訴你應該怎麼分。
- 典型應用：聚類分析、推薦系統中的相似用戶發現、異常檢測。

#### Self-supervised Learning（自監督式學習）

- 正式定義：模型從未標記的資料本身自動生成監督信號。常見方法：
  - 預測文本中被隱藏的詞（masked language modeling）。
  - 預測影像的旋轉角度。
  - 預測視頻的下一幀。
- 白話：系統自己製造問題和答案來訓練自己。BERT 隨機遮蓋句子中的某些詞，然後訓練模型去預測那些詞，不需要人工標記。
- 典型應用：大規模預訓練模型（BERT、GPT）、對比學習。

**這回答什麼行銷/商業問題**（材料依據：Unsupervised 段列出「推薦系統中的相似用戶發現、異常檢測」）：手上有標籤（過去的成交/退訂記錄）就走監督式做預測；沒標籤就先做客群分群或異常偵測；標籤貴但原始文本多（大量評論、客服對話）時，自監督預訓練＋少量標註微調是省標註成本的路。

### 2.2 IEEE ICDM 2006 Top 10 Data Mining Algorithms

> 2006 年，IEEE 國際資料探勘會議評選出十個最具影響力的資料探勘演算法。這十個演算法奠定了現代機器學習的基礎：

1. **C4.5**：決策樹演算法。用樹狀結構進行分類，通過遞迴分割特徵空間。人們現在通常用升級版本（Random Forest、XGBoost）。
2. **k-Means**：最經典的無監督聚類演算法。通過迭代找到 $k$ 個類別的中心，使資料點到中心的距離最小。
3. **Support Vector Machines（SVM）**：強大的監督學習方法。特別適合高維文本資料，通過找到最優的分割超平面來進行分類。**文本分類中最重要的演算法之一**。
4. **Apriori**：關聯規則挖掘演算法。常用於「購物籃分析」——發現商品之間的關聯性，例如「買了尿布的人也常買啤酒」。
5. **EM（Expectation Maximization）**：最大期望演算法。用於處理含有隱變數的統計模型，常用於高斯混合模型（GMM）的訓練。
6. **PageRank**：Google 的網頁排名演算法。通過分析網路連結結構來評估網頁重要性。改變了搜尋引擎的歷史。
7. **k-NN（k-Nearest Neighbors）**：最簡單的分類演算法。預測一個點的類別時，看它最近的 $k$ 個鄰居屬於什麼類別。簡單但有效。
8. **Naive Bayes**：**本課程的主角**。基於機率論的生成式分類器，雖然假設很強（特徵條件獨立），但在文本分類中表現出人意料地好。
9. **CART（Classification and Regression Trees）**：決策樹的另一個變體。更加通用，既可以做分類也可以做回歸。
10. **AdaBoost**：Boosting 演算法的代表。通過組合多個弱分類器得到強分類器。現代的 Gradient Boosting（如 XGBoost）是基於這個思想。

共同特點：**簡單、有效、可解釋**。即使到了深度學習時代的今天，這些古典方法仍然在許多場景中被廣泛使用。

**這回答什麼行銷/商業問題**（材料依據：Apriori 段的購物籃分析）：清單裡唯一直接對應行銷經典問題（交叉銷售、商品搭配）的是 Apriori；其餘是分類/排名/分群的工具箱底層。

### 2.3 Neural Networks 到 Deep Learning 的演進（教材標注「補，看白話」）

#### NN 基本架構

- 正式定義：人工神經網路是由許多簡單計算單元（神經元）互相連接組成的計算系統。每個神經元接收多個輸入，進行加權求和，然後通過非線性激活函數產生輸出。
- 基本三層結構：$\text{輸入層 (Input Layer)} \to \text{隱藏層 (Hidden Layer)} \to \text{輸出層 (Output Layer)}$

給定輸入向量 $\mathbf{x} = (x_1, x_2, \ldots, x_n)$，隱藏層輸出：

$$
\mathbf{h} = \sigma(W^{(1)}\mathbf{x} + \mathbf{b}^{(1)})
$$

輸出層：

$$
\mathbf{y} = \sigma(W^{(2)}\mathbf{h} + \mathbf{b}^{(2)})
$$

- $W^{(1)}$ 是權重矩陣、$\mathbf{b}^{(1)}$ 是偏差向量、$\sigma$ 是激活函數（如 ReLU、Sigmoid）。
- 白話：每一層都在上一層的基礎上進行更抽象的判斷。第一層可能學會識別低級特徵（如邊緣），第二層組合這些邊緣識別形狀，最後一層用形狀來判斷物體。
- 兩個關鍵算法：
  - **Backpropagation（反向傳播）**：計算每個權重對最終誤差的貢獻。通過鏈式法則從輸出層逐層反向傳播誤差梯度。
  - **Gradient Descent（梯度下降）**：沿著誤差減小的方向調整權重：

$$
W := W - \alpha \frac{\partial L}{\partial W}
$$

其中 $\alpha$ 是學習率，$L$ 是損失函數。

#### CNN：為什麼適合影像？

- 卷積操作（不把影像展平成長向量以免喪失空間結構）：

$$
y_{i,j} = \sum_{a,b} w_{a,b} \cdot x_{i+a, j+b} + b
$$

- 池化操作：

$$
\text{MaxPool}(2 \times 2) = \max(x_{2i:2i+2, 2j:2j+2})
$$

- 白話：影像有**局部相關性**——像素通常與它周圍的像素更相關。CNN 只看小區域，逐步組合信息，比把所有像素一視同仁的全連接層聰明得多。
- 為什麼有效：捕捉局部特徵（edge, corner, texture）→ 疊加卷積層組合成高級特徵（shape, object part, entire object）→ 權重共享大幅減少參數 → 具平移不變性。

#### RNN / LSTM：為什麼適合序列？

- RNN 在隱藏層引入「時間迴路」：

$$
h_t = \sigma(W^{(h)}h_{t-1} + W^{(x)}x_t + b)
$$

$$
y_t = W^{(y)}h_t + b'
$$

- 白話：序列資料（文本、語音、時間序列）**順序很重要**。「狗咬了人」和「人咬了狗」詞完全相同但意思相反。RNN 有「記憶」，每處理完一個詞，隱藏狀態 $h_t$ 記住到目前為止的資訊，再傳給下一時刻。
- RNN 的問題：梯度消失（Vanishing Gradient）。序列很長時，反向傳播的梯度指數衰減，早期輸入幾乎無法影響模型。
- LSTM 解決方案：引入「閘門機制」（Gate Mechanism）
  - **遺忘閘門**【原文此處公式區塊為空】：決定從細胞狀態 $C_{t-1}$ 中丟棄多少舊信息。
  - **輸入閘門**【原文此處公式區塊為空】：決定加入多少新信息。
  - **輸出閘門**【原文此處公式區塊為空】：決定隱藏狀態暴露多少資訊。
  - 細胞狀態更新：

$$
C_t = f_t \odot C_{t-1} + i_t \odot \tanh(W_c \cdot [h_{t-1}, x_t] + b_c)
$$

  - 隱藏狀態：

$$
h_t = o_t \odot \tanh(C_t)
$$

  - 為什麼有效：重要信息可以通過細胞狀態的「高速公路」直接傳遞，不受層層梯度影響。

#### Transformer / Self-Attention / BERT

- Attention 的想法：**每次生成一個詞時，根據當前需要自動地為編碼器的所有隱藏狀態分配不同的權重（注意力）**。

$$
\text{Attention}(q, k, v) = \text{softmax}\left(\frac{qk^T}{\sqrt{d_k}}\right)v
$$

- Self-Attention：序列中每個位置都對其他所有位置進行 Attention 計算。

$$
\text{MultiHeadAttention}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)W^O
$$

- 白話：multi-head 就像用多個「注意力透鏡」同時觀察，每個透鏡關注不同的關係（如語法角色、語義相關性等）。
- Transformer 架構（丟掉 RNN 的遞迴，完全基於 Attention）：

```text
Encoder:  
x → Embedding → Positional Encoding
  → [Self-Attention + FFN] × N → Output

Decoder:  
y → Embedding → Positional Encoding 
  → [Masked Self-Att + Cross-Att + FFN] × N → Output
```

- 為什麼改變遊戲規則：**並行化**（無需遞迴，整個序列並行處理）、**長距離依賴**（Attention 直接連接遠距位置，無梯度消失）、**可解釋性**（Attention 權重可視化）。
- BERT（2018, Google）的四個要點：
  - **雙向上下文**：訓練時既看前文也看後文。
  - **掩蓋語言模型**（Masked Language Modeling）：隨機遮蓋句子中 15% 的詞，訓練模型預測被遮蓋的詞。這是自監督學習的典範。
  - **Next Sentence Prediction**：訓練模型判斷兩個句子是否相鄰。
  - **大規模預訓練**：在 3.3 億詞的維基百科和 8 億詞的書籍語料上訓練。
- 預訓練 + 微調範式對比：

$$
\text{傳統：} \quad \text{隨機初始化} \to \text{用標記資料訓練} \to \text{測試}
$$

$$
\text{BERT：} \quad \text{隨機初始化} \to \text{用大規模無標記資料預訓練} \to \text{用少量標記資料微調} \to \text{測試}
$$

#### 這些背景與文字分類的關係（教材原文）

- **Naive Bayes 時代**（1990 年代）：簡單的機率模型，訓練快，效果對簡單文本分類已經很好。
- **SVM 時代**（2000 年代初）：引入了複雜的數學，能處理高維文本，成為最優方法。
- **深度學習時代**（2010 年代）：CNN 用於文本，RNN / LSTM 用於序列建模，Transformer 統一了所有任務。
- **大模型時代**（2020 年代至今）：BERT、GPT 等預訓練模型，文本分類變成簡單的微調任務。

有個有趣的現象：**Naive Bayes 至今仍然被廣泛使用**。因為它簡單、快速、可解釋、對很多場景效果足夠好。在實際工業界，經常是簡單方法配合好的特徵工程，效果不輸複雜深度學習模型。

**這回答什麼行銷/商業問題**（材料依據：上段「工業界常是簡單方法配合好的特徵工程」）：不要為了「看起來先進」上深度模型。要先問資料型態（序列/影像/表格）與資料量，這正是第 19 節與母頁流程圖的判準。

## 3. Text Classification 的正式定義

給定以下基本要素：

- 文件空間 $X$：所有可能文件的集合。每份文件 $d \in X$ 可以用各種表示方法。
- 類別集合 $C = \{c_1, c_2, \ldots, c_m\}$：預定義的 $m$ 個類別。
- 訓練集 $D = \{(d_1, c_{d_1}), (d_2, c_{d_2}), \ldots, (d_n, c_{d_n})\}$：已標記的文件-類別對。
- 分類函數（Classifier）$\gamma: X \to C$：一個映射函數，將任意文件對應到某個類別。

任務定義：給定訓練集 $D$，學習一個分類函數 $\gamma$，使得對於任意新的未見過的文件 $d' \in X$，$\gamma(d')$ 能夠準確預測它的類別。

形式化表述：

$$
\gamma(d) = \arg\max_{c_j \in C} \text{Score}(d, c_j)
$$

其中 $\text{Score}(d, c_j)$ 是文件 $d$ 屬於類別 $c_j$ 的某種分數（機率、相似度等，取決於使用的演算法）。

> **評註**：這個 $\arg\max \text{Score}$ 是全 Lecture 的統一骨架——Naive Bayes 把 Score 換成後驗機率、kNN 換成鄰域票數、SVM 換成決策函數值、RF 換成樹的投票數。讀後面任何模型時都可以回到這一行。

## 4. 特徵工程（一）：文件的向量表示

為了進行機器學習，我們需要將文本轉換為數值向量。

### 4.1 詞袋模型（Bag-of-Words, BoW）

- 定義：建立一個詞彙表 $V = \{w_1, w_2, \ldots, w_{|V|}\}$，包含出現在所有訓練文件中的所有不同詞。每份文件 $d$ 表示為一個 $|V|$ 維的向量 $\mathbf{x} = (x_1, x_2, \ldots, x_{|V|})$，其中 $x_i$ 是詞 $w_i$ 在文件 $d$ 中出現的次數。
- 例子：假設詞彙表為 $V = \{\text{人工}, \text{智慧}, \text{機器}, \text{學習}, \text{分類}\}$，文件「人工智慧和機器學習」表示為向量 $(1, 1, 1, 1, 0)$。
- 維度說明：如果訓練語料包含 50,000 個不同詞（在新聞語料中很常見），那麼特徵空間就是 50,000 維。

### 4.2 TF-IDF

- 定義：不用原始詞頻，而用加權詞頻。直觀上，某個詞如果在少數文件中頻繁出現，它更能代表這些文件的特徵；反之如果一個詞在幾乎所有文件中都出現，它就沒有區分性。

$$
\text{TF-IDF}(w_i, d) = \text{TF}(w_i, d) \times \text{IDF}(w_i)
$$

- **詞頻**：$\text{TF}(w_i, d) = \frac{f_{i,d}}{\sum_j f_{j,d}}$ — 詞 $w_i$ 在文件 $d$ 中出現次數除以文件 $d$ 的總詞數。
- **逆文件頻率**：$\text{IDF}(w_i) = \log\frac{|D|}{|\{d: w_i \in d\}|}$ — $|D|$ 是文件總數，分母是包含詞 $w_i$ 的文件數。
- 白話：「稀有而高頻的詞比普遍的詞更重要」。「的」和「一」在每份文件都出現，IDF 值小，TF-IDF 小，權重低。而「神經網路」在機器學習文件中高頻出現但在其他文件中稀少，IDF 大，權重高。
- 維度：同樣是詞彙表大小。

### 4.3 n-gram 模型

- 定義：不只看單個詞，而是看連續的 $n$ 個詞。詞彙表大小變為 $|V|^n$（理論上），但實際只計算出現過的 n-gram。
- **1-gram（unigram）**：單詞。「人工智慧」→ [人工], [智慧]
- **2-gram（bigram）**：雙詞。「人工智慧」→ [人工, 智慧]
- **3-gram（trigram）**：三詞。「人工智慧機器」→ [人工, 智慧, 機器]
- 優點：捕捉詞序信息，能區分「人工智慧」和「智慧人工」。
- 缺點：維度大幅增加，稀疏性加重。

### 4.4 Word Embeddings（詞嵌入）

- 定義：不用高維稀疏向量，而是用低維密集向量。通過無監督學習（如 Word2Vec、GloVe），將詞映射到 $d$ 維空間（$d$ 通常是 50-300）。
- 數學形式：詞彙表中的每個詞 $w_i$ 對應一個向量 $\mathbf{v}_i \in \mathbb{R}^d$。文件 $d$ 可以表示為其包含所有詞向量的平均：

$$
\mathbf{x}_d = \frac{1}{|d|} \sum_{w \in d} \mathbf{v}_w
$$

- 優點：維度低、密集、語義豐富（相似詞的向量相近）、通常效果更好。
- 缺點：黑盒性較高，可解釋性不如詞計數方法。

### 4.5 為什麼文件空間通常是高維空間

即使用了詞嵌入（相對低維），文本分類的特徵空間仍然遠高於其他領域：

| 領域 | 維度情況 |
|---|---|
| 圖像分類 | 輸入是 224×224 像素 = 50,176 維，但大多數像素高度相關（連續的像素），特徵空間實際複雜度低 |
| 語音識別 | 原始語音頻率達 16,000 Hz，但頻譜分析後特徵維度中等 |
| 結構化數據 | 通常只有幾十到幾百個特徵 |

文本資料不同：

- **詞彙量大**：英文主要語料的詞彙表常在 10,000-100,000。
- **長尾分佈**：99% 的詞只出現幾次，但無法忽略。
- **特徵稀疏性**：大多數詞在大多數文件中不出現。

所以，即使只是簡單的詞袋模型，文本分類也自然地發生在高維空間。

### 4.6 【Skill 規格層】四種文本特徵表示的選用規則

**【材料原文】的四項判準**（散在 4.1–4.4 各段的優缺點）＋**【評註】的決策規則**（教材沒有寫成一張表，這張表是為了 Skill 而整理，判準全部出自教材原句）：

| 表示法 | 維度 | 教材給的優點 | 教材給的缺點 | 什麼時候用（評註，依據教材判準） |
|---|---|---|---|---|
| **BoW（詞計數）** | $\|V\|$（5 萬詞語料就是 5 萬維） | 最簡單，直接可讀 | 詞頻沒有加權，停用詞會壓過關鍵詞 | 只當第一版 baseline；或當你要跑 Multinomial Naive Bayes（NB 的 $P(w\|c)$ 本來就吃詞計數，教材第 8 節） |
| **TF-IDF** | 同 $\|V\|$ | 「稀有而高頻的詞比普遍的詞更重要」，有區分性 | 仍然高維稀疏；無詞序 | **文本分類的預設選擇**。要向業務解釋「哪個詞把這篇推向這一類」時，TF-IDF + 線性模型的係數是最好講的。教材在 kNN 章也把 TF-IDF 列為文件向量的第一選項 |
| **n-gram** | 理論 $\|V\|^n$，實際只算出現過的 | 捕捉詞序，能區分「人工智慧」vs「智慧人工」 | 維度大幅增加、稀疏加重 | 當「詞序/搭配」本身就是判準時才加：品牌名（「不 + 推薦」vs「推薦」）、否定語（教材第 9 節明說 NB 假設「不」和「好」獨立是錯的，bigram 正是補這一刀）、產品型號。通常只加 bigram，且必須配 Feature Selection（第 10 節）壓維度 |
| **Word Embeddings** | 50–300 維，密集 | 維度低、語義豐富、通常效果更好 | 黑盒性較高，可解釋性不如詞計數 | 資料量夠、追求分數、且不需要逐詞解釋時。教材第 2.3 節的「大模型時代」：文本分類變成簡單的微調任務 |

**這回答什麼行銷/商業問題**（材料依據：TF-IDF 段的區分性論述 + 4.5 的結構化數據對照）：非結構化的行銷素材（評論、客服對話、商品描述）要進模型，必須先決定用「計數/TF-IDF」還是「embedding」。前者可解釋（可以直接看哪個詞推高了某類別），後者效果好但難對業務解釋——這正是行銷分析選型的核心 trade-off。此外 4.5 明說結構化數據只有幾十到幾百個特徵，意味著 CRM 表格資料的方法論（樹、RF）與文本（SVM）本來就不同。

## 5. Topic Classification 的兩個麻煩

### 5.1 層級分類（Hierarchical Classification）

在實際應用中，類別往往不是平面的，而是樹狀的層級結構。

```text
新聞
├─ 政治
│  ├─ 內政
│  └─ 外交
├─ 體育
│  ├─ 足球
│  ├─ 籃球
│  └─ 網球
└─ 娛樂
   ├─ 電影
   └─ 音樂
```

挑戰：

- **多層決策**：先判斷是否是「體育」，再判斷是「足球」還是「籃球」。錯誤在早層會傳播到後層。
- **類別相關性**：如果模型在「足球」類上出錯，預測為「籃球」，至少它預測的仍然在「體育」下，這比預測為「政治」要好。我們要利用這個層級關係。
- **計算複雜度**：簡單的方法是訓練 $|C|$ 個二元分類器（一個對所有其他）。但在層級下，能否以層級結構來優化？

常見解決方案：

- **層級 SVM / Naive Bayes**：在層級的每個節點訓練分類器。
- **不同粒度的特徵**：根據層級層數選擇不同的特徵。
- **損失函數改進**：定義層級感知的損失，錯誤預測為兄弟節點比父節點輕罰。

> **【評註】層級分類與第 19 節的呼應**：教材在「類別很多且很像時」那一節，把 **Hierarchical Classification 當成解法之一**（先分大類 5 個，再分小類，降低每層的分類難度）。所以層級結構在這門課裡有兩個身分：(1) 資料本身的麻煩；(2) 對付「50 個相近類別」的降難度手段。做電商商品自動歸類時兩件事同時發生。

### 5.2 多標籤分類（Multi-label Classification）

- 定義：一份文件可能同時屬於多個類別。
- 例子：
  - 論文「深度學習在物體檢測中的應用」→ 同時標記為「深度學習」和「物體檢測」。
  - 新聞「烏克蘭戰爭對能源供應的衝擊」→ 同時標記為「政治」、「經濟」、「能源」。
  - 商品「含糖咖啡」→ 同時標記為「飲品」和「含糖食品」。

與多類分類（Multi-class）的區別（原表為 LaTeX array）：

| 特徵 | 多類分類 | 多標籤分類 |
|---|---|---|
| 每份文件的標籤數 | 恰好 1 個 | 0 個或多個 |
| 輸出形式 | 單一類別 | 類別集合 |
| 模型複雜度 | 低（$m$ 種互斥的預測） | 高（$2^m$ 種可能的標籤組合） |

挑戰：

- **標籤相關性**：例如文件同時有「機器學習」和「特徵工程」標籤的機率，高於它們獨立出現機率的乘積。
- **不平衡標籤**：某些標籤可能非常罕見（比如「量子計算」），導致樣本不足。
- **輸出空間巨大**：可能的標籤組合達 $2^m$。如果有 100 個類別，可能的組合數是 $2^{100}$，無法窮舉。

常見解決方案：

- **二元相關性（BR, Binary Relevance）**：為每個標籤訓練一個獨立的二元分類器，忽視標籤間的相關性。
- **標籤翻譯（Label Powerset）**：把每個標籤組合當作新的類別，訓練多類分類器。
- **受限輸出空間（Classifier Chain）**：按順序訓練 $m$ 個分類器，第 $i$ 個分類器的輸入包括前 $i-1$ 個標籤的預測。
- **深度學習方法**：用 LSTM 或 Transformer 的多個輸出節點同時預測所有標籤。

> **【評註】三個解法的實務代價對照**（教材只列名字沒比較，以下是依教材各自的定義推出來的）：
> - **BR**：$m$ 個模型，可並行，最好維護；代價是丟掉標籤相關性（教材明說「忽視標籤間的相關性」），所以「政治+能源」這種常一起出現的組合學不到。多標籤的評估必須逐標籤看 P/R 再做 macro/micro 匯總（第 12 節）。
> - **Label Powerset**：把組合當新類別，相關性自動被保留；代價是類別數爆炸到 $2^m$ 且每個組合的樣本更稀疏——教材的「不平衡標籤」問題在這裡最嚴重。只適合 $m$ 很小、且實際出現的組合種類有限時。
> - **Classifier Chain**：用前 $i-1$ 個預測當特徵，能吃到相關性且模型數仍是 $m$；代價是序列相依（無法並行）＋早期錯誤會沿鏈傳播（與 5.1 層級分類的「錯誤在早層會傳播」是同一個病）。

**這回答什麼行銷/商業問題**（材料依據：商品「含糖咖啡」、產品類別樹 Electronics > Computers > Laptops）：電商商品上架自動歸類（層級）、內容/貼文自動打多標籤（多標籤）、客訴自動分派多部門。教材特別指出「不平衡標籤」——長尾商品類別樣本太少，是實務上最常爆掉的地方。

## 7. 三種分類思路：Manual / Rule-based / Statistical

> 教材原句：當我們面對分類問題時，有三條根本不同的道路可以走。它們代表了不同的哲學和權衡。

### 7.1 方式一：Manual Classification（人工分類）

**正式定義**：由人類專家手工檢查和標記文件。沒有自動化系統，只有人力。

**優點**

1. **高精度**：人類能理解複雜的語境、諷刺、文化參考等，分類準確度高。
2. **靈活適應**：新類別出現時，人類能迅速理解並開始分類。
3. **可解釋性最高**：人類能清楚解釋為什麼某份文件屬於某個類別。
4. **邊界清晰**：模糊邊界情況下，人類能做出更合理的判斷。

**缺點**

1. **極其昂貴**：需要大量訓練有素的人員。
2. **不可擴展**：網際網路每秒產生數十 GB 新內容，人工無法跟上。
3. **不一致**：不同標註者的標準可能不同（標註者間協議度 inter-rater agreement 可能不高）。
4. **耗時**：完成大規模分類可能需要數月或數年。
5. **員工流失風險**：人員離職導致知識喪失。

**使用場景**

- **Yahoo Directory（已停用）**：1990 年代的網路分類目錄，雇用編輯手工分類網站。最終因不可擴展性而放棄。
- **Open Directory Project（ODP）**：志願者版的 Yahoo Directory，完全由志願者維護。也因為規模和更新跟不上而停滯。
- **PubMed**：美國國立醫學圖書館維護的生物醫學文獻數據庫。標籤（MeSH headings）由訓練的標註者手工指定，確保醫學精度。儘管規模大（3000 萬篇論文），但靠專業人員團隊維持。
- **藝術品收藏**：博物館策展人手工分類和標記藝術品。
- **高價值決策**：法律文件審查、審計、風險評估——自動化風險太高。

**小總結（教材原文）**：人工分類是**品質保證和準確性的最後防線**。在自動化系統可靠性不足的領域（醫療、法律），仍然是首選。但對於網際網路規模的問題，已經完全不可行。

### 7.2 方式二：Rule-based Systems（規則式分類）

**正式定義**：專家或工程師手工編寫分類規則，通常採用布林邏輯的形式。每份文件通過檢查是否滿足規則來分類。

最簡單的規則是布林條件：

$$\text{Rule}_i: \quad \text{IF } (\text{condition}_1 \text{ AND/OR } \text{condition}_2 \text{ AND/OR } \ldots) \text{ THEN } \text{Class} = c_j$$

**具體例子**：垃圾郵件過濾規則

```text
Rule 1: IF (contains "viagra" OR contains "cialis") AND (from != whitelist)
        THEN Class = Spam

Rule 2: IF (sender_reputation > 0.8) AND (has_spf_record) 
        THEN Class = Legitimate

Rule 3: IF (subject contains "urgent action required" AND link_count > 5)
        THEN Class = Spam
```

**複雜規則例子**：新聞主題分類

```text
Rule_Sports: IF (contains "goal" OR contains "score" OR contains "team") 
                AND (contains "football" OR contains "basketball")
             THEN Class = Sports
             
Rule_Politics: IF (contains "parliament" OR contains "minister" OR contains "law")
               AND (contains "election" OR contains "bill" OR contains "senate")
               THEN Class = Politics
```

**優點**

1. **完全透明**：規則明確可見，任何人都能理解決策邏輯。
2. **易於調試**：如果分類錯誤，可以直接追蹤是哪條規則失效。
3. **快速**：規則匹配通常是簡單的字符串搜索，非常快。
4. **可控**：完全掌控分類決策，沒有「黑盒」。
5. **無需訓練資料**：不需要手工標記的樣本，只需要領域知識。

**缺點**

1. **工程量大**：編寫和維護規則很費時。一個好的規則系統可能需要數千條規則。
2. **脆弱**：規則對語言變體敏感。「運動」、「體育」、「比賽」可能指同一主題，需要一一列舉。
3. **難以調優**：規則間可能衝突或重疊，調整一條規則可能破壞其他規則的工作。
4. **無法學習**：規則不能從新資料中自動改進，需要人工更新。
5. **可達性有限**：某個臨界值以上不了。一個規則系統很難達到 95% 以上的精度（除非規則密集到極其複雜）。
6. **多語言成本**：對每種語言都要重寫規則。

**現實例子（教材原文）**

*垃圾郵件過濾系統的早期實現*：1990 年代，垃圾郵件過濾完全基於規則。例子：包含「Nigerian prince」→ 垃圾；包含全大寫文本 > 50% → 垃圾；寄件者不在聯繫人中且郵件包含「立即點擊」→ 垃圾。效果還不錯（當時垃圾郵件比較「笨」），但隨著垃圾郵件製造者學會規避這些規則，需要不斷添加新規則。最終，統計方法（Naive Bayes）的出現使得垃圾郵件過濾自動化、自適應。

*搜尋引擎結果排序*：Google 的早期排名也依賴許多手工規則（除了 PageRank）：頁面標題中包含查詢詞 → 加分；查詢詞在正文前 100 詞 → 加分；查詢詞在粗體或標題中 → 加分；頁面年齡（新鮮度）→ 加分或減分。這些規則有效，但隨著搜尋複雜性增加，基於學習的方法（機器學習排序，Learning to Rank）逐漸替代手工規則。

**小總結（教材原文）**：規則式系統是**透明性和可控性的巔峰**。適合用在「規則相對穩定，數量不爆炸」的場景。但對於「規則複雜，需要不斷適應」的現代應用，已經被統計和學習方法超越。有趣的是，在某些高風險領域（醫療診斷、金融決策），規則系統仍然被使用，因為可解釋性至關重要。但這些系統通常會結合機器學習（混合系統）：規則 + 學習模型。

### 7.3 方式三：Statistical / Probabilistic Systems（統計機率式）

**正式定義**：基於機率論，從訓練資料中統計學習分類規則。根據特徵和類別之間的機率關係進行分類。不同於規則式需要人工指定邏輯，統計式從資料中**自動發現規律**。

**代表方法（教材在此處先給三個縮影，細節在後面各章）**

**1. Naive Bayes**：使用貝葉斯定理計算 $P(\text{Class}|\text{Features})$。假設各特徵條件獨立，所以計算簡單。

**2. k-NN**：分類決策基於最近的 $k$ 個訓練樣本的標籤。

$$\text{Class}(x) = \text{MajorityVote}(\text{Class}(x_1), \ldots, \text{Class}(x_k))$$

其中 $x_1, \ldots, x_k$ 是距 $x$ 最近的 $k$ 個訓練樣本。優點：簡單、非參數（無需假設特定分佈）。缺點：慢（預測時要計算到所有訓練點的距離）、對特徵縮放敏感。

**3. SVM**：找一個超平面最優分割兩類（或多類），最大化分類邊界（margin）。

$$w^* = \arg\min_w \frac{1}{2}\|w\|^2 + C\sum_{i=1}^n \xi_i$$

其中 $\xi_i$ 是允許的違反邊界的懲罰項。優點：在高維空間表現優異（特別適合文本），可用核函數處理非線性。缺點：對核函數和正則化參數選擇敏感，訓練較慢。

### 7.4 No Free Lunch 定理（無免費午餐）

**定理陳述**：沒有一個統計演算法對所有問題都是最優的。在平均意義上，所有演算法的表現是一樣的。

**含義**

- 為什麼 A 演算法在某個資料集上比 B 好，在另一個資料集上卻更差？因為演算法對不同資料分佈的假設不同。
- 要找到好的演算法，必須理解你的特定問題的特性。

**對分類的啟示（這一段是第 24 節「模型假設」欄位的直接來源）**

- Naive Bayes 假設特徵條件獨立 → 在這個假設成立的資料上表現好。
- SVM 假設資料線性可分（或在高維空間線性可分）→ 對高維稀疏資料（如文本）有效。
- 決策樹假設特徵可逐層分割 → 對類別邊界由軸平行線定義的資料有效。

**實踐建議（教材原文四步）**

1. 了解你的資料特性（高維/低維、稀疏/密集、線性/非線性可分）。
2. 試試多個演算法（Naive Bayes, SVM, kNN 等）。
3. 用交叉驗證選擇最佳。
4. 不要期待一個演算法對所有問題都最優。

### 7.5 成本-精度-可解釋性對照表（教材原始 ASCII，這是很重要的一張圖）

統計式分類不同於規則式，需要投入來蒐集訓練資料：

```text
Manual Classification ←→ Rule-based ←→ Statistical ←→ Deep Learning
人工標記 0% ~ 10%       0%           20% ~ 50%      50%~100%+
成本：高                低           中等            高（但自動化程度高）
精度上限：100%          70% ~ 85%    85% ~ 95%      95%~99.5%
適應性：高              低           中等            高
可解釋性：高            高           中等            低
```

對於統計式分類，關鍵成本是**標記訓練資料**：

- **冷啟動**：要訓練一個新分類器（比如「檢測詐騙評論」），需要人工標記 500-5000 份例子。
- **維護成本**：隨著資料分佈漂移，需要不斷添加新標記資料。
- **標註質量**：標註者需要理解領域，標註不準確會嚴重影響模型。

**小總結（教材原文）**：統計式分類是現代機器學習的基礎。相比規則式，它能自動學習（隨著資料增加而改進），不需要完全的人工編寫。代價是需要訓練資料。在文本分類領域，統計方法（特別是 Naive Bayes 和 SVM）主導了 1990-2010 年代，並且至今仍廣泛使用。

**這回答什麼行銷/商業問題**（材料依據：7.5 的 ASCII 表 + 「冷啟動需要 500–5000 份標記」+ 第 19 節「一旦有 100+ 個標籤，就可以考慮機器學習」）：這張表是行銷分析專案的**報價與排程依據**。要做「詐騙評論偵測」「客訴自動分派」時，先算清楚：規則式 0 標註成本但精度天花板 70–85%；要跨過 85% 就必須付 500–5000 筆標註的錢；要上 95% 才需要談深度學習。另外「規則系統很難超過 95%」與「規則對語言變體敏感」是說服客戶從人工規則轉向模型的兩句話。

> **【評註】**：7.5 這張表的數字（精度上限 70–85% / 85–95% / 95–99.5%）是教材給的**經驗區間**，沒有引用來源，不要當成可以直接寫進提案的硬數據；但它作為「量級感」和四條路線的相對排序是這門課最實用的一張圖。

## 8. Naive Bayes 完整推導與實作流程

> 教材原句：Naive Bayes 是文本分類中最重要、最優雅的演算法之一。儘管它的假設看起來很粗糙，但在實踐中效果驚人。

### 8.1 什麼是機率分類器（Probabilistic Classifier）

**定義**：機率分類器不直接輸出一個決定，而是輸出一個機率分佈。給定文件 $d$，它計算 $d$ 屬於每個類別的機率：

$$P(c_1|d), P(c_2|d), \ldots, P(c_m|d)$$

其中 $\sum_{j=1}^m P(c_j|d) = 1$。最後，選擇機率最高的類別：

$$\text{predicted class} = \arg\max_{c_j} P(c_j|d)$$

**為什麼輸出機率而不是硬決定？（教材三個理由）**

1. **不確定性量化**：如果 $P(c_1|d) = 0.51$，$P(c_2|d) = 0.49$，我們知道這個決定很不確定。
2. **閾值調整**：在某些應用中，我們可能要調整決策閾值。例如，垃圾郵件過濾中，寧可漏掉一些垃圾，也不要誤殺正常郵件。
3. **排序和排除**：在搜尋引擎中，機率可以用來排序結果。

> **【評註】**：第 2 點是整個第 11 / 25 節（ROC、閾值、Precision vs Recall 取捨）的伏筆——**能輸出分數的模型才有閾值可以調，才畫得出 ROC**。行銷上「要不要主動打電話給這個可能流失的客戶」就是在調這個閾值。

### 8.2 先驗機率（Prior Probability）

**正式定義**：先驗機率 $P(c_j)$ 是在看到任何文件前，類別 $c_j$ 出現的機率。它完全基於訓練集中各類別的比例。

$$P(c_j) = \frac{\text{訓練集中屬於 } c_j \text{ 的文件數}}{\text{訓練集中文件總數}} = \frac{N_j}{N}$$

**例子**：假設訓練集有 1000 份郵件：800 份正常，200 份垃圾。

$$P(\text{Legitimate}) = \frac{800}{1000} = 0.8$$
$$P(\text{Spam}) = \frac{200}{1000} = 0.2$$

**白話說明**：先驗機率回答「在一無所知的情況下，某份郵件是垃圾的機率是多少？」答案就是：根據過去的經驗，80% 的郵件是正常的。

**重要性**：先驗機率體現了類別的基本頻率（base rate）。如果我們沒有任何特徵信息，最好的猜測就是選擇最常見的類別。

> **【評註】**：「沒有特徵時就猜最常見的類別」正是第 11.7 節 Accuracy 盲點裡那個「全部猜 A 得 80%」的 baseline。**先驗機率＝那個笨 baseline 的分數**，任何模型都必須明顯打贏它才叫有學到東西。

### 8.3 後驗機率（Posterior Probability）與投影片的年齡/性別表格

**正式定義**：後驗機率 $P(c_j|x_1, x_2, \ldots, x_n)$ 是在觀察到特徵 $x_1, \ldots, x_n$ 後，文件屬於類別 $c_j$ 的機率。這是我們真正想要的——根據觀察到的特徵，更新我們對類別的信念。

**例子**：現在有一份郵件，包含詞「Viagra」10 次、「Princess」5 次、「Click here」3 次（這些都是典型垃圾郵件詞）。這份郵件是垃圾的後驗機率是多少？直觀上應該遠高於先驗的 20%，可能是 95%。

**投影片表格範例（教材完整保留）**：假設有一個關於年齡和性別的表格：

| 性別 | 年齡 < 25 | 年齡 25-40 | 年齡 > 40 | 總計 |
|------|----------|----------|---------|------|
| 男性 | 100      | 150      | 75      | 325  |
| 女性 | 120      | 140      | 85      | 345  |
| 總計 | 220      | 290      | 160     | 670  |

問題：「如果一個人的年齡在 25-40 歲之間，他是男性的機率是多少？」這要求 $P(\text{Male} | \text{Age 25-40})$。根據後驗機率定義，我們只看「年齡 25-40」這一列中有多少男性：

$$P(\text{Male} | \text{Age 25-40}) = \frac{\text{年齡 25-40 且男性的人數}}{\text{年齡 25-40 的人數}} = \frac{150}{290} \approx 0.517$$

另一個方向的問題：「如果一個人是男性，他年齡在 25-40 的機率是多少？」

$$P(\text{Age 25-40} | \text{Male}) = \frac{150}{325} \approx 0.462$$

注意 $P(\text{Male} | \text{Age 25-40}) \neq P(\text{Age 25-40} | \text{Male})$，這正是貝葉斯定理要解決的問題。

**這回答什麼行銷/商業問題**：這張表就是最小的 CRM 交叉表。行銷人天天問的「25–40 歲的人裡有多少是男性」（規劃素材）和「男性裡有多少是 25–40 歲」（規劃投放）是**兩個不同的數字**，混用會讓受眾規模估錯。這是後面所有條件機率推論的地基。

### 8.4 Bayes' Rule 完整推導

**起點**：聯合機率的兩種分解方式。給定兩個事件 $A$ 和 $B$，它們的聯合機率 $P(A, B)$ 可以用條件機率表示：

$$P(A, B) = P(A|B) \cdot P(B) = P(B|A) \cdot P(A)$$

**推導步驟**：

$$P(A|B) \cdot P(B) = P(B|A) \cdot P(A)$$

兩邊同時除以 $P(B)$：

$$P(A|B) = \frac{P(B|A) \cdot P(A)}{P(B)}$$

這就是**貝葉斯定理**。

**在分類中的應用**：設 $A$ 為「類別 $c$」，$B$ 為「特徵集合 $X$」，得到：

$$P(c|X) = \frac{P(X|c) \cdot P(c)}{P(X)}$$

**各項含義**：

- **$P(c|X)$**（後驗）：給定特徵 $X$，屬於類別 $c$ 的機率。這是我們想要的。
- **$P(X|c)$**（似然度 likelihood）：給定屬於類別 $c$，觀察到特徵 $X$ 的機率。
- **$P(c)$**（先驗）：沒有任何特徵時，屬於類別 $c$ 的機率。
- **$P(X)$**（證據 evidence）：觀察到特徵 $X$ 的總機率，是一個標準化常數。

**教材的醫療檢驗白話（很重要的 base rate 教訓）**

假設一個人初步判斷某人有 1% 的機率感染某病（先驗）。但檢驗結果呈陽性。檢驗有 99% 的敏感性（給定患病，99% 機率陽性）和 99% 的特異性（給定不患病，99% 機率陰性）。那麼給定陽性結果，真正患病的機率是多少？

$$P(\text{Disease}|\text{Positive}) = \frac{P(\text{Positive}|\text{Disease}) \cdot P(\text{Disease})}{P(\text{Positive})}$$

計算：

- $P(\text{Disease}) = 0.01$
- $P(\text{Positive}|\text{Disease}) = 0.99$
- $P(\text{Positive}) = P(\text{Positive}|\text{Disease}) \cdot P(\text{Disease}) + P(\text{Positive}|\text{Not Disease}) \cdot P(\text{Not Disease}) = 0.99 \times 0.01 + 0.01 \times 0.99 = 0.0198$

代入：

$$P(\text{Disease}|\text{Positive}) = \frac{0.99 \times 0.01}{0.0198} \approx 0.50$$

教材評語：有趣的是，儘管檢驗準確度高達 99%，但一個陽性結果只能增加患病機率到 50%（從 1% 增加 50 倍）！**這是因為基本率很低。**

**這回答什麼行銷/商業問題**（材料依據：上面這個 1% base rate 例子）：行銷的正例通常極稀有——轉換率 1%、流失率 3%、詐騙率 0.1%。就算你的模型「準確率 99%」，被它標記為「會轉換」的人裡也可能只有一半真的會轉換。**向老闆解釋「為什麼名單品質沒有 99%」時，直接用這一段。** 這也是第 12 節不平衡資料處理的根本原因。

### 8.5 MAP Decision Rule（最大後驗決策規則）

我們的分類目標是選擇機率最大的類別：

$$c_{\text{MAP}} = \arg\max_{c_j \in C} P(c_j | x_1, x_2, \ldots, x_n)$$

使用貝葉斯定理展開：

$$c_{\text{MAP}} = \arg\max_{c_j} \frac{P(x_1, x_2, \ldots, x_n | c_j) \cdot P(c_j)}{P(x_1, x_2, \ldots, x_n)}$$

**關鍵觀察**：在比較不同類別時，分母 $P(x_1, \ldots, x_n)$ 對所有類別都是常數（它與我們觀察到的特徵集合有關，與類別無關）。因此可以忽略分母：

$$c_{\text{MAP}} = \arg\max_{c_j} P(x_1, x_2, \ldots, x_n | c_j) \cdot P(c_j)$$

**為什麼 $P(X)$ 可以忽略（教材的比值證明）**：

$$\frac{P(c_1|X)}{P(c_2|X)} = \frac{P(X|c_1) P(c_1) / P(X)}{P(X|c_2) P(c_2) / P(X)} = \frac{P(X|c_1) P(c_1)}{P(X|c_2) P(c_2)}$$

$P(X)$ 在分子分母中約分掉了。由於我們只關心哪個機率更大，$P(X)$ 無關。

**最終 MAP 形式**：

$$c_{\text{MAP}} = \arg\max_{c_j \in C} P(c_j) \prod_{i=1}^{n} P(x_i | c_j)$$

**教材的數值例子**：假設有兩類 Sport 和 Politics，$P(\text{Sport}) = 0.6$，$P(\text{Politics}) = 0.4$。給定一份新文件，特徵是詞「goal」和「team」：

- $P(\text{goal}|\text{Sport}) = 0.8$，$P(\text{goal}|\text{Politics}) = 0.1$
- $P(\text{team}|\text{Sport}) = 0.7$，$P(\text{team}|\text{Politics}) = 0.2$

$$P(\text{Sport} | \text{goal, team}) \propto 0.6 \times 0.8 \times 0.7 = 0.336$$
$$P(\text{Politics} | \text{goal, team}) \propto 0.4 \times 0.1 \times 0.2 = 0.008$$

因此預測類別為 Sport（0.336 > 0.008）。

> **【評註】忽略 $P(X)$ 的實務代價**：分母被丟掉之後，NB 輸出的「機率」其實只是**未歸一化的分數**。這是第 9 節「機率估不準但排序正確」的技術根源，也意味著 **NB 的輸出不能直接當成「這位客戶有 73% 會買」拿去算期望營收**；要當機率用必須先做 calibration（教材沒教這件事，見第 27 節缺漏）。

### 8.6 條件獨立假設

**條件獨立假設**：給定類別 $c$，所有特徵 $x_1, x_2, \ldots, x_n$ 條件獨立。

$$P(x_1, x_2, \ldots, x_n | c) = \prod_{i=1}^{n} P(x_i | c)$$

即聯合條件機率等於邊際條件機率的乘積。數學意義：如果 $A$ 和 $B$ 給定 $C$ 條件獨立，則 $P(A, B | C) = P(A|C) \cdot P(B|C)$。這意味著在知道 $C$ 的情況下，$A$ 和 $B$ 的發生完全獨立。

**Flu 症狀例子（教材完整版）**

假設我們要根據症狀判斷一個人是否患流感。症狀有：流鼻涕（runny nose）、竇炎（sinus）、咳嗽（cough）、發燒（fever）、肌肉酸痛（muscle ache）。

*不做獨立假設的情況*：要計算 $P(\text{runny nose, sinus, cough, fever, muscle ache}|\text{Flu})$，理論上需要考慮所有症狀間的相互依賴。例如，患有流感的人如果有流鼻涕，更可能同時有竇炎（因為它們都涉及鼻腔）。咳嗽和肌肉酸痛也常常伴隨。

要完全表示這個分佈，我們需要為所有可能的症狀組合存儲機率。有 5 個症狀，每個可能有或沒有，就是 $2^5 = 32$ 種組合。如果症狀有 20 個，組合數就是 $2^{20} = 1{,}048{,}576$！這被稱為**組合爆炸**。

*做獨立假設的情況*：

$$P(\text{runny nose, sinus, cough, fever, muscle ache}|\text{Flu})$$
$$= P(\text{runny nose}|\text{Flu}) \times P(\text{sinus}|\text{Flu}) \times P(\text{cough}|\text{Flu}) \times P(\text{fever}|\text{Flu}) \times P(\text{muscle ache}|\text{Flu})$$

現在，我們只需要 5 個條件機率，而不是 32 個聯合機率。

*假設的違反*：實際上，這個假設是**明顯錯的**。流感患者的症狀絕對不是獨立的。但 Naive Bayes 仍然常常有效，原因有兩個：(1) **分類只需要排序正確**；(2) **錯誤的方向相消**。

**最終分類公式**：

$$c_{\text{NB}} = \arg\max_{c_j \in C} P(c_j) \prod_{i=1}^{n} P(x_i | c_j)$$

等價的 log 形式（乘積變求和，既方便計算又避免數值下溢）：

$$c_{\text{NB}} = \arg\max_{c_j \in C} \left[ \log P(c_j) + \sum_{i=1}^{n} \log P(x_i | c_j) \right]$$

**這回答什麼行銷/商業問題**（材料依據：$2^{20} \approx 100$ 萬種組合的組合爆炸論述）：這一段解釋了為什麼「用 20 個客戶屬性做交叉分析」在傳統樞紐分析裡會爆掉（每個 cell 沒樣本），而 NB 用獨立假設把 100 萬個格子壓成 20 個數字。代價是丟掉屬性間的交互作用——**而交互作用正是第 22 節信用卡案例中決策樹能贏的地方**。這兩節放在一起讀，就是「NB vs 樹」的核心分歧。

### 8.7 訓練流程：TrainMultinomialNB

```text
演算法：TrainMultinomialNB(D)
輸入：訓練集 D = {(d₁, c₁), ..., (dₙ, cₙ)}
輸出：訓練好的分類器（所有機率估計）

1. 從訓練集中統計：
   - V ← 訓練集中出現的所有不同詞的集合
   - 對於每個類別 cⱼ ∈ C：
     a. ndocⱼ ← 訓練集中屬於類別 cⱼ 的文件數
     b. Nⱼ ← 訓練集中屬於 cⱼ 的所有文件中詞的總數（計重複）
     c. 對於詞彙表中的每個詞 wₖ：
        nₖⱼ ← 詞 wₖ 在類別 cⱼ 的所有文件中出現的總次數

2. 計算先驗機率：
   P(cⱼ) ← ndocⱼ / |D|  （其中 |D| 是訓練集中文件總數）

3. 計算條件機率（含 Laplace Smoothing）：
   P(wₖ|cⱼ) ← (nₖⱼ + α) / (Nⱼ + α|V|)

4. 返回所有機率估計
```

**$P(c_j)$ 的計算**：

$$P(c_j) = \frac{n_{doc_j}}{|D|}$$

例子：訓練集有 100 份文件，60 份「體育」、40 份「政治」→ $P(\text{Sport}) = 0.6$、$P(\text{Politics}) = 0.4$。

**$P(w_k|c_j)$ 的基本計算（無 Smoothing）**：

$$P(w_k | c_j) = \frac{\text{詞 } w_k \text{ 在類別 } c_j \text{ 中的總出現次數}}{\text{類別 } c_j \text{ 中所有詞的總出現次數}} = \frac{n_{k,j}}{N_j}$$

例子：訓練集中的「體育」類別文件合併後有 10,000 個詞，其中「進球」出現 150 次 → $P(\text{進球}|\text{Sport}) = 150/10000 = 0.015$。

**零機率問題（Sparse Data Problem）**

假設詞彙表有 50,000 個詞，訓練集相對較小。必然存在某些詞在某個類別中根本沒有出現過（$n_{k,j} = 0$）。例如「古墓奇兵」可能在「體育」類文件中從未出現：

$$P(\text{古墓奇兵}|\text{Sport}) = \frac{0}{10000} = 0$$

這導致問題：如果某份新文件包含「古墓奇兵」，那麼無論其他詞有多支持「體育」分類，整個乘積會變成 0：

$$P(\text{Sport} | \ldots, \text{古墓奇兵}, \ldots) \propto P(\text{Sport}) \times \cdots \times 0 \times \cdots = 0$$

教材評語：這太不合理。實際上「古墓奇兵」在「體育」類沒有出現，只是因為訓練資料限制，不代表它真的不可能在「體育」文件中出現。

### 8.8 Laplace Smoothing（拉普拉斯平滑）/ Add-one Smoothing

**目的**：為所有詞預留一點機率，避免零機率問題。

$$P(w_k | c_j) = \frac{n_{k,j} + \alpha}{N_j + \alpha|V|}$$

其中 $\alpha$ 是平滑參數（通常取 1，稱為 Add-one Smoothing），$|V|$ 是詞彙表大小。

**為什麼分母要加 $\alpha|V|$——教材的歸一化證明**：

$$\sum_{w_k \in V} P(w_k | c_j) = \sum_{w_k \in V} \frac{n_{k,j} + \alpha}{N_j + \alpha|V|} = \frac{\sum_{w_k}(n_{k,j} + \alpha)}{N_j + \alpha|V|} = \frac{(N_j + \alpha|V|)}{N_j + \alpha|V|} = 1$$

**$\alpha = 1$ 的特例**：

$$P(w_k | c_j) = \frac{n_{k,j} + 1}{N_j + |V|}$$

**例子對比（$\alpha = 1$，$|V| = 50000$）**

| 情況 | 不平滑 | 加 Laplace Smoothing |
|---|---|---|
| 「進球」在體育類出現 150 次，類別總詞數 10,000 | $150/10000 = 0.015$ | $(150+1)/(10000+50000) = 151/60000 \approx 0.00252$（略微降低） |
| 「古墓奇兵」從未在體育類出現 | $0/10000 = 0$（零機率！） | $(0+1)/(10000+50000) = 1/60000 \approx 0.0000167$（不是零了！） |

平滑的效果：出現過的詞機率略微降低；未出現的詞被分配一個小的非零機率。教材評語：這在直覺上更合理——**未看到不等於不可能**。

**平滑參數 $\alpha$ 的選擇**

- $\alpha = 0$：不平滑，會有零機率問題。
- $\alpha = 1$：最常用，Add-one Smoothing。
- $0 < \alpha < 1$：介於兩者，有時稱為 Lidstone Smoothing。
- $\alpha > 1$：過度平滑，傾向於均勻分佈。

在實踐中，$\alpha = 1$ 通常效果最好。

**這回答什麼行銷/商業問題**：新品/新活動關鍵詞在歷史資料裡從沒出現過（冷啟動），沒有平滑的模型會直接把它判成不可能，整篇評論或整封信被誤分。平滑就是「沒見過 ≠ 不可能」的工程化——上新品、開新檔期時特別重要。

### 8.9 測試流程：ApplyMultinomialNB 與 Underflow

```text
演算法：ApplyMultinomialNB(d)
輸入：新文件 d，訓練好的分類器（P(cⱼ), P(wₖ|cⱼ)）
輸出：預測的類別

1. 提取文件 d 中的詞：positions ← list of word positions in d

2. 計算每個類別的得分（使用 log 避免下溢）：
   對於每個類別 cⱼ ∈ C：
     score[cⱼ] ← log P(cⱼ)
     對於文件 d 中的每個詞位置 i：
       wₖ ← d 中位置 i 的詞
       score[cⱼ] += log P(wₖ|cⱼ)

3. 返回最高分的類別：
   return argmax_cⱼ score[cⱼ]
```

**Underflow 是什麼**：在 NB 中我們計算乘積 $P(c_j) \prod_{i=1}^{n} P(x_i | c_j)$，每個機率都是 0 到 1 之間的小數。在文本分類中 $n$ 可能很大（某份文件有數千個詞）。假設 $P(w_i|c_j) \approx 0.001$ 平均，$n = 10000$，計算機會計算：

$$(0.001)^{10000}$$

這是一個難以置信地小的數字。計算機的浮點數通常只能表示到約 $10^{-300}$，遠小於此。結果會被舍入為 0（underflow）。所以直接計算乘積是不可行的。

**Log 轉換的妙用**：利用 $\log(a \times b) = \log a + \log b$：

$$\log\left(P(c_j) \prod_{i=1}^{n} P(x_i | c_j)\right) = \log P(c_j) + \sum_{i=1}^{n} \log P(x_i | c_j)$$

現在乘積變成求和，涉及的數字不會過小。比如 $\log(0.001) \approx -6.9$，$10000 \times (-6.9) = -69000$——這是一個可以表示的數字。

**等價性證明**：

$$\arg\max_{c_j} P(c_j) \prod_{i=1}^{n} P(x_i | c_j) = \arg\max_{c_j} \left[\log P(c_j) + \sum_{i=1}^{n} \log P(x_i | c_j)\right]$$

因為對數是單調遞增的，所以 $\arg\max$ 的結果不變。

### 8.10 完整計算範例：AI / Programming 詞頻分類

**訓練資料**

- **AI 類**：10 份文件，合併後共 48 個詞（計重複）。詞彙：AI, algorithm, machine, learning, network, data, deep（其他未列出）。
- **Programming 類**：6 份文件，合併後共 42 個詞（計重複）。詞彙：code, program, network, algorithm, computer, system（其他未列出）。
- 訓練集中不同詞的總數（詞彙表）$|V| = 20$（假設）。

**第一步：計算 $P(c_j)$**

$$P(\text{AI}) = \frac{10}{10+6} = \frac{10}{16} = 0.625 \qquad P(\text{Programming}) = \frac{6}{16} = 0.375$$

**第二步：計算 $P(w_k|c_j)$（Add-one Smoothing，$\alpha = 1$）**

| 詞 | 在 AI 類次數 | 在 Prog 類次數 | $P(w\|\text{AI})$ | $P(w\|\text{Prog})$ |
|---|---|---|---|---|
| AI | 15 | 0 | $(15+1)/(48+20) = 16/68 \approx 0.235$ | $(0+1)/(42+20) = 1/62 \approx 0.016$ |
| code | 2 | 18 | $(2+1)/(48+20) = 3/68 \approx 0.044$ | $(18+1)/(42+20) = 19/62 \approx 0.306$ |
| algorithm | 10 | 5 | $(10+1)/(48+20) = 11/68 \approx 0.162$ | $(5+1)/(42+20) = 6/62 \approx 0.097$ |

**第三步：分類新文件「AI algorithm code」（用 log 形式）**

$$\log P(\text{AI} | \cdot) \propto \log(0.625) + \log(0.235) + \log(0.162) + \log(0.044)$$
$$\approx -0.470 - 1.447 - 1.821 - 3.129 = -6.867$$

$$\log P(\text{Programming} | \cdot) \propto \log(0.375) + \log(0.016) + \log(0.097) + \log(0.306)$$
$$\approx -0.981 - 4.135 - 2.334 - 1.183 = -8.633$$

**比較**：$-6.867 > -8.633$，所以預測類別為 **AI**。

**直覺檢驗（教材原文）**：「AI」在 AI 類高度出現（0.235），在 Programming 類罕見（0.016）；「code」在 Programming 類高度出現（0.306），在 AI 類少見（0.044）；「algorithm」兩類都有，但 AI 類稍多。新文件包含 AI（AI 類指標強）、algorithm（中立）、code（Programming 類指標），但 AI 的強度足夠大，所以分類為 AI。

> **【評註】這個範例值得直接搬進 Skill 當 worked example**：它同時示範了 (1) 先驗、(2) 平滑、(3) log 加總、(4) 「一個強證據可以壓過一個反向證據」的直覺，而且數字小到可以手算驗證。把「AI / Programming」換成「會續訂 / 會流失」、把詞換成客服對話裡的詞，就是一個行銷版的 NB 教學例。

## 9. 為什麼 NB 假設很爛卻常常有用

### 9.1 條件獨立假設的違反（教材舉了兩類）

**例子 1：詞的共現偏好**

- 「機器」和「學習」常常一起出現（短語「機器學習」）。
- 「深度」和「神經」常常一起出現（短語「深度神經網路」）。
- 如果文件中有「機器」，出現「學習」的機率大大增加。假設 $P(\text{學習}|\text{AI}) = 0.05$（無條件），但 $P(\text{學習}|\text{AI, 機器出現}) = 0.4$ → 違反獨立假設！

**例子 2：語言結構依賴**

- 「不」這個詞後面更可能跟消極詞語（「不好」、「不同意」）。
- 但 Naive Bayes 假設「不」和「好」的出現相互獨立。

### 9.2 關鍵洞察：分類只需要排序正確，不需要精確機率

假設兩類的真實後驗機率為 $P(\text{Class}_1|d) = 0.75$、$P(\text{Class}_2|d) = 0.25$。Naive Bayes 的計算可能給出（由於違反獨立假設）$P'(\text{Class}_1|d) = 0.62$、$P'(\text{Class}_2|d) = 0.38$。

絕對值都錯了，但排序仍然正確（0.62 > 0.38）！所以預測仍然是 Class 1，即使機率估計偏離事實。

**數學說明**：分類決策只依賴於 $\arg\max$：

$$\text{predicted class} = \arg\max_{c} P(c|d)$$

即使 Naive Bayes 計算的 $P'(c|d)$ 不準確，只要它們的相對大小排序正確，分類就是對的。而機率的精確值對於排序無關緊要。

### 9.3 NB 的實際優勢列表（教材九點）

1. **訓練極其快速**：只需要一次掃描訓練集，計算詞頻和先驗。$O(n + |V|)$ 時間複雜度。
2. **預測極其快速**：對於文件 $d$，計算 $\log P(c) + \sum \log P(w_i|c)$ 只需線性時間。
3. **小訓練集上有效**：不像深度學習需要大量資料，NB 用相對少的訓練資料也能工作。
4. **參數少**：只需要存儲 $|C| + |C| \times |V|$ 個機率。即使詞彙表很大，也可管理。
5. **可解釋性好**：可以直接看 $P(w|c)$ 理解哪些詞對某類別重要。
6. **多類別擴展簡單**：對於 $m$ 個類別，演算法複雜度只增加 $m$ 倍。
7. **實驗上有效**：儘管假設有問題，在文本分類、垃圾郵件過濾等任務上經常達到 80-90% 準確率。
8. **魯棒性**：對少量特異點（outlier）和訓練集偏差不太敏感。
9. **易於並行化**：訓練可以輕易並行化（各類別獨立計算）。

### 9.4 研究發現（教材引用）

- **Domingos & Pazzani (1997)**：即使在特徵高度相關的數據上，Naive Bayes 也常常達到最優或近最優的分類性能。原因是**錯誤傾向於相消**。
- **Rennie et al. (2003)**：多項 Naive Bayes（文本分類的標準版本）比高斯 Naive Bayes 更適合文本，因為詞計數自然遵循多項分佈。
- **工業界經驗**：垃圾郵件過濾早期完全基於 Naive Bayes，達到 98%+ 的準確率，直到今天仍在被使用。

**這回答什麼行銷/商業問題**（材料依據：9.3 的第 5 點「可以直接看 $P(w|c)$」＋ 9.2 的排序論述）：NB 適合當**行銷分析的第一版模型**：一天內做完、可以直接列出「哪些詞最像會流失的客戶」給業務看、不需要 GPU。但它的輸出**只能用來排序（選 Top N 名單），不能當成機率去算 ROI**（第 8.5 節評註）。這條界線要在提案裡講清楚。

## 10. 特徵工程（二）：Feature Selection = 單變數相關性篩選

### 10.1 為什麼需要特徵選擇

在訓練 Naive Bayes 時，詞彙表可能包含 50,000+ 個詞。並非所有詞都同等有用。

**無用的詞例子**

- **停用詞**：「的」、「是」、「一」在所有類別中幾乎等頻。
- **稀有詞**：只在 1-2 份文件中出現，不足以訓練。
- **平衡詞**：在所有類別中出現頻率相同，無區分力。

例如，在文本分類中，詞「the」（英文）或「的」（中文）在所有類別均勻分佈，無法幫助區分類別。

**特徵選擇的好處**

1. **降低計算複雜度**：特徵更少，訓練和預測都更快。
2. **改進準確率**：去除噪聲特徵，防止過擬合。
3. **改進可解釋性**：選中的特徵代表關鍵詞，更易理解模型。

### 10.2 Chi-square Test（卡方檢驗）

卡方檢驗是一種統計方法，測試詞和類別之間是否相關（獨立性檢驗）。

**建立列聯表**：對於詞 $w$ 和類別 $c$，構建 2×2 表格：

|  | 詞 $w$ 出現 | 詞 $w$ 不出現 |
|---|------------|-------------|
| 屬於 $c$ | $N_{11}$ | $N_{10}$ |
| 不屬於 $c$ | $N_{01}$ | $N_{00}$ |

其中 $N_{11}$ = 包含 $w$ 且屬於 $c$ 的文件數；$N_{10}$ = 不包含 $w$ 但屬於 $c$；$N_{01}$ = 包含 $w$ 但不屬於 $c$；$N_{00}$ = 不包含 $w$ 且不屬於 $c$。

**卡方統計量**：

$$\chi^2 = \frac{N(N_{11}N_{00} - N_{10}N_{01})^2}{(N_{11}+N_{10})(N_{11}+N_{01})(N_{10}+N_{00})(N_{01}+N_{00})}$$

其中 $N = N_{11} + N_{10} + N_{01} + N_{00}$ 是文件總數。

**解釋**：如果 $w$ 和 $c$ 獨立（不相關），$\chi^2$ 接近 0；如果 $w$ 和 $c$ 高度相關（總是一起出現或總是一起缺失），$\chi^2$ 很大。選擇 $\chi^2$ 值最大的 $k$ 個詞。

**教材的完整計算例子**：詞「進球」和類別「體育」：

|  | 進球出現 | 進球不出現 |
|---|--------|---------|
| 體育 | 150 | 50 |
| 非體育 | 10 | 790 |

$N = 1000$：

$$\chi^2 = \frac{1000(150 \times 790 - 50 \times 10)^2}{200 \times 160 \times 800 \times 840}$$

分子：$1000 \times (118500 - 500)^2 = 1000 \times 117000^2 \approx 1.37 \times 10^{16}$
分母：$200 \times 160 \times 800 \times 840 = 2.14 \times 10^{10}$
$\chi^2 \approx 640$（很大，表示強相關）

相比之下，詞「的」（停用詞）可能給出 $\chi^2 < 1$（不相關）。

### 10.3 Mutual Information（互信息）

互信息度量兩個隨機變數之間的依賴程度。詞 $w$ 和類別 $c$ 的互信息定義為：

$$I(w, c) = \sum_{w \in \{0,1\}} \sum_{c \in \{0,1\}} P(w, c) \log \frac{P(w, c)}{P(w)P(c)}$$

展開為四項：

$$I(w, c) = P(w, c) \log \frac{P(w, c)}{P(w)P(c)} + P(w, \neg c) \log \frac{P(w, \neg c)}{P(w)P(\neg c)}$$
$$+ P(\neg w, c) \log \frac{P(\neg w, c)}{P(\neg w)P(c)} + P(\neg w, \neg c) \log \frac{P(\neg w, \neg c)}{P(\neg w)P(\neg c)}$$

**解釋**：如果 $w$ 和 $c$ 獨立，$I(w, c) = 0$；如果完全相關，$I(w, c)$ 很大；$I(w, c) \geq 0$，總是非負的。

**與卡方的關係**：兩者都測量詞和類別的關聯性，但有細微差異——卡方是統計檢驗，量化觀察與獨立假設的偏離程度；互信息是資訊論角度，量化知道 $w$ 能減少多少關於 $c$ 的不確定性。

### 10.4 兩者差異對照表（教材原表）

| 方面 | Chi-square | Mutual Information |
|------|-----------|-------------------|
| 理論基礎 | 統計假設檢驗 | 資訊論 |
| 輸出範圍 | $[0, \infty)$ | $[0, \log \|C\|]$ |
| 計算複雜度 | 簡單（四則運算） | 稍複雜（含對數） |
| 對樣本大小敏感性 | 中等 | 低 |
| 實踐效果 | 好，廣泛使用 | 好，稍遜於卡方 |
| 適用場景 | 二元分類、多類別都好 | 多類別時需要適配 |

**選擇建議（教材原文）**：在實踐中，卡方檢驗因為易於計算和理解，更常被使用。但互信息在理論上更優雅。對於多類別問題，可以計算詞與每個類別的卡方/互信息，然後取最大值作為詞的重要性分數。

**這回答什麼行銷/商業問題**（材料依據：$\chi^2$ 例子中「進球 vs 體育」的 640 對比「的」的 <1）：這一節就是**單變數相關性篩選**的正式版——行銷分析裡的「哪些變數跟成交有關」。卡方適用於「類別 × 類別」（例如「是否持有黑卡」× 「是否購買」），而第 22 節的信用卡案例用的是相關係數（連續版本）。**兩者是同一件事的兩種尺**。

> **【評註】這一節與第 22 節必須連讀，這是整個 Lecture 3 最重要的方法論張力**：
> - 第 10 節教你「用單變數統計量挑特徵」（$\chi^2$ / MI 篩掉低分的詞）。
> - 第 22 節卻說「單變數相關性都很低（0.12–0.18），但三個變數組合起來購買率 85%」。
> - **兩者不矛盾，但適用前提不同**：在高維稀疏文本（幾萬個詞、詞與類別大致獨立貢獻）上做單變數篩選很有效；在低維表格（十幾個客戶屬性、交互作用強）上做單變數篩選會**誤刪掉組合後才有力的變數**。
> - 實務規則（評註）：**文本 → 先做 $\chi^2$/MI 篩選再建模；CRM 表格 → 不要用單變數相關性當去留標準，直接讓樹/RF 的 feature importance 去講話。**

## 11. 分類器評估：從 Confusion Matrix 到 ROC/AUC

### 11.1 為什麼一定要有獨立的 Test Data

**正式定義**：訓練資料（training data）與測試資料（test data）必須完全獨立，測試集中任何一筆資料都不能在訓練階段出現過。

**詳細解釋**：在機器學習中，我們的最終目標是評估模型在「未曾見過的新資料」上的泛化能力。如果測試集中的資料曾在訓練時被模型看見、學過，那麼模型的表現只是在反映「記住訓練資料」的能力，而非「理解規律、預測新資料」的能力。這種現象稱為**資料洩漏（data leakage）**。評估指標就會嚴重高估模型在實務中的真實表現。

**白話說明（教材「學長帶學弟」語氣）**：想像你給班上同學出考題。如果考卷就是上課時用過的原題，那麼考出來的成績根本不知道他們到底會不會。要真的測出他們的實力，你得出從沒出現過的新題。

### 11.2 Confusion Matrix（混淆矩陣）

| | 實際正類 | 實際負類 |
|---|---|---|
| **預測正類** | TP | FP |
| **預測負類** | FN | TN |

- **TP（True Positive，真陽性）**：模型預測為正，實際也是正。又稱「命中」（hit）。
- **TN（True Negative，真陰性）**：模型預測為負，實際也是負。又稱「正確拒絕」（correct rejection）。
- **FP（False Positive，偽陽性）**：模型預測為正，實際卻是負。又稱「假警報」（false alarm）或「第一型錯誤」（Type I error）。
- **FN（False Negative，偽陰性）**：模型預測為負，實際卻是正。又稱「未命中」（miss）或「第二型錯誤」（Type II error）。

**白話說明**：想像醫生用檢查結果判斷你有沒有生病。TP 就是「確實有病，也查出來了」，TN 是「沒病，也沒誤診」；FP 是「其實沒病，卻被誤診」（假警報），FN 是「有病卻被漏掉了」（最危險的）。醫療診斷時，FN 和 FP 的嚴重程度不同。

### 11.3 Precision（精確率／查準率）

$$P = \frac{TP}{TP + FP}$$

**解釋**：在所有被模型預測為「正類」的樣本中，有多大比例其實真的是正類。分母 $TP + FP$ 是模型做出的所有「肯定判斷」，分子 $TP$ 是其中正確的。若一個分類器的精確率為 0.8，代表它說「是正類」的 10 個案例中，平均有 8 個確實是，2 個是誤判。

**白話**：「你說對了多少比例？」比如搜尋引擎回傳 100 個結果，其中 80 個真的相關，精確率就是 80%。精確率高代表「不亂報」。**教材給的應用場景**：郵件過濾時不想誤刪重要信件、投資建議時不想害人虧錢，這時要求高精確率。

### 11.4 Recall（召回率／查全率）

$$R = \frac{TP}{TP + FN}$$

**解釋**：在所有真正是「正類」的樣本中，有多大比例被模型正確地找了出來。分母 $TP + FN$ 是實際存在的所有正類。若召回率為 0.9，代表真實的 10 個正類案例中，模型找到了 9 個，漏掉了 1 個。

**教材的推導邏輯（P/R 為何衝突）**：在分類評估時，有兩種「遺憾」：(1) 誤判負類為正類（FP 造成的），(2) 漏掉真正的正類（FN 造成的）。Precision 懲罰第一種，Recall 懲罰第二種。它們的目標衝突：**要提高 Recall，可以把閾值降低，把更多東西歸為正類，但這樣 FP 會增加，Precision 會下降。**

**別名**：召回率也稱為 True Positive Rate（TPR，真陽性率）、Sensitivity（敏感度，醫學領域常用）、Hit Rate（命中率）。

**白話**：「你漏掉了多少？」比如要查出所有欠債的人，找到了 90 個，其實應該有 100 個，召回率就是 90%。**教材給的應用場景**：疾病篩檢時漏掉患者很危險、法律搜查時漏掉證據很嚴重，這時要求高召回率。

### 11.5 其他相關指標

**False Positive Rate（FPR，偽陽性率／假警報率）**

$$\text{FPR} = \frac{FP}{FP + TN}$$

在所有實際為負類的樣本中，有多少被模型誤判為正類。FPR 越低越好。

**Accuracy（準確率）**

$$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} = \frac{TP + TN}{\text{全部}}$$

模型預測正確的樣本數佔全部樣本的比例。這是最直觀的指標，**但在類別不平衡時會很有問題**。

**Specificity（特異度）**

$$\text{Specificity} = \frac{TN}{FP + TN} = 1 - \text{FPR}$$

在所有實際為負類的樣本中，有多少被正確地判為負類。與 Recall 對稱：Recall 看正類被抓住的比例，Specificity 看負類被正確排除的比例。

### 11.6 F1 Score 與調和平均的完整推導

$$F_1 = \frac{2PR}{P + R}$$

F1 Score 是 Precision 和 Recall 的**調和平均數**（harmonic mean），而非算術平均數。調和平均數的定義：

$$H = \frac{n}{\frac{1}{x_1} + \frac{1}{x_2} + \cdots + \frac{1}{x_n}}$$

對於 Precision 和 Recall 兩個值，推導如下：

$$\frac{1}{F_1} = \frac{1}{2}\left(\frac{1}{P} + \frac{1}{R}\right)$$

兩邊同乘 $F_1$：

$$1 = \frac{1}{2}\left(\frac{F_1}{P} + \frac{F_1}{R}\right)$$

兩邊同乘 2：

$$2 = \frac{F_1}{P} + \frac{F_1}{R} = F_1\left(\frac{1}{P} + \frac{1}{R}\right) = F_1\left(\frac{P+R}{PR}\right)$$

$$F_1 = \frac{2PR}{P+R}$$

**為什麼要用調和平均而非算術平均**：假設 $P = 0.9, R = 0.1$，

- 算術平均 = $(0.9 + 0.1) / 2 = 0.5$，看起來還不錯。
- 調和平均 = $\frac{2 \times 0.9 \times 0.1}{0.9 + 0.1} = \frac{0.18}{1} = 0.18$，一下子掉下來。

調和平均的特性是**只要一個值很小，整體就被嚴重拖下來**。這符合實務需求：分類器不應該「只擅長精確但漏掉一堆」或「只擅長召回但誤報一堆」，要兩者都顧到才算好。

**白話**：「P 和 R 要一起好，F1 才會好；有一個爛掉就沒救」。比如某個疾病檢測器，精確率 95% 但召回率只有 30%，那它找到的患者很可信，但漏掉了七成患者，整體不行。F1 會把這個矛盾暴露出來。

### 11.7 Accuracy 的盲點（多數類陷阱）

**問題場景**：考慮一個不平衡的資料集——類別 A：800 筆；類別 B：200 筆；合計 1000 筆。若分類器採用「全部猜 A」的策略：預測正確 800 筆，Accuracy = $800/1000 = 80\%$。

看起來 accuracy 很高，但模型實際上什麼都沒學會——它就是坐享 A 類的高比例。**此時對 B 類的 Precision、Recall、F1 都是 0%。**

**嚴格解釋**：Accuracy 公式為 $\text{Accuracy} = \frac{c}{n}$（$c$ 是正確預測數，$n$ 是總樣本數）。在**類別分布高度不平衡**的情況下，多數類的樣本數會主導分子，使得 Accuracy 被「多數類陷阱」（majority class trap）所困。一個毫無區分能力的「總是預測多數類」的分類器，也會獲得看起來不低的 Accuracy。

**白話**：分班考試中，某班有 80 個人，其中 8 個成績差。用 accuracy 只會看全班有多少人及格，卻看不出那 8 個弱生有沒有進步。你得分別看弱生的進度，才算真的評估有效。

### 11.8 ROC Curve 與 AUC

**背景與動機**：大多數分類器（如邏輯迴歸、SVM）並非直接輸出 0/1 標籤，而是輸出**置信度或分數**。我們通過設定**分類閾值**（threshold）來決定：當分數超過閾值時預測為正，否則為負。不同閾值會導致不同的 Precision、Recall。

**ROC Curve 的定義**：ROC（Receiver Operating Characteristic）曲線繪製**不同閾值下分類器的表現**：

- X 軸：$\text{FPR} = \frac{FP}{FP + TN}$
- Y 軸：$\text{TPR} = \frac{TP}{TP + FN} = \text{Recall}$

**閾值變化時的軌跡**

- **最嚴格閾值**（例如要求 99% 確定才預測為正）：幾乎所有樣本都被預測為負，故 TP ≈ 0, FP ≈ 0，點位置為 (0, 0)。
- **最寬鬆閾值**（例如任何正分數都預測為正）：所有樣本都被預測為正，故 TP = 全部正類, FP = 全部負類，點位置為 (1, 1)。
- **完美分類器**（可完全分離）：沿著 (0, 0) → (0, 1) → (1, 1) 這條路徑，先把所有正類找齊（TPR=1）再說負類（FPR 才增加）。

**ROC 曲線的性質**

1. ROC 曲線總是從 (0, 0) 開始，到 (1, 1) 結束。
2. **對角線** $y = x$ 代表「隨機分類器」：任意猜測 50% 正類、50% 負類。
3. **曲線越往左上方凸起**，分類器越好。
4. 曲線**完全在對角線上方**，代表模型勝過隨機。

**AUC（Area Under the ROC Curve）**：ROC 曲線下方的面積，範圍在 0 到 1。

**AUC 的統計學解釋**：**隨機選一個正類樣本和一個負類樣本，分類器給正類分配更高分數的概率**。設隨機正類樣本分數為 $s_p$，隨機負類樣本分數為 $s_n$：

$$\text{AUC} = P(s_p > s_n)$$

**AUC 的解讀（教材的分級）**

| AUC | 意義 |
|---|---|
| 0.5 | 與隨機分類無異 |
| 0.7 ~ 0.8 | 分類器有一定區分能力 |
| 0.8 ~ 0.9 | 相當不錯的分類器 |
| 0.9 以上 | 非常強的分類器 |
| 1.0 | 完美分類 |

**為什麼 AUC 比 Accuracy 更好（教材三點）**

1. **不受分類閾值影響**：AUC 整合了所有可能的閾值下的表現。
2. **處理類別不平衡**：即使正負類樣本數差異大，AUC 仍然有意義。
3. **單一數字總結**：把整條 ROC 曲線濃縮成一個值，便於比較。

**白話（教材的警察比喻）**：想像你是警察，調整查案標準的嚴格度——標準很嚴時，你抓的都是真正嫌疑人（低 FPR），但漏掉了不少（低 TPR），點在左下；標準很鬆時，什麼人都想查（高 FPR），但確實把大部分嫌疑人都抓了（高 TPR），點在右上。ROC 曲線就是把你在所有標準下的表現都連起來，AUC 就是這條曲線的面積。

### 11.9 Naive Bayes vs 其他方法的 Reuters 比較

**資料集簡介**：Reuters 是經典文本分類資料集——文件總數約 800,000 篇；詞彙量（word types）約 400,000 個詞；類別數多類別（約 90 多個主題類別）；特徵為 TF-IDF 向量或其他統計特徵。

**不同演算法的 F1 對比（教材原表）**

| 方法 | 代表特性 | 典型 F1 | 優點 | 缺點 |
|---|---|---|---|---|
| **Naive Bayes (NB)** | 機率圖模型 | ~0.74~0.78 | 訓練快、可解釋 | 特徵獨立假設太強 |
| **Rocchio** | 向量空間、相似度 | ~0.68~0.72 | 簡單直觀 | 不夠靈活 |
| **kNN** | 鄰域投票 | ~0.75~0.80 | 無需訓練、非參數 | 測試慢、維度詛咒 |
| **Decision Trees** | 樹狀分割 | ~0.72~0.76 | 易解釋、可處理非線性 | 容易過擬合、對文本效果一般 |
| **SVM** | 最大邊界 | ~0.82~0.86 | **最穩定、最高效** | 參數調優複雜 |

**實驗結論（教材四點）**

1. **Naive Bayes 表現不俗**：在快速分類、特別是資料量不足時，NB 常有不錯表現；但整體仍不如 SVM。
2. **SVM 通常最強且最穩定**：特別在高維稀疏特徵（文本特有）上表現優異。
3. **kNN 中等偏上**：不需訓練，但測試時計算成本高。
4. **Rocchio 和 Trees 次之**：前者理論簡單但缺乏表現力，後者容易過擬合。

> **【評註】注意這張表與第 18 節 Fernández-Delgado 研究的表面矛盾**：這裡「決策樹對文本效果一般（0.72–0.76），SVM 最強」；第 18 節卻是「179 個分類器、121 個資料集，Random Forest 排名第一」。**不矛盾——因為資料型態不同**：Reuters 是高維稀疏文本（SVM 的主場）；UCI 121 個資料集以表格資料為主（RF 的主場）。這正是母頁流程圖第一個分岔問「資料型態？」的原因。**行銷分析多半是表格 + 文本混合，所以兩個結論都要記住。**

## 12. 不平衡資料的處理，與 micro / macro / weighted 平均

### 12.1 教材給的不平衡資料應對方案（原文四點）

當遇見類別不平衡資料時：

1. **不用 Accuracy 作為主要評估指標**，改用 Precision、Recall、F1。
2. **分別計算各類別的 Precision 與 Recall**，看是否有某個類別表現極差。
3. **使用 macro-averaged 或 weighted-averaged 指標**。
4. **在訓練時採用類別加權**或 oversampling / undersampling 等技巧。

> **【評註】教材對第 4 點只有這一行，沒有細節。以下是為了 Skill 補的最小可用說明（教材未涵蓋，屬評註）**：
> - **class weight（類別加權）**：在損失函數裡把少數類的錯誤放大（例如權重 = 反比於類別頻率）。不改變資料、不製造假樣本，是**首選**，因為它不會破壞資料分布，也不會有重複樣本造成的樂觀偏誤。SVM 的 $C$ 可以逐類設定（第 14 節的 $C$ 就是這個鈕）、樹/RF 也普遍支援。
> - **oversampling（過抽樣）**：複製或合成少數類樣本。純複製會讓模型過擬合到那幾筆；合成法（如 SMOTE）教材完全沒提。
> - **undersampling（欠抽樣）**：丟掉多數類樣本。資料量夠大時可行且訓練變快，但丟掉的是真實資訊。
> - **極重要的一條紀律（教材未寫）**：任何重抽樣**只能在訓練集上做，測試集必須保持原始分布**，否則第 11.1 節的 data leakage 就發生了，評估數字會虛高。

### 12.2 Macro-averaging（宏平均）

**正式定義**：

1. 分別計算每個類別 $i$ 的 Precision $P_i$、Recall $R_i$、F1 $F_{1,i}$。
2. 對所有類別取算術平均：

$$P_{\text{macro}} = \frac{1}{n}\sum_{i=1}^{n} P_i \qquad R_{\text{macro}} = \frac{1}{n}\sum_{i=1}^{n} R_i \qquad F_{1,\text{macro}} = \frac{1}{n}\sum_{i=1}^{n} F_{1,i}$$

其中 $n$ 是類別總數。

**特點**：**每個類別獲得等權重，無論該類別的樣本多寡。**

### 12.3 Micro-averaging（微平均）

**正式定義**：

1. 把所有類別的 TP、FP、FN 逐個加總：

$$\text{TP}_{\text{total}} = \sum_{i=1}^{n} TP_i, \quad \text{FP}_{\text{total}} = \sum_{i=1}^{n} FP_i, \quad \text{FN}_{\text{total}} = \sum_{i=1}^{n} FN_i$$

2. 用加總後的數值計算全域指標：

$$P_{\text{micro}} = \frac{\text{TP}_{\text{total}}}{\text{TP}_{\text{total}} + \text{FP}_{\text{total}}} \qquad R_{\text{micro}} = \frac{\text{TP}_{\text{total}}}{\text{TP}_{\text{total}} + \text{FN}_{\text{total}}}$$

$$F_{1,\text{micro}} = \frac{2 P_{\text{micro}} R_{\text{micro}}}{P_{\text{micro}} + R_{\text{micro}}}$$

**特點**：**大類別由於樣本數多，對全域指標的影響更大，相當於隱含地按類別大小加權。**

### 12.4 數值範例（教材完整保留）

考慮三類分類，類別樣本數與準確率如下：

| 類別 | 樣本數 | Accuracy |
|---|---|---|
| Class A | 800 | 80% |
| Class B | 100 | 60% |
| Class C | 100 | 60% |
| **合計** | **1000** | — |

假設三個類別的 TP、FP、FN 都恰好對應這些數字（簡化計算）：

**Macro-averaging**：

$$\text{Macro Accuracy} = \frac{80\% + 60\% + 60\%}{3} = 66.67\%$$

**Micro-averaging**：

$$\text{Micro Accuracy} = \frac{800 \times 0.8 + 100 \times 0.6 + 100 \times 0.6}{1000} = \frac{640 + 60 + 60}{1000} = 76\%$$

**相等條件**：**若各類別的樣本數都相同，則 Macro = Micro。**

### 12.5 白話說明與選擇指南（教材原文）

想像班級考試成績：Class A 有 800 人，B 和 C 各 100 人。

- **Macro 平均**就是「每班算平均，再對三班取平均」。B 班和 C 班雖然人少，但在整體評分裡跟 A 班一樣重要。這方法**照顧「弱勢班級」**。
- **Micro 平均**就是「全校統一算」，A 班 800 人的成績權重遠高於 B、C 班。這方法**反映「全校整體表現」**。

選擇時：

- 如果**各類別同樣重要**（e.g. 醫學診斷中各罕見疾病都很關鍵），用 **Macro**。
- 如果**關心整體效能**或**類別數量反映真實分布**，用 **Micro**。

### 12.6 【Skill 規格層】micro / macro / weighted 的差異與選擇時機

**【材料原文】的三個事實**

1. Macro = 各類指標的算術平均，每類等權。
2. Micro = 先加總 TP/FP/FN 再算，等於隱含按類別大小加權。
3. 類別樣本數相同時，Macro = Micro。

**【評註】補完 weighted 與三者的關係**（教材只在 12.1 提到 weighted-averaged 這個詞，沒給定義）：

$$P_{\text{weighted}} = \sum_{i=1}^{n} \frac{N_i}{N} P_i \qquad \text{其中 } N_i \text{ 是類別 } i \text{ 的真實樣本數}$$

三者的關係可以這樣記：

| 平均方式 | 權重來源 | 大類主導？ | 小類被看見？ | 在單標籤多類別下的特性 |
|---|---|---|---|---|
| **Macro** | 每類 $1/n$ | 否 | **是**（小類的爛分數會直接拉低總分） | 最嚴格，最能揭露長尾失效 |
| **Micro** | 隱含 = 各類樣本數 | **是** | 否（小類幾乎無影響） | 在單標籤多類別任務中，micro-P = micro-R = micro-F1 = Accuracy（評註） |
| **Weighted** | 明確 = $N_i/N$ | **是** | 部分（至少每類都算過一次 P/R） | 數值接近 micro，但保留了「逐類先算再加權」的結構 |

**選擇規則（評註，判準全部源自教材 12.5）**

1. **問題本身在意小類 → Macro。** 行銷例：長尾商品類別自動歸類、客訴類型分派（「資安投訴」件數少但一件都不能漏）。教材原句依據：「各類別同樣重要，用 Macro」。
2. **問題在意整體流量／成本 → Micro（或 Accuracy）。** 行銷例：全站商品自動打標，你在乎的是「總共錯幾件、要人工修幾件」，這時大類本來就該主導。教材原句依據：「關心整體效能或類別數量反映真實分布，用 Micro」。
3. **要對外報一個數字但不想被大類完全綁架 → Weighted。**（評註）
4. **兩個都報，並看差距。**（評註，但這是最實用的一條）：**Macro 遠低於 Micro ＝ 你的模型在小類上失效了**。這個差距本身就是最有用的診斷訊號，比任何單一數字都有價值。第 12.4 的例子就是示範：66.67% vs 76%，差 9.3 個百分點，說明兩個小類明顯較弱。

**這回答什麼行銷/商業問題**：老闆問「模型準不準」時，回答哪個數字會決定專案生死。做「客訴自動分派」如果只報 micro/accuracy，長尾類別（件數少但重要）全錯也看不出來，上線後爆炸；做「全站商品打標」如果只報 macro，會被幾個只有 5 筆樣本的冷門類別拖成低分而被砍案。**先問「這個類別漏掉的商業代價」，再選平均方式。**

## 13. kNN（k-Nearest Neighbors）

### 13.1 向量空間觀點與相似性假設

kNN 建立在一個核心假設之上：

> **Similarity Hypothesis：相似的文件（或特徵向量）應該屬於相似的類別。**

在向量空間中，文件被表示為 $d$ 維空間裡的一個點。每份文件 $d$ 可以用一個向量 $\vec{v}(d) \in \mathbb{R}^d$ 表示。在文本分類中，常見的表示方法包括：

1. **TF-IDF 向量**：第 $i$ 維對應詞典中第 $i$ 個詞的 TF-IDF 值。
2. **詞頻向量**：第 $i$ 維是詞 $i$ 的出現次數或比例。
3. **One-hot 向量**（對於受限詞彙）：出現則 1，不出現則 0。
4. **嵌入向量**（modern 方法）：Word2Vec、BERT 等向量表示。

**距離度量**

$$\text{距離}(\vec{x}, \vec{y}) = \sqrt{\sum_{i=1}^{d} (x_i - y_i)^2} \quad \text{（歐幾里得距離）}$$

或使用餘弦相似度（**特別適合文本**）：

$$\text{sim}_{\cos}(\vec{x}, \vec{y}) = \frac{\vec{x} \cdot \vec{y}}{\|\vec{x}\| \|\vec{y}\|}$$

**白話**：把每份文件看成平面（或高維空間）裡的一個點，詞彙越接近、詞頻越相似，點就離得越近。相同主題的文件會自然聚在一塊。kNN 就是說：看你周圍最近的 $k$ 個鄰居是什麼，你就跟他們是一類人。

### 13.2 kNN 的基本規則

給定測試文件 $d$，kNN 分類演算法執行以下步驟：

1. 計算 $d$ 與所有訓練文件 $d_1, d_2, \ldots, d_n$ 的相似度（或距離）。
2. 選出相似度最高的 $k$ 個訓練文件，記為 $N_k(d)$（$d$ 的 $k$ 近鄰）。
3. 在這 $k$ 個鄰居中進行**多數投票**（majority voting）。
4. 將 $d$ 分類為獲票最多的類別。

**機率解釋**：設 $c$ 為某個類別，$i$ 為 $d$ 的 $k$ 個最近鄰中屬於類別 $c$ 的數量，則：

$$P(c|d) \approx \frac{i}{k}$$

即 $d$ 屬於類別 $c$ 的機率，近似於其鄰域內屬於 $c$ 的比例。

**白話**：「看你旁邊最近的 $k$ 個人，大多是哪一類，你就是哪一類」。比如在派對裡，如果你周圍 5 個人有 4 個是工程師、1 個是設計師，多數投票就說你也是工程師。

### 13.3 為什麼 k 不能只取 1

若 $k=1$（只看最近的一個鄰居），這種方法稱為「最近鄰」（Nearest Neighbor, NN）。教材列出三個問題：

1. **非典型樣本的影響**：若訓練集中有某個「離群值」（outlier），孤立在遠離其所屬類別的地方，當測試文件恰好離這個 outlier 最近時，就會被錯誤分類。舉例：垃圾郵件分類中若訓練集有個被錯誤標記為「正常郵件」的垃圾郵件，任何新垃圾郵件只要特徵相近就會被誤分。
2. **標籤錯誤的脆弱性**：訓練資料難免有人工標籤的錯誤。$k=1$ 時一個標籤錯誤就能決定整個分類。
3. **噪音放大**：即使標籤正確，測試文件若因巧合而靠近某個邊界樣本，也會被誤導。

**取多個鄰居的穩定性**：當 $k > 1$（例如 $k=5$）：需要多數鄰居同意才能改變分類；單一錯誤、噪音或 outlier 的影響被平均化了；決策更加穩健。

**$k$ 的選擇**：在實務中，$k$ 通常通過**交叉驗證**（cross-validation）來選擇——在訓練集上進行 5 折或 10 折交叉驗證；對每個 $k$ 值（如 1, 3, 5, 7, 10, …）測試；選擇驗證集誤差最小的 $k$。

**白話**：問 1 個朋友「我這件衣服好不好看」，他可能剛心情不好隨便說不好。問 5 個朋友，少數幾個人的壞心情影響不了多數人的判斷。

### 13.4 kNN 的優缺點

**優點**

1. **演算法直觀**：概念簡單，容易理解與解釋。「近朱者赤，近墨者黑」這個人類直覺與 kNN 完全吻合。
2. **無需顯式訓練**：不像決策樹或 SVM，kNN 不需要在訓練階段學習參數。唯一的「訓練」就是存儲訓練資料。
3. **非參數方法**：不對資料分布做假設（如 Naive Bayes 假設條件獨立），因此具有高度靈活性。
4. **多類別友好**：直接支援多類別分類，無需額外轉換（如 SVM 的 OvA/OvO）。
5. **常有不錯準確率**：在許多實務應用中，kNN 的表現往往出乎意料地好。

**缺點**

1. **測試時計算昂貴**：每次預測都要計算新文件與所有訓練文件的相似度，時間複雜度為 $O(n \times d)$。訓練集 800,000 文件時，每次預測都很慢。
2. **訓練集越大越慢**：與大多數學習演算法相反（訓練慢、測試快），kNN 是**訓練快但測試慢**。這在需要實時預測的場景下很受限。
3. **需要優質的相似度度量**：kNN 的成敗完全在於距離函數。若距離度量不當，演算法無法發揮。
4. **維度詛咒（Curse of Dimensionality）**：在高維空間中，所有點之間的距離趨於相同，鄰域概念變得模糊。文本通常有成千上萬的特徵，容易觸發此問題。
5. **記憶體開銷大**：需要存儲所有訓練資料，對大型資料集不友善。

**白話**：kNN 像個記憶力超強的同學：他上課不用做什麼，就是把所有題目都背下來。考試時你問他問題，他翻翻記錄本，找出最像的幾道題，告訴你答案。優點是他永遠不會「過擬合」（非常靈活），缺點是每次回答都得翻一堆題目，要是題目有 100 萬道，他就得查好久。

### 13.5 與 Inverted Index 的關係（IR 技術移植到分類）

**Inverted Index 基礎**：一個反向映射

$$\text{term} \rightarrow \{\text{(doc\_id, term\_frequency)}\}$$

即對每個詞，記錄出現該詞的所有文件及其詞頻。構建時間 $O(n \times d)$，但查詢非常快。

**應用於 kNN 加速**：在 kNN 分類時，測試文件 $d_{\text{test}}$ 的最近鄰搜尋可視為一個「檢索問題」：

1. 把 $d_{\text{test}}$ 視為查詢（query）。
2. 用 inverted index 快速找出與 $d_{\text{test}}$ 共享詞彙的訓練文件。
3. 只在這些候選文件中計算距離，而非全部 $n$ 個文件。

**效率提升**

- **未優化 kNN**：計算全部 $n$ 個距離，$O(n \times d)$。
- **用 Inverted Index 優化**：候選文件數通常遠小於 $n$，時間降至 $O(k' \times d)$，其中 $k' \ll n$。

**更深層的洞察（教材原文）**：IR 的許多技術不僅用來搜尋，也能支援分類——TF-IDF 計算方式同時適用於 IR 和分類的文件向量化；文件相似度度量（如餘弦相似度）在兩領域都是標準做法；Inverted index、query expansion、pseudo-relevance feedback 等 IR 技術都能被移植到分類。

**白話**：假設你是圖書館館員，要從 100 萬本書中快速找出和新書《機器學習基礎》最相似的 10 本。不可能逐本比較。但如果你有個反向索引：「'決策樹' 出現在 {書 A, 書 B, 書 C, …} 這些書裡」，你就能快速找出包含關鍵詞的書，然後只在這個小集合裡比較。

**這回答什麼行銷/商業問題**（材料依據：13.1 的 similarity hypothesis + 13.4 的「無需訓練」）：kNN 是「**找像他的人**」這類行銷問題的直接對應物——lookalike 受眾擴展、相似商品推薦、「跟這位高價值客戶最像的 100 個潛在客」。它的優點（無需訓練、隨時加入新資料就生效）正好對上行銷資料每天在變；缺點（預測 $O(n)$）意味著它適合離線批次跑名單，不適合即時 API。

## 14. SVM（Support Vector Machines）

### 14.1 核心思想：不只要分開，要找最穩的那條線

傳統的線性分類（如 Naive Bayes 或簡單的邏輯迴歸）只需要找一條能「分開」正負類的決策邊界。但 SVM 的哲學不同：

> **SVM 不只要分開，更要找到「最穩」的那條線。**

**詳細解釋**：給定可線性分離的資料，存在無限多條分隔線都能完美分開正負類。但並非所有分隔線在「未曾見過的新資料」上表現相同。靠近資料點的分隔線容易過擬合：新來的邊界附近點稍微擾動就會被誤分。而「離兩邊資料都遠」的分隔線對邊界擾動更有容忍度，泛化能力更強。

**Large-Margin Classifier**：SVM 的目標是找一個決策邊界，使得

$$\text{到最近資料點的距離（邊界寬度）最大}$$

**優點（教材三點）**

1. **對邊界附近點不敏感**：即使測試集有些點在邊界附近，也不易被誤分。
2. **更好的泛化能力**：在獨立測試集上表現更佳，不會因訓練集的細微特徵而過擬合。
3. **統計學基礎**：大邊界等價於降低 VC 維（Vapnik-Chervonenkis dimension），從而降低泛化誤差上界。

**白話**：想像你要在馬路上畫一條線，把左邊的停車格和右邊的草坪分開。最偷懶的做法是貼著某邊的邊緣畫，但稍微有點誤差就會跨界。聰明的做法是畫在中間。要是馬路稍微移動一點，這條中線還是能正確分隔。

### 14.2 超平面的數學定義與 margin 寬度推導

在 $d$ 維空間中，超平面（hyperplane）是一個 $(d-1)$ 維的子空間：

$$\vec{w}^T \vec{x} + b = 0$$

其中 $\vec{w} \in \mathbb{R}^d$ 是法向量、$\vec{x} \in \mathbb{R}^d$ 是空間中的點、$b \in \mathbb{R}$ 是偏置項。

**幾何意義**：$\vec{w}$ 的方向垂直於超平面；$\vec{w}/\|\vec{w}\|$ 是單位法向量；距離超平面的有向距離可由 $\frac{\vec{w}^T \vec{x} + b}{\|\vec{w}\|}$ 給出。

**分類規則**：若 $\vec{w}^T \vec{x} + b > 0$ 分類為 $+1$（正類）；若 $< 0$ 分類為 $-1$（負類）。

**支持邊界**：SVM 定義兩條平行於決策邊界的超平面：

$$\vec{w}^T \vec{x} + b = +1 \quad \text{（正類邊界）} \qquad \vec{w}^T \vec{x} + b = -1 \quad \text{（負類邊界）}$$

這兩條邊界之間的區域稱為**邊界間隙（margin）**。

**邊界寬度**：

$$\rho = \frac{|1 - (-1)|}{\|\vec{w}\|} = \frac{2}{\|\vec{w}\|}$$

**教材的完整推導**：取 $+1$ 超平面上一點 $\vec{x}_+$，滿足 $\vec{w}^T \vec{x}_+ + b = 1$。沿著法向量 $\vec{w}$ 方向移動距離 $d$，到達點 $\vec{x}_- = \vec{x}_+ - d \frac{\vec{w}}{\|\vec{w}\|}$。要使該點落在 $-1$ 超平面上，需：

$$\vec{w}^T \left(\vec{x}_+ - d \frac{\vec{w}}{\|\vec{w}\|}\right) + b = -1$$

$$1 - d \frac{\vec{w}^T \vec{w}}{\|\vec{w}\|} = -1 \quad \Rightarrow \quad 1 - d \|\vec{w}\| = -1 \quad \Rightarrow \quad d = \frac{2}{\|\vec{w}\|}$$

**最大化邊界的目標**：

$$\text{maximize} \quad \rho = \frac{2}{\|\vec{w}\|} \quad \Leftrightarrow \quad \text{minimize} \quad \|\vec{w}\| \quad \Leftrightarrow \quad \text{minimize} \quad \frac{1}{2}\|\vec{w}\|^2$$

### 14.3 Support Vectors

**正式定義**：支持向量（Support Vectors）是指那些在最優決策邊界下，恰好位於邊界線上（$\vec{w}^T \vec{x} + b = +1$ 或 $-1$）的訓練樣本。

**關鍵特性**

1. **決定邊界的關鍵點**：SVM 的決策邊界只由支持向量決定，與其他訓練點無關。
2. **數量通常遠少於訓練集**：假設訓練集有 10,000 個樣本，支持向量可能只有 100 個。
3. **邊界上的點**：移動任何非支持向量，只要不越過邊界，都不會改變 SVM 的決策面。

**白話**：想像你在指揮一場球隊的防守。球隊的防線（決策邊界）只由「最靠前的進攻者」決定。只要前鋒們保持陣型，後面的球員隨便站都無所謂。

**計算效率上的意義**：SVM 訓練後，分類新點只需計算該點與支持向量的相似度，而非與全部訓練點。若支持向量數 $m \ll n$，分類就非常快。

### 14.4 SVM 的最佳化問題與對偶

**可線性分離的情況**：假設訓練集 $\{(\vec{x}_i, y_i)\}_{i=1}^n$，其中 $y_i \in \{-1, +1\}$ 且資料完全線性可分。

$$\text{minimize} \quad \frac{1}{2}\|\vec{w}\|^2 \qquad \text{subject to} \quad y_i(\vec{w}^T \vec{x}_i + b) \geq 1 \quad \forall i$$

**約束條件的意義**：若 $y_i = +1$（正類），需 $\vec{w}^T \vec{x}_i + b \geq 1$（在 $+1$ 邊界或更遠處）；若 $y_i = -1$，需 $\leq -1$。兩式統一寫成 $y_i(\vec{w}^T \vec{x}_i + b) \geq 1$。

**問題類型**：這是一個**凸二次規劃問題**（Convex Quadratic Programming）——目標函數是凸函數（Hessian 矩陣正定）；約束條件是線性的（凸集）；**問題有唯一全域最優解**。

**對偶問題**：引入拉格朗日乘數 $\alpha_i \geq 0$：

$$L(\vec{w}, b, \vec{\alpha}) = \frac{1}{2}\|\vec{w}\|^2 - \sum_{i=1}^n \alpha_i [y_i(\vec{w}^T \vec{x}_i + b) - 1]$$

通過 KKT 條件（Karush-Kuhn-Tucker），可推導出對偶問題：

$$\text{maximize} \quad \sum_{i=1}^n \alpha_i - \frac{1}{2}\sum_{i,j} \alpha_i \alpha_j y_i y_j \vec{x}_i^T \vec{x}_j$$

$$\text{subject to} \quad 0 \leq \alpha_i, \quad \sum_{i=1}^n \alpha_i y_i = 0$$

對偶問題的優點：只涉及向量內積 $\vec{x}_i^T \vec{x}_j$（為引入 Kernel 埋伏筆）；維度獨立，可處理高維資料；可用 Sequential Minimal Optimization (SMO) 等高效演算法求解。

### 14.5 Soft Margin SVM 與正則化參數 C

**為什麼需要 Soft Margin**：現實中資料很少完全線性可分。原因包括特徵選擇不當、測量誤差或雜訊、類別本身有重疊。若堅持在線性可分假設下求解，優化問題可能無可行解。

**引入鬆弛變數（Slack Variables）** $\xi_i \geq 0$：

$$y_i(\vec{w}^T \vec{x}_i + b) \geq 1 - \xi_i \quad \forall i$$

- $\xi_i = 0$：樣本被正確分類且在邊界外。
- $0 < \xi_i < 1$：樣本被正確分類但在邊界內。
- $\xi_i > 1$：樣本被誤分類。

**修改後的目標函數**：

$$\text{minimize} \quad \frac{1}{2}\|\vec{w}\|^2 + C\sum_{i=1}^n \xi_i$$

$$\text{subject to} \quad y_i(\vec{w}^T \vec{x}_i + b) \geq 1 - \xi_i, \quad \xi_i \geq 0 \quad \forall i$$

**正則化參數 $C$ 的意義**（控制「邊界寬度」與「訓練誤差」的權衡）

- $C \to \infty$：不容忍任何違規，$\xi_i$ 被迫為 0，回到硬邊界 SVM；**可能過擬合**。
- $C$ 很小：容忍大量違規，決策邊界變寬，但訓練誤差增大；**可能欠擬合**。
- $C$ 中等：平衡邊界寬度和訓練準確率。

**白話**：分辨垃圾郵件時，有些正常郵件看起來很像垃圾郵件，有些垃圾郵件混在正常郵件裡。Soft Margin SVM 說「沒關係，容忍一點錯誤」，用 $\xi_i$ 記錄每個點的「犯規程度」。$C$ 就是「規則有多嚴」。

**實務選擇**：$C$ 通常通過交叉驗證選擇。常用的搜尋範圍是 $C \in \{0.1, 1, 10, 100, 1000\}$。

### 14.6 多類別 SVM：OVA vs OVO

SVM 的原始設計是二元分類器。若有 $m > 2$ 個類別，需要轉換策略。

**方案 1: One-versus-Rest (OVA)**

概念：對每個類別 $i$ 訓練一個 SVM 分類器 $f_i$——正類是類別 $i$ 的樣本，負類是所有非 $i$ 的樣本。結果是 $m$ 個二元 SVM。

預測：計算新樣本對每個分類器的決策函數值 $f_i(\vec{x})$，選擇決策值最高的類別 $\hat{y} = \arg\max_i f_i(\vec{x})$。

- 優點：訓練時間短（只需訓練 $m$ 個分類器）、簡單直觀。
- 缺點：類別 $i$ 的 SVM 收到大量「負類」樣本（其他 $m-1$ 類），**造成訓練集不平衡**；對大 $m$ 下的大類別不利。

**方案 2: One-versus-One (OVO)**

概念：為每對類別 $(i, j)$ 訓練一個 SVM 分類器 $f_{i,j}$。總共需訓練 $\binom{m}{2} = \frac{m(m-1)}{2}$ 個分類器。

預測：用每個 $f_{i,j}$ 對新樣本投票，選擇獲票最多的類別。或依序比較，每次淘汰一個類別。

- 優點：每個分類器只用兩個類別的資料，**訓練集均衡**；通常準確率略高於 OVA。
- 缺點：訓練時間長（需訓練 $O(m^2)$ 個分類器）；預測時計算多。

**白話比較**：OVA 就像在班級裡選班長——每個候選人都要跟「其他所有人」比賽，問題是對手團隊人數很多，不夠均勻。OVO 就像單循環賽——每對候選人都單獨比一場，比的場次多（$m^2$ 級），但每場都很公平。

**選擇建議**：$m$ 小（3-5）時 OVO 不錯；$m$ 大（10+）時 OVA 訓練更快；追求最高準確率時傾向 OVO。

> **【評註】OVA 的隱藏成本**：教材指出 OVA 天生造成訓練集不平衡——這意味著**你在多類別 SVM 上同時要處理第 12 節的不平衡問題**，而且是被演算法設計硬生出來的、不是資料本身的。所以多類別 SVM 的評估一定要看 macro（否則小類全部被壓成負類還看不出來）。

### 14.7 Non-linear SVM 與 Kernel Trick

**線性不可分問題**：若資料分布為「圓形」（內圈為正類，外圈為負類），沒有直線能完美分開。

**特徵映射與高維線性化**：核心思想是將資料從低維映射到高維，在高維空間中可能變得線性可分。

$$\Phi: \vec{x} \in \mathbb{R}^d \rightarrow \phi(\vec{x}) \in \mathbb{R}^D \qquad D > d，通常 D \gg d$$

**例子**：2D 到高維的多項式映射

$$\vec{x} = (x_1, x_2) \rightarrow \phi(\vec{x}) = (x_1^2, x_2^2, \sqrt{2}x_1 x_2, \sqrt{2}x_1, \sqrt{2}x_2, 1)$$

映射後 $\phi(\vec{x}) \in \mathbb{R}^6$，通常在這個 6 維空間中資料變得線性可分。

**計算複雜度爆炸**：$D$ 可能極大（多項式核時 $D = O(d^p)$）；計算 $\phi(\vec{x}_i)$ 的成本高；計算 $\phi(\vec{x}_i)^T \phi(\vec{x}_j)$ 也非常昂貴。這在實務中無法接受。

**Kernel Trick**：Kernel 函數定義為

$$K(\vec{x}_i, \vec{x}_j) = \phi(\vec{x}_i)^T \phi(\vec{x}_j)$$

**神奇之處**：可以直接計算 $K(\vec{x}_i, \vec{x}_j)$，而**不用顯式計算** $\phi(\vec{x}_i)$ 和 $\phi(\vec{x}_j)$。

**常見 Kernel 函數**

1. **線性核（Linear Kernel）**

$$K(\vec{x}, \vec{z}) = \vec{x}^T \vec{z}$$

對應無映射，即原始空間中的線性 SVM。

2. **多項式核（Polynomial Kernel）**

$$K(\vec{x}, \vec{z}) = (\vec{x}^T \vec{z} + 1)^d$$

隱含映射到 $O(d^p)$ 維空間（所有 $\leq d$ 次項的組合）。教材的推導示例（$d=2$ 的 2 次多項式核）：

$$(\vec{x}^T \vec{z} + 1)^2 = (x_1 z_1 + x_2 z_2 + 1)^2$$
$$= (x_1 z_1)^2 + (x_2 z_2)^2 + 1 + 2x_1 z_1 x_2 z_2 + 2x_1 z_1 + 2x_2 z_2$$

對應的映射為 $\phi(\vec{x}) = (x_1^2, x_2^2, \sqrt{2}x_1 x_2, \sqrt{2}x_1, \sqrt{2}x_2, 1)$。計算 $\phi(\vec{x})^T \phi(\vec{z})$ 會得到完全相同的結果，但少了冗長計算。

3. **高斯／RBF 核（Gaussian / Radial Basis Function Kernel）**

$$K(\vec{x}, \vec{z}) = \exp\left(-\frac{\|\vec{x} - \vec{z}\|^2}{2\sigma^2}\right)$$

**隱含映射到無限維空間**。$\sigma$ 是頻寬參數，控制映射的「局部性」。

**白話**：「Kernel 就像一個魔法鏡片，讓你在低維看到高維的分法」。kernel trick 說「你不用真的升到高維，我告訴你一個公式，直接算出高維空間的距離」。

**Kernel 的選擇（教材原文，這是第 24 節表格的來源）**

- **線性核**：資料本身線性可分，或**特徵維度已經很高（如文本）**時。
- **多項式核**：**特徵之間的交互項很重要**時。
- **RBF 核**：**通用選擇，常有不錯效果；但容易過擬合，需調參**。

### 14.8 為什麼 SVM 特別適合文字分類

**文本特徵空間的三個特性**

1. **極高的維度**：現實文本分類的詞彙表常有 10,000~100,000 詞，維度至少如此。
2. **極度稀疏**：每份文件只包含詞彙表的一小部分詞，向量大部分為 0。例如，1000 詞文件在 100,000 維空間中有 99% 的 0 值。
3. **樣本相對稀少**：相比維度，標記好的訓練文件數往往相對不足。這是「**高維小樣本**」情況。

**SVM 的四個優勢**

1. **大邊界原則的有效性**：高維稀疏空間中，樣本點之間距離往往都很大（因為稀疏）。SVM 的 large-margin 理念在這種幾何上特別有效。
2. **維度獨立**：SVM 對偶問題與維度 $d$ 無關，只依賴樣本數 $n$ 和 kernel 計算。
3. **避免維度詛咒**：kNN 在高維下距離退化（所有點等距），但 SVM 利用 kernel 技巧，可在有效高維空間中工作而不受「維度詛咒」困擾。
4. **稀疏性友善**：SVM 訓練後，決策只依賴支持向量。若文本向量稀疏，支持向量也傾向稀疏，內積計算很快（跳過 0 值）。

**經典文本分類 Benchmark 結果**

| 方法 | F1 / Accuracy |
|---|---|
| Naive Bayes | ~0.74~0.78 |
| kNN (k=10) | ~0.75~0.80 |
| 決策樹 | ~0.72~0.76 |
| **SVM (RBF/Polynomial)** | **~0.82~0.88** |

**結論（教材原文）**：SVM 在文本分類中的統治地位在於：它的理論與實務都天然契合「高維稀疏」的文本特性。正因如此，在 deep learning 大行其道前的十多年裡，SVM 一直是文本分類的金牌。

**白話**：文本分類的特點是「維度超高但很空」。大多數演算法在這種環境下容易迷茫（比如 kNN 無法區分距離大小），但 SVM 反而如魚得水，就像在大草原上看得特別遠。

**這回答什麼行銷/商業問題**（材料依據：14.8 的「高維小樣本」＋ 14.5 的 $C$ 調參成本）：只要行銷任務的輸入是文字（評論情感、客訴分類、社群貼文主題），且你只有幾千筆標註，**Linear SVM + TF-IDF 幾乎一定是最強的 baseline**。但兩個代價要先講：(1) 訓練 $O(n^2)$–$O(n^3)$，資料破 10 萬筆就要換（第 19 節）；(2) $C$ 和 kernel 要調參，不像 RF 用預設值就能跑。

### 14.9 Part 2 總結（教材原文）

本部分涵蓋了分類器評估的完整知識鏈：

1. **評估指標**：從混淆矩陣出發，衍生出 Precision、Recall、F1，再到 ROC/AUC。每個指標都有其特定的應用場景。
2. **kNN**：簡單卻有效的方法，利用相似性假設，但在高維、大規模資料上有計算瓶頸。
3. **SVM**：優雅的大邊界理論配合 kernel trick，特別適合高維稀疏問題如文本分類。

三者各有所長，在實務中的選擇常依賴於資料特性、計算資源、準確率要求等。掌握它們的核心思想和數學基礎，才能在模型選擇與調優時做出明智判斷。

## 15. Decision Tree（決策樹）

### 15.1 基本精神

**正式定義**：決策樹（Decision Tree）是一種樹狀結構的分類模型，利用資料集中每筆樣本的已知特徵（特徵欄位），通過遞迴地選擇最優分裂屬性，將樣本空間逐層分割，最終達到目標變數（類別標籤）的預測。

**詳細嚴格的解釋**：決策樹的核心是一套**條件式切分（conditional partitioning）機制，而非線性加總**。每個內部節點對應一個特徵與分裂條件，每條邊代表該條件的取值範圍，每個葉子節點對應最終的預測類別。建樹的過程是**貪心遞迴**：在每個節點，根據資訊增益或 Gini 係數等準則選擇最優分裂特徵，在該特徵處進行分割，對每個分割後的子集合重複同樣的過程，直到達到終止條件（樣本全為同一類、無可用特徵、樣本量過小）。

**白話說明**：你可以把決策樹想像成一個流程圖——就像醫生看病一樣：「先看症狀 A 如何？」→「再看症狀 B 如何？」→ 最後下判斷。決策樹做的就是這件事：自動從資料裡找出「最重要的判斷順序」。這個流程圖有個超強的優點：**你可以直接用自然語言讀懂它**。

**投影片原文（3-2 Slide 3）**：「利用資料庫內每筆資料的已知欄位，預測目標欄位之值，並做為分類的依據 — 可以將大量資料轉化成人類易於了解的知識樹 — 常見應用：信用評等、消費行為預測、病症診斷」。

**常見應用場景（教材四項，全部是商業場景）**

- **信用評等**：銀行根據年收入、貸款歷史、負債比率決定核貸與否。
- **消費行為預測**：電商根據購買歷史、季節、年齡決定推薦商品。
- **病症診斷**：診所根據症狀、年齡、既往史決定初步疑似診斷。
- **客戶流失預測**：電信商根據費用、客服通話次數、網路使用量預測離網率。

**這回答什麼行銷/商業問題**：教材給的四個應用有三個是行銷/金融直球——信用評等、消費行為預測、客戶流失預測。決策樹之所以在這些場合被選中，不是因為它最準，而是因為**輸出是可以拿去開會的規則**（見 15.7 的自然語言規則）。

### 15.2 眼科診所病例：Contact Lenses Dataset

**資料背景**：某眼科診所有 24 筆患者就診紀錄，每筆記錄包含：

- 年齡（3 類：兒童／成人／老年）
- 視力狀況（2 類：近視／遠視）
- 散光（2 類：有／無）
- 淚液分泌（2 類：正常／分泌不足）

目標是預測隱形眼鏡處方（3 類：不可配戴／軟式／硬式）。

**決策樹建構的關鍵洞察（教材強調）**：這個例子的重點**不是眼科知識**，而是「怎麼切才最聰明」。第一刀應該切哪個特徵？

答案是：**淚液分泌**。為什麼？因為如果患者淚液分泌不足，**幾乎所有情況下都無法配戴隱形眼鏡**。這一個特徵單獨就能解決 50% 的樣本，純度最高。相比之下，如果先切年齡，會發現 3 個分支都還很混亂，需要進一步細分。

**完整決策樹結構**

```text
ROOT (24 筆)
├─ 淚液分泌 = 分泌不足
│  └─ 不可配戴 [12.0]
│
└─ 淚液分泌 = 正常 (12 筆)
   ├─ 散光 = 無 (6 筆)
   │  └─ 軟式 [6.0/1.0 誤分1筆]
   │
   └─ 散光 = 有 (6 筆)
      ├─ 近視或遠視 = 近視 (3 筆)
      │  └─ 硬式 [3.0]
      │
      └─ 近視或遠視 = 遠視 (3 筆)
         └─ 不可配戴 [3.0/1.0 誤分1筆]
```

括號內數字表示該節點的樣本數和誤分數。**注意葉子節點不一定 100% 純**——如果進一步分割的訊息增益太小，通常不值得繼續往下切。

> **【評註】這個例子的行銷可轉譯性**：「淚液分泌不足 → 直接不可配戴」對應到行銷上的**硬性排除條件**（例如「未滿 18 歲 → 不可投放信貸廣告」、「已退訂 → 不進 EDM 名單」）。決策樹的價值就是**自動找出這種「一刀砍掉一半樣本」的條件並放在最上層**，而線性模型會把它平均成一個係數。

### 15.3 Weather / Play Tennis 範例與 Information Gain 完整計算

這是機器學習領域最經典的小例子（來自 Quinlan 的 ID3 論文）。某高爾夫球俱樂部的 14 天記錄：

| Outlook | Temperature | Humidity | Windy | Play? |
|---------|-------------|----------|-------|-------|
| Sunny | Hot | High | False | No |
| Sunny | Hot | High | True | No |
| Overcast | Hot | High | False | Yes |
| Rain | Mild | High | False | Yes |
| ... | ... | ... | ... | ... |

共 14 筆資料，Play? 的分布是：Yes (9 筆)、No (5 筆)。

**核心問題：Which attribute to choose？**（教材稱這是「決策樹建構的靈魂問題」）

我們有 4 個可用特徵（Outlook、Temperature、Humidity、Windy），應該用哪個作為第一層的分裂標準？直覺上，好的分裂應該讓分割後的子集合「**更純**」——即每個子集合中 Yes 和 No 的比例差異更大。資訊增益（Information Gain）就是量化這個直覺的工具。

**Information Gain 的計算範例**

先計算原始集合的 Entropy：

$$H(S) = -\frac{9}{14} \log_2 \frac{9}{14} - \frac{5}{14} \log_2 \frac{5}{14} = 0.94$$

若用 **Outlook** 分裂：

- Sunny (5 筆)：2 個 Yes、3 個 No，$H = -\frac{2}{5}\log_2\frac{2}{5} - \frac{3}{5}\log_2\frac{3}{5} = 0.97$
- Overcast (4 筆)：4 個 Yes、0 個 No，$H = 0$（純）
- Rainy (5 筆)：3 個 Yes、2 個 No，$H = 0.97$

加權平均：

$$H_{\text{after}} = \frac{5}{14} \times 0.97 + \frac{4}{14} \times 0 + \frac{5}{14} \times 0.97 = 0.694$$

$$IG(\text{Outlook}) = 0.94 - 0.694 = 0.246$$

同樣計算其他特徵：

$$IG(\text{Humidity}) = 0.94 - 0.788 = 0.152$$
$$IG(\text{Windy}) = 0.94 - 0.892 = 0.048$$
$$IG(\text{Temperature}) = 0.94 - 0.911 = 0.029$$

**結論**：Outlook 的訊息增益最高（0.246），所以第一層應該用 Outlook 分裂。

**投影片原始寫法（3-2 Slide 8，教材用的是 purity 近似值而非嚴格 entropy）**

```text
ig(outlook)     = average(3/5, 4/4, 3/5) = 0.73
ig(humidity)    = average(4/7, 6/7)      = 0.71
ig(windy)       = average(6/8, 3/6)      = 0.63
ig(temperature) = average(2/4, 4/6, 3/4) = 0.64

• Which attribute to choose ?
  – choose the attribute that produces the "purest" nodes
  – …and more informative
  – 常見演算法 Information gain (ID3, C4.5, C5)
```

**Slide 9 的原文說明**：「第一層選擇 outlook，往下重複產生分支，直到結束或終止條件為止」——在 sunny 與 rainy 子集合中，要再用剩下的 humidity、windy、temperature 重複挑選最佳欄位（sunny 分支最後選 humidity）。

> **【評註】兩套數字的關係**：投影片的 `average(3/5, 4/4, 3/5) = 0.73` 是**多數類比例的平均**（一種 purity 近似），講義補的 0.246 是**嚴格的 entropy-based IG**。兩套排序結論一致（outlook 最好），所以不衝突。做 Skill 時要用嚴格版公式，但要知道投影片講的是同一件事的簡化算法。

### 15.4 Entropy（熵）的完整定義

**正式定義（資訊論角度）**：給定一個樣本集合 $S$，如果其中有 $c$ 個類別，第 $i$ 個類別的樣本比例為 $p_i$，則該集合的熵定義為：

$$H(S) = -\sum_{i=1}^{c} p_i \log_2 p_i$$

其中約定 $0 \log 0 = 0$（因為 $\lim_{p \to 0^+} p \log p = 0$）。

**特殊情況：二元分類**

$$H(S) = -p_+ \log_2 p_+ - p_- \log_2 p_- = -p_+ \log_2 p_+ - (1-p_+) \log_2(1-p_+)$$

**性質與解釋**

- 當 $S$ 中所有樣本都屬於同一類別時，$H(S) = 0$（**最純**）。
- 當 $S$ 中各類別比例相等時，$H(S)$ 達到最大值（**最亂**）。
  - 在二元分類中，$p_+ = p_- = 0.5$ 時，$H(S) = 1$。
  - 在 $c$ 分類中，$p_1 = \cdots = p_c = 1/c$ 時，$H(S) = \log_2 c$。

**白話說明**：想像你有一個盒子裝著球。如果盒子裡全是紅球，你一點都不驚訝——熵為 0。如果盒子裡一半紅、一半藍，每次隨便拿出一球都不知道會是什麼顏色——熵最高。如果盒子裡 90% 紅、10% 藍，那驚訝程度介於兩者之間。熵本質上在量：「我對這個盒子的內容有多少確定性？」

### 15.5 Information Gain 的完整定義

$$IG(S, A) = H(S) - \sum_{v \in \text{Values}(A)} \frac{|S_v|}{|S|} H(S_v)$$

其中 $H(S)$ 是集合 $S$ 本身的熵；$\text{Values}(A)$ 是特徵 $A$ 的所有可能取值集合；$S_v$ 是 $S$ 中特徵 $A$ 取值為 $v$ 的子集合。

**計算步驟拆解**

1. 計算原始熵 $H(S)$。
2. 對特徵 $A$ 的每個取值 $v$：把 $S$ 分出子集合 $S_v$，計算該子集合的熵 $H(S_v)$。
3. 計算加權平均：$\sum_{v} \frac{|S_v|}{|S|} H(S_v)$（分裂後的熵）。
4. 信息增益 = 原熵 − 分裂後加權熵。

**直觀理解**：資訊增益衡量的是「用這個特徵分裂後，資料的不確定性下降了多少？」越高越好。$IG = 0$ 代表這個特徵沒有幫助；$IG > 0$ 代表有訊息量；$IG$ 越大分裂效果越好。

**白話說明（教材的班級例子）**：假設班上有 20 個學生，12 個通過考試、8 個沒通過。

- 用「性別」分裂：男生 10 人（7 通過、3 沒通過），女生 10 人（5 通過、5 沒通過）——分裂後兩組都還是混亂，資訊增益小。
- 用「是否做過練習」分裂：有練習 12 人（11 通過、1 沒通過），沒練習 8 人（1 通過、7 沒通過）——分裂後兩組都很純，資訊增益大。

所以「是否做過練習」更適合作為決策樹的分裂點。

### 15.6 Gini Index 的完整定義

$$\text{Gini}(S) = 1 - \sum_{i=1}^{c} p_i^2$$

**特殊情況：二元分類**

$$\text{Gini}(S) = 1 - p_+^2 - p_-^2 = 2 p_+ p_- = 2 p_+ (1-p_+)$$

**性質**

- $\text{Gini} = 0$：$S$ 中全是同一類（最純）。
- $\text{Gini}$ 最大：當所有類別比例相等時。二元情況 $p_+ = p_- = 0.5$ 時 $\text{Gini} = 0.5$；$c$ 分類 $p_i = 1/c$ 時 $\text{Gini} = 1 - 1/c$。
- 範圍：$[0, 1-1/c]$。

**Gini Gain**

$$\text{GiniGain}(S, A) = \text{Gini}(S) - \sum_{v \in \text{Values}(A)} \frac{|S_v|}{|S|} \text{Gini}(S_v)$$

**Entropy vs. Gini 的比較（教材原表；Notion 版此處公式區塊為空，用本機講義補回）**

| 性質 | Entropy | Gini |
|------|---------|------|
| 最純時值 | 0 | 0 |
| 最亂時值 | $\log_2 c$ | $1 - 1/c$ |
| 計算複雜度 | 包含對數，較慢 | 只有平方運算，較快 |
| 常用算法 | ID3、C4.5、C5 | CART |
| 使用領域 | 文本、通用場景 | 迴歸樹、商業軟體 |

**白話說明**：Gini 和 Entropy 就像兩把不同的尺——目的相同（都在量化混亂程度），算法不同。Entropy 用對數、Gini 用平方。在實務上，它們通常給出相似的結果，但 Gini 計算更快。CART 用 Gini，所以**如果你用的是 scikit-learn 的 `DecisionTreeClassifier` 預設參數，就是 Gini**。

### 15.7 決策樹的遞迴建構流程（ID3）

```text
def BuildTree(S, Attributes):
    if S 中所有樣本屬於同一類:
        return 葉子節點標記為該類

    if Attributes 是空的:
        return 葉子節點標記為 S 中最多的類

    # 選最佳分裂特徵
    A_best = argmax(IG(S, A)) for A in Attributes

    # 在 A_best 處分裂
    for each value v of A_best:
        S_v = S 中 A_best = v 的子集

        if S_v 是空的:
            創建葉子節點標記為 S 中最多的類
        else:
            遞迴: BuildTree(S_v, Attributes - {A_best})
```

**詳細步驟**

- **第一層：全局決策**——計算當前集合 $S$ 的熵；對每個未使用過的特徵 $A$ 計算其資訊增益；選擇 $IG(S, A)$ 最大的特徵作為分裂點。
- **第二層及以後：遞迴細分**——在最佳特徵處將 $S$ 分裂為若干子集合；對每個子集合重複上述選擇過程；每個遞迴層級都用剩下的未使用特徵。

**終止條件（三個）**

1. **純度夠高**：節點內所有樣本屬於同一類別 → 不需再分。
2. **特徵用完**：Attributes 集合變空 → 無法繼續分割。
3. **樣本過少**：如果剩餘樣本 < 設定閾值（如 5 筆）→ 停止分割以避免過擬合。

**最終決策樹結果（Weather 範例）**

```text
Outlook?
├─ Overcast
│  └─ Play = Yes
│
├─ Sunny
│  └─ Humidity?
│     ├─ High
│     │  └─ Play = No
│     └─ Normal
│        └─ Play = Yes
│
└─ Rainy
   └─ Windy?
      ├─ True
      │  └─ Play = No
      └─ False
         └─ Play = Yes
```

**翻譯成自然語言規則**

- **規則 1**：若 Outlook = Overcast → Play = Yes
- **規則 2**：若 Outlook = Sunny ∧ Humidity = High → Play = No
- **規則 3**：若 Outlook = Sunny ∧ Humidity = Normal → Play = Yes
- **規則 4**：若 Outlook = Rainy ∧ Windy = False → Play = Yes
- **規則 5**：若 Outlook = Rainy ∧ Windy = True → Play = No

**決策樹最強的地方（教材原文）**：你可以直接把樹轉換成業務可以理解的規則。不像神經網絡黑盒子，決策樹的每個分支都能解釋：「為什麼預測『不能打高爾夫』？因為陽光天且濕度高。」這在**金融、醫療、法律**等高風險領域特別重要。

### 15.8 Decision Tree 的五大實用價值

**投影片原文（3-2 Slide 11）：What does Decision Tree help ?**

```text
• 自動嘗試所有欄位排列組合
• 找出關鍵決策因素之優先順序
• 自動切割適當值
• 自動排除無關因素，並排除少數狀況(pruning)
• 可用以解釋、協助決策或預測之用
```

講義展開版：

1. **自動特徵篩選與排序**
   - 演算法自動嘗試所有特徵的所有分裂組合。
   - 排在樹頂部的特徵證明了最高的預測能力。
   - 根本用不上的特徵會被自動忽略（不出現在樹中）。
   - 不像線性模型需要手工特徵選擇。

2. **自動發現決策門檻**
   - 對連續變數，決策樹自動找出最佳切點。
   - 例如：「收入 > 50000 時」或「年齡 ≤ 25 時」。
   - **不需要人工決定分箱或分段。**

3. **捕捉非線性與交互作用**
   - 線性模型假設特徵與目標呈線性關係。
   - 決策樹可以學到「當 A 高時，B 的效果不同」這樣的交互作用。
   - 天然地處理邏輯門（AND、OR）關係。

4. **高度可解釋性**
   - 直接產出人類可讀的規則。
   - **監管部門要求解釋決策時是必備工具。**
   - 業務人員和技術人員都能理解。

5. **適應多種資料型態**
   - 無須數值化特徵（名義變數直接處理）。
   - 不敏感於特徵的量綱（**不需標準化**）。
   - 自動處理缺失值（可在分裂時單獨處理）。

**這回答什麼行銷/商業問題**（材料依據：價值 1「找出關鍵決策因素之優先順序」＋價值 2「自動切割適當值」）：這正是行銷分析最常被要求交付的兩件事——「**到底哪個變數最重要**」（樹頂部的特徵就是答案）和「**年齡要切在哪裡**」（樹自動找切點，不用再爭論 25 歲還是 30 歲當分界）。價值 2 尤其重要：客群分群的年齡/消費金額分界線通常是拍腦袋定的，決策樹讓資料自己講。

### 15.9 Tree Pruning（剪枝）

**為什麼需要剪枝**：決策樹有一個臭名昭著的問題——**容易過擬合（overfitting）**。

想像訓練資料中有噪音——一個本應屬於 A 類、但誤記為 B 類的樣本。未剪枝的決策樹會說：「好啊，我看到一個特殊組合 X ∧ Y ∧ Z 對應 B 類，我記住它。」結果在測試集上，遇到同樣組合 X ∧ Y ∧ Z 的正確樣本（確實屬於 A 類），樹就預測錯了。

另一個問題是**複雜度爆炸**。如果不加節制，樹會一直長，直到每個葉子節點只有 1 筆樣本（100% 純）。這樣的樹完全記住了訓練資料，對新資料的泛化能力極差。

**投影片原文（3-2 Slide 12）**：Tree pruning「reduces the size of decision trees by removing sections of the tree that provide little power to classify instances. — reduces the complexity of the final classifier, and hence improves predictive accuracy by the reduction of overfitting.」

**Pruning 的目標**：刪掉貢獻很小的枝節（用驗證集評估貢獻）；降低模型複雜度；提升泛化能力（測試集上的表現）。

**兩種剪枝方法**

| | 預剪枝（Pre-pruning / Early Stopping） | 後剪枝（Post-pruning） |
|---|---|---|
| 做法 | 在樹的建構過程中就停止生長：設定最小樣本量／最大深度／最小信息增益 | 先把樹長到最大（允許過擬合），再從葉子節點往上刪 |
| 步驟 | 若節點樣本 < 閾值就停；樹的層數 ≤ 設定值；分裂後增益 < 閾值就不分 | ①完整建樹 ②用驗證集評估每個節點的貢獻 ③自底向上逐個評估刪除某子樹是否能改善驗證集表現 ④若刪除後驗證集準確率提高或持平就刪掉 |
| 優點 | 速度快（不需要先長大再剪） | 決策空間更大，通常效果更好 |
| 缺點 | 閾值難以設定，容易欠擬合或過擬合 | 計算量大，需要單獨驗證集 |

**白話**：預剪枝就像「在養樹時就控制澆水量，防止長太大」；後剪枝是「先讓樹完全長出來，再用剪刀修剪掉不必要的枝條」。在實務中，**許多工程師用預剪枝（因為快），但機器學習競賽選手常用後剪枝（因為準）**。

### 15.10 Decision Tree 的變形與不同分裂準則

| 演算法 | 分裂準則 | 特點 | 發布時間 |
|--------|--------|------|--------|
| ID3 | Information Gain | 傾向選擇取值多的特徵 | 1986 |
| C4.5 | Gain Ratio（修正版 IG） | 降低對多值特徵的偏好 | 1993 |
| C5.0 | 改進的 Gain Ratio | 更快速、支持加權 | 1998 |
| CART | Gini Index | 適用迴歸樹，計算快 | 1984 |

**Information Gain 的偏差（ID3 的問題）**：Information Gain 有個隱藏的傾向——**偏好取值多的特徵**。

教材的例子：假設有個「顧客 ID」特徵（每個顧客 ID 獨一無二）。用它分裂會產生很多子集合，每個子集合可能都只含一個類別 → 高純度 → 高 IG。**但「顧客 ID」對新顧客完全沒有預測力！**

**Gain Ratio 的改進（C4.5）**

$$\text{GainRatio}(S, A) = \frac{IG(S, A)}{H_{\text{split}}(S, A)}$$

其中

$$H_{\text{split}}(S, A) = -\sum_{v \in \text{Values}(A)} \frac{|S_v|}{|S|} \log_2 \frac{|S_v|}{|S|}$$

分母是「分裂本身產生的熵」。取值越多的特徵，分母越大，增益率越小 → **懲罰多值特徵**。

**這回答什麼行銷/商業問題**（材料依據：顧客 ID 的例子）：這是行銷資料建模最常踩的地雷之一——**把高基數 ID 類欄位（會員編號、訂單號、門市代碼、Email）丟進模型**。ID3 會愛上它們（IG 最高），但它們對新客戶零預測力，這就是資料洩漏的一種形式。實務規則：建模前先掃描每個欄位的 unique 值數量，接近樣本數的欄位一律先排除或做適當編碼。

## 16. 三種分類器的決策邊界比較

**投影片原文（3-2 Slide 14）**：「幾種分類器的概念比較 • Simple dataset with two predictors：Decision Tree / Nearest Neighbors / SVM」。圖像補述：本頁把同一組二維資料分別用 Decision Tree、Nearest Neighbors、SVM 來畫出決策邊界，讓你直觀看到三種分類器的形狀差異。

假設我們有二維資料（特徵 $x_1$、$x_2$），需要分成兩個類別（紅點、藍點）。

**Decision Tree 的決策邊界**

```text
特徵2
│     ┌─────┐藍
│     │紅紅 │
│  紅 ├─────┤
│  紅 │     │
│     │  紅 │
└─────┼─────┼─── 特徵1
      │  藍 │
      │ 藍藍│
      └─────┘
```

決策樹的邊界是**軸平行的矩形切分**。每條邊界都垂直或水平於坐標軸。這是因為決策樹的每次分裂都是形如「$x_1 > 5$」或「$x_2 \leq 3$」的單特徵條件。

- 優點：容易解釋。
- 缺點：可能需要很多小矩形才能適應複雜的邊界形狀。

**k-Nearest Neighbors 的決策邊界**

```text
特徵2
│   ～～～～紅～～～
│ ～ 紅      紅     ～
│ 紅 ~ 藍藍藍藍藍 ~紅
└─～～─藍───藍─～～ 特徵1
    ～ 藍  藍藍  藍
      ～ 藍    ～
        ～～～～
```

邊界是**彎曲的、貼近局部資料分布**。kNN 沒有全局模型，每個測試點看周圍 $k$ 個鄰居，所以邊界會追蹤資料的局部形狀。

- 優點：靈活，適應複雜邊界。
- 缺點：容易過擬合，測試時計算量大。

**SVM 的決策邊界**

```text
特徵2
│
│      ╱╱╱  紅
│    ╱╱ ╱  紅紅
│  ╱╱ ╱ ╱ 紅  ←── margin 最大化
│╱╱ ╱ ╱
│──────────── 特徵1
│  ╱  藍藍藍
│ ╱   ╱  藍藍
│╱   ╱   ╱藍
      ╱╱╱╱
```

邊界是**全域性幾何分隔面**，目標是讓最近的紅點和藍點到邊界的距離最大（margin）。

- 優點：理論基礎紮實，泛化能力強，高維也有效。
- 缺點：複雜邊界需要很多支援向量，超參數要調參。

**本質區別（教材原表）**

| 方法 | 決策方式 | 邊界特性 | 適合場景 |
|------|--------|--------|--------|
| Decision Tree | 逐層條件篩選 | 軸平行矩形 | 類別型特徵、需要可解釋 |
| kNN | 鄰域投票 | 局部彎曲 | 小資料、複雜邊界 |
| SVM | 最大 margin | 全局光滑 | 高維稀疏、文本分類 |

**關鍵洞察（教材原文）**：「**沒有最好的分類器，只有不同的看資料方式**」。選哪個，要看：

- 資料長什麼樣（線性可分？複雜邊界？）
- 什麼最重要（速度？精度？可解釋性？）
- 實務約束（訓練時間？預測延遲？）

> **【評註】這三張圖是整個 Lecture 3 最值得記住的視覺**。它們解釋了為什麼同一份資料換模型結果會差很多：**軸平行矩形**天生擅長「年齡 < 30 且 信用卡 = 黑卡」這種門檻組合（第 22 節案例）；**局部彎曲**擅長「跟他很像的人」；**全局光滑 + 大 margin** 擅長高維稀疏。模型選擇的第一問其實是「**我的類別邊界比較像哪一張圖**」。

## 17. Ensemble Learning（集成學習）

### 17.1 核心精神

**正式定義**：集成學習（Ensemble Learning）是指建構多個分類器或迴歸器，讓它們各自在訓練資料上學習，最後通過某種方式（投票、加權、平均）綜合它們的結果，來進行最終預測的機器學習範式。

**為什麼要集成？（大數法則）**：假設你有 100 個獨立的預言家，每個人預測正確率是 60%（好過 50% 的亂猜）。如果讓他們各自預測，再看大多數人的共識，共識的正確率會接近 100%（在獨立假設下）。單一模型可能偏掉（overfitting、運氣差），但多個模型的平均通常更穩健。

**白話說明**：想像你要買房，去問 5 個房產仲介要價。如果只信第一個仲介，他可能存心報高價。但如果問 5 個、看中位數，結果通常比較公允。集成學習就是這概念——每個分類器 ≈ 一個仲介；訓練資料 ≈ 市場行情；最終預測 ≈ 大多數人的共識。

### 17.2 Bias-Variance Tradeoff 的觀點（整章的理論骨架）

模型的預測誤差可以分解為：

$$\text{Error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible Noise}$$

- **Bias**：模型系統性的偏差（欠擬合）。
- **Variance**：模型對訓練資料變化的敏感度（過擬合）。

單一複雜模型常有高方差問題。多個模型平均後，**方差會下降**（因為不同模型的誤差不完全相同），**但 Bias 保持不變**。所以集成特別適合降低高方差問題。

母頁總結版：**Bagging 降 Variance，Boosting 降 Bias。集成的威力：多個模型平均 → 方差 ÷ M。**

### 17.3 Bagging（Bootstrap Aggregating）

**正式定義（Breiman, 1996）**：Bagging 是一種**並行**集成方法。給定訓練集 $S$，大小為 $n$：

1. **Bootstrap Sampling**：對每個 $i = 1, 2, \ldots, M$（$M$ 是學習器數量）
   - 從 $S$ 中**有放回地隨機抽取** $n$ 筆樣本，組成 $S_i$。
   - 用 $S_i$ 訓練第 $i$ 個分類器 $h_i$。

2. **Aggregation**（預測時）
   - 分類問題：$\hat{y} = \text{argmax}_c \sum_{i=1}^{M} \mathbb{1}(h_i(x) = c)$（多數決投票）
   - 迴歸問題：$\hat{y} = \frac{1}{M} \sum_{i=1}^{M} h_i(x)$（算術平均）

**投影片原文（3-2 Slide 15）**：「組合算法 Bagging (Breiman, 1996) — 每種分類器的特性不同，可以使用一種或多種分類器，配合多回合的學習（每一回合都從原訓練資料中抽取若干作為訓練資料）。最後，對於分類問題，採用投票方式作判別。」

**Bootstrap Sampling 詳解**

「Bootstrap」意為「靠自己的力量拉起」，又稱**拔靴法**。在統計學中，bootstrap 是一種再抽樣方法，用來評估統計量的分布而不依賴理論假設。

具體做法：

1. 初始化空集合 $S' = \{\}$。
2. 重複 $n$ 次：從 $S$ 中均勻隨機選一筆樣本 $(x_j, y_j)$，加入 $S'$。**注意：選完後放回，所以同一筆樣本可能被選多次。**
3. 返回 $S'$（大小為 $n$，但包含重複）。

Notion 版補的白話：「就是有一個袋子中放有 20 顆球，為了建構抽樣樣本，因此需要從中進行抽取，每次抽取後放回，抽 20 次形成一組樣本，並重複此行為，就是拔靴法。」

**統計性質**：經過有放回抽樣 $n$ 次，一筆特定樣本被選中至少一次的概率：

$$P(\text{被選中}) = 1 - \left(1 - \frac{1}{n}\right)^n \approx 1 - e^{-1} \approx 0.632$$

反過來說，一筆樣本**從未被選中**（out-of-bag）的概率約為 $e^{-1} \approx 0.368$。

**Out-of-Bag (OOB) 評估**：Bagging 的美妙之處在於——訓練第 $i$ 個分類器用的 $S_i$ 中，平均有 **36.8%** 的原始資料沒有出現。這部分資料可以直接拿來驗證 $h_i$！

$$\text{OOB Error} = \frac{1}{n} \sum_{j=1}^{n} \mathbb{1}(h_{\text{oob}(j)}(x_j) \neq y_j)$$

其中 $h_{\text{oob}(j)}$ 是所有未見過樣本 $j$ 的分類器的投票。**這給了我們一個免費的驗證集！**

**為什麼 Bagging 有效——誤差分析**

如果每個分類器獨立地以概率 $p$ 犯錯，那麼 $M$ 個分類器的多數決結果出錯的概率是：

$$P(\text{多數決錯}) = \sum_{k > M/2}^{M} \binom{M}{k} p^k (1-p)^{M-k}$$

當 $p < 0.5$ 且 $M$ 足夠大時，這個概率**指數級下降**。例如：若 $p = 0.4$，$M = 100$，多數決錯誤率 $\approx 10^{-30}$！

**但這有個重要假設**：各分類器的誤差必須獨立。

**為什麼 Bootstrap 能創造獨立性**：每個分類器看到不同的訓練資料 → 學到不同的模式 → 犯錯的情況不同 → 接近獨立性。但如果基礎分類器太簡單（如單層決策樹），各模型仍會相似，集成效果就差。**這是後來發明 Random Forest 的原因**——要在 Bagging 基礎上進一步增加多樣性。

**主要效果：降低 Variance**

$$\text{Var}(\text{平均}) = \frac{\text{Var}(\text{單個})}{M} + \text{相關性項}$$

當 $M$ 足夠大，相關性項足夠小，整體方差就下降了。

**這回答什麼行銷/商業問題**（材料依據：OOB 的 36.8%「免費驗證集」）：行銷資料常常「只有這麼多筆」（一次活動只有 3,000 個回應者），切出 20% 當驗證集很痛。**Bagging/RF 的 OOB error 讓你不用切驗證集就有一個無偏的估計**，這在小樣本的行銷專案裡是實質的資料節省。

### 17.4 Boosting（增強算法）

**正式定義（Shapire et al., 1998）**：Boosting 是一種**序列型**集成方法。與 Bagging 的並行訓練不同，Boosting 按順序訓練多個學習器，每一輪都特別重視前一輪分類失敗的樣本。

**投影片原文（3-2 Slide 16）**：「增強算法 Boosting (Shapire et al., 1998) — 在多回合的學習中，初始化時以等權重、有放回抽取樣方式進行訓練，接下來每次訓練要特別留意前一次分類失敗的訓練樣本，並賦以較大的權重進行抽樣。而在多分類器中，給予準確率較高者較大權重，反之較小。最終採用有權重的投票方式作判別。• 好像人在學習，訂正答案後，把上次做錯的於下次特別加強，經過如此針對性的練習，解題能力自然會上升 • 與 Bagging 的差異，在於前者大部分採均勻抽取，而 Boosting 根據錯誤率來抽取。Bagging 和 Boosting 都可以提高分類的準確性，在多數研究中，**Boosting 又會比 Bagging 再高一些**」。

**演算法框架**

給定訓練集 $S = \{(x_1, y_1), \ldots, (x_n, y_n)\}$：

1. **初始化**：所有樣本的權重 $w_i = \frac{1}{n}$（均勻分布）。

2. **對每一輪** $t = 1, 2, \ldots, M$：

   a. 按權重分布 $w$ 對訓練集進行重新抽樣（或加權訓練）。

   b. 在加權訓練集上訓練弱學習器 $h_t$。

   c. 計算該學習器的加權誤差率：

   $$\varepsilon_t = \sum_{i: h_t(x_i) \neq y_i} w_i$$

   d. 計算該學習器的權重（$\varepsilon_t$ 越小，$\alpha_t$ 越大）：

   $$\alpha_t = \frac{1}{2} \ln \frac{1 - \varepsilon_t}{\varepsilon_t}$$

   e. **更新樣本權重**：

   $$w_i \leftarrow \frac{w_i \exp(-\alpha_t y_i h_t(x_i))}{Z_t}$$

   其中 $Z_t$ 是歸一化常數。本質上：分類正確的樣本 $w_i$ 下降；分類錯誤的樣本 $w_i$ 上升。

3. **最終預測**（投票時賦予不同權重）：

$$\hat{y} = \text{sign}\left(\sum_{t=1}^{M} \alpha_t h_t(x)\right)$$

**Boosting vs. Bagging 的關鍵差異（教材原表）**

| 面向 | Bagging | Boosting |
|------|---------|----------|
| 訓練方式 | 並行（互不影響） | 序列（前後相關） |
| 樣本選擇 | 均勻重抽樣（每輪獨立） | 根據前輪結果動態調整權重 |
| 學習器權重 | 相同（多數決） | 不同（準確度高的權重大） |
| 目標 | 降低 Variance | 降低 Bias |
| 訓練速度 | 快（可並行） | 慢（必須序列） |

**直觀比喻（教材原文）**

- **Bagging**：「你做 100 份試卷，每份用隨機選題，最後看大多數答案」——每份試卷獨立做，誰都沒在幫誰；最後多數決，都一樣重要。
- **Boosting**：「學生第一次考，看哪些題目做錯了。第二次考試時，老師特意出了更多類似題目。第三次更是針對性強化。最後綜合三次成績，但做對難題的那次權重最大。」——每次都針對上次的弱點做強化；最後的綜合不是平等，而是「有進步的那次更重要」。

**效果對比**

- Bagging：誤差 $\approx \frac{1}{M} \sum_{i=1}^{M} \varepsilon_i$（直接平均）
- Boosting：誤差 $\leq \prod_{t=1}^{M} \sqrt{\varepsilon_t(1-\varepsilon_t)}$（**指數級下降**）

在理想情況下，Boosting 的誤差下降得比 Bagging 快得多！

**但 Boosting 的風險**：Boosting 對訓練誤差關注度高，如果**訓練資料有噪音，重複強化錯誤樣本會導致過擬合**。而且它**對異常值很敏感**。Bagging 則相對魯棒。

### 17.5 AdaBoost

AdaBoost（Adaptive Boosting）是 Boosting 的最經典實現。名字中「Adaptive」表示它動態調整樣本權重。

```text
初始化: w_i = 1/n 對所有樣本

For t = 1 to M:
  1. 訓練弱學習器:
     在加權分布 w 下訓練得到 h_t

  2. 計算錯誤率:
     ε_t = ∑_{h_t(x_i)≠y_i} w_i

  3. 計算權重係數:
     α_t = (1/2) ln((1-ε_t)/ε_t)

  4. 更新樣本權重:
     對正確分類的樣本: w_i → w_i · exp(-α_t)
     對誤分類的樣本: w_i → w_i · exp(α_t)

  5. 歸一化: ∑w_i = 1
```

**為什麼「Adaptive」**：權重會根據每輪的誤差自動調整。不夠準確的弱學習器權重低，因此即使訓練集中有些樣本一直被誤分，也不會被無限強化。

**弱學習器的定義**：Boosting 並不要求單個分類器準確，只要它的準確率 > 50%（對二元分類），就算「弱學習器」。但通過 boosting，弱學習器可以組合成非常強的最終分類器。

**這回答什麼行銷/商業問題**（材料依據：17.4 的「對噪音敏感、對異常值敏感」）：行銷資料的標籤常常很髒（人工標的客訴分類、被誤記的退訂原因、機器人流量）。**教材這句警告直接決定選型**：資料髒 → 選 Bagging/RF；資料乾淨且要衝分數 → 選 Boosting。這也是為什麼第 19 節在「標記資料很少」時把 Boosting 列入「避免」清單。

## 18. Random Forest（隨機森林）

### 18.1 正式定義與地位

**正式定義（Breiman, 2001）**：隨機森林（Random Forest）是在 Bagging 基礎上進一步引入**隨機特徵選擇**的集成算法。它訓練多棵決策樹，每棵樹在不同的自助樣本上生長，且在每個分裂節點隨機選擇特徵子集來確定最優分裂。

**投影片原文（3-2 Slide 17）**：「Random Forest (Breiman, 2001) • Construct the "forest" from decision trees — add an additional layer of randomness to bagging：1. construct each tree using a different bootstrap sample of the data 2. each node is split using the best among a subset of predictors randomly chosen (instead of all attributes)」

**投影片原文（3-2 Slide 18）**：「• Comparison — counterintuitively but outperform very well • compared to discriminant analysis, support vector machines and neural networks • robust against overfitting — very user-friendly; only two parameters concerned • number of variables in the random subset at each node • number of trees in the forest」

**地位與影響**：隨機森林發表於 2001 年，立刻成為機器學習實務中最受歡迎的算法之一。它因為效果好、調參簡單、可平行化、適用於多種資料型態而聞名。

### 18.2 完整演算法

**輸入**：訓練集 $S$；決策樹數量 $N_{\text{trees}}$；每個節點隨機抽取的特徵數 $m_{\text{try}}$；總特徵數 $p$。

```text
For i = 1 to N_trees:
  1. Bootstrap Sampling:
     從 S 中有放回抽取 n 筆樣本，得 S_i

  2. Grow Tree T_i on S_i:
     呼叫 GrowTree(S_i, m_try)

For each node in T_i:
  - 從 p 個可用特徵中隨機選 m_try 個
  - 在這 m_try 個特徵中找最佳分裂
  - 遞迴生長左右子樹
  - 不進行任何剪枝（grow full tree）

Return: Forest = {T_1, T_2, ..., T_{N_trees}}
```

**預測時的聚合**

- **分類**：$\hat{y} = \text{mode}(\{T_1(x), T_2(x), \ldots, T_{N_{\text{trees}}}(x)\})$（多數決投票）
- **迴歸**：$\hat{y} = \frac{1}{N_{\text{trees}}} \sum_{i=1}^{N_{\text{trees}}} T_i(x)$（算術平均）

**投影片 flow chart 補述（3-2 Slide 20）**：從 for each tree → choose training subset → 判斷 stop condition → build next split → calculate prediction error，右側再拆出節點內部如何選變數與計算 Gini index。

### 18.3 為什麼要在節點層級再隨機抽特徵（RF 相對 Bagging 的關鍵創新）

**沒有特徵隨機化的問題（教材用的正是行銷例子）**

> 假設某個特徵特別強，比如「**購買歷史**」在預測「是否會再次購買」時很重要。如果只做 Bagging（不隨機特徵），所有 100 棵樹都會傾向在根節點或次級節點選「購買歷史」，因為它的資訊增益最高。

結果：

- 所有樹都長得很像。
- 它們的預測會高度相關。
- Ensemble 效果打折（因為「大家意見一致」，集成的降方差效應減弱）。

**特徵隨機化的效果**：引入 $m_{\text{try}}$ 後——每個節點，樹只「允許」看 $m_{\text{try}}$ 個特徵（隨機選）；有時候強特徵「被抽籤沒被選到」，樹被迫用次級特徵；不同樹看到不同的特徵集合 → 學到不同的模式 → 預測更多樣化 → 集成更有力。

**白話類比（教材的班長選舉）**

假設班上要選班長，有 10 個候選人，其中甲同學特別受歡迎。

- **沒有特徵隨機化**：班級大會，50 個同學投票，每個人都根據「甲同學的人氣」投票 → 結果幾乎所有人都選甲。
- **有特徵隨機化**：分成 10 個小組，每組隨機抽 5 個候選人投票 → 有的小組抽不到甲，改看乙的才華；有的小組抽到甲，還是選甲 → 最後綜合各小組結果，雖然甲還是贏，但其他候選人也有被認可的機會，決策更全面、更穩健。

**這回答什麼行銷/商業問題**（材料依據：教材直接用「購買歷史」當強特徵的例子）：行銷資料幾乎一定有一個壓倒性強的特徵——**最近一次購買距今天數（Recency）**或**歷史消費金額**。如果不做特徵隨機化，所有樹都只講這一個變數，你的 feature importance 報告就只會有一行，**其他可行銷操作的變數（渠道、素材、時段）全部被遮蔽**。RF 的節點層級隨機抽特徵，正是讓次級變數有機會被看見的機制——這對「我們該調整什麼」的行銷決策比純預測分數更有價值。

### 18.4 Random Forest 的超參數

隨機森林最大的優點：**超參數極少，而且不太敏感**。

**只需要管兩個**

1. **$m_{\text{try}}$**（每個節點隨機抽多少個特徵）
   - 預設值（通常就夠用）：分類 $m_{\text{try}} = \sqrt{p}$（$p$ 是總特徵數）；迴歸 $m_{\text{try}} = p/3$。
   - 範圍：通常 $m_{\text{try}} \in [1, p]$。
   - 小 $m_{\text{try}}$：樹更多樣，但可能欠擬合。
   - 大 $m_{\text{try}}$：樹更相似，趨近普通 Bagging。

2. **$N_{\text{trees}}$**（森林有多少棵樹）
   - 預設值：100 ~ 500（看資料大小）。
   - 範圍：無上限（越多通常越好，只是時間和記憶體成本）。
   - 實務做法：邊際效應遞減，通常 100 棵已經夠好，200+ 就很強。
   - **不會過擬合！**（多加樹只是變平緩，不會變差）

**不需要調的**

- 樹的最大深度：隨機森林通常不限制（長到自然停止）。
- 節點最小樣本量：有預設，通常不動。
- 學習率：隨機森林沒有這個概念（不像 Boosting）。

**超參數調整的策略（教材四步）**

1. 用預設值試試 → 多數情況已經很好。
2. 如果想更精細，調 $m_{\text{try}}$：過擬合就減小、欠擬合就增大。
3. 如果想更強，增加 $N_{\text{trees}}$ → 但邊際效應遞減。
4. 用 **OOB 誤差**或交叉驗證評估。

### 18.5 Random Forest 的六大優點

**1. 表現一流**

- 在許多基準測試上，RF 都是前三名（Fernández-Delgado et al., 2014：179 個算法、121 個數據集，RF 平均排名最前）。
- 特別在表格資料（tabular data）上極強。
- 常常是 baseline 首選。

**2. 對過擬合相對穩健**

- Bagging 本身就能降低方差；隨機特徵選擇進一步增加多樣性。
- 你可以不剪枝，讓樹完全生長，它仍然表現好。

**3. 調參簡單**

- 只需管 $N_{\text{trees}}$ 和 $m_{\text{try}}$，預設值往往就很好（$\sqrt{p}$ 和 100 棵樹）。
- 不像 SVM 要調核函數和 $C$、$\gamma$；不像神經網絡要調層數、學習率。
- 適合工程師快速出結果。

**4. 資料型態容忍度高**

- 可以直接處理類別變數（**不需 one-hot**）。
- 自動處理缺失值（有特殊機制）。
- 對特徵量綱不敏感（**不需標準化**）。
- 混合型資料（有連續、有類別）友善。

**5. 可以自動做特徵選擇**

- 計算每個特徵的「重要度」（**Gini importance** 或 **permutation importance**）。
- 自動識別無關特徵。
- **幫助業務人員理解哪些變數最重要。**

**6. 可並行化**

- 多棵樹可以在不同 CPU/GPU 上同時訓練；預測時也可以並行；實務部署容易擴展。

### 18.6 Fernández-Delgado et al. (2014) 大型比較研究

這是機器學習社區最權威的算法對比研究之一。

**投影片原文（3-2 Slide 21）**：「Comparison (Fernández-Delgado, Manuel, et al, 2014) • "Do we need hundreds of classifiers to solve real world classification problems?" — evaluate 179 classifiers arising from 17 families • discriminant analysis, Bayesian, neural networks, support vector machines, decision trees, rule-based classifiers, boosting, bagging, stacking, random forests and other ensembles, generalized linear models, nearest-neighbors, partial least squares and principal component regression, logistic and multinomial regression, multiple adaptive regression splines and other methods) • implemented in Weka, R (+caret package), C and Matlab • 121 data sets from UCI」

**研究規模**：179 個分類器、來自 17 個算法家族；121 個數據集、來自 UCI 機器學習庫；完全自動化評估（防止人為偏好）。

**Top 3 結果**

| 排名 | 算法 | 實現 | 平均準確率 |
|------|------|------|----------|
| 1 | Random Forest | R (caret) | 94.1% |
| 2 | SVM (Gaussian) | C + LibSVM | 92.3% |
| 3 | Neural Networks | WEKA | 91.2% |

**詳細發現**：Friedman 秩檢驗（非參數統計測試）的排名結果：

```text
Rank Interval (95% confidence):
RF:      [3.5,  8.2]   ← 前三名，且區間窄
SVM:     [7.8, 13.2]   ← 居中，方差大
NB:      [8.5, 16.1]   ← 變動大
kNN:     [10.2, 18.5]  ← 不穩定
```

**結論**

- Random Forest 平均排名最前（秩平均 Mean rank $\approx 5.9$）。
- 且**表現穩定**（不同數據集上差異小）。
- SVM 準度有時更高，但變動大（有的數據集接近 RF，有的遠不如）。

**重要警告（教材原文）**：這不代表「RF 永遠最好」。結論是：

- **如果你什麼都不知道，先試 RF** → 常常有驚喜。
- **如果資料特性你很清楚**（如已知線性可分），專用算法（如 logistic regression）可能更好。
- **不同場景可能有不同冠軍** → 沒有通用最優解。

3-2 補充的限制條件（Part XI）：如果是**極高維稀疏文本**、**特別大的線性可分問題**、**需要極強的表徵學習**，那 SVM 或深度模型仍可能更適合。

**這回答什麼行銷/商業問題**（材料依據：94.1% vs 92.3% 與 rank interval 的寬窄）：這份研究是「**為什麼行銷分析的預設模型是 Random Forest**」的權威引用。而且重點不是那 1.8 個百分點，而是**區間寬窄** —— RF 的 [3.5, 8.2] 很窄代表「換一份資料它還是會不錯」，這對顧問/內部分析師來說比「某次特別高分」值錢得多：**你敢在還沒看過資料前就承諾用它**。

### 18.7 決策樹與集成的完整回顧（母頁）

**為什麼決策樹是集成的基礎？**

- 決策樹可以快速訓練 → 適合多次 bootstrap 或 boosting。
- 決策樹有高 variance（容易過擬合）→ 最適合 Bagging。
- 決策樹結構簡單但可組合 → ensemble 後產生複雜的決策邊界。

**Random Forest 何以成功？**

- Bagging 的並行性 + Boosting 的多樣性（特徵隨機化）。
- 調參簡單 + 效果好 = 實務最愛。
- 可解釋性還過得去（每棵樹可解釋，合起來就難了，但 **feature importance 有幫助**）。

## 19. 實務上怎麼選分類器（Notion 標題原文：「這個最重要！！」）

### 19.1 沒有標記資料時

**情況描述**：你有一堆文件、郵件、圖片，但沒有標籤。無法進行監督學習。

**選擇**

1. **人工規則**：根據領域知識寫 if-then 規則。
   - 成本：人力投入（特別是複雜場景）。
   - 優點：完全可控、可解釋。
   - 缺點：難以應對複雜邊界。

2. **蒐集標記資料**：投入成本標註數據。
   - 成本：人工標註費用。
   - 優點：一勞永逸，機器學習威力大。
   - 缺點：前期投入大。

3. **弱監督／半監督**（進階方向）：用規則生成弱標籤（noisy labels）；用少量人工標籤 + 大量無標籤資料；模型自學習。

**建議（教材原文，這是很具體的門檻）**：先用規則快速 MVP（最小可行產品），並在運行過程中逐步蒐集真實標籤。**一旦有 100+ 個標籤，就可以考慮機器學習。**

### 19.2 標記資料很少時（< 1000 筆）

**情況描述**：你有 100~500 筆標籤數據，想做分類。

**算法選擇順序**

1. **Naive Bayes（首選）**
   - 參數少（只需樣本的統計特性）。
   - 小資料時 variance 低。
   - 訓練快、預測快。
   - 通常表現驚人好。
   - 缺點：假設強（特徵條件獨立）。

2. **Decision Tree（簡單樹）**
   - 可解釋性高、自動特徵選擇。
   - 小資料時容易過擬合 → **要剪枝**。

3. **SVM with RBF kernel**（如果有耐心調參）
   - 高維也能工作。
   - 但小資料時容易過擬合。
   - 需要仔細調 $C$ 和 $\gamma$。

4. **避免**
   - **神經網絡**：小資料時無法發揮，易過擬合。
   - **Random Forest**：多樹集成對小資料不划算。
   - **Boosting**：容易過度擬合小資料。

**策略**：先用 Naive Bayes 快速出結果 → 如果 ok，停止。如果 NB 不夠好，試簡單 SVM 或淺層決策樹。**邊蒐集數據邊迭代** → 資料量增加後，複雜模型才會閃耀。

### 19.3 資料很多時（> 100K 筆）

**情況描述**：你有百萬級別的訓練資料。**現在瓶頸不是資料，而是計算成本。**

**算法選擇**

1. **Random Forest（推薦）**：可並行訓練，充分利用多核；預測也快；效果強。
2. **Naive Bayes（仍然實用！）**：有時被忽視，但大資料下還是很快；記憶體效率高；如果特徵確實獨立，結果很好。
3. **避免 SVM**：訓練時間 $O(n^2)$ 或 $O(n^3)$（根據演算法）；100K+ 樣本時訓練太慢；除非用特殊的大規模 SVM（如 liblinear、SGD）。
4. **避免 kNN**：預測時複雜度 $O(n)$（必須遍歷所有訓練樣本）；100K 樣本意味著每次預測都要比較 100K 個距離；不實用。
5. **Logistic Regression（簡單且快）**：線性模型，訓練和預測都是 $O(np)$；大資料時非常實用；如果資料線性可分，效果很好。

**關鍵洞察（教材原文）**：大資料是把雙刃劍。複雜模型（深度網絡）會因資料充足而大放光彩，但簡單模型也因資料充足而表現出色。**在大資料時代，計算成本往往比模型複雜度更重要。**

### 19.4 類別很多且很像時

**情況描述**：你要分 50 個類別，它們在特徵空間中非常接近。這是一個「困難」問題。

**困難在何處**：少數、明確分開的類別容易 → 任何分類器都行。**類別多且接近是本質難題** → 即使理想算法也無法完美區分。

**解決方向（四個）**

1. **改進特徵工程**：現有特徵不夠判別力；手工設計新特徵或用深度學習提取特徵。例如：分類手寫數字 vs 分類 50 種動物 → 後者需要更複雜特徵。
2. **Classifier Combination**：結合多個分類器的輸出（Voting, Stacking）；不同分類器對不同類別可能有優勢；Random Forest 本身就是這個思想。
3. **Hierarchical Classification**：先分大類（5 個），再分小類。例如先分「動物/植物/礦物」，再分細類。**降低每層的分類難度。**
4. **Mixed Automatic / Manual**：機器學習處理容易區分的類別；人工介入判斷相似的類別。**實務中常見（成本 vs 精度平衡）。**

**這回答什麼行銷/商業問題**（材料依據：19.1 的「100+ 標籤」門檻、19.2/19.3 的資料量分界、19.4 的 Mixed Automatic/Manual）：這一節就是行銷分析專案的**選型 SOP**。三個可以直接寫進提案的數字門檻：**100 筆標籤**＝可以開始談模型；**1,000 筆**＝從 NB 換到 RF/SVM 的分界；**100K 筆**＝必須放棄 SVM/kNN 改用 RF 或 Logistic Regression。第 4 點的「Mixed Automatic/Manual」是最務實的一條：商品自動歸類不必追求 100% 自動，把模型有信心的部分自動化、其餘丟人工，成本最低。

## 20. 特徵工程（三）：文本分類的加權技巧

教材原句：模型選擇固然重要，**特徵工程常常是決勝因素**。

**文本分類為例（五個技巧）**

1. **提高標題詞權重**
   - 標題通常濃縮了文章主題。
   - 特徵提取時，**標題詞出現 = 普通詞出現 × 3（加權）**。

2. **提高每段第一句權重**
   - 新聞寫作習慣：第一句是摘要。
   - 提高首句詞彙的特徵權重。

3. **提高包含標題詞句子的權重**
   - 若句子含有標題中的詞，表示該句特別重要。
   - 增加該句特徵的權重。

4. **先做自動摘要，再特徵化**
   - 不用整個文本，用生成的摘要做分類。
   - 優點：特徵空間大幅縮小，雜訊減少。
   - 缺點：多一個模型環節（摘要模型的品質影響最終結果）。

5. **領域詞典**
   - 識別領域特定詞彙（停用詞表、同義詞表）。
   - 例如：醫療文本中「MI」常代表「心肌梗塞」，應保留。

**關鍵觀念（教材原文）**：「**特徵工程佔機器學習成功的 80%**」。即使用最先進算法，若特徵垃圾，結果也垃圾。反之，好特徵 + 簡單模型，常常贏過差特徵 + 複雜模型。

**這回答什麼行銷/商業問題**（材料依據：技巧 1 的「標題 × 3」與技巧 5 的領域詞典）：做評論情感分析、社群貼文分類時，**貼文標題／首句／hashtag 的訊息密度遠高於正文**，直接乘權重是幾行程式碼就能拿到的提升。技巧 5 對應行銷的**品牌詞與產品詞典**——「小七」= 7-ELEVEN、「XS」是尺碼不是驚嘆——這些同義詞/專有名詞的處理往往比換模型有效。

## 21. Concept Drift（概念漂移）與模型長期維護

**定義**：類別定義或資料分布隨時間改變。訓練好的模型在某個時間點突然表現下降，**不是因為模型本身壞了，而是世界變了**。

**經典例子：季節變化**

- 郵件垃圾分類器：**聖誕節前「50% off!」是正常行銷郵件，平時是垃圾郵件。**
- 新聞分類：「COVID」在 2019 年無關，2020 年後成了高頻詞。

**另一個例子：政治人物分類**

- 1999 年：「Clinton」是美國總統特徵 → 用它預測政治新聞效果很好。
- 2002 年：Clinton 不是總統了 → 該特徵失效。

**怎麼應對（四點）**

1. **持續監控模型表現**
   - 定期評估模型在新鮮資料上的 Precision/Recall。
   - **設定告警閾值（如果準確率跌 5% 以上）。**

2. **定期重新訓練**
   - 使用最新資料重新訓練（如每個月）。
   - 策略：全新訓練 vs. 增量更新。

3. **資料洗淨與維護**
   - 移除過時特徵（如已卸任官員的名字）。
   - 新增新興特徵（如新流行的商品類別）。

4. **使用 Online Learning 方法**（進階）
   - 不一次性訓練，而是邊預測邊學習。
   - 自動適應資料變化。

**啟示（教材原文）**：機器學習模型不是「訓練完就一勞永逸」。**長期維護同等重要。**

**這回答什麼行銷/商業問題**（材料依據：「聖誕節前 50% off 是正常行銷郵件」這個例子本身就是行銷例）：這一節是行銷模型最容易死掉的原因。**行銷環境的漂移速度遠高於一般領域**——檔期、競品活動、平台演算法改版、疫情。三條可以直接落地的維護規則出自教材：(1) 監控 P/R 而不是只看一次上線的分數；(2) 跌 5% 就告警；(3) 每月重訓，並在重訓時清掉過期特徵（下架商品、結束的活動代碼）。

## 22. 樹 / RF 與線性模型的特性比較：信用卡購買預測案例全流程

> 這一節是 Part 3 的收尾，也是整個 Lecture 3 **最直接的行銷應用**。它的原始出處是投影片最後一頁的 Exercise。

### 22.1 原始投影片（3-2 Slide 26，Exercise）

```text
Exercise
• 思考決策樹與迴歸的特性
  – 目標值可能是一個不連續、非線性的分布
  – 造成任何一個變數與目標值的相關性都不高
  – 但是可能多個變數合成之後相關性就提高
  – 若再加上條件判斷(conditional) 則相關性更高
```

**圖像補述（3-2 原文）**：本頁是開放式 exercise，要求思考：當目標值是非連續、非線性時，單一變數與目標的線性相關可能不高，但多變數加上條件判斷後，decision tree 類方法反而可能更有力。

**3-2 Part XII 的解讀（教材原文）**：這其實就是 decision tree / random forest 很重要的優勢來源：

> 它們擅長抓非線性、門檻效果、交互作用。

3-2 給的第一個舉例：假設某商品購買機率不是由「收入」單獨決定，也不是由「年齡」單獨決定，而是：

- 年輕 + 高收入 + 夜間活躍 → 高機率
- 中年 + 家庭族群 + 周末活躍 → 另一類高機率
- 單看任何一個變數都不夠

這時 decision tree 類方法往往能把這些條件式規則切出來。

### 22.2 線性模型的假設

**Logistic Regression / Linear SVM 假設**：目標變數與特徵之間**線性可分**或**單調相關**。

### 22.3 實務常見的四種非線性模式（講義完整版）

#### 模式 1：目標值的非連續性（非單調）

```text
用戶購買意願 vs. 收入

收入 < 10K:    購買率 = 5%
10K - 50K:     購買率 = 15%
50K - 100K:    購買率 = 30%
> 100K:        購買率 = 28%  ← 不是單調！
```

**決策樹會在每個收入階段切一個節點，捕捉到這個模式。線性模型則會被迷惑。**

> **【評註】為什麼線性模型會被迷惑**：Logistic Regression 只能給「收入」一個係數 $\beta$，它必須在整個收入範圍上維持同一個方向（單調）。當高收入族群的購買率反轉下降（30% → 28%），這個係數會被拉成一個折衷值，導致**兩端都預測錯**。決策樹是分段常數，每一段自己一個值，天生沒有這個問題。行銷上這個反轉極常見：最高收入族群反而不買促銷品、最年輕族群反而不用信用卡。

#### 模式 2：多個變數合成後的相關性 ← **這就是信用卡購買預測案例**

```text
單變數相關性：
- 年齡 vs 是否購買：相關係數 = 0.15（弱）
- 城市 vs 是否購買：相關係數 = 0.18（弱）
- 信用卡類型 vs 是否購買：相關係數 = 0.12（弱）

但三個變數合成：
年紀 < 30 ∧ 城市=大都市 ∧ 信用卡=黑卡 → 購買率 = 85%
```

**教材結論**：線性模型看每個變數都弱，不會想到組合。**決策樹會自動發現。**

#### 模式 3：條件判斷與門檻效果（AND 邏輯）

```text
if 溫度 > 25°C AND 濕度 > 60% then 下雨概率 = 70%
else 下雨概率 = 20%
```

這是一個 AND 邏輯（**兩個條件都要滿足才有效**）。**線性模型無法表示 AND**，只能表示「溫度 + 濕度的加權和」。

#### 模式 4：交互作用（Interaction Effect）

```text
購買決策 = 收入 × 教育程度

低收入 + 高教育 ≠ 高收入 + 低教育（儘管「分數」相同）
- 前者：學生、積蓄少但品味高 → 買高端小眾品
- 後者：藍領、收入穩定但追求實用 → 買大眾品
```

線性模型無法自動捕捉這種乘法交互，決策樹可以（**通過在不同分支建立不同規則**）。

### 22.4 信用卡購買預測案例的完整建模流程（本 digest 的重點整理）

**【材料原文】提供的素材**：三個變數（年齡、城市、信用卡類型）＋各自對「是否購買」的相關係數（0.15 / 0.18 / 0.12）＋一條組合規則（年紀 < 30 ∧ 城市 = 大都市 ∧ 信用卡 = 黑卡 → 購買率 85%）＋「線性模型不會想到組合、決策樹會自動發現」的結論。

**【評註】把它展開成一條可執行的分類建模流程**（步驟骨架來自教材各節，數字來自本案例）：

**Step 0：定義目標變數與類別型態（第 1.3 節）**

- 目標：`是否購買`（二元）。
- 這是**二元分類 + 不平衡**的典型：實際母體購買率通常遠低於 50%，所以第 11.7 節的 Accuracy 盲點與第 12 節的處理都適用。

**Step 1：單變數相關性掃描（第 10 節的精神）**

| 變數 | 型態 | 與「是否購買」的關聯 | 單看的結論 |
|---|---|---|---|
| 年齡 | 連續 | 相關係數 = 0.15 | 弱 |
| 城市 | 類別 | 相關係數 = 0.18 | 弱 |
| 信用卡類型 | 類別 | 相關係數 = 0.12 | 弱 |

**這一步的正確用途與錯誤用途（關鍵）**

- ✅ **正確**：用它了解資料、發現資料品質問題、發現極強的單一驅動因子（如果有 0.6 的變數，那條路徑先走）。
- ❌ **錯誤**：**用 0.15 / 0.18 / 0.12 都「太低」為理由把這三個變數丟掉**。這正是教材要你避開的陷阱。三個都「弱」，組合起來卻是 85% 購買率。
- 【評註】對類別變數（城市、信用卡類型）而言，更合適的單變數統計量其實是第 10.2 節的**卡方檢驗**，而不是相關係數；相關係數要求變數有序。教材此處統一寫成「相關係數」是簡化。

**Step 2：意識到單變數篩選會失效，改用能抓交互的模型（第 15.8 / 22.3 節）**

判準（教材給的四條「決策樹擅長」）：

$$\text{非線性程度高} \rightarrow \text{決策樹擅長}$$
$$\text{交互作用多} \rightarrow \text{決策樹擅長}$$
$$\text{門檻效應明顯} \rightarrow \text{決策樹擅長}$$
$$\text{類別特徵多} \rightarrow \text{決策樹擅長}$$

本案例四條全中：年齡有門檻（< 30）、三變數交互、城市與信用卡類型都是類別特徵。**→ 選 Decision Tree / Random Forest。**

**Step 3：讓樹自己找門檻與組合（第 15.5 / 15.8 節）**

- 樹會**自動找到「年齡 < 30」這個切點**（第 15.8 節價值 2：不需要人工決定分箱）——你不用先爭論該切 25 歲還是 30 歲。
- 樹會**自動把三個變數串成一條路徑**（AND 邏輯），得到一條葉節點規則：

```text
年齡 < 30
 └─ 城市 = 大都市
     └─ 信用卡 = 黑卡  →  購買率 85%   ← 高價值區隔
```

- 這條路徑就是第 15.7 節「翻譯成自然語言規則」的產物，可以直接拿去開會。

**Step 4：處理過擬合（第 15.9 節）**

- 「85% 購買率」這條規則若只由少數幾筆樣本支撐，就是過擬合。做法：預剪枝（設定葉節點最小樣本量）或後剪枝（用驗證集）。
- 【評註】驗收這條規則的最低標準：該葉節點的樣本數要夠（教材第 15.7 節終止條件舉例「剩餘樣本 < 5 筆就停」，實務上行銷規則至少要幾十到上百筆才敢投放）。

**Step 5：從單棵樹升級到 Random Forest（第 18 節）**

- 單棵樹 variance 高（第 18.7 節），換一批資料規則就會變 → 不能直接把一條規則當永久策略。
- RF 給你兩個東西：**穩定的預測**（多數決）＋ **feature importance**（第 18.5 節優點 5：幫助業務人員理解哪些變數最重要）。
- 【評註】RF 的代價是失去單一條可讀規則。實務折衷：**用 RF 做預測與變數排序，用一棵淺樹（或從 RF 抽出高支持度路徑）做溝通**。

**Step 6：評估（第 11 / 12 / 25 節）**

- **不能用 Accuracy**：購買是稀有事件，全猜「不買」就有高 accuracy（第 11.7 節）。
- 主指標：**Precision / Recall / F1 對「購買」這一類單獨算**（第 12.1 節第 2 點）。
- 選 Precision 還是 Recall 看商業成本（第 25 節規則）：發實體 DM／打電話（每接觸成本高）→ 重 **Precision**；發 App push／EDM（成本近零，漏掉才可惜）→ 重 **Recall**。
- 模型比較用 **AUC**（第 11.8 節：不受閾值影響、能處理不平衡）。

**Step 7：上線後監控（第 21 節）**

- 「年輕 + 大都市 + 黑卡 → 85%」這條規則會隨檔期與競品變化而失效（Concept Drift）。監控 P/R，跌 5% 告警，每月重訓。

### 22.5 決策樹 / RF 的優勢總結與線性模型的反擊

**決策樹 / Random Forest 的優勢總結（教材四條公式，見 Step 2）**

**但線性模型也有優勢（教材三點）**

- **訓練快**（大資料時）。
- **解釋更簡潔**：「每增加 1 年齡，購買機率 +0.5%」很清晰。
- **外推能力強**：超出訓練範圍時，仍能合理預測；**樹則易無法預測**。

**實務選擇（教材原文三行）**

- **線性資料** → Logistic Regression、Linear SVM
- **非線性、複雜交互** → Decision Tree、Random Forest
- **不確定** → 先試 RF（它往往效果好），再用線性模型做對比

> **【評註】「外推能力」對行銷的具體意義**：樹的預測值在訓練資料範圍外會被夾在最後一個葉節點的值上。如果你的模型是用「月消費 0–50,000」訓練的，來了一位月消費 500,000 的客戶，樹只會給出和 50,000 那群一樣的預測；線性模型至少會沿趨勢外推。**新市場、新價格帶、新客群上線時，這是選線性模型的正當理由。**

**這回答什麼行銷/商業問題**：這一整節就是行銷分析的核心場景——**「哪些人會買」＋「為什麼是他們」**。它同時回答了兩個常見困境：(1) 老闆說「你算的相關係數都很低，這個分析沒用」→ 用 0.15/0.18/0.12 組合出 85% 這個例子反駁；(2) 分析師想直接上 Logistic Regression 交差 → 說明它結構上抓不到 AND 與交互，會漏掉最有價值的區隔。

## 23. 高維空間與維度詛咒的完整論述

教材對「高維」的討論散在四個地方，這裡集中整理（全部是【材料原文】，出處已標注）。

### 23.1 為什麼文本一定是高維（Part 1，第 4.5 節）

三個原因：**詞彙量大**（英文主要語料的詞彙表常在 10,000–100,000）、**長尾分佈**（99% 的詞只出現幾次，但無法忽略）、**特徵稀疏性**（大多數詞在大多數文件中不出現）。

跨領域對照（教材原表，見第 4.5 節）：圖像 224×224 = 50,176 維但像素高度相關，**特徵空間實際複雜度低**；語音頻譜分析後維度中等；**結構化數據通常只有幾十到幾百個特徵**。

> 教材結論：即使只是簡單的詞袋模型，文本分類也自然地發生在高維空間。

### 23.2 維度詛咒的正式敘述（Part 2，kNN 缺點第 4 點）

> **維度詛咒（Curse of Dimensionality）：在高維空間中，所有點之間的距離趨於相同，鄰域概念變得模糊。文本通常有成千上萬的特徵，容易觸發此問題。**

同時 kNN 缺點第 3 點補充：kNN 的成敗完全在於距離函數。若距離度量不當，演算法無法發揮，**例如用歐幾里得距離於高維稀疏文本向量時會有「維度詛咒」問題**。

母頁總結版把它列為 kNN 的兩大缺點之一：「測試慢（$O(n)$）」與「**高維退化（維度詛咒）**」。

### 23.3 為什麼 SVM 不怕高維（Part 2，第 14.8 節）

教材給的三個理由：

1. **大邊界原則在高維稀疏下更有效**：高維稀疏空間中，樣本點之間距離往往都很大（因為稀疏），SVM 的 large-margin 理念在這種幾何上特別有效。
2. **維度獨立**：SVM 對偶問題與維度 $d$ 無關，只依賴樣本數 $n$ 和 kernel 計算。高維不會直接增加計算成本。
3. **明確對比 kNN**：「kNN 在高維下距離退化（所有點等距），但 SVM 利用 kernel 技巧，可在有效高維空間中工作而不受『維度詛咒』困擾。」

並且教材把文本的處境命名為「**高維小樣本**」：相比維度，標記好的訓練文件數往往相對不足。

### 23.4 高維的兩個對策（Part 1，第 10 節；Part 1，第 4.4 節）

- **Feature Selection**（第 10 節）：詞彙表 50,000+，用 $\chi^2$ / MI 篩選 → 降低計算複雜度、改進準確率（去除噪聲特徵、防止過擬合）、改進可解釋性。
- **Word Embeddings**（第 4.4 節）：把高維稀疏換成 50–300 維密集向量。

### 23.5 【評註】維度詛咒的方法論總結（給 Skill 用）

教材沒有把這四處串起來，以下是串接後的判斷規則，**每一條都能追溯到上面的原文**：

| 現象 | 誰受害 | 誰免疫 | 對策 |
|---|---|---|---|
| 距離在高維下失去區分力 | **kNN**（缺點 4）、任何以歐氏距離為核心的方法 | **SVM**（維度獨立 + kernel）、**決策樹/RF**（每次只看單一特徵的切點，不算全域距離） | 換模型（SVM）、降維（embeddings）、篩特徵（$\chi^2$） |
| 特徵數 ≫ 樣本數（高維小樣本） | 神經網路（第 19.2 節：小資料時無法發揮）、深樹 | **Naive Bayes**（第 19.2 節首選：參數少、小資料 variance 低）、**Linear SVM** | 用參數少的模型；先做 Feature Selection |
| 稀疏（99% 是 0） | 需要稠密運算的方法 | SVM（稀疏性友善，內積跳過 0 值） | 保持稀疏表示，不要無腦 one-hot 後轉稠密 |

**【評註】給行銷分析的實務推論**：**行銷資料同時存在兩個世界**——CRM 表格（幾十個特徵，低維，樹/RF 的主場）與文本（上萬維，SVM 的主場）。把兩者直接 concat 成一個矩陣（例如把 TF-IDF 5 萬維接上 20 個 CRM 欄位）會讓那 20 個關鍵欄位在維度上被完全淹沒。**評註做法：兩邊分開建模再做 ensemble（第 19.4 節的 Classifier Combination / Stacking），或先把文本壓成少數幾個分數（情感分數、主題分數）再併入表格模型。**（教材沒有明講這一點，這是本 digest 的推論。）

## 25. 【Skill 規格層】評估指標的選擇規則

> 【材料原文】提供了所有指標的定義、Accuracy 的盲點、micro/macro 的選擇原則與 AUC 的三個優點；本節把它們組織成可執行的規則。標【評註】者為教材未涵蓋的補充。

### 25.1 Accuracy 什麼時候會騙人（材料原文）

**會騙人的條件**：**類別分布高度不平衡**（第 11.7 節）。

**教材的量化示範**：A 類 800 筆、B 類 200 筆，「全部猜 A」→ Accuracy = 80%，但**對 B 類的 Precision / Recall / F1 全部是 0%**。教材稱之為「多數類陷阱（majority class trap）」。

**診斷方法（材料原文，第 12.1 節第 2 點）**：**分別計算各類別的 Precision 與 Recall，看是否有某個類別表現極差。**

**【評註】三個一眼判斷的訊號**

1. 你的 Accuracy 大約等於最大類別的佔比 → 模型可能什麼都沒學到（拿先驗機率當 baseline 比較，第 8.2 節評註）。
2. Macro 遠低於 Micro（第 12.6 節）→ 小類失效。
3. 正類的 Recall 很低但 Accuracy 很高 → 典型的「稀有事件被全部判為負類」。

### 25.2 Precision / Recall / F1 各自何時重要

**【材料原文】給的判準**

| 指標 | 回答的問題 | 教材給的應用場景 |
|---|---|---|
| **Precision** = $\frac{TP}{TP+FP}$ | 「你宣稱的東西裡，真的有多少」——**不亂報** | 郵件過濾時不想誤刪重要信件；投資建議時不想害人虧錢（11.3） |
| **Recall** = $\frac{TP}{TP+FN}$ | 「該找的，你找到了多少」——**不漏掉** | 疾病篩檢時漏掉患者很危險；法律搜查時漏掉證據很嚴重（11.4） |
| **F1** = $\frac{2PR}{P+R}$ | 兩者要一起好；**有一個爛掉就沒救**（調和平均的特性） | 精確率 95% 但召回率 30% 的疾病檢測器——F1 會把矛盾暴露出來（11.6） |

**兩者為何衝突（材料原文，第 11.4 節）**：要提高 Recall，可以把閾值降低，把更多東西歸為正類，但這樣 FP 會增加，Precision 會下降。

**【評註】行銷版的選擇規則（用教材的成本邏輯換場景）**

- **每次「動作」有明顯成本 → 重 Precision。** 打電話、寄實體 DM、送贈品、業務拜訪、給折扣碼（打錯的人 = 白花錢 + 侵蝕毛利）。與教材「不想誤刪重要信件」同構：FP 的代價高。
- **漏掉一個機會的代價高、動作成本近零 → 重 Recall。** App push、EDM、站內推薦位、流失預警（漏掉一個即將流失的高價值客 = 損失整個 LTV）。與教材「疾病篩檢漏掉患者」同構：FN 的代價高。
- **要對外報一個綜合數字、或兩邊代價相當 → F1。**
- **【評註】最實用的做法**：不要只報一個數字，報「**在 Precision ≥ X 的前提下，Recall 有多少**」。行銷的真正約束通常是預算（能接觸幾萬人）而不是某個統計指標。

### 25.3 不平衡資料的處理（材料 + 評註）

見第 12.1 節。教材四點：不用 Accuracy 當主指標 → 逐類看 P/R → 用 macro / weighted → 訓練時類別加權或 over/under-sampling。

【評註】補充：class weight 優先於 oversampling；重抽樣只在訓練集做，測試集保持原始分布；教材未提 SMOTE。

### 25.4 micro vs macro vs weighted（材料 + 評註）

見第 12.6 節完整表格與四條選擇規則。核心兩句（材料原文）：

- **各類別同樣重要 → Macro。**
- **關心整體效能或類別數量反映真實分布 → Micro。**

以及【評註】最有價值的一條：**兩個都報，看差距。Macro 遠低於 Micro ＝ 小類失效。**

### 25.5 ROC / AUC 何時用

**【材料原文】給的三個理由（第 11.8 節）**

1. **不受分類閾值影響**：AUC 整合了所有可能的閾值下的表現。
2. **處理類別不平衡**：即使正負類樣本數差異大，AUC 仍然有意義。
3. **單一數字總結**：便於比較。

**AUC 的機率解釋**：$\text{AUC} = P(s_p > s_n)$ ——隨機選一正一負，模型給正類更高分的機率。

**【評註】AUC 的適用時機**：**模型之間的比較**（哪個演算法/哪組特徵更好）與**排序能力的評估**（名單排序品質）。它**不告訴你該用哪個閾值**，也不直接對應任何商業行動。所以流程是：**先用 AUC 選模型，再用 P/R 選閾值。**

### 25.6 PR curve vs ROC curve —— 【評註】（教材完全沒有 PR curve）

**先明確標注**：本 digest 已在三份本機檔案 + 三個 Notion 子頁全文搜尋，**教材沒有任何 PR curve（Precision-Recall curve）的內容**。以下整段是【評註】，是為了補齊 Skill 規格而加，不可標為教材內容。

| | ROC curve | PR curve |
|---|---|---|
| 兩軸 | X = FPR、Y = TPR(Recall) | X = Recall、Y = Precision |
| 是否用到 TN | **用到**（FPR 的分母是 $FP + TN$） | **完全不用 TN** |
| 極度不平衡時的行為 | 大量的 TN 會讓 FPR 分母很大 → 即使 FP 很多，FPR 仍然很小 → **曲線看起來很漂亮，AUC 虛高** | Precision 的分母是 $TP + FP$，FP 一多 Precision 立刻掉 → **忠實反映名單品質** |
| 隨機基準線 | 固定是對角線 $y = x$（AUC = 0.5） | 是一條水平線 $y = $ 正類佔比（所以 1% 正類時基準只有 0.01） |
| 何時用（評註規則） | 正負類大致平衡；或要比較模型的整體排序能力；或報告對象習慣看 AUC | **正類稀有（< 10%）且你關心的是「被挑出來的那批人準不準」** |

**與教材的一致性檢查**：教材第 11.8 節說 AUC「處理類別不平衡：即使正負類樣本數差異大，AUC 仍然有意義」——這句話成立（AUC 不像 Accuracy 那樣會被多數類綁架），但**它只是「仍然有意義」，不代表「最靈敏」**。上表第三列說明了為什麼在極度不平衡時 PR curve 更能反映實務痛點。**這是本 digest 對教材的補強，不是反駁。**

**行銷上的具體判斷（評註）**：轉換率 1%、流失率 3%、詐騙率 0.1% 這類任務，**主看 PR curve / Average Precision，AUC 只當輔助**。因為你真正在意的是「發出去的 10,000 封 DM 裡有多少人真的買」（= Precision），而不是「所有沒買的人裡有多少被誤發」（= FPR，分母大到失去意義）。

### 25.7 【Skill 規格層】評估指標選擇的決策順序

```text
Step 1. 類別是否平衡？
  ├─ 平衡（各類接近）→ Accuracy 可以用，但仍建議附上逐類 P/R
  └─ 不平衡 → 禁用 Accuracy 當主指標（教材 11.7）
                ↓
Step 2. 是單標籤多類別、還是二元 + 稀有正類？
  ├─ 多類別 → 同時報 Macro 與 Micro（教材 12.5 + 評註）
  │            ├─ 小類也重要 → 以 Macro 為主
  │            └─ 在意整體件數/成本 → 以 Micro 為主
  │            └─ 兩者差距大 → 診斷：小類失效（評註）
  └─ 二元稀有正類 → 對「正類」單獨算 P / R / F1（教材 12.1 第 2 點）
                ↓
Step 3. FP 與 FN 哪個貴？（教材 11.3 / 11.4）
  ├─ FP 貴（每次動作有成本：電話、DM、贈品）→ 主看 Precision
  ├─ FN 貴（漏掉機會代價高、動作近乎免費：push、EDM）→ 主看 Recall
  └─ 相當 → F1
                ↓
Step 4. 現在是在「比模型」還是在「定閾值」？
  ├─ 比模型 → AUC（教材 11.8：不受閾值影響）
  │            └─ 正類 < 10% → 改看 PR curve / AP（評註 25.6）
  └─ 定閾值 → 畫 P/R vs 閾值曲線，用商業約束（預算能接觸幾人）反推（評註）
                ↓
Step 5. 上線後 → 定期監控 P/R，跌 5% 告警，每月重訓（教材第 21 節）
```

**Lecture 3-1 主線回顧（母頁）**

核心概念鏈：$\text{文字分類問題} \rightarrow \text{類別定義} \rightarrow \text{算法選擇} \rightarrow \text{評估指標}$

1. **文字分類的本質**：把文件映射到類別空間。類別可能是二元（垃圾/非垃圾）、多元（新聞類別）、多標籤（藥物副作用）、階層式（動物→哺乳動物→犬科）。
2. **手工 vs. 自動化**：Manual（工程師手寫規則，精確但難擴展）／Rule-based（專家編寫判斷規則，同上）／Machine Learning（讓機器從資料中學，無需人工，可擴展）。
3. **Naive Bayes**：利用 Bayes 定理 $P(C|X) = \frac{P(X|C)P(C)}{P(X)}$；假設特徵條件獨立 $P(X|C) = \prod_i P(x_i|C)$。優點：快速、穩定、小資料好用。缺點：獨立假設常不成立、機率估不準。
4. **k-Nearest Neighbors**：假設相似文件屬相似類別；預測時計算距離、找 k 個鄰居、多數決。優點：直觀、多類別友善、無需訓練。缺點：測試慢（$O(n)$）、高維退化（維度詛咒）。
5. **Support Vector Machine**：找最大邊際（margin）的分隔超平面。優點：margin 最大化保證泛化性、核技巧可解決非線性、理論紮實。缺點：訓練慢（$O(n^2)$ 或 $O(n^3)$）、多類別需特殊處理、超參數多。
6. **評估指標的完整體系**：Accuracy（容易被類別不平衡迷惑）／Precision／Recall／F1（調和平均）／Micro-averaging（全局匯總再計算 P/R，重視多數類）／Macro-averaging（先算各類 P/R 再平均，公平對待）。

**Lecture 3-2 主線回顧（母頁）**

核心概念鏈：$\text{單一模型侷限} \rightarrow \text{集成學習} \rightarrow \text{決策樹} \rightarrow \text{隨機森林}$

1. **Decision Tree**：本質是條件式遞迴分割（不是線性加總）；分裂準則 Information Gain（entropy 下降）、Gini Index；優點自動特徵選擇、可解釋、自動發現非線性/交互；缺點容易過擬合 → 需剪枝；應用信用評估、病症診斷、客戶分類。
2. **Bagging**：bootstrap 重抽樣 → 訓練多個模型 → 投票/平均；優點並行訓練、降低 variance、OOB 免費驗證；主要效果方差下降 $\approx \frac{1}{M}$；何時有效——基礎模型高 variance（如深決策樹）。
3. **Boosting**：序列訓練 → 每輪加強前輪失敗樣本 → 加權投票；優點誤差指數級下降；主要效果降低 Bias；何時有效——基礎模型高 bias（弱學習器）；缺點對噪音敏感、訓練慢。
4. **Random Forest**：Bagging + 節點層級特徵隨機化；超參數少（只需 $m_{\text{try}}$、$N_{\text{trees}}$）；表現一流（大規模對比研究排名第一）；適用 tabular data、需要速度、不想調參；困難場景序列資料、高維影像（這時深度學習更強）。
5. **Bias-Variance-Noise 分解**：$\text{誤差} = \text{Bias}^2 + \text{Variance} + \text{不可約雜訊}$；Bagging 降 Variance，Boosting 降 Bias；集成的威力——多個模型平均 → 方差 ÷ M。

**3-1 的「你最該抓住的 10 個核心句子」（教材原文）**

1. Text classification 本質是把文件映射到類別。
2. 類別可能是單標籤，也可能是多標籤、階層式。
3. Manual 與 rule-based 可行，但難以擴展。
4. Naive Bayes 用 Bayes rule 加條件獨立假設做分類。
5. NB 的強項是快、穩、資料少時好用。
6. kNN 的核心是假設相似文件屬相似類別。
7. kNN 強在直觀，但測試成本高。
8. SVM 強在找最大 margin 的分隔面。
9. 評估時不能只看 accuracy，還要看 precision、recall、F1。
10. 真實世界要考慮資料量、類別規模、concept drift、特徵工程與維運成本。

## 28. 可重用資產

### 28.1 分類建模的十步檢查清單（可直接做成 Skill 的 checklist）

```text
□ 1. 類別型態定案（第 1.3 節）
     二元 / 多元 / 多標籤 / 階層式？→ 決定模型形式與評估指標形式

□ 2. 標籤盤點（第 19.1 節）
     有標籤嗎？幾筆？
     0 筆 → 先寫規則 MVP，邊跑邊蒐集
     100+ → 可以開始談模型
     < 1000 → NB / 淺樹；> 100K → RF / LR（避免 SVM、kNN）

□ 3. 資料型態分岔（母頁流程圖，第 26 節）
     序列 → LSTM/Transformer；影像 → CNN；表格 → 看資料量；混合/不確定 → 先試 RF

□ 4. 切出獨立測試集（第 11.1 節）
     任何在訓練時看過的資料都不能拿來測 → data leakage 會讓數字虛高
     ⚠ 行銷資料常有時序，考慮按時間切而非隨機切（評註，教材未提）

□ 5. 特徵表示決策（第 4.6 節）
     文本：BoW（baseline）/ TF-IDF（預設）/ +bigram（詞序重要時）/ embeddings（追分數）
     表格：不需標準化、不需 one-hot（若用樹/RF，第 18.5 節優點 4）
     ⚠ 排除高基數 ID 欄位（第 15.10 節顧客 ID 陷阱）

□ 6. 單變數篩選——但要看場景（第 10 節 + 第 22.4 節 Step 1）
     文本高維 → 做 χ² / MI 篩選
     表格低維 → 不要用單變數相關性當去留標準（0.15/0.18/0.12 → 組合 85% 的教訓）

□ 7. 不平衡處理（第 12.1 節）
     禁用 Accuracy 當主指標 → 逐類算 P/R → class weight 優先 → 重抽樣只在訓練集做

□ 8. 選模型並跑 baseline（第 24 節主表）
     永遠先跑一個「猜最大類」的 baseline（= 先驗機率，第 8.2 節評註）
     再跑教材建議的首選，比較是否顯著更好

□ 9. 評估指標按 25.7 的決策順序選
     比模型 → AUC（正類 < 10% 改看 PR/AP）
     定閾值 → P/R vs 閾值 + 商業約束

□ 10. 上線與維護（第 21 節）
     監控 P/R；跌 5% 告警；每月重訓；清掉過期特徵
```

### 28.2 決策規則卡（可直接寫進 Skill 的 rules）

**模型選擇**

1. 資料型態決定第一分岔（序列/影像/表格），不是資料量。（母頁流程圖）
2. 表格資料、不確定時，**先試 Random Forest**；好就停，不好再談特徵工程。（第 18.6 / 22.5 節）
3. 標註 < 1000 筆，**先用 Naive Bayes**；避免 NN / RF / Boosting。（第 19.2 節）
4. 標註 > 100K 筆，**避免 SVM（$O(n^2)$–$O(n^3)$）與 kNN（預測 $O(n)$）**。（第 19.3 節）
5. 輸入是文字且只有幾千筆標註 → **TF-IDF + Linear SVM** 是最強 baseline。（第 11.9 / 14.8 節）
6. 需要拿給業務或監管看的規則 → 決策樹（單棵、剪枝過）。（第 15.7 / 15.8 節）
7. 資料標籤髒 / 有異常值 → 選 Bagging/RF，**不要選 Boosting**（對噪音敏感）。（第 17.4 節）
8. 需要外推到訓練範圍外（新價格帶、新市場）→ 線性模型比樹安全。（第 22.5 節）
9. 交互作用/門檻效應明顯（單變數都弱、組合起來很強）→ 樹 / RF。（第 22.3 / 22.4 節）
10. 高維稀疏 → SVM；高維 + kNN = 維度詛咒，換模型。（第 23 節）

**評估**

11. 類別不平衡 → **禁用 Accuracy 當主指標**。（第 11.7 節）
12. FP 貴（每次動作有成本）→ 重 Precision；FN 貴（漏掉機會）→ 重 Recall。（第 11.3 / 11.4 節）
13. 多類別 → **Macro 與 Micro 都報，差距本身就是診斷訊號**。（第 12.6 節）
14. 各類等重要 → Macro；在意整體件數/成本 → Micro。（第 12.5 節）
15. 比模型用 AUC；正類 < 10% 改看 PR curve / AP。（第 11.8 節 + 25.6 評註）
16. AUC 不告訴你閾值。先用 AUC 選模型，再用 P/R + 預算約束定閾值。（評註）
17. NB 的輸出只能排序，不能當機率去算 ROI。（第 8.5 / 9.2 節）
18. 任何重抽樣只在訓練集做，測試集保持原始分布。（評註，依第 11.1 節推）

**特徵工程**

19. 排除高基數 ID 欄位（會員編號、訂單號）——IG 會愛上它們但零預測力。（第 15.10 節）
20. 文本：標題詞權重 × 3、首句加權、領域詞典。（第 20 節）
21. 未見過的詞 ≠ 不可能 → 一律用 Laplace smoothing（$\alpha = 1$）。（第 8.8 節）
22. 用樹/RF 時不需要標準化、不需要 one-hot。（第 18.5 節）
23. 文本特徵與 CRM 表格特徵不要直接 concat（20 個關鍵欄位會被 5 萬維淹沒）→ 分開建模再 ensemble，或把文本壓成分數再併入。（評註，第 23.5 節）

### 28.3 診斷順序（模型結果不對時的排查流程）

```text
症狀：Accuracy 很高但業務說名單很爛
  → 查類別分布。Accuracy ≈ 最大類佔比？（第 11.7 節）
  → 對正類單獨算 P/R。Recall 是不是接近 0？
  → 改看 PR curve；重設閾值或加 class weight（第 12.1 / 25.6 節）

症狀：Macro F1 遠低於 Micro F1
  → 小類失效。列出每一類的 P/R/support（第 12.6 節）
  → 小類樣本太少 → 補標註 / class weight / 合併相近小類 / 改層級分類（第 19.4 節）

症狀：訓練分數很高、測試分數很差
  → 過擬合。若是單棵樹 → 剪枝（第 15.9 節）
  → 若是 SVM-RBF → 降 C、調 γ（第 14.5 節）
  → 若是小資料 + 複雜模型 → 換 NB（第 19.2 節）
  → 檢查有沒有 data leakage / 高基數 ID 欄位（第 11.1 / 15.10 節）

症狀：模型上線一段時間後變差
  → Concept Drift（第 21 節）。比較新舊資料的特徵分布與類別比例
  → 重訓 + 清掉過期特徵（下架商品、結束的活動代碼）

症狀：所有單變數相關性都很低，老闆說這份資料沒用
  → 這正是第 22 節的情境。改用樹/RF 找交互與門檻
  → 拿 0.15 / 0.18 / 0.12 → 組合 85% 這個教材例子說明

症狀：kNN 在文本上表現很差
  → 維度詛咒（第 23.2 節）。換餘弦相似度、降維（embeddings）、或直接換 SVM

症狀：預測太慢，撐不住即時流量
  → kNN 是 O(n)（第 13.4 節）→ 換 LR 或已訓好的 RF（第 19.3 節）

症狀：RF 的 feature importance 只有一個變數獨大
  → 檢查 m_try（第 18.3 / 18.4 節）：太大時所有樹都選同一強特徵
  → 也要檢查那個變數是不是洩漏（例如「已成交金額」用來預測「是否成交」）
```
