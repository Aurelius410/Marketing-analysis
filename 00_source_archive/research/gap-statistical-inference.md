## 1. 四個深挖題的答案

### 深挖 (1)：RFM/CAI 這類全期指標拿去預測時的洩漏

`G4` 已經抓到主線（強制 `as_of_date`），而且 `references/05` 的 SQL 確實每一支都帶 `WHERE txn_date <= as_of`。這一層是對的。**但 `as_of` 只解決了「未來資訊流進特徵」，沒解決另外三件事：**

**(a) 標籤與特徵的機械同義。** 若流失標籤定義成「as_of 之後 90 天沒有交易」，而特徵含 `R = as_of - 最後購買日`，則對月購一次的顧客，R 與標籤幾乎是同一個變數的兩個切法。這不是傳統定義的洩漏（沒有用到未來），但後果一樣：AUC 0.89 看起來很強，實際模型只學到「把最久沒買的人排前面」。**判別方法只有一個：跟「只用 R 排序」的 naive baseline 比。** skill 目前沒有任何一處要求做這個比較 → 見 S9。

**(b) 右設限資訊被主動刪掉。** `references/05 §一` 與 `§4.2` 步驟 5 把「刪除每位客戶的最後一筆」寫成必做且漏了會降等的硬步驟（實測 5,294 → 5,194 列）。被刪掉的那一筆對應的是「最後一次購買 → 觀測終點」的**開放區間**，而這正是唯一攜帶「這個人是不是已經停了」的量。刪掉之後，$\hat\lambda$ 只由**已完成**的區間估計，對正在流失的人系統性低估。→ 見 S4。

**(c) 觀測窗截斷 ≠ tenure。** `G3` 用 `tenure_days` 處理「新客 F 天生比較低」，方向對。但 tenure 是共變量校正，處理不了「觀測窗長度 < 該顧客的典型購買週期」時 $\lambda$ 根本不可估的問題（$n_i=1$ → NaN，$n_i=2$ → 只有一個區間，CAI 恆為 0）。→ 見 S6。

**我的判斷**：G4 是必要條件而非充分條件。真正的防線是「as_of 切點 + 標籤窗分離 + out-of-time 驗證 + naive baseline 對照」四件一起，缺任何一件都可能產出一個「沒有洩漏但也沒有預測力」的模型。

### 深挖 (2)：分群數選擇與穩定性的統計依據

教材（`03_clustering_sequence.md`）給的是：Elbow（明說客觀性低、靠人眼）、CH Index（唯一可自動最大化者）、先驗知識，以及一句反覆出現的「K 要反映業務需求，不能純粹靠數學」。教材 §15 自己列出缺口：Silhouette 只列名無公式、ARI 只列名、Gap Statistic 完全沒有、**分群穩定性/bootstrap 驗證完全沒有**、**標準化/尺度處理完全沒有提及**、Ward 只在延伸閱讀列了論文標題（而 HW8 直接要求 Ward + 2-step）。

`G7` 已經開了「elbow／silhouette／gap statistic + bootstrap ARI + k 要寫理由」這張處方。**但 G7 的順序錯了，而且漏了兩個比 k 更嚴重的東西：**

- **尺度決策比 k 更前置。** RFM 三個指標的量級差 4 個數量級（課程資料集：M 最大 150,681、F 最大 85、R 最大 401）。不標準化的 Euclidean K-means，WGSS 幾乎完全由 M 決定 —— 此時討論 k 是幾、穩定不穩定，都只是在量「M 支配」這件事的穩定度（而它會非常穩定，因為 M 的四分位切法本來就穩定）。→ 見 S2，我把它列為 critical，而 G7 只是 important。
- **分群後的檢定是循環的。** 這是我在整份審查裡認為**最嚴重且最沒有被任何一條規則攔住**的問題。IB5082 分析動作 18 明文要求「分群後輪廓描述的統計檢定套組 —— 卡方獨立性檢定（人口統計變數）、**F 檢定/單因子 ANOVA（獲利指標）**、事後檢定」。卡方那半沒問題（人口變數不是分群輸入，E2 白名單已經把它們排除在分群之外）。**但「獲利指標」正是分群輸入變數本身**（R/F/M/RFM Score/CAI/CRI 就是 E2 白名單的內容）。K-means/Ward 的目標函數是最小化 WGSS、也就是最大化 $\text{BGSS}/\text{WGSS}$，而這正是單因子 ANOVA 的 F 統計量。**對這些變數跑 ANOVA，等於用最佳化後的目標函數值去檢定它自己**。→ 見 S1，critical。

**我的判斷**：k 的選擇本身其實不是最危險的部分（選錯 k 的代價是「分群不好用」，行銷團隊自己會發現）。真正危險的是**用一個必然顯著的 p 值去證明分群有效**，因為它會讓一個由 M 單一變數主導、換個 seed 就變的分群，帶著「p < 0.001」的權威進到管理決策。

### 深挖 (3)：廣告歸因在沒有實驗時能主張到什麼程度

先講素材給了什麼：`research/02` B.16 已經很誠實 ——「**Markov 歸因不是真正的因果推論**，它是在觀察到的路徑上做的結構化功勞分配，仍受選擇偏誤影響（會看廣告的人本來就更可能買）」。02 Part 5 §5.2 也給了界線：只有隨機化設計「在談處理效果時比觀察性設計更有說服力」。

**能主張什麼，我的答案分四層：**

| 層級 | 沒有實驗時能說的句子 | 需要什麼才能說 |
|---|---|---|
| 描述性歸因 | 「這批轉換的路徑中，付費搜尋出現在 62% 的路徑裡」 | 完整觸點路徑資料。**這只是計數，不是效果** |
| 結構化功勞分配（Markov removal effect / Shapley） | 「若移除付費搜尋，模型下的轉換數會降 18%」 | 路徑資料 + 明說這是「模型內的移除效應」，不是「停投會少 18%」 |
| 條件關聯（logistic 控制共變數） | 「在控制客群、既有消費、其他渠道後，曝光組的購買勝算約為對照組的 3.2 倍（95% CI 2.6–3.9）」 | 02 §6.3 Step 4 的完整流程 + 抽樣設計已登錄 |
| 增量（causal） | 「這檔活動帶來 X 筆增量訂單」 | **只有**隨機分派、地理實驗、或通過識別假設檢查的準實驗 |

**沒有實驗時，絕對不能說的三句話**：「廣告使購買率提升 X%」、「這檔活動帶來 X 筆增量訂單」、「ROAS = 6.0 所以應該加碼」。

**skill 現在的問題不是不知道這件事，而是把它做成了一個沒有門檻的標籤。** 藍圖 §4 S6 第三道關說「每一條行銷建議標上證據等級：相關／預測／準實驗／實驗」，`G6` 說「想主張因果就要走 uplift／DiD／實驗設計」。但**沒有任何一處寫出「標成準實驗需要滿足什麼」**。結果是：任何人跑一次 DiD 就可以標「準實驗」，而 DiD 需要平行趨勢、uplift 需要 overlap 與無混淆 —— 這兩者本身都是觀察型方法，做錯了只是換一種方式主張因果。→ 見 S11。

另外一個被完全漏掉的、且是這份素材裡最現成的資產：**回溯式抽樣的界線**。02 Part 5 §5.3 用七條原文講清楚「case-control 樣本不能報比例，只有 OR 可估」，§6.3 Step 0 甚至已經做成檢查清單。**這套規則一個字都沒有進 skill**，而行銷場景幾乎天天在做 case-control 抽樣（「撈出買的人和沒買的人各一批，回頭看誰看過廣告」）。→ 見 S3，critical。

還有一個更廉價但更常見的錯誤：**季節性混淆**。促銷本來就排在旺季，raw ROAS 高不代表增量高。`G5` 講的是「沒有 spend 資料就不要談 ROI」，這是資料有無的問題；季節混淆是**有了 spend 資料之後才會犯的錯**，兩者不重複。→ 見 S10。

### 深挖 (4)：「檢查計算過程不檢查答案」的訓練會養成什麼盲點

原文（HW4）：「你們不用擔心你們分析的結果，跟我的檔案中數字不同，我們只檢查步驟是否正確而已」；配套的是「無計算過程／直接貼結果 → D」。這在教學上完全合理 —— 它防的是抄答案，逼學生留下可檢查的軌跡。**但它培養出三個盲點，而且 skill 目前把這三個盲點都繼承下來了：**

**盲點一：把「步驟齊全」當成「結論正確」的代理。**
最直接的證據是 `references/07` 的權重分配。E1–E22 全部來自 214 份報告的**成績反推** —— 它們優化的目標函數是「不被扣分」，不是「結論正確」。於是 skill 的品質檢查清單有「每個 ANOVA 都接了事後檢定」（因為漏了會掉一級，27 人實證），卻**沒有**「ANOVA 前檢查等變異與常態」（教材 §13.8 步驟 6–8 明訂，但漏了不會被扣分，因為老師看不出來）、**沒有**「卡方期望次數 ≥ 5」（教材 F2 明訂）、**沒有**「不顯著結論附 MDE」。
**結果**：一份 ANOVA 在嚴重異質變異下跑出來、接了 Tukey、每張表有中文結論、11 章全綠、`verify_outputs.py` 全過 —— 而 F 檢定的 p 值根本不可信。這份報告會拿 A+，也會通過 skill 的所有 gate。

**盲點二：不對數字建立事前預期，因此永遠只能偵測「格式異常」而非「數值錯誤」。**
E9 是唯一的數值防線：「同欄數量級差 >100 倍即警告」。這是純形狀檢查 —— 它抓得到 `3217.258` 混在 3.2~3.5 之間，抓不到「CAI 係數符號反了」「相關係數 0.47 其實是把 15 個品類的 0/1 矩陣算錯粒度得到的」。**缺的動作是：在算之前先寫下預期（符號、量級、單調方向），算完比對。**

**盲點三：把「對得上課程基準值」誤讀成「方法正確」。**
`references/05 §八` 把 11 個檢核值稱為 ground truth 並註明「已用 DuckDB SQL 重建並確認每一位小數都相符」。這是**實作正確性**的極好證據（我完全支持保留），但它只覆蓋一個 100 人、7,764 筆、2012 年的資料集。文件的措辭（"ground truth"、"逐位比對通過"）在「不檢查答案」的文化下極容易被讀成「對得上就對了」。**當 skill 被拿去跑 222 MB 那份新資料時，沒有任何一張網會攔住錯誤的數字**，因為 `test_metrics.py` 的斷言全部綁在課程資料集的具體值上。

**具體會出錯的情境（盲點三）**：把 skill 套到電商資料。`references/05 §二` 的 F 是 `COUNT(*) FROM fact_transaction`，而藍圖 §3 明訂 `fact_transaction` 的 grain 是「發票明細一列一品項」。信用卡資料一列一次刷卡，兩者恰好相等，基準值照樣通過；電商資料一張訂單 5 個品項，`COUNT(*)` 算出來的是**品項數**。某顧客 3 張訂單 15 個品項 → F = 15，被 NTILE(5) 切進最高頻五分位，進 VIP 名單。`test_metrics.py` 全綠，因為它跑的是課程資料集。

**修補方向**：`tests/test_metrics.py`（綁定具體值，證明實作正確）之外，另加一支 `tests/test_invariants.py`（跨資料集恆成立的性質，每個專案都跑）。候選不變量：
`R ≥ 0`；`R = 0 ⟺ 基準日當天有交易`；`F_days ≤ F_txn`；`F ≥ 1`；`M_net ≤ M_gross`；`λ ≥ 1`（去重後最小間隔一天）；`n_intervals = F_days - 1`；`n_intervals = 1 ⟹ CAI = 0`；`NTILE(5) 各組大小差 ≤ 1`；`Σ 群人數 = n`；`|r| ≤ 1` 且 `|r| = 1 ⟹ 已標記樣本不足`；`Σ 百分比欄 ≈ 100`；`所有機率 ∈ [0,1]`；`Deviance ≥ 0`；`VIF ≥ 1`。這些**沒有一條依賴課程資料集**，因此在新資料上照樣有效。

## 2. 缺口清單

編號用 **S 系列**（Statistical inference），與現有 E1–E22 / G1–G16 / T1–T10 不重疊。

### 2.1 critical — 會直接產出錯誤結論，且現有規則攔不住

#### S1｜分群後對「分群輸入變數」跑 ANOVA/事後檢定 = 循環推論

| | |
|---|---|
| **層** | S5 分析執行 / S6 驗證 |
| **適用** | 全部（凡有分群章節） |

**現況**：IB5082 分析動作 18 要求「F 檢定/單因子 ANOVA（獲利指標）+ 事後檢定」，SKILL.md 入口指引寫「分群後必跑檢定套組」，E1 把 `ANOVA → 事後檢定` 綁成不可分離。三份文件加起來的效果是：**強制對分群輸入變數跑 ANOVA**。

### 2.2 important — 會讓結論不穩、不可信，或把「看不出來」誤讀成「沒有」

#### S6｜CAI 沒有抽樣分布；切群門檻 sd = 15 是憑空常數；CAI 對 $n_i$ 極度敏感

| | |
|---|---|
| **層** | S4 指標工程（硬卡點③） |
| **適用** | CRM、電商、POS |

**現況**：`references/05 §4.2` 記錄「**分佈機率化**：`NORM.DIST(x, mean, sd, 1)`，課程範本用 `mean=0, sd=15`」，執行順序步驟 9「常態累積分佈 → 切『非常活躍群／非常不活躍群』→ 用人口統計比較兩群」。**mean=0、sd=15 是課程 Excel 的固定常數，不是從資料估計的參數**，文件照抄未加警語。更根本的是：CAI 是一個由 $n_i - 1$ 個區間算出來的統計量，它的抽樣變異隨 $n_i$ 劇烈變化，而整條流程用同一個 sd 對待所有人。

**會怎麼出錯**：
- 顧客甲：3 次購買，兩個區間 5 天與 45 天。$\text{MLE} = 25$，$\text{WMLE} = \frac{1 \times 5 + 2 \times 45}{1+2} = 31.67$，$\text{CAI} = \frac{25 - 31.67}{25} \times 100 = -26.7$。
- 顧客乙 = 客戶 89（實測）：85 次購買、84 個區間，$\text{MLE} = 10.279$、$\text{WMLE} = 11.571$、$\text{CAI} = -12.56$。

用 `NORM.DIST(x, 0, 15)` 切「非常不活躍群」（例如累積機率 < 10%，即 $\text{CAI} < -19.2$）：**甲入列、乙不入列**。
但甲的 CAI 完全由兩個數字決定 —— 把 5 和 45 的順序調換就變成 $+26.7$，符號翻轉、絕對值不變；乙的 CAI 由 84 個區間決定，估計穩定得多。
行動：500 元喚回券發給一批「其實只是購買次數太少、CAI 純屬雜訊」的人（假設這類 $n_i \le 4$ 的顧客佔名單 40%，1,000 人名單 × 500 元 = 20 萬，其中 8 萬直接浪費）；同時真正在減速的高頻大客戶（像乙，$\text{CAI} = -12.6$、$M = 150{,}681$）因為沒過門檻而被漏掉 —— **這是最不該漏的人**。
另外兩個一定會發生的邊界：$n_i = 2$（只有一個區間）時 $\text{MLE} = \text{WMLE}$，**CAI 恆等於 0**，與「節奏完美穩定」在資料上完全無法區分；$n_i = 1$ 時 CAI 為 NaN。

**修補動作**：
1. `build_features.py` 的 CAI 輸出**必須同時帶 `n_intervals`**；`n_intervals < 5` 的 CAI 一律寫 NULL，並在報告標「樣本不足，不可解讀」——**完全比照 E10 對 $|r| = 1$ 的處理方式**（同一個病理：稀疏樣本上的統計量看似極端，其實是雜訊）。
2. 用置換法給每位顧客自己的 null 分布：把該顧客的區間序列隨機重排 B = 2,000 次重算 CAI，得到 $p_i$ 與 CI。**「非常活躍／非常不活躍」的切群改用 $p_i < 0.05$，取代固定 sd = 15。** 這支腳本很短（一個 groupby + numpy shuffle），成本低於它避免的錯誤。
3. `references/05 §4.2` 的 `mean=0, sd=15` 必須加註：「課程範本的固定常數，非估計值。保留供對照課程結果，正式切群請用置換法的 null 分布。」
4. 執行順序步驟 9「切極端兩群 → 用人口統計比較」加註**極端組設計（extreme-group design）會膨脹效果量**：兩尾各取 10% 再比較，會讓任何弱關聯看起來很強，且後續期間必然出現向均值回歸。此處的差異不可用來估計「活躍度與教育程度的關聯強度」，只可用於名單產出。

#### S7｜F 與 λ/CAI 的粒度不一致，ARFM 的 A 維與 F 維可以互相矛盾

| | |
|---|---|
| **層** | S4 指標工程（硬卡點③） |
| **適用** | CRM、電商、POS |

**現況**：`references/05 §一` 開頭寫「行銷交易資料的分析單位是**天**，不是筆。同一顧客同一天多筆交易要壓成一筆」；`§二` 卻寫「$F_i$ 的口徑：預設**交易筆數（去重前的原始筆數）**」，SQL 是 `COUNT(*)`。同一份文件裡兩個相反的粒度宣告，而 λ / MLE / WMLE / CAI 全部建在去重後的 `stg_customer_day` 上。實測落差很大：**7,764 → 5,294，去重掉了 32%。**

**會怎麼出錯**：信用卡資料同一天多筆刷卡極常見（一天在超市、加油站、餐廳各刷一次 = 3 筆、1 天）。假設某顧客 $F_\text{txn} = 85$，但去重後只有 30 個購買日。
- **F 維**：85 筆進 `NTILE(5)`，切進最高頻五分位 → 標「忠誠」。
- **A 維**（來自 λ 與其分散程度）：30 個購買日、$\hat\lambda = 365/30 \approx 12$ 天，且分散度大 → 標「不活躍／隨機」。
ARFM 標籤變成「高活躍性…低頻」或反過來的邏輯互斥組合。報告小結寫「本群為高頻但活躍度偏低的矛盾客群，建議透過訂閱制提升行為規律性」，並設計一套訂閱制專案。
**這個「矛盾」是口徑造成的，不是行為造成的。** 更麻煩的是它不會被任何檢查抓到：$R = 19$、$F = 85$、$M = 150{,}681$ 對得上基準值（因為課程資料集一列一次刷卡，`COUNT(*)` 恰好等於刷卡次數），`test_metrics.py` 全綠。

**另一個更嚴重的版本**（跨資料型態）：藍圖 §3 明訂 `fact_transaction` 的 grain 是「發票明細一列一品項」。用同一支 SQL 跑電商資料，`COUNT(*)` 算出來的是**品項數**：某顧客 3 張訂單、15 個品項 → $F = 15$，切進最高頻五分位、進 VIP 名單。而真正的高頻客（12 張訂單、每張 1 品項 → $F = 12$）排在他後面。

**修補動作**：
1. `templates/metric_definitions.csv` 每個指標新增 **`grain` 欄位**（`txn_line` / `txn` / `customer_day` / `customer`）。沒有 grain 的指標不准進 `build_features.py`（比照 `references/05 §九`「沒有基準值的指標不准進」的既有紀律）。
2. **廢除單名 `F`**，一律輸出三個具名指標：`F_line`（品項數）、`F_txn`（交易筆數，用 `COUNT(DISTINCT 發票號碼)`）、`F_days`（購買天數，`COUNT(DISTINCT txn_date)`）。報告中出現「F」時必須指明是哪一個。
3. **ARFM 的 A 維與 F 維強制同粒度**（都用 `customer_day`），否則兩維會互相矛盾。
4. `tests/test_invariants.py` 加：`F_days ≤ F_txn ≤ F_line`；`n_intervals = F_days − 1`；`abs(1/λ̂ − F_days/observed_days) < tol`。這三條在任何資料集上都成立，與課程基準值無關。

#### S8｜顧客-期 panel 資料用預設標準誤 → SE 低估、t 值虛胖

| | |
|---|---|
| **層** | S5 分析執行 / S6 驗證 |
| **適用** | 全部（凡有「顧客 × 期間」或「門市 × 日」的迴歸） |

**現況**：藍圖 §4 S5 的「異質性／動態性強制檢核」在**模型形式**上寫得對（單一全域 β ⇒ 同時假設掉異質性與動態性；需要 $\beta_i$ → 階層／隨機係數；需要 $\beta_t$ → 時變參數；兩者都要 → panel model）。**但完全沒有一句提到 panel 結構對標準誤的影響**，而這是行銷資料最常見、後果最直接的錯誤。素材本身也承認這塊是空的：01 §14 第 10 條「Durbin-Watson、Newey-West、WLS、robust SE、Box-Cox、穩健迴歸、bootstrap：材料只列為『可能的解決方式』，無公式與實作」。教材的獨立性假設只到「殘差圖波浪狀 → 自我相關」的視覺判讀（§13.3）。

**會怎麼出錯**：100 位顧客 × 24 個月 = 2,400 列，跑 `月消費金額 ~ 促銷月旗標 + 客層 + 月份`。`smf.ols(...).fit()` 用預設 nonrobust SE、以 $n = 2{,}400$ 計算：促銷係數 1,850 元、SE = 600、t = 3.08、p = 0.002。報告寫「促銷月每人平均多消費 1,850 元（p < 0.01）」，據此把促銷檔期從一年 4 檔加到 8 檔，新增成本約 480 萬。
**但同一位顧客的 24 個月殘差高度自相關**（愛買的人每個月都愛買），有效樣本數接近 100 而非 2,400。改用 cluster-robust（`cluster = cust_id`）後 SE = 1,150、t = 1.61、p = 0.11 —— **根本不顯著**。480 萬花在一個看不出效果的動作上，而且報告給了主管一個 p = 0.002 的錯誤信心。

**修補動作**：
1. `scripts/stats_utils.py` 新增 `ols_panel(formula, data, cluster)`：內部呼叫
   `smf.ols(formula, data).fit(cov_type='cluster', cov_kwds={'groups': data[cluster]})`，
   並**回傳 naive SE 與 cluster SE 的並列表**（讓落差被看見）。時間序列（門市 × 日）另提供 `cov_type='HAC', cov_kwds={'maxlags': L}`。
2. S5 加硬規則：**任何「一列不是一位顧客」的迴歸，禁用預設 SE。** 寫進 SKILL.md「絕對不要出現的東西」，與 T3（`anova_lm(typ=3)`）同級處理 —— 兩者的共同點是「不會報錯，只會給錯的數字」。
3. `verify_outputs.py` 加 CHECK：「每個迴歸結果物件都有 `cov_type` 欄位；當 `data_grain ≠ 'customer'` 時 `cov_type ≠ 'nonrobust'`」。
4. `references/06` 補一節「獨立性違反的三種形態與處方」：顧客內重複觀測 → cluster-robust；時間序列自相關 → HAC / Newey-West；空間或門市群聚 → 雙向 cluster。並補 Durbin-Watson 的實作（`statsmodels.stats.stattools.durbin_watson`）—— 素材只有名字。

#### S9｜沒有樣本外／out-of-time 驗證，也沒有 naive baseline

| | |
|---|---|
| **層** | S5 分析執行（DI 層）/ S6 驗證 |
| **適用** | 全部（凡有預測型交付物：流失預測、CLV 預測、回應率預測） |

**現況**：`G4` 管住「as_of 切點」，這是防洩漏。**但「不洩漏」不等於「有預測力」**，而 skill 沒有任何一處要求樣本外驗證。素材也是空的：01 §14 第 8 條「Criterion-based 只講了 AIC，BIC、Mallows' $C_p$、交叉驗證在材料中僅被提及名稱，無展開」。整份素材（含 6 份 Quiz、所有 GLM 案例）**沒有一次做過樣本外評估** —— 全部是 in-sample 的 Deviance / GOF / AIC。而 02 Part 5 D7 已經警告「先選變數後再看 p-value，會有選後 p-value 偏樂觀的問題」，D8「刪掉不顯著的變數，通常會讓留下的變數看起來更顯著」，方向對，但沒有給出唯一有效的解法（樣本外）。

**會怎麼出錯**：`as_of = 2012-06-30`，用 RFM + CAI + CRI + 因素分數共 14 個特徵建 logistic，預測「未來 6 個月是否再購買」。做了 backward elimination 留下 6 個變數，in-sample AUC = 0.89。報告寫「模型可有效識別流失風險（AUC 0.89）」，行銷對預測流失機率前 20% 的顧客投喚回預算（1,000 人 × 800 元 = 80 萬）。
**三個沒做的檢查**：
- 沒有 out-of-time 驗證（換 `as_of = 2012-09-30` 重建特徵與標籤再評估）。
- 沒有跟 naive baseline 比 —— 實測「只用 R 單變數排序」的 AUC 是 0.86。整套 14 特徵 + 因素分析的工程只多 0.03。
- 沒有察覺標籤（未來 6 個月是否再購買）與特徵 R（as_of 前多久沒買）對低頻顧客而言幾乎是同一件事的兩個切法。
**結果**：80 萬花在一個實質等於「把最久沒買的人挑出來」的排序上（那件事免費、一行 SQL 就有），並且錯過了真正該喚回的人 —— 高價值、剛開始減速、但 R 還不大的顧客。同時 backward elimination 後的 6 個 p 值全部偏樂觀（D7），報告的「顯著因子」清單不可信。

**修補動作**：
1. `build_features(as_of)` 之外強制配一支 `make_label(as_of, horizon)`；兩者的時間窗必須不重疊，且函式簽章要求明寫 `horizon`。
2. `05_models/` 固定產出一張三欄比較表：
   | 模型 | in-sample | out-of-time |
   |---|---|---|
   | naive baseline（單一 R 排序） | | |
   | naive baseline（RFM Score 排序） | | |
   | 候選模型 | | |
   **out-of-time 必須用更晚的 `as_of` 重建特徵，不可用隨機切列**（隨機切列在有時間結構的資料上會過度樂觀）。
3. 報告模板加固定小節「與 baseline 的比較」；**候選模型相對 naive baseline 的提升 < 0.03 AUC 時，強制寫「不建議上線，用 baseline 排序即可」**。
4. 變數選擇後的 p 值一律加註（沿用 D1–D8 的措辭模板），並在報告寫明「本節係數的顯著性為選後推論，偏樂觀」。
5. `verify_outputs.py` 加 CHECK：「任何預測型交付物都有 `out_of_time_metric` 與 `baseline_metric` 欄位」。

**修補動作**：
1. 新增 `scripts/seasonal_baseline.py`：任何跨時間區間的成效比較，**強制輸出兩個數字** —— raw 與「控制 `month`／`week_of_year` dummy + 線性趨勢（有去年資料時加同期基期）後的增量」。

#### S12｜不顯著結論沒有檢定力／最小可偵測效果（MDE），「沒差異」與「看不出差異」被混為一談

| | |
|---|---|
| **層** | S1 開案對焦（前移）+ S5 / S6 |
| **適用** | 全部 |

**現況**：E16 要求「『不顯著』要列表、要寫商業意涵」，E17 要求「所有群 × 所有人口變數都要出現，不顯著標『—』」。方向對（不顯著本身是資訊），**但沒有任何一處要求說明「這個樣本量本來能偵測多大的差異」**。教材也沒有 —— 素材全篇沒有一次算過檢定力或樣本量。結果是所有卡點都掛在 p 值上，沒有一處問「這個 n 能偵測多大的效果」。

**會怎麼出錯**：群 3（$n = 21$）與群 4（$n = 12$）比較平均客單價，$t = 1.12$、$p = 0.27$。報告依 E16 老實寫「兩群客單價無顯著差異，可沿用同一套定價策略」。
**但**：$n_1 = 21$、$n_2 = 12$、SD ≈ 3,000 元時，$\alpha = 0.05$ 雙尾、power = 0.8 的 MDE 約
$\text{MDE} = (1.96 + 0.84) \times 3{,}000 \times \sqrt{1/21 + 1/12} \approx 3{,}010$ 元。
也就是說**即使兩群真實差異有 2,500 元（約 40% 的客單價落差），這個樣本也大概率看不出來**。「無顯著差異」在這裡的正確翻譯是「這個樣本量看不出 3,000 元以內的差異」。行動：兩群被合併成一套定價，放棄了一個實際存在的價差機會；更糟的是報告用 E16 的格式把它寫成了一個「發現」。

**修補動作**：
1. `scripts/stats_utils.py` 新增 `mde_mean(n1, n2, sd, alpha=0.05, power=0.8)` 與 `mde_prop(n1, n2, p_base, ...)`（`statsmodels.stats.power` 已有現成的 solver，只需包裝成統一介面）。
2. 報告模板的每一列「不顯著」結論**強制多一欄「本樣本可偵測的最小差異」**；E16 的處方相應升級為「不顯著要列表 + 寫商業意涵 + 附 MDE」。
3. `verify_outputs.py` 加 CHECK：「所有 $p > \alpha$ 的結論列都有 `mde` 欄位」。
4. **把檢定力前移到 S1**：Check List 矩陣加一列「**這個決策需要偵測多大的差異？現有樣本量夠嗎？**」。這一列填不出來，等於這個決策事後只能得到「看不出來」——依 S1 的既有規則（任一格填不出來 ⇒ 該決策不被資料支援），應該當場明確放棄或改設計，而不是做完才發現。

### 2.3 nice-to-have — 品質與可信度，但不會直接翻轉結論方向

#### S14｜離群值刪除只交代樣本數變化，沒有量化「刪與不刪」對結論的影響

**現況**：教材 §13.2 Step 7 有敏感度分析（「移除可疑點重估，看係數／標準誤／$R^2$ 是否實質改變」），寫得很好。E22 要求交代樣本數變化。**但 skill 沒有把敏感度分析變成交付要求** —— 於是「刪了 3 筆」被記錄了，「刪了 3 筆之後結論翻盤」沒有。

**會怎麼出錯**：迴歸「年消費 ~ 年齡 + 教育 + CAI」，因 Cook's D > 1 刪掉 3 位大戶（合計佔營收 18%）。刪前 CAI 係數 1,240（p = 0.03），刪後 380（p = 0.41）。報告依 E22 老實寫「原始資料庫包含 100 位客戶，最終建模樣本 97 位，差異來自影響點處理」，但主結論仍用刪前的數字：「活躍度每上升一單位，年消費增加 1,240 元」。讀者無從得知這個結論完全依賴那 3 個人。

**修補動作**：`scripts/run_diagnostics.py` 對每個刪除決策自動產出並排係數表（含 / 不含 × 係數 / SE / p / $R^2$ / $\hat\sigma$），存成 `05_models/sensitivity_<model>.csv`，報告附錄固定收錄；`verify_outputs.py` CHECK「每一筆排除紀錄都有對應的 sensitivity 檔案，且若任一係數的顯著性在刪除前後改變，正文必須註明」。

#### S16｜貝氏收縮平均的 $\tau^2$／$s^2$ 沒有定義，且對高度右偏的 M 用常態收縮不當

**現況**：`references/05 §五` 給了 $\hat\theta_i = \lambda_i \bar x_i + (1-\lambda_i)\mu$、$\lambda_i = \frac{n_i \tau^2}{n_i \tau^2 + s^2}$，並誠實註明「官方 Excel 範本不在已取得的檔案中，公式形式待與 HW5 附件核對」。缺的是統計層面的兩件事：$\tau^2$（群間變異）與 $s^2$（群內變異）**要怎麼估**、以及**收縮的目標 $\mu$ 是誰**（全體？同 cohort？同分群？）。

**會怎麼出錯**：客單價分布高度右偏（教材 §13.6 明訂右偏要取 log）。直接對原始金額做常態收縮，$\mu$ 用全體平均（被少數大戶拉高）：買 2 次、平均 800 元的小客戶被收縮到 3,500 元，於是「預估客單價」欄位讓他進了「中價值」名單，收到一張門檻 3,000 元的滿額券，回應率為 0。收縮的方向對（小樣本要往母體拉），但**拉去的目標錯了**（拉到一個被右尾拉高的平均）。

**修補動作**：`references/05 §五` 補明三件事 —— (1) 在 `log(M)` 尺度上做收縮，回報時再 `exp`（並註明這是幾何平均意義）；(2) $\tau^2$、$s^2$ 用 method-of-moments 或直接改用 `statsmodels` 的 `MixedLM`（隨機截距模型的 BLUP 就是收縮估計，且定案文件 §3 已實測 MixedLM 可用，只是沒被指派這個任務）；(3) 收縮目標 $\mu$ 必須寫進指標字典的 `shrink_target` 欄位（全體 / cohort / 分群），因為它直接決定小樣本顧客會被拉到哪裡。核對 HW5 附件時把這三項一起定下來。

## 3. 對藍圖與 Skill 的更正建議

見 `blueprint_corrections`（結構化輸出）。摘要如下，每一條都附理由：

1. **`references/05 §四` 的 `NORM.DIST(x, 0, 15)` 照抄未加警語** —— sd = 15 是課程 Excel 的固定常數，不是估計值。
2. **`references/05 §一` 與 `§二` 的粒度自相矛盾** —— §一 說「分析單位是天不是筆」，§二 說「F 預設去重前原始筆數」。
3. **`references/05 §二` 的 `COUNT(*) FROM fact_transaction` 在 grain 上是錯的** —— 藍圖 §3 明訂 fact_transaction 一列一品項，`COUNT(*)` 算的是品項數。信用卡資料恰好相等所以基準值通過，換電商資料會靜默算錯。
4. **`references/05 §一` 步驟 5「刪每人最後一筆」寫成無條件必做，未提醒丟掉右設限資訊。**
5. **`references/05 §四` 執行順序步驟 9 的極端組設計未加警語** —— 兩尾各取 10% 再比較會膨脹效果量。
6. **`references/07` G8「統一 Benjamini-Hochberg FDR」與教材的 Tukey/Bonferroni/Scheffé 是不同的錯誤率目標** —— FDR ≠ FWER，且事後檢定用 Tukey 之後再對同一批 p 套 BH 是重複校正。
7. **`references/07` G7 的處方順序錯** —— 尺度與轉換決策在 k 之前。
8. **藍圖 §3.2 分域啟用表把 CLV 無條件列入「D1+D2+D3 可做」是高估** —— 歷史加總型可做，預測型需要設限模型與足夠長的觀測窗。
9. **藍圖 §4 S5 的異質性／動態性檢核只講模型形式，沒講標準誤** —— 低估了 panel 結構對 SE 的影響，而 MixedLM 已在選型清單裡卻沒被指派這個任務。
10. **藍圖 §5.1 #6 / G6 的「想主張因果就走 uplift／DiD／實驗設計」高估了 uplift/DiD 的門檻低** —— 兩者本身都是觀察型方法。
11. **SKILL.md 品質檢查清單的重心偏向「會被扣分的呈現錯誤」而非「會讓結論錯的推論錯誤」** —— 這是「檢查計算過程不檢查答案」的訓練遺留，建議把清單分成「呈現與評分（E 系列）」與「推論正確性（S 系列）」兩區。
12. **`references/07 §八` 的 12 條 CHECKS 全部是格式與一致性檢查，沒有一條是推論有效性檢查。**
13. **`references/05 §八` 把課程基準值稱為 ground truth，在「不檢查答案」的文化下容易被誤讀成「對得上就對了」** —— 需要一支跨資料集的 `tests/test_invariants.py` 補位。

## 4. 我認為不需要補的地方（明確說沒有）

- **迴歸與 ANOVA 的假設檢查流程**：教材 01 §13.2 / §13.3 / §13.8 已經是可以直接照抄的規格，我沒有實質可加的東西。唯一的問題不是內容缺失，而是這些內容**沒有被寫進 skill 的品質檢查清單**（見更正建議 11）——那是搬運問題，不是缺口。
- **GLM 的模型評估與 overdispersion**：教材 02 §6.4 / §6.5 的順序與判準都對，且比多數教科書更務實（「先跑 rich model，GOF 過了就只是漏變數」）。沒有缺口。
- **多重比較的原理與方法選擇**：01 §10.8 / §10.9 完整。缺的只是「家族界定」這個實務層問題（更正建議 6），不是原理缺口。
- **因果措辭**：02 Part 5 §5.1 的 ✔/✘ 句型模板品質很高，直接搬就好。缺的是**門檻**（S11），不是措辭。
- **變數選擇的推論陷阱**：D1–D8 八條把 post-selection inference 講得比很多統計教科書清楚。缺的只是解法（樣本外，見 S9）。
