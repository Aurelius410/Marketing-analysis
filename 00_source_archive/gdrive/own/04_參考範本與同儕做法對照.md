## 1. 主題 A：CLV / 階層貝氏收縮估計（HB、CRI）

### 1.1 【材料原文】學生A `04_海誓山盟…` 的完整計算鏈

六個工作表，線性管線：

```
Step 0_1  客戶靜態檔     欄：客戶ID | 性別 | 婚姻狀況 | 分群
Step 0_2  交易明細       欄：客戶ID | 刷卡日期 | 刷卡金額     （7764 筆）
Step 1    交易明細+分群   D2 =VLOOKUP(A2,'Step 0_1'!$A$2:$D$101,4,)
Step 2    個體樞紐        列標籤=客戶ID；計數-刷卡金額 / 平均值-刷卡金額 / 變異數-刷卡金額
Step 3    分群樞紐        列標籤=分群；  平均值-刷卡金額 / 變異數-刷卡金額
Step 4    估計            見下
```

`Step 4` 的欄位與公式（**逐字保留**）：

| 欄 | 標題 | 公式 |
|---|---|---|
| A | 列標籤（客戶ID） | （貼值） |
| B | 計數 - 刷卡金額 | （貼值，記為 n） |
| C | 平均值 - 刷卡金額 | （貼值，記為 x̄ᵢ） |
| D | 變異數 - 刷卡金額 | （貼值，記為 s²ᵢ） |
| E | 分群 | `=VLOOKUP(A2,'Step 1'!$A$2:$D$7765,4,FALSE)` |
| F | 分群平均數 | `=VLOOKUP(E2,'Step 3'!$A$4:$C$7,2,FALSE)` |
| G | 分群變異數 | `=VLOOKUP(E2,'Step 3'!$A$4:$C$7,3,FALSE)` |
| H | W1 | `=G2/(G2+(D2/B2))` |
| I | W2 | `=(D2/B2)/(G2+(D2/B2))` |
| J | 更正後HB估計值 | `=H2*C2+I2*F2` |
| K | （貼值 = J） | |
| L | 投影片公式CRI | `=((C2-K2)/(C2-F2))*100` |
| M | 正統背氏估計公式 | `=((C2*B2/D2)+(F2/G2))/((B2/D2)+(1/G2))` |

數學形式（τ² = 分群變異數 G，σ²ᵢ = 個體變異數 D，nᵢ = 筆數 B）：

```
W1 = τ² / (τ² + σ²ᵢ/nᵢ)
W2 = (σ²ᵢ/nᵢ) / (τ² + σ²ᵢ/nᵢ)          （W1 + W2 = 1）
HB = W1·x̄ᵢ + W2·μ_group                （加權平均式）
HB = (x̄ᵢ·nᵢ/σ²ᵢ + μ_group/τ²) / (nᵢ/σ²ᵢ + 1/τ²)   （精確度加權式）
CRI = (x̄ᵢ − HB)/(x̄ᵢ − μ_group) × 100
```

### 1.2 【評註】她做對、而且值得抄的一件事

**她把同一個估計用兩條路算了兩遍（J 欄「加權平均式」與 M 欄「正統背氏估計公式」），並讓兩欄並排。**
兩欄數值到小數點後 10 位以上一致（例：1772.2919598883134 vs 1772.2919598883136），差異只有浮點尾數。
這是**零成本的自我驗證**：如果打錯一個括號，兩欄立刻分岔。欄位還取名「正統背氏估計公式」，明示這是拿來對照投影片版本的。

代數上兩式恆等，可以自己證：
```
HB = W1·x̄ + W2·μ
x̄ − HB = x̄ − W1·x̄ − W2·μ = W2·(x̄ − μ)
⟹ CRI = (x̄ − HB)/(x̄ − μ)·100 = W2 × 100
```
也就是說 **L 欄的 CRI 恆等於 I 欄的 W2 乘 100**（對照資料：I2=0.0036491085983032293、L2=0.3649108598303092）。
她並沒有在檔案裡點破這件事 —— 但這代表 CRI 的語意就是「**向群體均值收縮的百分比**」，n 越大、個體變異越小，CRI 越接近 0（越相信自己的資料）。

### 1.4 【評註】兩人**都**踩到的同一個方法學問題：τ² 用錯層級

`Step 3` / `分群樞紐分析` 的「變異數 - 刷卡金額」是**對該群內所有交易列**做的樞紐變異數，
也就是 `Var(所有交易金額 | 群)`。這個量 = 群內「顧客間變異」+「顧客內變異」的總和。

但 HB 模型裡 τ² 的定義是**顧客真實均值在群內的變異**（between-customer variance），不含顧客內雜訊。
正確的動差估計是：
```
τ̂² = Var(顧客均值 x̄ᵢ) − mean(σ²ᵢ / nᵢ)          （動差法，可能為負，須 clip 至 0）
```
用交易層總變異取代 τ² 會**高估 τ²** → W1 偏大 → **收縮不足**。
對照資料可見後果：群 2 的 τ̂² 被填成 33,858,875，而個體 `σ²ᵢ/nᵢ` 動輒只有 10⁴~10⁵ 量級，
於是 W1 幾乎全部落在 0.98~0.9999，**HB 估計值幾乎等於原始樣本均值，收縮效果被抵銷掉了**。
Step 4 的 100 位顧客裡，CRI（=收縮%）超過 10% 的只有極少數（客戶 1314 的 10.90%、客戶 1250 的 8.28%），
其餘多在 0.01%~5%。整個 HB 幾乎沒發揮作用。

同樣地，`F 欄 分群平均數` 是樞紐的**交易加權平均**，不是顧客均值的簡單平均。
群 2 裡客戶 605 一個人就有 955 筆交易（占全體 7764 筆的 12%），平均金額只有 96.6，
他一個人就把群 2 的 μ 往下拉。若目的是「這一型顧客的典型水準」，應該用**未加權的顧客均值平均**。

> **這是三份檔案共通的錯**，而且鄭仲凱的 hw4_內文.pdf 也沒有討論到，推測是課程投影片本身就這樣教。
> 對 Skill 的意義：這正是「**照著投影片做會得到一個合法但被閹割的估計**」的案例，
> 值得在方法選擇章節明講「τ² 的三種取法及其後果」。

## 2. 主題 B：購物籃分析 —— 同一個問題，三條合法路徑

三個人做的**都不是** Apriori / support-confidence-lift。實際出現的是三種路徑：

### 路徑 1：相關係數法（學生A、學生D、鄭仲凱都做了）

共通管線：
```
交易明細
  → 樞紐：列 = 籃子單位、欄 = 品類、值 = 計數        （Step 1 / Step2）
  → 二元化：=IF(樞紐儲存格>0,1,0)                    （Step 2 / Step3）
  → 資料分析工具箱「相關係數」→ 下三角矩陣           （Step 3 / Step4）
  → 取消樞紐(unpivot) 攤成 三欄：Column1 | 屬性 | 值  （Step 4 / Step 2-5）
  → 排序取 Top 20 / Bottom 20
```

二元矩陣上的 Pearson 相關係數 = **φ 係數（phi coefficient）**，等價於 2×2 列聯表的 √(χ²/n)。
它**同時懲罰「兩者皆無」**，這是它跟 lift/confidence 最大的行為差異。

**關鍵分歧：籃子單位（basket unit）與 item 粒度**

| | 學生A 05 | 學生D 05 | 鄭仲凱 hw5-2 |
|---|---|---|---|
| 資料集 | 信用卡交易檔（7764 筆 / 100 人） | 3C 零售交易檔（3077 筆 / 200 人 / 1130 品項） | 信用卡交易檔（同學生A） |
| 籃子單位 | **客戶**（一人一列） | **客戶**（一人一列） | **客戶** |
| item | 刷卡產品產業分類（15 類） | Category 品類（29 類） | 產業分類（15 類） |
| 矩陣大小 | 100 × 15 | 200 × 29 | 100 × 15 |
| 門檻 | `=(IF(B42>0.3,B42,0))` | 無門檻，直接排序 | 無（改用 factor loading > 0.4） |

學生A與鄭仲凱**得到完全相同的 Top 20**（0.47253841814808034、0.41819228691100985、0.41396578451314037…逐位相同），
證實兩人是同一份資料、同一條管線 —— 可作為 Skill 產出的**回歸測試黃金值**。

> **注意：「籃子 = 客戶」不是傳統購物籃分析。**
> 傳統啤酒尿布是「籃子 = 一次結帳」。用「客戶」當籃子，量到的是
> **「這兩類東西會不會被同一種人買」**（跨時間的品味相關），不是「會不會被一起拿去結帳」。

## 3. 主題 C：序列 / 遷徙路徑（「下次購買什麼」）

兩人都做了，公式幾乎同構，但**前處理差很多**。

### 3.1 【材料原文】兩人的「下一筆」公式

學生D `Step 2-1` I 欄「下次購買」：
```excel
I2 =IF(C2=C3,G3,6666)          '同一顧客(C欄)則取下一列的品類(G欄)，否則填哨兵 6666
```
學生A `Step-2` J 欄「下次購買產品」：
```excel
J2 =IF(C3=C2,E3,9999)          '哨兵改用 9999
```

兩人都用「**同 ID 就抓下一列，否則放哨兵**」這個 Excel 慣用法。前提是資料必須先依 (顧客, 日期) 排序。

### 3.2 【材料原文】兩人的正規化都除以**總計**，不是列總計

學生D `Step 2-4`：
```excel
B2 ='Step 2-3'!B2/'Step 2-3'!$AF$32
```
學生A `Step5`：
```excel
B2 ='Step-4'!B3/Step5!$Q$17
```

`$AF$32` / `$Q$17` 都是轉移次數矩陣的**總計格**。所以兩人算出來的是
**聯合機率 P(A 且下一次是 B)**，不是條件轉移機率 P(B | A)。

### 3.3 【評註】除以總計 vs 除以列總計：這是最該寫進 Skill 的一個決策點

- 除以**總計** → 聯合機率 = 支持度。Top-N 會被**高頻品類的自我重複**霸榜。
  實證：學生D `Step 2-6` 排序後前三名是 `EPSON墨水→EPSON墨水` (0.01610)、`HP墨水→HP墨水` (0.01053)、`DVD燒錄片→DVD燒錄片` (0.00619) —— 全是對角線。
  學生A `Step5` 同理：對角線 `13_交通→13_交通` = 0.13642、`06_公用事業→06_公用事業` = 0.15463、`12_量販超市→12_量販超市` = 0.10130 遠遠壓過所有跨品類轉移。
  **這種排行榜只是在重述「哪個品類賣得多」，沒有任何遷徙資訊。**
- 除以**列總計**（Step-4 的 Q 欄已經現成算好了！）→ 條件機率 P(B|A)，每列加總為 1，
  這才是馬可夫轉移矩陣，才能回答「買了 A 的人接下來最可能買什麼」。
- 若要「**比隨機更可能**」則需再除以 B 的邊際：lift = P(B|A)/P(B)。

學生A的 `Step-4` 工作表**明明已經有 Q 欄的列總計**（26 / 171 / 26 / 1103 / 490 / 174 / 261 / 254 / 462 / 1116 / 1436 / 202 / 234 / 153 / 42），
換成 `='Step-4'!B3/'Step-4'!$Q3` 就是條件機率 —— **一個 `$` 的位置差別，結論天差地遠**。

### 3.4 序列分析的去重規則：兩人不一致，而且我驗算出誰對

同一份 7764 筆信用卡交易，要壓成「一天一筆」才能談序列：

| | 學生A | 鄭仲凱 hw3-2 | 真值（pandas 驗算） |
|---|---|---|---|
| 去重後列數 | **6252** | **5294** | `drop_duplicates(['客戶ID','刷卡日期'])` = **5294** |

學生A的去重公式（`信用卡交易記錄檔 (條件）` I 欄）：
```excel
I2 =IF(AND(C3=C2, D3=D2), "", "保留")
```
邏輯是「若**下一列**同顧客同日期則丟棄本列」—— 也就是保留同日連續段的**最後一列**。

**兩個問題：**
1. **欄位名稱與邏輯相反。** 欄位叫「同天第一筆交易資料」，但公式保留的是**最後一筆**。
2. **致命的是：這張表沒有先排序。** 我用 pandas 驗算：
   ```
   信用卡交易記錄檔 (條件）  7764 列
   是否已依 (客戶ID, 刷卡日期) 排序？  False
   模擬她的公式 → 保留 6252 列
   Step-1 實際列數 → 6252 列                  （吻合，確認是這條公式的產物）
   Step-1 內真正相異的 (客戶ID, 刷卡日期) → 5294
   ```
   **有 958 個重複的「顧客-日期」倖存下來**，因為相鄰比對只能消掉**相鄰**的重複。
   這些殘留會被 `Step-2` 當成獨立的「下一筆」，直接污染轉移矩陣。

> **這是這批材料裡最乾淨、最可驗證的一個錯誤實例。**
> 錯誤型態：「用相鄰列比對做去重，但沒有先排序」。
> 它極度隱蔽 —— 公式本身無誤、沒有 `#N/A`、結果看起來合理，只有拿真值對照才會現形。

## 4. 主題 D：RFM 計分（鄭仲凱 hw3-1）—— 三種切法並排比較

### 4.1 【材料原文】原始指標

```excel
B2 =$F$2-E2                                          'Recency，$F$2 = 基準日 2012-12-01
C2 =COUNTIF(信用卡交易記錄檔!C:C,A2)                  'Frequency
D2 =SUMIF(信用卡交易記錄檔!C:C,A2,信用卡交易記錄檔!G:G) 'Monetary（總額）
E2 = {陣列公式}                                       '最後消費日期
```

### 4.2 【材料原文】三種計分法

**(a) 原版 Bob Stone**（`原版Bob stone` 工作表）
```excel
E2 =IFS(B2<=90,24, B2<=180,12, B2<=270,6, B2<=360,3, B2>360,0)   ' R
F2 =ROUND(C2*4,0)                                                 ' F
G2 =MIN(INT(D2*0.01),9)                                           ' M
H2 =SUM(E2:G2)                                                    ' RFM Score
I2 =RANK(H2,H:H)
```

**(b) 自訂 Bob Stone**（`自訂Bob stone` 工作表）
```excel
E2 =IFS(B2<=30,48, B2<=24,10, B2<=90,12, B2<=120,6, B2<=150,3, B2>151,0)
F2 =ROUND(C2*4,0)
G2 =MIN(INT(D2*0.0001),9)
H2 =SUM(E2:G2)
I2 =RANK(H2,H:H)
```

**(c) 五等分法**（`五等分法` 工作表）
```excel
E2 =PERCENTRANK.INC(B:B,B2)     ' R 的百分位
F2 =PERCENTRANK.INC(C:C,C2)
G2 =PERCENTRANK.INC(D:D,D2)
H2 =IF(E2<=0.2,"5",IF(E2<=0.4,"4",IF(E2<0.6,"3",IF(E2<0.8,"2","1"))))   ' R 反向
I2 =IF(F2>=0.8,"5",IF(F2>=0.6,"4",IF(F2>=0.4,"3",IF(F2>0.2,"2","1"))))
J2 =IF(G2>=0.8,"5",IF(G2>=0.6,"4",IF(G2>=0.4,"3",IF(G2>0.2,"2","1"))))
K2 =H2+I2+J2
L2 =RANK(K2,K:K)
```

### 4.3 【材料原文】他怎麼比較這三種切法（`總比較表`）

```excel
U3 =S3-N3                    ' 自訂 Bob Stone RANK − 原版 Bob Stone RANK
V3 =STDEV(U3:U102)           ' → 2.4908722256359206
V5 =AVERAGE(U3:U102)         ' → 0.24
W3 =I3-N3                    ' 五等分法 RANK − 原版 Bob Stone RANK
X3 =STDEV(W3:W102)           ' → 11.2006493318265
X5 =AVERAGE(W3:W102)         ' → -3.2
```

【材料原文】hw3-1_內文.pdf 的結論：
> a. 自訂之 Bob stone 與原版 Bob stone 所測出之效果相差不大，但 Bob Stone 法與五等分法分數差異卻十分顯著。
> b. 五等分法透過此次分析可證實存在無法有效切割客群的缺點，因為資料實際上並非如理想均勻分配，
>    且切割點不客觀、採用 Ordinal scale 也不適合日後作統計分析。

### 4.4 【評註】值得抄：用「排名差的標準差」量化兩種計分法的分歧

這是很聰明的做法。兩種計分法的**絕對分數不可比**（Bob Stone 分數上看 3800，五等分法上限 15），
但**排名**可比。用 `RANK 差的標準差` 當作「兩法有多不一致」的單一數字，直接得到 2.49 vs 11.20 的對照，
比目視兩張排行榜有說服力得多。**這個技巧可以直接搬進 Skill：任何兩種計分/分群方案的比較，先轉成排名再比。**

### 4.5 【評註】三個實作缺陷

1. **`自訂Bob stone` 的 R 分級公式有 unreachable branch（實作與規格不符）。**
   規格（hw3-1_內文.pdf 的表格，逐字）：
   > Recency：最近 30 天內 48 分／最近 31-60 天內 24 分／最近 61-90 天內 12 分／
   >          最近 91-120 天內 6 分／最近 121-150 天內 3 分／最近 151 天以上 0 分

   實作：`=IFS(B2<=30,48, B2<=24,10, B2<=90,12, B2<=120,6, B2<=150,3, B2>151,0)`

   第二個條件 `B2<=24` **永遠不會被觸發**（`B2<=30` 先攔截），應該是 `B2<=60,24` 打成 `B2<=24,10`。
   後果：**「31–60 天」這一級完全消失**，該區間的顧客掉到 `B2<=90` 拿 12 分（規格是 24 分）。
   `IFS` 的短路特性讓這個錯誤**完全靜默**，不報錯、不出 `#N/A`。

2. **M 欄的文件與實作不符。** 規格說「**平均**刷卡金額 * 0.0001」，
   但 `D 欄` 是 `SUMIF(...)` 的**總**刷卡金額，`G2 =MIN(INT(D2*0.0001),9)` 吃的是總額。
   （原版 Bob Stone 更是用 `*0.01`，兩張表的 M 定義不一致卻拿來比排名。）

3. **五等分法的邊界運算子不一致。** R 用 `<=0.2, <=0.4, <0.6, <0.8`（第 3、4 段變成嚴格小於），
   F/M 用 `>=0.8, >=0.6, >=0.4, >0.2`（最後一段變成嚴格大於）。
   在 100 筆、百分位有大量並列的情況下，邊界上的顧客會依欄位不同而分到不同組。
   另外 `IF` 回傳的是**文字** `"5"`，靠 `K2=H2+I2+J2` 的隱式轉型才變成數字 —— 能跑，但脆弱。

## 5. 主題 E：CAI / WMLB 活躍度（鄭仲凱 hw3-2）

### 5.1 【材料原文】完整計算鏈

```
信用卡交易記錄檔（已先去重成 5294 筆 顧客-日期）
  ↓  工作表「算間隔」
C2 =IF(A3=A2, B3-B2, 9999)          ' 到下一次刷卡的天數；顧客最後一筆填 9999
  ↓  工作表「刪除9999」  → 5192 筆（每位顧客少一筆，100 位 → 少 100 筆 + 表頭）
  ↓  工作表「算權值」
D2 =IF(A2=A1, 1+D1, 1)              ' 顧客內的流水序號 1,2,3,... 當權重（越晚權重越大）
E2 =C2*D2                            ' 間隔 × 權值
  ↓  樞紐（列=客戶ID）：平均值-間隔 / 加總-權值 / 加總-間隔X權值
  ↓  工作表「WMLB&CAI」
E2 =D2/C2                            ' WMLB = Σ(間隔×權值) / Σ(權值)
F2 =((B2-E2)/B2)*100                 ' CAI = (簡單平均間隔 − WMLB) / 簡單平均間隔 × 100
```

語意：權重隨購買序遞增，所以 WMLB 是**偏重近期的加權平均購買間隔**。
CAI > 0 ⟺ WMLB < 簡單平均 ⟺ **近期間隔變短 = 加速消費 = 活躍**；CAI < 0 = 冷卻中。

樣本值：
```
客戶 89  ：平均間隔 10.2794  WMLB 11.5708  CAI -12.5625   （冷卻）
客戶 106 ：平均間隔 10.8182  WMLB 10.0335  CAI  +7.2536   （活躍）
客戶 605 ：平均間隔  2.2965  WMLB  2.2651  CAI  +1.3684
客戶 179 ：平均間隔 147.0    WMLB 164.8333 CAI -12.1315
```

### 5.2 【評註】

**值得抄：** `D2 =IF(A2=A1, 1+D1, 1)` 是純 Excel 做「group-wise 累加序號」（等同 SQL 的
`ROW_NUMBER() OVER (PARTITION BY 客戶ID ORDER BY 日期)`）的標準寫法，靠自我遞迴引用上一列。
搭配 `IF(A3=A2, ..., 哨兵)` 做 group-wise lead，兩個 idiom 就能在 Excel 裡完成大部分 window function 的活。

**陷阱：** `WMLB&CAI` 的樞紐總計列（第 99 列）也套了同一組公式：
```excel
E99 =D99/C99   → 5.769814497027907
F99 =((B99-E99)/B99)*100 → 46.48837685583064
```
這個「全體 CAI = 46.49」是**把所有顧客的權值混在一起除**得到的，沒有意義（權值只在顧客內可比）。
它沒有被引用到後續分析，但如果有人不小心當成「整體活躍度」引用就會出事。
**通則：任何 group-wise 正規化的指標，樞紐的「總計」列必定是垃圾，要主動刪掉或標記。**

**另一個結構性問題：** CAI 的分母是「簡單平均間隔」，對只有 2–3 次交易的顧客極不穩定
（例：客戶 179 只有 4 筆交易 → 3 個間隔，平均 147 天，CAI 就靠這 3 個數字決定）。
CAI 應該搭配最低交易筆數門檻，或對低頻顧客做收縮（正好就是 §1 的 HB 手法）。

> 第一欄客群 RFM 之標皆為最高代表該客群在近期有多次刷卡，然而 CRI 最低，代表穩定度不高，
> 可能是剛辦卡的嚐鮮用戶，因此稱為「新星群」。……
> 第四欄客群雖然 RFM 明顯不如其他三群，但具有較高的穩定性，符合成熟客戶的特性，因此稱為「穩定群」。

**F 檢定用的是取對數後的依變數**：`LN_RFM Score`、`LN_刷卡總金額`、`LN_刷卡平均金額`。

### 6.1 【評註】

**值得抄（三點）：**
1. **對右偏的金額變數先取 LN 再做 ANOVA。** RFM Score（F 分量可達 3820）與刷卡金額都是極度右偏，
   直接做 ANOVA 會被少數大戶主導。他全部改用 `LN_` 前綴的變數，這是正確且常被學生忽略的一步。
2. **用「多個指標的側寫」而非單一指標替群命名。** 他同時看 R/F/M/CAI/CRI 五個維度才下名字，
   而且名字帶有時間方向性（新星／凋零／活躍／穩定），直接可對應行動。
3. **他自己承認樣本不足並排除。**（原文）
   > 由於樣本數僅 97 人，因此在 K-means 群及分析下「新星群」、「凋零群」各只有 1 人，
   > 不具參考價值，因此將資料庫之價值著重在「活躍群」與「穩定群」。

   **這是這批材料裡少見的、主動承認方法侷限的段落。**

**錯誤實例：**
1. **K-means 退化解未處理。** 4 群裡有 2 群只有 1 人 —— 這是 k 選太大 + 未標準化 + 右偏變數（F 值域 175~3820）
   共同造成的。正確處置是**標準化後重跑、或降低 k、或先做離群值處理**，而不是事後把兩群丟掉。
   （丟掉之後 CAI/CRI 的群平均已經被那兩個離群值汙染過了。）
2. **文字與表格不一致。** 內文寫「活躍群 11 人、**穩定群 97 人**」，但表格是 84 人（1+1+11+84=97）。
   應為 84 誤植為 97（把總數寫成群數）。
3. **大量不顯著結果仍逐格報告。** 卡方那張表的 p 值全部在 0.572~0.909，全不顯著，
   卻仍完整列出 12 個職業 × 4 群的百分比 —— 在 n=1 的群報「100%」是誤導性的呈現。

## 8. 值得抄的做法（正面清單）

1. **同一估計用兩條代數路徑並排算，當作免費的斷言。**
   學生A 04 的 `J 欄（加權平均式）` vs `M 欄（精確度加權式）`，一致到浮點尾數。
   → Skill 應該把「HB 估計」實作成兩式並回傳 `max_abs_diff` 當健康檢查。

2. **把兩種合法方法並排在同一張表，逐條檢查分歧，並誠實面對門檻附近的灰色地帶。**
   鄭仲凱 hw5-2 的 `與TOP20購物籃分析的比較`：左邊相關係數 Top20、右邊 SPSS 旋轉成分矩陣，

3. **比較兩種計分法時先轉成排名，再用「排名差的標準差」當單一分歧度指標。**
   鄭仲凱 `總比較表`：`STDEV(自訂RANK − 原版RANK)` = 2.49 vs `STDEV(五等分RANK − 原版RANK)` = 11.20。
   絕對分數不可比，排名可比。

4. **把分群編碼規則寫成公式而不是手動貼值。**
   鄭仲凱 hw4 的三層 `IF`（性別 → 教育程度 → 交叉分群）可追溯、可重跑；
   學生A的 `分群` 欄是貼死的數字，無法驗證編碼是否正確。

5. **右偏金額變數先取 LN 再做 ANOVA / F 檢定。** 鄭仲凱 hw7 全面使用 `LN_` 前綴變數。

6. **Excel 的 window function 兩個 idiom：**
   ```excel
   ' group-wise lead（下一列，跨組時放哨兵）
   =IF(A2=A1, B2-B1, 9999)         或  =IF(C2=C3, G3, 6666)
   ' group-wise row_number（組內流水號）
   =IF(A2=A1, 1+D1, 1)
   ```
   兩者合用即可在純 Excel 完成 `LAG/LEAD/ROW_NUMBER OVER (PARTITION BY ...)`。

7. **主動宣告樣本不足並限縮結論範圍。** 鄭仲凱 hw7 承認 n=1 的群「不具參考價值」。

8. **用「取消樞紐」把矩陣攤平成三欄長表再排序取 Top-N。**
   三個人都用 `Column1 | 屬性 | 值` 的長表格式來排序相關係數矩陣 —— 這是 Excel 裡處理
   對稱矩陣 Top-N 的標準做法（矩陣本身無法直接排序）。

### 10.2 `dump_xlsx.py` —— 通用 Excel 逆向工程腳本

**這是本次最實用的可重用資產。** 它同時載入 `data_only=False`（公式）與 `data_only=True`（快取值），
把每格輸出成 `座標{公式 => 值}` 或 `座標[值]`，讓「別人的 Excel 到底怎麼算的」一次看完。

```python
import openpyxl, sys, os, io

def cellstr(c):
    v = c.value
    return '' if v is None else str(v)

def dump(path, out, maxrow=40, maxcol=35):
    wb  = openpyxl.load_workbook(path, read_only=False, data_only=False)  # 公式
    wbv = openpyxl.load_workbook(path, read_only=False, data_only=True)   # 快取值
    out.write('\nFILE: %s (%d bytes)\nSHEETS: %s\n' % (os.path.basename(path),
              os.path.getsize(path), wb.sheetnames))
    for ws in wb.worksheets:
        wsv = wbv[ws.title]
        out.write('\n### SHEET %r rows=%s cols=%s\n' % (ws.title, ws.max_row, ws.max_column))
        nr, nc = min(ws.max_row or 0, maxrow), min(ws.max_column or 0, maxcol)
        def emit(r, tag=''):
            parts = []
            for ci in range(1, nc + 1):
                c, cv = ws.cell(r, ci), wsv.cell(r, ci)
                f, v = cellstr(c), cellstr(cv)
                if not f and not v: continue
                parts.append('%s{%s => %s}' % (c.coordinate, f, v[:40]) if f.startswith('=')
                             else '%s[%s]' % (c.coordinate, f[:60]))
            if parts: out.write('  ' + tag + ' | '.join(parts) + '\n')
        for r in range(1, nr + 1): emit(r)
        if (ws.max_row or 0) > maxrow:                    # 尾列常藏總計/晚加的公式
            out.write('  ... (%d more rows) ...\n' % (ws.max_row - maxrow))
            for r in range(max(nr + 1, ws.max_row - 4), ws.max_row + 1): emit(r, 'TAIL ')
    wb.close(); wbv.close()

if __name__ == '__main__':
    with io.open(sys.argv[1], 'w', encoding='utf-8') as out:
        for p in sys.argv[2:]:
            try: dump(p, out, maxrow=int(os.environ.get('MAXROW', '40')))
            except Exception as e: out.write('\nERROR %s: %r\n' % (p, e))
```

用法：`MAXROW=25 python dump_xlsx.py 輸出.txt 檔1.xlsx 檔2.xlsx`

**設計要點（踩過的坑）：**
- 必須用 `read_only=False`。`read_only=True` 的 `ReadOnlyWorksheet` **沒有** `.dimensions` 屬性，也不能雙開。
- 一定要「頭 N 列 + 尾 5 列」：總計列、事後補的公式、拖曳沒拉到底的邊界錯誤全在尾部（陷阱 #5、#13 都是這樣抓到的）。
- 輸出寫**檔案**不要印到 stdout —— Windows 終端會把中文變亂碼，寫 UTF-8 檔再用 Read 工具看。

### 10.3 Big5 zip 解壓片段

```python
import zipfile, os
z = zipfile.ZipFile(path)
for i in z.infolist():
    nn = i.filename
    if not (i.flag_bits & 0x800):          # 沒設 UTF-8 flag ⇒ 是 Big5/cp950
        raw = nn.encode('cp437')
        for enc in ('big5', 'cp950', 'utf-8'):
            try: nn = raw.decode(enc); break
            except Exception: pass
    tgt = os.path.join(out, nn)
    if i.is_dir(): os.makedirs(tgt, exist_ok=True); continue
    os.makedirs(os.path.dirname(tgt), exist_ok=True)
    open(tgt, 'wb').write(z.read(i))
```
注意 `flag_bits & 0x800` 的判斷 —— 少了它，已是 UTF-8 的項目會在 `.encode('cp437')` 炸掉。
