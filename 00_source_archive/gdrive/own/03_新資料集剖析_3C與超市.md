### 三個必答問題的答案（先給結論）

**Q1：品項分類表是幾層？購物籃／因素分析該在哪一層做？**

分類表本身 **3 層**（大類 5 / 中類 12 / 小類 98），但交易檔的 `小分類名稱` 是 **6 碼**，比小類多一層，
所以實際可用階層是 **4 層 + SKU 共 5 個粒度**。實測各層矩陣密度後結論：

- **因素分析 → 做在「中類」（13 個，n/p = 15.4，密度 0.392）**，且必須先剔除零變異欄
- **購物籃關聯規則 → 做在「小類」（98 個）或「中類」**，籃子用 `交易編號`（562 張單，每單平均 3.82 個中類）
- 細類（297）與 SKU（2,030）密度只有 0.042 / 0.008，除非只做 top-N 品項否則規則會全是雜訊

**Q2：與信用卡資料集的結構比較？** → 見 §5。三份都算得出 RFM；
CAI 三份都算得出；**購物籃／因素分析只有 3C 與超市能做**（信用卡沒有品項階層，只有 15 個產業分類且無層級）。

**Q3：DuckDB → Parquet + RFM 可行嗎？** → **可行**。12 個新 Parquet 已落地，
兩份 RFM 皆實算完成，Monetary 與原始交易檔加總**完全相符（誤差 0）**。

```
F3 = Date的意思是取日期，Left是從該字串最左邊起開始取數字，2是取兩位數字的意思，
F4 = Mid則是選擇從中間第幾(像輸入3)就是從3開始取兩位數字，right則是由右往左取，看完自己在上面輸入=, enter就好了
```

**【材料原文】驗證 E 欄：**

```
以 DuckDB 重算每位會員 MAX(交易日期) 並與 工作表1!E 比對：
 n = 200, 相符 = 200      ← 100% 相符，陣列公式正確
```

**【評註】** F2 是**老師給的民國轉西元公式**（前面沒有 `=`，所以是文字說明不是公式），
F3/F4 是操作指引。**這是課程教材的一部分，要原樣保留。**
`DATE(LEFT(E2,2)+1911, MID(E2,3,2), RIGHT(E2,2))` 明確證實 **`交易日期` 是民國年**，
不是西元兩位數。等價 SQL：

```sql
make_date(CAST(交易日期/10000 AS INT) + 1911,
          CAST((交易日期/100) % 100 AS INT),
          CAST(交易日期 % 100 AS INT))
```

### 3.7 【重大瑕疵】超市基準日錯誤

**【材料原文】用檔內原始基準日 2010-01-01 實算的結果：**

```
Recency 負值人數: 124 / 200   （min = -363, max = +363）
```

**【評註】診斷與修正建議：**

資料期間是 2009-01-01 ～ 2010-12-30，**基準日 2010-01-01 落在正中間**，
導致 62% 的會員 Recency 為負（他們的最後消費在基準日「之後」）。

**最可能的成因（推論）**：民國 99 年 12 月 30 日的隔天是**民國 100 年 1 月 1 日 = 西元 2011-01-01**。
出題者套用 `LEFT(...)+1911` 的心智模型時，把年份誤算成 `99 + 1911 = 2010`，
應該是 `100 + 1911 = 2011`。**這是「民國跨百年」的經典錯誤。**

**修正方案：基準日改用 `2011-01-01`（民國 100/1/1，= max 交易日 + 2 天）。**
理由：(a) 與另外兩份「max + 1 天」的慣例最接近；(b) 民國 100/1/1 是自然的整年切點；
(c) 修正後 **Recency 負值 = 0，min = 2 天、max = 728 天**，分布合理。

**寫報告時的建議措辭**：
> 本研究基準日採 2011-01-01（民國 100 年 1 月 1 日）。原始檔案 `工作表1!G2` 標示為 2010-01-01，
> 惟該日期落於資料期間（2009-01-01 ～ 2010-12-30）之內，將導致 124 位會員之 Recency 為負值，
> 應係民國 99→100 年轉換時之筆誤，故予以修正並於此註明。

```python
con.execute("COPY (SELECT * FROM vsm_tx) TO '%s' (FORMAT PARQUET, COMPRESSION ZSTD)" % path)
```

**【評註】三個踩到的坑：**

1. **DuckDB 的 `rows` 是保留字** —— `COUNT(*) rows` 直接 ParserException。改用中文別名 `列數` 即可。
2. **子查詢的欄位不會自動外傳** —— `SELECT COUNT(DISTINCT x) FROM (SELECT y, COUNT(DISTINCT x) FROM ...)`

3. **Windows 路徑要轉正斜線** —— `path.replace('\\','/')` 才能塞進 SQL 字串。

### 6.5 RFM 五分位評分（兩份共用範本）

**【材料原文】SQL 範本（R 反向計分）：**

```sql

         DATE '<基準日>' - MAX(交易日) AS R,
         COUNT(DISTINCT 交易單號)      AS F,
         SUM(金額)                     AS M
```

### 7.3 關聯規則實測（support / confidence / lift）

**【材料原文】SQL（自 join 求成對共現，DuckDB 原生可跑）：**

```sql
WITH basket AS (SELECT DISTINCT 交易編號, 中類名稱 FROM vsm_tx WHERE 中類名稱 <> 'False'),
 n    AS (SELECT COUNT(DISTINCT 交易編號)*1.0 AS N FROM basket),
 sup1 AS (SELECT 中類名稱 AS i, COUNT(*)*1.0 c FROM basket GROUP BY 1),
 pair AS (SELECT a.中類名稱 AS A, b.中類名稱 AS B, COUNT(*)*1.0 c
          FROM basket a JOIN basket b
            ON a.交易編號 = b.交易編號 AND a.中類名稱 < b.中類名稱   -- < 避免重複與自配對
          GROUP BY 1,2)
SELECT A, B, CAST(p.c AS INT) AS 共同出現,
  ROUND(p.c/n.N, 4)                              AS support,
  ROUND(p.c/sa.c, 4)                             AS conf_A2B,
  ROUND(p.c/sb.c, 4)                             AS conf_B2A,
  ROUND((p.c/n.N)/((sa.c/n.N)*(sb.c/n.N)), 3)    AS lift
FROM pair p, n JOIN sup1 sa ON sa.i = p.A JOIN sup1 sb ON sb.i = p.B
WHERE p.c >= 20 ORDER BY lift DESC
```

7. **偵測重複欄名**（超市有三個 `商品品項分類`）→ pandas 會加 `.1` `.2`，必須 rename
8. **偵測無表頭 sheet**（超市分類表第一列就是資料）→ 判準：第一列全是「看起來像資料」的值
9. **讀 `ws.merged_cells.ranges`**，合併儲存格代表階層 → 用 `ffill()` 展開
10. **展開後驗證代碼前綴一致性**（`子碼[:n] == 父碼`）→ 不一致的就是孤兒節點
11. **雙讀 `data_only=True` / `data_only=False`**，抽出所有公式，**用正則 `re.sub(r'\d+','#',f)` 歸納「公式樣式」**
    （3C 的 6,154 個公式只有 2 種樣式；超市 8,962 個只有 2 種）
12. **檢查巢狀 `IF` 是否缺最內層 else** → 缺的話會產生布林 `FALSE` 混進字串欄
13. 逐欄統計：型別 / 非空 / 缺失率 / nunique；類別欄 nunique < 30 就全列
14. **判定粒度**：`COUNT(*) / COUNT(DISTINCT 交易單號)`。> 1 表示「一列 = 明細」
15. **主鍵搜尋**：從單欄到全欄逐步試 `duplicated()`。**若全欄組合仍有重複 → 加 `row_id` 代理鍵，不要 `drop_duplicates()`**
16. **驗證單頭鍵**：`GROUP BY 交易單號` 後 `客戶/日期/店` 的 nunique 是否都 = 1
17. 參照完整性：事實表外鍵 → 維度表（雙向孤兒都要查）
18. **金額語意三選一**：單價？列小計？單頭合計？→ 用 `Amount == 售價 × 數量` 與 `SUM(明細) == 總金額` 兩個檢查判定
19. **日期格式三選一**：datetime / 西元 int / **民國 int**。民國判準：`值 < 1000000` 且前兩碼 < 115
20. **檢查負數量／負金額**（退貨）與零金額（贈品／手續費）
21. **樞紐殘留偵測**：末列是否為 `總計` / `(空白)`
22. **零變異欄偵測**：二元矩陣做因素分析前，剔除滲透率 <5% 或 >95% 的欄
