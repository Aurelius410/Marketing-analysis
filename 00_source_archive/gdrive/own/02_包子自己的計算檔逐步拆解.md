### 1.2 各工作表欄位結構

#### `RFM 資料表(公式)` — 第一個中間產物（RFM 三維度原始值）

【材料原文】欄位：

| 欄 | 標題 | 內容 |
|---|---|---|
| A | `客戶ID` | 200 個客戶（貼上的值） |
| B | `Recency` | 公式 |
| C | `Frequency` | 公式 |
| D | `Monetary Value` | 公式 |
| E | `最後消費日期` | 公式（轉成日期型別） |
| F | `最後消費日期` | 陣列公式（取 YYYYMMDD 整數最大值） |
| G | `基準日期` | 常數，僅 G2 一格 = `2008-01-01` |

【材料原文】公式逐字（整欄僅 1 種樣式，以第 2 列為代表）：

```excel
B2: =$G$2-E2
C2: =COUNTIF(交易記錄檔!C:C,'RFM 資料表(公式)'!A2)
D2: =SUMIF(交易記錄檔!C:C,A2,交易記錄檔!F:F)
E2: =DATE(LEFT(F2,4),MID(F2,5,2),RIGHT(F2,2))
F2: {=MAX(IF((交易記錄檔!C:C=A2),交易記錄檔!B:B,FALSE))}      ← ArrayFormula
G2: 2008-01-01（常數）
```

實測值範例：`A2=62` → `B2=8`、`C2=18`、`D2=8356`、`E2=2007-12-24`、`F2=20071224`

【評註】等價 SQL：

```sql
-- 基準日期 as_of = DATE '2008-01-01'
SELECT  t.ID                                        AS 客戶ID,
        DATE '2008-01-01' - MAX(t.Date_d)           AS Recency,   -- 天數
        COUNT(*)                                    AS Frequency, -- 注意：品項列數，非購物籃數
        SUM(t.Amount)                               AS Monetary_Value,
        MAX(t.Date_d)                               AS 最後消費日期
FROM   (SELECT ID, Amount,
               CAST(strftime('%Y-%m-%d',
                    substr(CAST(Date AS TEXT),1,4)||'-'||
                    substr(CAST(Date AS TEXT),5,2)||'-'||
                    substr(CAST(Date AS TEXT),7,2)) AS DATE) AS Date_d
        FROM 交易記錄檔) t
GROUP BY t.ID;
```

等價 Python：

```python
import pandas as pd
AS_OF = pd.Timestamp("2008-01-01")
tx = pd.read_excel(HW1, "交易記錄檔", usecols="A:F")
tx["Date_d"] = pd.to_datetime(tx["Date"].astype(int).astype(str), format="%Y%m%d")

rfm = (tx.groupby("ID")
         .agg(最後消費日期=("Date_d", "max"),
              Frequency=("Date_d", "size"),       # = COUNTIF，品項列數
              MonetaryValue=("Amount", "sum"))    # = SUMIF
         .reset_index())
rfm["Recency"] = (AS_OF - rfm["最後消費日期"]).dt.days
```

【評註】三個需要注意的定義選擇：
1. **基準日期是硬編的 `2008-01-01`**，即資料期末 +1 天，寫在 `G2` 單一儲存格並以 `$G$2` 絕對參照鎖定（可重用設計：改一格就全表重算）。`交易記錄檔!L1` 也放了同一個日期常數，是同一個東西的備份。
2. **Frequency 用 `COUNTIF` 數的是品項列數（3077 層級），不是購物籃次數（1815 層級）**。所以客戶 62 的 Frequency = 18 是「買過 18 個品項」。這與 Bob Stone 規則文字「過去兩年購買次數」有語意落差。
3. `MAX(IF(...))` 陣列公式取的是 `YYYYMMDD` 整數的最大值，因為整數大小順序恰好等於日期順序，所以正確；再用 `DATE(LEFT/MID/RIGHT)` 轉回日期型別後才能相減。這是「不用輔助欄就地轉型」的手法。

#### `Bob Stone 規則` — 參數表（原版）

【材料原文】逐字（B2:E5）：

| 構面 | 給分機制 | 權重 | 原因 |
|---|---|---|---|
| 最近一次購買日<br>Recency (R) | 最近 30 天內為 5 分<br>最近 31 ~ 60 天內為 4 分<br>最近 61 ~ 90 天內為 3 分<br>最近 91 ~ 120 天內為 2 分<br>最近 121 ~150 天內為 1 分<br>最近 151 天以上為 0 分 | 低 | 採用與範例相同之設定 |
| 過去兩年購買次數<br>Frequency (F) | 購買次數/2 | 高 | （空白） |
| 平均購買金額<br>Monetary Value (M) | 平均購買金額 x 0.25% (四捨五入至整數)<br>最高 10 分 | 中 | （空白） |

#### `RFM 轉 Bob Stone` — 中間產物（原版 Bob Stone 計分）

【材料原文】欄位 A `客戶ID`、B `Recency`、C `Frequency`、D `Monetary Value`（A:D 為貼上的值）、E `R (Recency)`、F `F (Frequency)`、G `M (Monetary Value)`、H `RFM Score`、I `Rank`。另有 K8 一格 `=0.25%` → 0.0025（權數備忘）。

【材料原文】公式逐字：

```excel
E2: {=_xlfn.IFS(B2<=30,5,B2<=60,4,B2<=90,3,B2<=120,4,B2<=150,1,B2>150,0)}   ← ArrayFormula
F2: =ROUNDUP(C2/2,0)
G2: =MIN(INT(D2*0.0025),10)
H2: =SUM(E2:G2)
I2: =RANK(H2,H:H)
```

實測：`A2=62, B2=8, C2=18, D2=8356` → `E2=5, F2=9, G2=10, H2=24, I2=42`

【評註】**這裡有兩個實作與規則表不一致的地方，必須記錄**：

1. **`IFS` 的第 4 個分支寫成 `B2<=120, 4`，規則表寫的是「91~120 天為 2 分」。**
   逐字比對：規則 5/4/3/**2**/1/0，公式 5/4/3/**4**/1/0。這是打字錯誤，且該錯誤原樣複製到了 `自訂 Bob Stone 權重法` 的 E 欄。影響：Recency 落在 91~120 天的客戶多拿 2 分。
2. **M 分數的輸入 `D2` 是「消費總額」而非規則表所稱的「平均購買金額」。**
   `D` 欄來自 `SUMIF` 的總和。所以 `MIN(INT(總額×0.0025),10)` 在原版下幾乎所有客戶都撞到 10 分上限（客戶 62 總額 8356 → `INT(20.89)=20` → `MIN(...,10)=10`）。這正是他在自訂版把 0.25% 改成 0.02% 的實際原因（見 1.3）。

等價 Python：

```python
def bobstone_R(recency_days):
    # 【原樣重現，含 <=120 給 4 分的筆誤】
    if recency_days <= 30:  return 5
    if recency_days <= 60:  return 4
    if recency_days <= 90:  return 3
    if recency_days <= 120: return 4    # 規則表原意應為 2
    if recency_days <= 150: return 1
    return 0

import math
rfm["R"] = rfm["Recency"].apply(bobstone_R)
rfm["F"] = np.ceil(rfm["Frequency"] / 2)                    # ROUNDUP(x,0)
rfm["M"] = np.minimum(np.floor(rfm["MonetaryValue"] * 0.0025), 10)   # INT() 對正數 = floor
rfm["RFM_Score"] = rfm[["R","F","M"]].sum(axis=1)
rfm["Rank"] = rfm["RFM_Score"].rank(ascending=False, method="min").astype(int)  # =RANK(x, 範圍) 預設降冪
```

#### `五等分法` — 中間產物（百分位五等分計分）

【材料原文】欄位 A `客戶ID`、B `Recency`、C `Frequency`、D `Monetary Value`、E `Recency (%)`、F `Frequency (%)`、G `Monetary Value (%)`、H `R (Recency)`、I `F (Frequency)`、J `M (Monetary Value)`、K `RFM Score`、L `Rank`。

【材料原文】公式逐字：

```excel
E2: =_xlfn.PERCENTRANK.INC(B:B,B2)
F2: =_xlfn.PERCENTRANK.INC(C:C,C2)
G2: =_xlfn.PERCENTRANK.INC(D:D,D2)
H2: =IF(E2<=0.2,"5",IF(E2<=0.4,"4",IF(E2<=0.6,"3",IF(E2<0.8,"2","1"))))
I2: =IF(F2<=0.2,"1",IF(F2<=0.4,"2",IF(F2<=0.6,"3",IF(F2<0.8,"4","5"))))
J2: =IF(G2<=0.2,"5",IF(G2<=0.4,"4",IF(G2<=0.6,"3",IF(G2<0.8,"2","1"))))
K2: =H2+I2+J2
L2: =RANK(K2,K:K)
```

實測：`B2=8 → E2=0.1 → H2=5`；`C2=18 → F2=0.738 → I2=4`；`D2=8356 → G2=0.442 → J2=3`；`K2=12`、`L2=5`

【評註】關鍵參數選擇：
- **R 與 M 的分數方向相反於 F**。R 用 `5,4,3,2,1`（百分位越低＝越近期＝分數越高，正確）；**M 也用 `5,4,3,2,1`（百分位越低＝金額越低＝分數越高）**，方向與 F 相反。這在 J 欄是 `IF(G2<=0.2,"5",...)`，白紙黑字。實測 `D2=8356`（第 44 百分位）拿 3 分、`D201=400`（第 1.5 百分位）拿 5 分 → **M 分數是「花越少分越高」**。這與 RFM 常識相反，是本檔的第二個實作瑕疵（也可能是他刻意把 M 定義成「單次金額低＝高頻小額客」，但檔內無說明）。
- 級距切點：`<=0.2 / <=0.4 / <=0.6 / <0.8 / else`。注意第 4 段用嚴格 `<0.8`，前三段用 `<=`，切點不一致但不影響大局。
- 分數是**文字字串**（`"5"`），靠 `H2+I2+J2` 的隱式轉型才能相加（若用 `SUM()` 會得 0）。

等價 SQL / Python：

```sql
-- PERCENTRANK.INC 等價於 (rank_asc - 1) / (n - 1)
WITH r AS (
  SELECT 客戶ID, Recency, Frequency, MonetaryValue,
         (RANK() OVER (ORDER BY Recency)        - 1.0)/(COUNT(*) OVER () - 1) AS R_pct,
         (RANK() OVER (ORDER BY Frequency)      - 1.0)/(COUNT(*) OVER () - 1) AS F_pct,
         (RANK() OVER (ORDER BY MonetaryValue)  - 1.0)/(COUNT(*) OVER () - 1) AS M_pct
  FROM rfm)
SELECT 客戶ID,
  CASE WHEN R_pct<=0.2 THEN 5 WHEN R_pct<=0.4 THEN 4 WHEN R_pct<=0.6 THEN 3 WHEN R_pct<0.8 THEN 2 ELSE 1 END AS R_score,
  CASE WHEN F_pct<=0.2 THEN 1 WHEN F_pct<=0.4 THEN 2 WHEN F_pct<=0.6 THEN 3 WHEN F_pct<0.8 THEN 4 ELSE 5 END AS F_score,
  CASE WHEN M_pct<=0.2 THEN 5 WHEN M_pct<=0.4 THEN 4 WHEN M_pct<=0.6 THEN 3 WHEN M_pct<0.8 THEN 2 ELSE 1 END AS M_score
FROM r;
```

```python
def percentrank_inc(s):
    return (s.rank(method="min") - 1) / (len(s) - 1)   # = PERCENTRANK.INC

def cut_desc(p):   # R 與 M 用（低百分位 → 高分）
    return 5 if p<=0.2 else 4 if p<=0.4 else 3 if p<=0.6 else 2 if p<0.8 else 1
def cut_asc(p):    # F 用（高百分位 → 高分）
    return 1 if p<=0.2 else 2 if p<=0.4 else 3 if p<=0.6 else 4 if p<0.8 else 5
```

#### `Bob Stone 規則 (自訂)` — 參數表（自訂版）

【材料原文】與原版唯一的差異在 M 的權數與「原因」欄：

| 構面 | 給分機制 | 權重 |
|---|---|---|
| 最近一次購買日 Recency (R) | （與原版完全相同的 6 段級距） | 低 |
| 過去兩年購買次數 Frequency (F) | 購買次數/2 | 高 |
| 平均購買金額 Monetary Value (M) | **平均購買金額 x 0.02% (四捨五入至整數)**<br>最高 10 分 | 中 |

【材料原文】E3「原因」欄逐字（這是全檔唯一明寫權重理由的地方）：

> ─ 3C產業具有：交易頻率相對較低，單次金額較高的特性因此 Frequency 在整體價值衡量上能較敏銳地反映「忠誠度」或「商家依賴程度」，因此給予 Frequency 較高的權重。
>
> ─ 3C商品通常單價高，零售利潤空間相對大，且單次交易往往對整體獲利的影響性較大，因此將 Monetary Value 之權重設定為中等，同時將權重設定為 0.02%，較能顯著區別各訂單的差異性，以避免採用原始權數導致過多筆資料都呈現最高分的情形。
>
> ─ 3C產品的購買週期較長，最近一次購買雖可反映是否近期有消費，但不一定代表立刻再次購買的意願，例如：若客戶 3 個月內未回購，未必表示此客戶流失，有可能只是預算或消費週期未到，因此將其權重設定為低。

#### `Step 2` — 中間產物②：購買間隔與序位權重

【材料原文】A `ID`、B `Date`、C `Date`、D `Interpurchase Time`、E `Weight`、F `Int * Weight`、H1 標題 `去除 "刪除"項`（操作備忘）。

```excel
C2: =DATE(LEFT(B2,4),MID(B2,5,2),RIGHT(B2,2))
D2: =IF(A3=A2,C3-C2,"刪除")
E2: 1                                    ← 每人第一列硬填 1
E3: =IF(A3=A2,E2+1,1)
F2: =D2*E2
```

實測：客戶 62 → `D2=50, E2=1, F2=50`；`D3=40, E3=2, F3=80`；…；最後一列 `D1744="刪除"`、`F1744=#VALUE!`

【評註】三個設計要點：
1. **`Interpurchase Time` 是「本次 → 下一次」的天數（forward-looking）**，不是「上次 → 本次」。所以每個客戶的**最後一列**沒有下一次 → 標 `刪除`。
2. **`Weight` = 客戶內的購買序位 1,2,3,…** —— 這就是 CAI 的「近期加權」機制：越晚發生的間隔權重越大。權重是**線性遞增的自然序號**，不是指數衰減，也沒有可調參數。
3. `F` 欄在 `刪除` 列會產生 `#VALUE!`，他選擇「留著錯誤、下一步整列刪掉」而不是包 `IFERROR` —— 錯誤值本身就是刪除標記。

等價 SQL / Python：

```sql
SELECT ID, Date_d,
       LEAD(Date_d) OVER (PARTITION BY ID ORDER BY Date_d) - Date_d      AS interpurchase_time,
       ROW_NUMBER()  OVER (PARTITION BY ID ORDER BY Date_d)              AS weight
FROM step1
QUALIFY interpurchase_time IS NOT NULL;   -- 等價於「去除刪除項」
```

```python
s = step1.sort_values(["ID", "Date_d"]).copy()
s["Weight"] = s.groupby("ID").cumcount() + 1
s["IPT"]    = s.groupby("ID")["Date_d"].shift(-1).sub(s["Date_d"]).dt.days
s["Int_x_W"] = s["IPT"] * s["Weight"]
step3 = s.dropna(subset=["IPT"])          # 1743 → 1593
```

#### `WMLE & CAI` — 核心計算

【材料原文】A `客戶ID`、B `MLE`、C `加權加總`、D `加權值加總`、E `WMLE`、F `CAI`。A:D 為 Pivot 貼上的值。

```excel
E2: =D2/C2
F2: =((B2-E2)/B2)*100
```

實測：`B2=55.23076923076923, C2=91, D2=4803` → `E2=52.78021978021978`、`F2=4.436927974532435`

【評註】**公式意義（這是 CAI 的定義本體）：**

```
MLE  = 平均購買間隔（未加權）        = Σ IPT_i / n
WMLE = 加權平均購買間隔（近期加權）  = Σ (w_i × IPT_i) / Σ w_i ，w_i = 購買序位
CAI  = (MLE − WMLE) / MLE × 100 (%)
```

CAI > 0 ⇒ 近期的間隔比整體平均短 ⇒ 購買頻率在加快 ⇒ **活躍**。
CAI < 0 ⇒ 近期間隔拉長 ⇒ **不活躍／流失中**。
CAI 本質是「購買節奏的加速度指標」，值域理論上 (−∞, 100)。

【評註】**欄位標題與內容有錯位**：`C1` 標 `加權加總` 但放的是 `Σ Weight`；`D1` 標 `加權值加總` 但放的是 `Σ (IPT×Weight)`。公式 `=D2/C2` 是對的，標題命名容易誤導。

等價 SQL：

```sql
SELECT ID,
       AVG(interpurchase_time)                                        AS MLE,
       SUM(weight)                                                    AS sum_w,
       SUM(interpurchase_time * weight)                               AS sum_wx,
       SUM(interpurchase_time * weight) * 1.0 / SUM(weight)            AS WMLE,
       (AVG(interpurchase_time) - SUM(interpurchase_time*weight)*1.0/SUM(weight))
         / AVG(interpurchase_time) * 100                              AS CAI
FROM step3
GROUP BY ID;
```

```python
g = step3.groupby("ID")
cai = pd.DataFrame({
    "MLE":  g["IPT"].mean(),
    "sum_w": g["Weight"].sum(),
    "sum_wx": g["Int_x_W"].sum(),
})
cai["WMLE"] = cai["sum_wx"] / cai["sum_w"]
cai["CAI"]  = (cai["MLE"] - cai["WMLE"]) / cai["MLE"] * 100
```

## 3. HW4 — 階層貝氏顧客價值估計（`04_海誓山盟：顧客終身價值與遷徙路徑之預測…xlsx`）

> **【評註 — 必讀的預期落差】**
> 檔名叫「顧客終身價值與遷徙路徑之預測」，但**活頁簿內容不是 CLV，也不是遷徙路徑**。
> 全檔 6 張工作表、41 個共用字串，經關鍵字掃描確認：**沒有折現率、沒有存活率、沒有 CLV 公式、沒有狀態定義、沒有轉移矩陣、沒有遷徙機率**。
> 實際做的是 **Hierarchical Bayes（階層貝氏）收縮估計**：用「顧客所屬分群的平均客單價」當先驗，把「顧客自己的樣本平均客單價」往先驗方向收縮，得到更穩健的個人客單價估計，並計算 **CRI**（收縮幅度指標）。
> 這在 CLV 建模中是「預測未來每次交易金額 M̂」的那一塊零件，但**折現、期數、留存率完全不在這個檔案裡**。
> **真正的「轉移矩陣」在 HW5**（品類 → 下次購買品類），見第 4 節。若專案需要 CLV 折現與顧客狀態遷徙，本批 Excel 無素材，須另尋期末報告 PDF 或課程投影片。

【評註】**方法論還原 —— 這是整份檔案的核心，逐條說明：**

設顧客 i 屬於分群 g(i)：
- n_i = 交易筆數，x̄_i = 個人平均客單價，s²_i = 個人客單價樣本變異數
- μ_g = 分群平均客單價（先驗均值），τ²_g = 分群客單價變異數（先驗變異數）
- 個人平均的抽樣變異數 = s²_i / n_i（標準誤平方）

則：

```
W1 = τ²_g / (τ²_g + s²_i/n_i)              ← 個人資料的可信度權重
W2 = (s²_i/n_i) / (τ²_g + s²_i/n_i)        ← 先驗（分群均值）的權重
W1 + W2 = 1（恆等）

HB 估計值  θ̂_i = W1 · x̄_i + W2 · μ_g

正統貝氏形式（M 欄，數學上完全等價）：
θ̂_i = ( x̄_i·n_i/s²_i + μ_g/τ²_g ) / ( n_i/s²_i + 1/τ²_g )
     = ( 個人精確度加權 + 先驗精確度加權 ) / 精確度總和

CRI = (x̄_i − θ̂_i) / (x̄_i − μ_g) × 100   ← 收縮比例（%），恆等於 W2 × 100
```

**兩個實測可驗證的恆等式（品質檢查用）：**
1. `J 欄 ≡ M 欄`（HB 加權形式 = 正統貝氏精確度形式）。實測 r2 兩者皆 465.44504311117777；r4 為 2638.3931801302433 vs 2638.3931801302438（僅浮點尾差）。**他保留兩條公式並列，就是為了做這個交叉驗證。**
2. `L 欄（CRI） ≡ I 欄（W2）× 100`。實測 r2：`I2=0.0011339478248075215` vs `L2=0.1133947824807567`；r3：`I3=0.09721983518890223` vs `L3=9.721983518890266`。完全對得上。

**方法論直覺**：交易筆數多（n 大）或個人變異小（s² 小）→ W1→1 → 幾乎全用自己的平均；交易筆數少（如 r201 只有 2 筆）→ W1 變小 → 大幅往分群平均收縮，避免「只買 2 次就被當高價值客」的過度外推。CRI 就是量化「這個人被收縮了幾 %」。

等價 Python（完整可跑）：

```python
import pandas as pd

# Step 2 等價：個體層
ind = (tx.groupby("客戶ID")["交易金額"]
         .agg(n="count", xbar="mean", s2=lambda s: s.var(ddof=1))   # Excel VAR = ddof=1
         .reset_index())

# Step 3 等價：群體層（注意：對「交易列」取平均與變異數，非對顧客均值取）
tx_seg = tx.merge(cust[["客戶ID", "分群"]], on="客戶ID")
grp = (tx_seg.groupby("分群")["交易金額"]
             .agg(mu="mean", tau2=lambda s: s.var(ddof=1))
             .reset_index())

# Step 4 等價
df = ind.merge(cust[["客戶ID","分群"]], on="客戶ID").merge(grp, on="分群")
df["se2"] = df["s2"] / df["n"]
df["W1"]  = df["tau2"] / (df["tau2"] + df["se2"])
df["W2"]  = df["se2"]  / (df["tau2"] + df["se2"])
df["HB"]  = df["W1"] * df["xbar"] + df["W2"] * df["mu"]
df["HB_bayes"] = ((df["xbar"]*df["n"]/df["s2"]) + (df["mu"]/df["tau2"])) / ((df["n"]/df["s2"]) + (1/df["tau2"]))
df["CRI"] = (df["xbar"] - df["HB"]) / (df["xbar"] - df["mu"]) * 100
assert (df["HB"] - df["HB_bayes"]).abs().max() < 1e-6      # 交叉驗證
assert (df["CRI"] - df["W2"]*100).abs().max() < 1e-9       # 恆等式檢查
```

等價 SQL：

```sql
WITH ind AS (
  SELECT 客戶ID, COUNT(*) n, AVG(交易金額) xbar, VAR_SAMP(交易金額) s2
  FROM step1 GROUP BY 客戶ID),
grp AS (
  SELECT 分群, AVG(交易金額) mu, VAR_SAMP(交易金額) tau2
  FROM step1 GROUP BY 分群)
SELECT i.客戶ID, i.n, i.xbar, i.s2, c.分群, g.mu, g.tau2,
       g.tau2 / (g.tau2 + i.s2/i.n)                                    AS W1,
       (i.s2/i.n) / (g.tau2 + i.s2/i.n)                                AS W2,
       g.tau2/(g.tau2 + i.s2/i.n)*i.xbar
         + (i.s2/i.n)/(g.tau2 + i.s2/i.n)*g.mu                         AS HB估計值,
       ((i.xbar*i.n/i.s2) + (g.mu/g.tau2)) / ((i.n/i.s2) + (1.0/g.tau2)) AS 正統貝氏,
       (i.s2/i.n)/(g.tau2 + i.s2/i.n) * 100                            AS CRI
FROM ind i JOIN 客戶 c USING (客戶ID) JOIN grp g ON g.分群 = c.分群;
```

#### `Step 2-4` — 轉移機率矩陣（中間產物⑩）

【材料原文】A1 `品項`、B1:AE1 = 30 個品類，A2:A31 = 30 個品類（無總計列/欄）。整片公式唯一樣式：


實測：`B2 = 1/1615 = 0.0006191950464`；`G7（EPSON墨水→EPSON墨水）= 26/1615 = 0.01609907121`；`H8（HP墨水→HP墨水）= 17/1615 = 0.01052631579`

【評註】**這是本檔最重要的方法論判讀 —— 分母是「全域總轉移數 1615」，不是「該列的列總計」。**

因此 `Step 2-4` 是 **聯合機率矩陣** P(from = A **且** to = B)，全矩陣加總 = 1，**不是**條件轉移機率 P(to = B | from = A)。

真正的馬可夫轉移矩陣應為 `='Step 2-3'!B2/'Step 2-3'!$AF2`（除以列總計 AF 欄、鎖欄不鎖列），使每列加總 = 1。

兩者都有用途，但意義不同：
- 聯合機率（他做的）：回答「最常見的『買 A 之後買 B』組合是什麼」→ 適合排 Top 20 推薦組合。
- 條件機率（馬可夫）：回答「買了 A 的人，下次最可能買什麼」→ 適合做次購預測與遷徙路徑推演。

## 5. 跨檔案的方法論共通模式【評註】

把四份檔案疊在一起看，可以萃出他固定的操作習慣，這些就是要寫進 Skill 的東西：

### 5.1 `Step n` 分階段命名法
`Step 0_1 / Step 0_2 → Step 1 → Step 2 → Step 3 → Step 4`（HW4）
`Step 1 → Step 2 → Step 3`（HW2）
`Step 1-1 → 1-2 → 1-3 → 1-4`、`Step 2-1-1 → 2-1-2 → 2-2 → 2-3 → 2-4 → 2-5`（HW5）
**每一個可獨立驗證的計算階段 = 一張工作表**，不會把兩步併在同一張表裡。多題作業用 `Step {題號}-{步驟}` 二階編號。

### 5.2 「篩選/刪除」欄的顯性化
不直接刪資料，而是先建一個標記欄寫 `保留`/`刪除`（HW2 `Step 1!D`、`Step 2!D`；HW5 `Step 1-4!D`），檢查完再實際刪除，並把刪除前後的表都留著。列數差本身就是稽核軌跡（1815→1743→1593；1815→1615）。

### 5.3 雙軌交叉驗算
- HW1：`Pivot` 樞紐 vs `COUNTIF` 公式，兩邊都算一次
- HW4：`J 欄 HB 加權式` vs `M 欄 正統貝氏精確度式`，兩條數學等價公式並列，比對浮點尾差
- HW4：`L 欄 CRI` 恆等於 `I 欄 W2 × 100`，隱含第三重檢查
- 各表都保留 `總計` 列/欄，用來對照母體總數（3077 / 1615 / 435 / 900）

### 5.4 參數集中化
可調參數不散在公式裡，而是集中放置後用絕對參照引用：
- 基準日期 → `$G$2`（HW1）
- 評分規則與權重 → 獨立的 `Bob Stone 規則` / `Bob Stone 規則 (自訂)` 工作表，並附「原因」欄
- 分群編碼對照 → `Step 0_1!H1:M4`（HW4）
- 轉移矩陣分母 → `$AF$32`（HW5）

### 5.5 「查表表」模式
把要重複 VLOOKUP 的側寫欄位先做成一張表（HW2 `金額查詢`），再讓所有下游分群表對它查，而不是每張表各自重算。VLOOKUP 一律用 `$A3` 混合鎖定，方便橫向填滿只改 `col_index`。

### 5.6 分群後必寫文字描述
每個分群結果都配一張 `…描述` 工作表，格式固定：性別比 → 區域五區逐一列數 → 年齡（區間 / 平均 / 逾 40 歲人數） → 消費總額與最大單筆平均 → **剔除離群值後重算再比一次** → 行為推論。

### 6.1 可直接搬進 Skill 的計算核心（Python）

```python
# ─────────────────────────────────────────────────────────────
# A. RFM 三維度（HW1 Step: RFM 資料表(公式)）
# ─────────────────────────────────────────────────────────────
def rfm_base(tx, id_col="ID", date_col="Date", amt_col="Amount", as_of=None):
    """tx.Date 為 YYYYMMDD 整數。as_of 預設為資料期末 +1 日。"""
    t = tx.copy()
    t["_d"] = pd.to_datetime(t[date_col].astype(int).astype(str), format="%Y%m%d")
    as_of = pd.Timestamp(as_of) if as_of else t["_d"].max() + pd.Timedelta(days=1)
    r = (t.groupby(id_col)
           .agg(最後消費日期=("_d","max"), Frequency=("_d","size"), MonetaryValue=(amt_col,"sum"))
           .reset_index())
    r["Recency"] = (as_of - r["最後消費日期"]).dt.days
    return r, as_of

# B. Bob Stone 計分（權數與上限外部化為參數）
def bobstone_score(rfm, m_rate=0.0025, m_cap=10, r_bins=(30,60,90,120,150), r_scores=(5,4,3,2,1,0)):
    import numpy as np
    def R(d):
        for b, s in zip(r_bins, r_scores):
            if d <= b: return s
        return r_scores[-1]
    out = rfm.copy()
    out["R"] = out["Recency"].apply(R)
    out["F"] = np.ceil(out["Frequency"] / 2)
    out["M"] = np.minimum(np.floor(out["MonetaryValue"] * m_rate), m_cap)
    out["RFM_Score"] = out[["R","F","M"]].sum(axis=1)
    out["Rank"] = out["RFM_Score"].rank(ascending=False, method="min").astype(int)
    return out
# 重現原檔（含筆誤）：r_scores=(5,4,3,4,1,0)；原版 m_rate=0.0025,m_cap=10；自訂版 m_rate=0.0002,m_cap=9

# C. 五等分法
def quintile_score(rfm, cuts=(0.2,0.4,0.6,0.8)):
    def prank(s): return (s.rank(method="min") - 1) / (len(s) - 1)
    def desc(p): return 5 if p<=cuts[0] else 4 if p<=cuts[1] else 3 if p<=cuts[2] else 2 if p<cuts[3] else 1
    def asc(p):  return 1 if p<=cuts[0] else 2 if p<=cuts[1] else 3 if p<=cuts[2] else 4 if p<cuts[3] else 5
    o = rfm.copy()
    o["R_pct"], o["F_pct"], o["M_pct"] = prank(o["Recency"]), prank(o["Frequency"]), prank(o["MonetaryValue"])
    o["R"], o["F"], o["M"] = o["R_pct"].map(desc), o["F_pct"].map(asc), o["M_pct"].map(asc)  # M 建議用 asc（原檔用 desc）
    o["RFM_Score"] = o[["R","F","M"]].sum(axis=1)
    o["Rank"] = o["RFM_Score"].rank(ascending=False, method="min").astype(int)
    return o

# ─────────────────────────────────────────────────────────────
# D. CAI（HW2 Step 1→2→3→Pivot→WMLE & CAI）
# ─────────────────────────────────────────────────────────────
def cai(baskets, id_col="ID", date_col="Date_d", min_tx=3):
    b = baskets.sort_values([id_col, date_col]).copy()
    b = b[b.groupby(id_col)[id_col].transform("size") >= min_tx]        # Step 1：≤2 筆剔除
    b["Weight"] = b.groupby(id_col).cumcount() + 1                     # Step 2：序位權重
    b["IPT"] = b.groupby(id_col)[date_col].shift(-1).sub(b[date_col]).dt.days
    b = b.dropna(subset=["IPT"])                                       # Step 3
    g = b.groupby(id_col)
    out = pd.DataFrame({"MLE": g["IPT"].mean(),
                        "sum_w": g["Weight"].sum(),
                        "sum_wx": (b["IPT"]*b["Weight"]).groupby(b[id_col]).sum()})
    out["WMLE"] = out["sum_wx"] / out["sum_w"]
    out["CAI"] = (out["MLE"] - out["WMLE"]) / out["MLE"] * 100
    return out.reset_index()

def cai_segments(cai_df, lo=0.2, hi=0.8):
    q_lo, q_hi = cai_df["CAI"].quantile(lo), cai_df["CAI"].quantile(hi)
    cai_df = cai_df.copy()
    cai_df["群體"] = np.where(cai_df["CAI"] >= q_hi, "活躍",
                      np.where(cai_df["CAI"] <= q_lo, "不活躍", "穩定"))
    return cai_df

# ─────────────────────────────────────────────────────────────
# E. 階層貝氏收縮估計 + CRI（HW4 Step 2/3/4）
# ─────────────────────────────────────────────────────────────
def hb_shrinkage(tx, cust_seg, id_col="客戶ID", amt_col="交易金額", seg_col="分群"):
    ind = (tx.groupby(id_col)[amt_col]
             .agg(n="count", xbar="mean", s2=lambda s: s.var(ddof=1)).reset_index())
    t = tx.merge(cust_seg[[id_col, seg_col]], on=id_col)
    grp = (t.groupby(seg_col)[amt_col]
             .agg(mu="mean", tau2=lambda s: s.var(ddof=1)).reset_index())
    d = ind.merge(cust_seg[[id_col, seg_col]], on=id_col).merge(grp, on=seg_col)
    d["se2"] = d["s2"] / d["n"]
    d["W1"] = d["tau2"] / (d["tau2"] + d["se2"])
    d["W2"] = d["se2"] / (d["tau2"] + d["se2"])
    d["HB"] = d["W1"]*d["xbar"] + d["W2"]*d["mu"]
    d["HB_bayes"] = ((d["xbar"]*d["n"]/d["s2"]) + (d["mu"]/d["tau2"])) / ((d["n"]/d["s2"]) + (1/d["tau2"]))
    d["CRI"] = (d["xbar"] - d["HB"]) / (d["xbar"] - d["mu"]) * 100
    assert (d["HB"] - d["HB_bayes"]).abs().max() < 1e-6     # 雙軌交叉驗算
    assert (d["CRI"] - d["W2"]*100).abs().max() < 1e-9
    return d

# ─────────────────────────────────────────────────────────────
# F. 購物籃相關 + 轉移矩陣（HW5 主線 A / B）
# ─────────────────────────────────────────────────────────────
def category_corr_pairs(tx, id_col="ID", cat_col="Category"):
    mat = pd.crosstab(tx[id_col], tx[cat_col])          # Step 1-1
    binary = (mat > 0).astype(int)                      # Step 1-2
    corr = binary.corr()                                # Step 1-3
    import numpy as np
    p = (corr.where(np.tril(np.ones(corr.shape), k=-1).astype(bool))
             .stack().rename("相關係數").reset_index())
    p.columns = ["品名1", "品名2", "相關係數"]
    return mat, binary, corr, p.sort_values("相關係數", ascending=False)   # Step 1-4

def category_transition(baskets, id_col="ID", date_col="Date", cat_col="Category",
                        normalize="global"):
    """normalize='global' 重現原檔（聯合機率）；'row' 為標準馬可夫條件轉移機率。"""
    b = baskets.sort_values([id_col, date_col]).copy()
    b["下次購買"] = b.groupby(id_col)[cat_col].shift(-1)          # Step 2-1-2（NaN = 原檔的 8888）
    valid = b.dropna(subset=["下次購買"])
    counts = pd.crosstab(valid[cat_col], valid["下次購買"])       # Step 2-3
    if normalize == "row":
        prob = counts.div(counts.sum(axis=1), axis=0)             # 每列加總 = 1（馬可夫）
    else:
        prob = counts / counts.values.sum()                       # 全矩陣加總 = 1（原檔 Step 2-4）
    long = prob.stack().rename("值").reset_index()                # Step 2-5
    long.columns = ["品項", "品項2", "值"]
    return counts, prob, long.sort_values("值", ascending=False)
```
