# 行銷數據分析 Skill

一套給 Claude Code 用的完整行銷數據分析工具包。目標是：**把資料丟進來 → 一連串的討論與分析 → 拿到可執行的提案**。

不是「幫我跑個統計」，而是一條有卡點、有降級路徑、會主動說「這份資料回答不了這個問題」的產線。

## 這套東西在解決什麼

多數人手上有 raw data，但沒有一套能反覆使用的分析體系。每接一個新專案就重新想一次「該做什麼、順序是什麼、哪些前提要先檢查」，結果是分析品質完全取決於當下的狀態。

這個 Skill 把那套體系固定下來：**13 個模組、4 個硬卡點、6 條貫穿紀律**。

## 架構

```
M0  開案與問題定義      ▣  五問 → 處境分流 → 拆樹 → 兩份專案記憶檔
M1  資料體檢            ▣  EDA、敘述統計、缺值異常值、六域缺口盤點
M2  資料特徵檢驗            檢定下游方法的前提 → 發通行證或禁行令
M3  前處理與轉換            七情境轉換順位、winsorize 嚴格順序
M4  特徵檢驗複檢        ▣  驗證轉換有沒有改善，以及有沒有轉壞
M5  業務規則標籤            （選做）
M6  分群                    K-Means × HDBSCAN 交叉比對、k 決定、穩定性驗證
M7  迴歸建模                （選做）依 Y 的型態選模型族
M8  行銷專用分析            RFM/CAI/CRI/CLV/遷徙/購物籃/成長分解/促銷拆解
M9  預測建模                （預測型才做）時間切分、機率校準、Lift、SHAP
M10 文本分析                （有文本才做）關鍵詞分層、吸睛字詞、SEO
M11 決策轉譯            ▣  sizing、損益兩平反應率、經驗校準
M12 實驗設計                （獨立模組）A/B、地理實驗、switchback

▣ = 硬卡點，走完要停下來等回覆
```

## 六條貫穿紀律

1. **決策驅動欄位** —— 從「管理者要做什麼決策」倒推，不從「這批資料能做什麼」出發
2. **每階段都留成果** —— 中間產物一步一檔絕不覆寫，分析人員要能逐步確認品質
3. **雙路徑交叉驗算** —— 有兩種等價算法的指標一律都算，不一致就停
4. **參數必附理由** —— k 為什麼是 4、切點為什麼是 20/60/20，寫不出來代表還沒想清楚
5. **證據等級標籤** —— 每個結論標明相關／預測／準實驗／實驗，禁止把相關寫成因果
6. **降級不留空** —— 跑不出來要降級並說明。沒跑出來不是理由，沒有備案才是

## 技術堆疊

| 層 | 選擇 |
|---|---|
| 倉儲 | DuckDB 1.5.5 + Parquet (zstd) + DuckLake |
| 轉換 | 純 SQL 檔 + Python runner |
| 品質 | SQL 斷言（主力）+ pandera（出口） |
| 統計 | statsmodels、pingouin、scikit-posthocs |
| 行銷模型 | pymc-marketing、mlxtend、factor_analyzer、lifelines |
| 因果 | dowhy / EconML / causalml（**須在 Python 3.12 次環境**） |
| 視覺化 | Altair + matplotlib + great-tables |
| 交付 | Jinja2 單檔 HTML / python-pptx / marimo |

**環境注意**：Python 3.14 會讓 `dowhy` 靜默降版到 2022 年的 0.8 版且不警告，`EconML` 與 `google-meridian` 直接裝不起來。所以因果推論那條線必須另開 Python 3.12 venv，兩個環境用 Parquet 傳資料。

## 關於素材來源

`00_source_archive/` 的內容是課程與專案素材的**方法論萃取**，用於建構這套分析框架。已做兩項處理：

- **第三方個資匿名化** —— 素材中出現的他人姓名與學號已統一替換為代號（`scripts/anonymize_pii.py`），對照表僅存本機且不進版控
- **課程講義的逐頁重建不公開** —— 兩份近乎逐頁重建課堂投影片的 digest 已排除於版控之外，避免著作權爭議
