## 0. 先承認一個結構問題

三份缺口審查的指控一致，而且我認為它們對：

> 中間那七步（S2–S6）做得比多數商業分析團隊嚴謹，**兩頭卻是懸空的**。

具體是：

- **上游懸空**：從「客戶丟一句模糊的話」到「Check List 的欄位 A–E」之間缺一整層。IB5082 的 Check List 矩陣把「管理者要做的五個決策」留成**空白給學生填**，而真實客戶不會列出五個具名決策，他只會說「業績不好」。
- **下游懸空**：從「S6 驗證通過的統計結論」到「行銷團隊明天早上按下的那顆按鈕」之間也缺一整層。

這不是巧合。四份素材沒有一份的最終產物是**一個要花錢的行動** —— IB5082 給了「該算什麼」但沒給「該做什麼決策」；MBA5045 是學術演練、資料乾淨、無交付對象；大數據與商業分析只到方法；TMBA 補上了問題定義但它服務 case interview，不需要交出名單檔、不需要對預算負責、不需要半年後被追問「你說的 30% 呢」。

所以下面的脈絡，**S1 前面補了一層、S7 前面補了一層**。

### 為什麼「11 章齊全卻沒人知道要做什麼」

審查給了一條可驗證的成因鏈，值得原樣保留：

```
成因1 章節由方法驅動不由決策驅動 → 每章結論是統計事實不是行動
   ↓
成因2 沒有北極星，11 個發現無法排序 → 讀者看到 11 個「顯著」，不知道哪個跟營收有關
   ↓
成因3 金字塔缺中間層 → 只有「章內小結」與「第 11 章策略」，中間的「洞察」層不存在
   ↓
成因4 建議沒有規模與成本 → 三個策略並列，主管只能挑看起來最便宜的
   ↓
成因5 摘要是散文不是決策介面 → 優先序無處承載
   ↓
成因6 被排除的選項沒有交付 → 主管無法判斷你想過他心裡那個可能性，只能重問一輪
```

**結論：報告無法行動不是「寫得不好」，是結構上不可能行動 —— 它的目錄是分析師的工作日誌，不是決策者的決策樹。**

修補順序要**倒著來**：先有北極星（成因 2）→ 才能有 sizing（成因 4）→ 才能排優先序（成因 5）→ 才能反推該做哪些章（成因 1）。單獨加一個「決策摘要」章節不會解決問題，因為摘要裡的優先序沒有東西可以生成。

## 2. 逐階段：實際說什麼、實際落什麼檔

### S0 問題定義 ▣（新增）

**不碰資料。** 走五問（來自 TMBA×Minto 合併）：

```
Q1 現況是什麼？        → 要能畫出來（一個結構或一個流程）
Q2 發生了什麼事？      → External / Internal / Recently Recognized
Q3 現在不喜歡的結果？  → 必須可觀測：哪個指標、掉多少、從何時開始
Q4 想要的結果？        → 指標名 + 目標數字 + 時間邊界
Q5 至今做過什麼？      → 這一問決定用哪種樹
```

**Q5 決定路線（處境分流器）：**

| 處境 | 用哪種樹 | 不該做什麼 |
|---|---|---|
| 完全不知道怎麼辦 | 議題樹 → 轉假說樹 | — |
| 有方案不確定對不對 | 假說樹 | 不要重拆議題樹 |
| 方案定了不知怎麼執行 | 演繹樹 | 跳過根因診斷 |
| 做了但失效 | 議題樹，根節點＝「方案為何失效」 | 不要假設原診斷正確 |
| 多方案選不出來 | 2×2 矩陣 | 不要再產生新方案 |
| **知道 R1 講不出 R2** | **先不拆樹，做目標設定** | **不要碰資料** |
| **知道 R2 不確定在不在 R1** | **現況量測／benchmarking** | **不做因果分析** |

最後兩列是關鍵：**有兩種情況，正確答案是「這還不是一個分析問題」。**

**每個葉節點要能填完這句話**，填不完就不是可分析的假設，只是待查清單項：

> 「我認為 ______，因為 ______，**若為真則資料上會看到 ______**」

**落檔**：`00_intake/問題定義.md`、`00_intake/假說登錄表.csv`（假說 / 依據 / 預期資料徵象 / 驗證方法 / 狀態）

**實際對話**：不會直接開檔，而是回問「這個『配預算』具體是哪幾個決策？通路之間、客群之間，還是檔期之間分配？」

### S2 進場剖析 ▣（最重要的一關）

跑 `check_schema_contract.py` → `profile_dataset.py` → `check_data_quality.py`。

**體檢報告實際長這樣：**

```
交易檔 42 萬列，粒度＝訂單明細，主鍵＝(order_id, line_no)
會員檔 8.6 萬列，但 3,200 個 ID 在交易檔找不到（孤兒 3.7%）
廣告報表只到「日 × 通路」，沒有活動層級

⛔ error（擋住，不准往下）
  · spend 欄有 12% 無法 cast（含千分位與 NT$）
  · 三個廣告帳戶中一個是 USD，dim_fx_rate 缺該日匯率
  · int 欄有 100 個 9999（疑似哨兵，數量恰等於客戶數）

⚠ warning
  · UTM 未對照率 4.2%（facebook / Facebook / fb / FB 各自成列）
  · 交易檔無 txn_type 欄 → R 與 F 無法正確計算

因此建議：
  ✅ 做 通路預算配置（D4 有資料，且幣別可解）
  ❌ 不做 活動層 uplift（沒有活動層級資料）
  ❌ 不做 歸因分析（沒有點擊層資料）
  ⚠ RFM 可做但 R 不可信（缺 txn_type，退貨會污染 R）
```

**兩個新增的門檻：**
- **覆蓋率門檻**：每個要用的指標算得出來的顧客占比。低於門檻（如 30%）的指標不准進報告，或必須標覆蓋率。
- **哨兵掃描**：`9999` 這類值若出現次數恰等於某個 group-by 鍵的相異值數 → 列為 error。實測代價：課程資料集的 `int` 欄含 100 個 9999，不排除算平均間隔得 **199.46**，真值 **10.79**，差 18.5 倍 → 流失門檻會被設成 200 天 → 100 人裡只標出 3 人流失（真實 28 人），漏掉的 25 人合計營收占 6.4%。

**落檔**：`00_intake/體檢報告.md`、`contracts/<source>.yml`

### S4 指標工程 ▣

強制 `as_of_date`。**欄名帶口徑後綴**（`f_txn_cnt` / `f_active_days` / `m_net_twd`），禁止裸 `F`/`M` —— 因為客戶 89 的 `f_txn_cnt=85` 但 `f_active_days=68`，用前者算客單價 1,773、後者 2,216，差 25%。

三個恆成立的不等式當免費檢查：`f_active_days ≤ f_txn_cnt ≤ f_item_cnt`

**回報**：指標分布圖、極端樣本、覆蓋率、口徑確認（基準日／退貨／F 定義）

### S6 驗證與自我攻擊 ▣

**回報實際長這樣**：

```

  ✗ ANOVA 殘差非常態（Shapiro p<0.001）→ 已改用 Kruskal-Wallis
```

### S6.5 洞察合成與 sizing ▣（新增的下游層）

這一層是修補「11 章齊全卻無法行動」的核心。三件事：

**① 跨章洞察合成**（補金字塔的中間層）
11 個章內小結 → 3–5 個跨章洞察。每個洞察要引用至少兩章的證據。

**② 每條建議做 sizing**
不只「怎麼做」，還要「值多少」：

| 欄位 | 例 |
|---|---|
| 目標客群 | 群 2 沉睡高價值，1,240 人 |
| 動作 | 簡訊 + 滿額折 200 |
| 覆蓋率 | 有手機號者 78% → 967 人可觸及 |
| 單位成本 | 簡訊 0.8 元 + 折抵 200 元 |
| **損益兩平反應率** | **需 3.2% 兌換率才打平** |
| 歷史對照 | 同類活動歷史兌換率 5–8% |
| 預期區間 | +NT$ 180k ~ 420k |
| 證據等級 | 相關（非因果）|

**損益兩平反應率是關鍵欄位** —— 它讓樂觀假設變得可被反駁。

**③ 排優先序**
用北極星樹 + sizing 排序，並列出**已考慮但排除**的選項與理由。

**落檔**：`05_models/insights.md`、`05_models/recommendations.csv`

### S7 交付 ▷

四種交付物，但**依聽眾分層而非依格式分層**：

| 聽眾 | 交付物 | 長度 |
|---|---|---|
| 決策者 | **決策摘要**（三欄表 + 4 條 Key Insights，不是散文） | 1 頁 |
| 行銷執行 | 名單檔 + 活動規格 | Excel |
| 分析同儕／稽核 | 完整 11 章報告 | 25–35 頁 |
| 自己探索 | 儀表板 | — |

**儀表板依 D1–D3 分層**：預設 L1（Altair `selection` 單檔，可寄 email）；需要瀏覽器端重跑 SQL 才升 L2（marimo `html-wasm`，**需 URL 不能雙擊**）；資料 >200MB 或機密才用 L3（`marimo run`，明確告知「這份不能寄」）。

**所有圖表從同一個純函式衍生**：`build_chart(df) -> alt.Chart`，四種交付物不准各寫一套。

**名單檔要有規格**（不然最後一哩會把正確分析執行成錯誤活動）：客群編號、觸達管道、排除名單（近 30 天已接觸／已退訂）、有效期限、預期反應率、回收欄位。

**產出前跑 `verify_outputs.py`**：11 章全綠、百分比加總≈100、同欄無 >100 倍離群、`|r|=1` 已標樣本不足、無 NaN/inf、術語表校驗、每條建議有證據等級、跨越量測變更日的趨勢圖有斷線標記。

## 4. 這個脈絡與「直接叫 AI 分析」的差別

差別不在會不會跑統計，而在**五個會主動說「不」的地方**：

| 階段 | 說什麼「不」 |
|---|---|
| **S0** | 「這還不是一個分析問題 —— 你要的 R2 還沒定義出來，先別碰資料」 |
| **S2** | 「這份資料回答不了那個問題」＋「這個指標覆蓋率只有 22%，不准進報告」 |
| **S5** | 「這個群只有 47 人，檢定力不足」 |
| **S6** | 「這個結論只能到相關，不能到因果」 |
| **S6.5** | 「這條建議需要 3.2% 兌換率才打平，而你的歷史是 1.8% —— 不建議做」 |

一般的 AI 分析會把這五個地方全部滑過去，給你一份看起來完整、結論站不住的報告 —— 那正是 214 份期末報告裡拿 B+ 的那幾份在做的事。
