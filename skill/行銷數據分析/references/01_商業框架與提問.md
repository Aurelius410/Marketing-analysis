# M0 開案與問題定義

這份文件管的是整條管線最上游那一段：從「你幫我看一下這批資料」到「這次要支援哪三個決策、北極星是什麼、拆哪種樹、哪些分析明確不做」。它是唯一一個**做錯了後面十二個模組全部白做**的模組——M1 到 M11 每一步都在回答 M0 定下的那一題，M0 定錯題，後面做得越漂亮損失越大。

跳過 M0 的代價不是「不夠嚴謹」，而是**交出一份 35 頁、11 章齊全、統計全對、但治錯病的報告**。素材裡的實例：客戶說「回購率從 34% 掉到 28%，幫我做顧客分群」，照做交出 5 群 + 卡方 + ANOVA + 事後檢定，A+ 品質；但客戶真實處境是「三個月前上了新會員分級制度，想知道對不對」，正確設計是分級上線前後 × 受影響/未受影響客群的 DiD。結果行銷團隊照建議發了 40 萬折扣券，回購率短暫回到 30%，六個月後掉回 27%；真正的病灶（免運門檻從 599 拉到 899，打掉 3,200 位中頻客、佔營收 22%）從頭到尾沒被提及。**花 40 萬治症狀，還把「精準推播無效」寫進下一次專案的前提。**（`research/gap-business-translation.md` BT-01）

M0 是四個硬卡點的第一個。**走完必須停下來等包子回覆**，不准自己往下跑。

## 一、開案五問

五問是 TMBA 的 SMART Problem Statement（`notion/TMBA/01_tmba_and_frameworks.md` §2，管顧思維 PDF p.4）與 Minto 問題定義五元素（同檔 §8.2.2，Minto Pyramid Principle Ch.8）的合併版。兩者互補：SMART 管「目標寫得夠不夠硬」，Minto 管「現況、觸發事件、已做過什麼」——後三項 SMART 完全沒有，而**處境分流全靠 Q5**。

| # | 問題 | 怎樣算答完（判準） | 答不出來怎麼辦 |
|:--:|---|---|---|
| **Q1** | 現況（Starting Point） | 能畫出一張圖：組織圖／門市分布／會員生命週期／訂單流程／通路結構。**畫不出來不算答完** | 追問「這件事發生在哪個環節」，不接受「整體業績」 |
| **Q2** | 發生什麼事（Disturbing Event） | 能指出事件 + 時點（月份精度），並歸到 **External**（競爭者、法規）／**Internal**（改制度、上新系統）／**Recently Recognized**（績效落後被發現）之一 | 三類都對不上就寫「無法指認」。Minto 原書明講：**不准硬掰**，直接跳 Q3 |
| **Q3** | 不喜歡的結果 R1 | **指標名 + 變化量 + 起始時點**。「回購率從 34% 掉到 28%，自 2026/02 起」合格；「業績不好」不合格 | 給不出數字 → 處境 7（見 §二） |
| **Q4** | 想要的結果 R2 | **指標名 + 目標水準 + 時間邊界**，用終局狀態措辭。「2026 Q4 前回購率回到 33%」合格；「提升顧客忠誠度」不合格 | Minto 的逃生門：**允許「R2 未定」，但必須登記為分析任務 #1**。這是處境 6 |
| **Q5** | 至今做過什麼 | 能列出「做什麼／何時／結果／還在跑嗎」四欄。答「沒做過」也合法，但要確認是真沒做 | 先查上一版 `_log/decisions.csv` 預填，再向包子確認 |

Q4 有三種假合格：「提升顧客回購率」（缺水準與時限）；「營收成長 20%」但介入手段是「調高會費」（手段與 Q1 錨點無因果連結，即 SMART 的 Not Relevant，原投影片的「TMBA 應該提高社費」型錯誤）；「回購率回到 33%」但 R1 是「毛利率下滑」（Q3 與 Q4 不是同一指標，補 §五 的指標樹證明傳導路徑才算數）。

```text
Problem Statement 五槽位模板（管顧思維 PDF p.4）
──────────────────────────────────────────────────────
[現況/根因錨點]  __________________________  ← Specific（Q1+Q2）
[介入手段]       藉由 ______________________  ← Action-oriented
[目標指標]       可讓 ______________________  ← Measurable（Q4）
[目標水準]       達 ________________________  ← Measurable
[時間邊界]       於 ________________ 前       ← Time-bound
──────────────────────────────────────────────────────
Relevant 檢查：介入手段是否真的作用在「現況/根因錨點」上？
              否 → 回 §三 重拆樹，不要直接開工

範例（合格）：
「本站中頻客（月消 600–900 元）自 2026/02 免運門檻上調後流失，
  藉由門檻分層與定向補貼，可讓整體回購率於 2026 Q4 前由 28% 回到 33%」
```

## 二、客戶處境分流器

同一組 R1/R2，客戶站的位置不同，**要回答的題、要拆的樹、不該做的事全都不同**。出自 Minto Ch.8 的七種讀者處境（同檔 §8.2.3、§11.2）。分流依據 100% 來自 Q5。

| # | 客戶處境 | 該回答的 Question | 用哪種樹 | **不該做什麼** |
|:--:|---|---|---|---|
| 1 | 完全不知道怎麼辦 | How do we get from R1 to R2? | **議題樹** → 收斂後轉假說樹 | — |
| 2 | 有方案但不確定對不對 | Is it the right solution? | **假說樹** | **不要重拆議題樹**，重拆等於把已知答案再算一遍 |
| 3 | 方案確定，不知怎麼執行 | How do we implement it? | **演繹樹**（實施路徑） | 跳過根因診斷，不要再做一輪 EDA 找原因 |
| 4 | 做了但失效 | What should we do now? | **議題樹**，根 = 方案為何失效 | 不要假設原診斷正確，原診斷本身是嫌疑人 |
| 5 | 多個方案選不出來 | Which one should we pick? | **2×2 優先序 + 演繹樹** | 不要再產生新方案，客戶要排序不要發想 |
| 6 | 知道 R1，講不出 R2 | What exactly is R2? | **先不拆樹** | **不要碰資料** |
| 7 | 知道 R2，不確定在不在 R1 | Are we actually at R1? | **現況量測 / benchmarking** | **不做因果分析** |

```text
Q5：針對這件事，你們已經做過什麼？
│
├─ 「什麼都還沒做」
│    └─ Q4（R2）具體嗎？
│         ├─ 具體 ─────────────────────► 處境 1（議題樹）
│         └─ 不具體 ───────────────────► 處境 6 ★
│
├─ 「還沒做，但想好要做 X」
│    ├─ 只有一個 X ──────────────────► 處境 2（假說樹）
│    └─ 有 X/Y/Z 選不出來 ────────────► 處境 5（2×2 + 演繹樹）
│
├─ 「已決定做 X，卡在怎麼落地」─────────► 處境 3（演繹樹）
├─ 「做了 X，沒效」──────────────────► 處境 4（議題樹，根 = X 為何失效）
└─ 「不確定現在到底有沒有問題」─────────► 處境 7 ★
     （徵狀：Q3 講不出變化量與起始時點，只有「聽說同業都…」）

★ 處境 6 與 7：這還不是一個分析問題。
```

### 2.1 處境 6 與 7：正確答案是「這還不是一個分析問題」

這兩格是分流器存在的主要理由。它們**看起來像分析需求，但資料進來也產不出可用的答案**，硬做的結果是一份數字全對、沒有人能拿去做決策的報告。

| | **處境 6：知道 R1，講不出 R2** | **處境 7：知道 R2，不確定在不在 R1** |
|---|---|---|
| 典型說法 | 「回購率一直掉，你看看能做什麼」 | 「同業回購率都 40%，我們是不是有問題？」 |
| 缺的是 | **目標**——沒有目標就沒有排序鍵，M11 排不出順序 | **現況基線**——不知道自己在哪，談不上因果 |
| 硬做會怎樣 | 交出 11 個「顯著」，主管問「哪個先做」，報告答不出來 | 直接跑 DiD／uplift，把「本來就是這個水準」誤判成「某事件造成的下滑」，整份證據等級報廢（見 18-G6） |
| **M0 正確產出** | **目標設定工作坊**：先做指標樹（§五）+ 歷史/同業區間，把 R2 敲定，登記為分析任務 #1；不准做分群、迴歸、預測與任何策略建議 | **現況量測**：只做 M1 資料體檢 + 指標基線表 + 對照，明寫「本輪不做因果」；不准出現「造成／帶來／驅動」 |
| 轉正條件 | R2 具體化 → 轉處境 1 | 確認確實偏離基線 → 帶著 R1 轉處境 1 |

```text
M0 硬卡點回報第一行永遠是這三個字段，缺一不得標記完成：
處境編號：____（1–7）
選定樹種：____（議題樹 / 假說樹 / 演繹樹 / 不拆樹）
因此不做：____（逐條列，會抄進報告附錄的「不做清單」）

處境 = 6 或 7 時：本輪交付物 = 目標設定卡 / 現況基線表，
且《專案核心.md》的「是否為行銷分析」填「否——尚在問題定義階段」
```

## 三、拆樹與假說登錄

### 3.1 三種樹怎麼選

定義出自管顧思維 PDF p.5（同檔 §3）。Minto Ch.9 用另一組詞講同一件事，且抱怨業界把 "Issue Analysis" 濫用成任何邏輯樹：**診斷框架（找原因）與邏輯樹（產生並檢驗解方）是不同用途的樹，不該混用**。

| | **議題樹**（Minto：診斷框架） | **假說樹** | **演繹樹**（Minto：邏輯樹） |
|---|---|---|---|
| 目的 | 把宏觀問題拆成可解決的子問題 | 把假說拆成可驗證的子假說 | 以策略先行發展合適解方 |
| 分支判準 | 都應是所欲解決的問題 | 都應呼應主要假說且能銜接策略 | 都應是「以終為始」的解方 |
| 對應處境 | 1、4 | 2 | 3、5 |

行銷最常用的兩個現成模板（同檔 §11.5，Victor Cheng）：**獲利/營收下滑型**（Profits → Revenue/Cost，三步 SEGMENT → ISOLATE → EXPLORE）與 **4C 清單**（Customer / Product / Company / Competition，當 CE 補漏用）。注意 BCG 的警告：`Imposing a generic framework is a recipe for failure`——模板是補漏用的，不是整套套上去的。

### 3.2 MECE 品質門檻

```text
對每一層兄弟節點：
□ ME 檢查：任兩個節點有包含關係或概念重疊嗎？
           測試句「研究生 vs 博士生」——有沒有一個吃掉另一個？
           行銷版：「新客 / 沉睡客 / 低頻客」→ 後兩者重疊 → 不 ME
□ CE 檢查：所有兄弟節點的聯集 = 父節點嗎？漏了誰？
           測試句「大一～大四」——研究生跑哪去了？
           行銷版：「App / 官網 / 門市」→ 電話訂購與經銷跑哪去了？
           → 卡住時用 4C 清單掃一遍補漏

對每一個葉節點：
□ 甜蜜點檢查：對應的解方可執行嗎？
           太表層（「發折價券」）→ 再拆一層
           太深層（「改變消費者的價值觀」）→ 收回一層
□ 假說化檢查：見 §3.3
□ 驗證方法檢查：能對應到 數據分析 / 訪談 / 問卷 其中之一嗎？

停止條件（兩個都要滿足，缺一不可）：
□ (a) 再往下拆會違反 MECE
□ (b) 葉節點落在甜蜜點
只滿足 (a)：拆得太淺或太深，調整層級重來，不要將就。
```

### 3.3 葉節點的假說化門檻

葉節點必須能填完這一句（BCG casebook，同檔 §8.4／§11.3）：

> **「我認為 ______，因為 ______，若為真則資料上會看到 ______。」**

填不完的**不是可分析的假設，是待查清單項**。差別在第三格：填得出「資料上會看到什麼」代表可證偽；填不出來代表無論資料長什麼樣都能自圓其說。

| 寫法 | 判定 |
|---|---|
| 「我認為中頻客流失，因為免運門檻從 599 拉到 899，若為真則資料上會看到 2026/02 後月消 600–899 區間顧客數月減 >8%，而月消 >900 區間不變」 | ✅ 三格齊全，第三格帶方向、區間、門檻 |
| 「我認為顧客忠誠度下降」 | ❌ 缺因、缺可觀測後果 → 待查項 |
| 「…因為社群互動變少，若為真則資料上會看到年輕客營收下滑」 | ⚠️ 第三格太鬆，無門檻無對照群，任何雜訊都算命中 |

### 3.4 假說登錄表（M0 硬卡點必填）

葉節點一律登錄成表，**不准只存在腦子裡或對話裡**。這張表是 M11 排優先序的原料，也是報告附錄「不做清單」的來源。欄位：`假說ID`（H1, H2…，報告與 sizing 表用它交叉引用）／`假說敘述`（§3.3 三格句一字不漏）／`預估投入`+`預估價值`（各 1–5 分）／`2×2象限`（Do Now 低投入高價值／Do Next 高投入高價值／Do Later／**Don't Do**）／`驗證方法`（對應哪個模組）／`資料來源`（填不出來就回 §四）／`完成判準`／**`決策連結`**／`狀態`。

**`決策連結` 是最便宜的高價值檢查**：必須填成「若結果是 A 我會做 X；若結果是 B 我會做 Y」。**X == Y ⇒ 這個分析不做。** 素材說它能砍掉真實專案裡約三分之一的「習慣性分析」（BT-13）。實例：訂閱制客戶只賣一種月費盒、品類 3 類，照 11 章規格硬跑購物籃相關矩陣（3×3 共 3 組合）與因素分析（3 個變數擠出 1 個因素），花掉 3 天——單品訂閱制沒有搭售決策，X == Y。而真正該做的「訂閱到期日效應 × 續訂提醒時點」因時間用完沒做；實測最佳提醒時點是到期前第 7 天而非到期後第 3 天，續訂率差 11pp，以 8,000 訂戶 × 月費 890 元計，**每月約 78 萬的續訂金額差異**。

```text
00_intake/hypothesis_register.csv
假說ID,假說敘述,預估投入,預估價值,象限,驗證方法,資料來源,完成判準,決策連結,狀態
H1,"我認為…，因為…，若為真則資料上會看到…",2,5,Do Now,M8-1 CAI,fact_transaction,"CAI<-10 人數與營收佔比","若>15% 做主動關懷；若<5% 不做",待驗證
H7,"…",4,1,Don't Do,—,—,—,"兩種結果都不改變行動 → 不做",已排除
```

## 四、Check List 矩陣

出自 IB5082 第二講 p.24（`local/大數據行銷IB5082/02_建構顧客關係行銷資料庫.md` §2、§8.2）。原講義矩陣是留空給學生填的，且**沒交代「決策 A–E 從哪來」**——那正是 §一～§三 補的那一段。硬規則：**欄位 A–E 必須來自假說登錄表的葉節點，不准憑空列**。

**列**（六個必答問題）是 p.23 七步流程的第 ②–⑦ 步，強制執行 decision-first、field-last 的順序：

| 管理者需要做的決策： | A: ______ | B: ______ | C: ______ | D: ______ | E: ______ |
|---|---|---|---|---|---|
| 1. 這個決策所需要的資訊是什麼？ | | | | | |
| 2. 這項資訊要透過何種分析方法獲得？ | | | | | |
| 3. 該分析方法所需之資料型態為何？ | | | | | |
| 4. 資料庫中要怎麼定義這些欄位？ | | | | | |
| 5. 這些欄位現在有沒有？覆蓋率多少？ | | | | | |
| 6. 沒有的話從哪個來源補（POS／CRM／問卷／APP／感測器）？ | | | | | |

> 原講義第 5、6 列是「欄位如何轉成問卷題目／問卷透過何種管道蒐集」。本 skill 的專案多半是既有資料而非新建問卷，故改寫成「現在有沒有 + 覆蓋率」與「從哪補」，語意角色不變（都是「這欄位從哪來」），但把覆蓋率提前到 M0 就問。

| 情況 | 判定 | 動作 |
|---|---|---|
| 一整欄六格都填得出來 | 該決策被資料支援 | 進入 §三 的 2×2 排優先序 |
| **任一格填不出來** | **該決策目前不被資料支援** | 二選一：回頭補欄位（寫進 M1 補件清單），或**明確放棄並記入「不做清單」**。不准留白往下走 |
| 第 5 列覆蓋率 < 60% | 指標不可靠 | **不得作為分群輸入變數，也不得作為建議依據**，只能當描述性補充，圖表標題必須帶「（僅 N 人／覆蓋率 X%）」 |
| 第 2 列填「分群」且第 4 列出現人口變數 | **違反 18-E2** | 分群輸入只能用行為指標（R/F/M/RFM Score/CAI/CRI/因素分數/LN_F/LN_M）；人口變數只准出現在卡方那一章 |
| 第 1 列填「活動有沒有效」但無 `fact_marketing_spend` | **踩到 18-G5** | 報告必須明寫「本分析無法歸因至行銷投入」，建議一律標證據等級「相關」（見 18-G6） |

覆蓋率門檻不是拍腦袋來的。汽車經銷商 2,400 位車主、平均換車間隔 1,800 天、觀察期 1,095 天，CAI 需 ≥3 次購買才有 2 個間隔可比，符合的只有 71 人（**覆蓋率 3.0%**）。CAI 照樣算得出來、卡方 ANOVA 照樣有 p 值，報告建議「CAI < −10 觸發主動關懷」並附 18 人名單，行銷團隊理解成「全庫只有 18 人有流失風險」，**2,329 位（97%）車主完全沒被納入喚回設計**；而汽車業真正的流失訊號是保養回廠間隔與保固到期日，那兩欄這次連問都沒問。以每台車年保養產值 1.2 萬計，若 5% 因此流失 = 140 萬產值（BT-07）。

## 五、北極星指標樹

**這是後續排優先序的唯一依據。沒有它，M11 的建議無法排序**——十一個「顯著」並列，主管只能挑看起來最便宜的那個。

$$\text{北極星} = \text{驅動指標}_1 \times \text{驅動指標}_2 \times \cdots \times \text{驅動指標}_k$$

最常用的行銷版展開：

$$\text{12 個月交易總額} = \text{活躍顧客數} \times \text{平均購買頻率} \times \text{平均客單價}$$

| 層 | 是什麼 | 數量 | 硬規則 |
|---|---|:--:|---|
| **目標層（北極星）** | 唯一一個，整個專案的排序鍵 | 1 | 必須能寫成驅動指標的算式。寫不出算式 = 不是北極星 |
| **驅動層** | 能代入北極星算式的乘數 | 3–5 | 每個都要能被行銷動作影響。影響不了的（如總體景氣）歸情境變數 |
| **護欄層** | 越線則建議無效的底線 | 2–3 | 至少要有毛利率下限與折扣率上限。**沒有護欄的成長建議不得輸出** |
| 診斷層 | RFM／CAI／CRI／購物籃／因素分數全歸這層 | 不限 | 每個必須填 `links_to`（它是哪個驅動指標的先行訊號）。**填不出 `links_to` 的指標，這次不做** |

**北極星的三個否決條件**（BT-03）：不可是比率單獨存在（「回購率」上升可能只是把不活躍會員清掉、分母縮小）；不可是無法歸因到行銷動作的財務數字（「淨利」受折舊、匯率、原料價格影響，行銷團隊按不到那顆按鈕）；不可跨越護欄（「GMV 成長 12%」但折扣率從 8% 拉到 19%，那不算成長）。

沒有北極星會怎樣：信用卡專案交出三個策略，報告建議把 **80% 的挽回預算（40 萬中的 32 萬）** 投給「大台北防禦圈」，目標是集群 4（13 人，均消 $1,895，年交易額約 2.5 萬）。**投 32 萬追一個上限 2.5 萬的池子**；同時佔營收 61% 的活躍主力群（76 人）客單價 −5%（−$95 × 76 × 年頻率 37 ≈ **−27 萬**）完全沒出現在任何一條建議裡，因為它統計上不顯著。**32 萬追 2.5 萬，同時放掉 27 萬的流血點。**

## 六、三個宣告

三個宣告在 M0 一次做完，寫進《專案核心.md》。它們共同決定**這次專案的分析深度上限**——宣告完之後超出上限的分析一律不做，理由不是「做不到」，是「這批資料與這個產業結構撐不住那個結論」。

### 6.1 產業定位五維診斷（決定分析深度上限）

出自 IB5082 第二講 p.5（同檔 §8.8）。五維：**客戶對象**（消費者／公司）、**客戶數量**（極多／多／不多）、**客戶類型**（多樣／較同質）、**購買頻度**（高／中／低）、**購買內容**（多樣／同質）。原文參考基準六列：百貨零售業／金融服務業＝消費者・極多・多樣・高・多樣；生產製造業＝公司・多・較同質・中・較同質；觀光旅館業／汽車經銷商＝消費者・多・多樣・**低**・同質；流通服務業＝公司・不多・較同質・中・較同質。

**購買頻度是最關鍵的那一維：**

| 五維組合 | 分析深度上限 | 具體限制 |
|---|---|---|
| 高頻 × 多樣 × 極多（百貨零售、金融服務、電商） | 全開 | R/F/M、CAI、CRI、CLV、購物籃、遷徙矩陣全部可做 |
| 中頻 × 較同質 × 多（生產製造、流通服務） | 到顧客價值層 | 購物籃與因素分析價值低（品類數不足，見 18-E12）；改走客戶集中度與續約 |
| **低頻 × 同質（汽車經銷、觀光旅館、建材、婚攝）** | **R/F/M 以外全部先做可行性檢查** | CAI/CRI/CLV 需 ≥3 次購買，低頻產業覆蓋率常 <10%（見 §四）。**改走靜態變數 + 產業專屬行為訊號**：保養回廠間隔、保固到期日、合約到期日 |
| B2B（對象＝公司、數量不多） | 不做分群 | n 太小，每群 n<30 一律標「樣本不足，僅供觀察」；改走個案層 account plan |

### 6.2 成熟度目標（AI → BI → CI → DI）

出自 IB5082 第一講 P75–82、P126（`local/大數據行銷IB5082/01_大數據時代之行銷戰略.md` §10.4、§22.2）。**M0 就要宣告這次停在哪一階**，它決定 M7/M9/M12 做不做。原講義的原話：**「停在 BI ＝ 只是報表，不算分析交付。」**

| 階 | 全名 | 方法 | 數學形式 | 回答的問題 |
|:--:|---|---|---|---|
| **BI** | Business Intelligence | Pivot Analysis | $\mathrm{Corr}(X_1,X_2)$ | 現況如何？誰和誰同時發生？ |
| **CI** | Contextual Intelligence | Prediction | $Y=\alpha+\beta_1X_1+\beta_2X_2+\varepsilon$，其中 $\beta_1=\gamma_1Z_1+\gamma_2Z_2+\delta$ | 在什麼情境 $Z$ 下，$X$ 對 $Y$ 的影響有多大？ |
| **DI** | Decision Intelligence | Simulation | $\mathrm{Prob}(X_1=x)=?$ | 若我把 $X$ 調到 $x$，會發生什麼？ |

升階動作是明確的：BI→CI 是把某個變數從 $X$（效果）改判為 $Z$（情境），讓係數隨它變動；CI→DI 是停止把 $X$ 當已知，改為模擬 $X$ 的分布。DI 必須含 closed-loop learning（建議與實際決策比對回填），且 **augments, not replaces** 人類決策。

| 宣告 | 必做模組 | 交付物下限 |
|:--:|---|---|
| BI | M1–M6, M8, M11 | 交叉表 + 分群輪廓 + 例外名單。**只有趨勢圖沒有越線名單 = 不合格** |
| CI | 上列 + M7（或 M9） | 情境化係數 + 效果量 + 信賴區間 |
| DI | 上列 + M9 + M12 | 情境模擬 + 建議 + 回看排程 + `_log/decisions.csv` |

### 6.3 證據等級目標

M0 就講清楚這次最高能達到哪一級，避免 M11 寫出資料撐不住的動詞。

| 等級 | 必要設計條件（缺一即降級） | 允許動詞 | 禁止動詞 |
|---|---|---|---|
| **相關** | 無對照組，或無時間先後 | 與…同時出現、與…相關、在…族群中較高 | 帶來、造成、提升、驅動、貢獻、增量 |
| **預測** | out-of-time holdout + AUC/lift + 校準圖 | 可用於排序、可用於篩選名單、命中率 X% | 任何 intervention 語句 |
| **準實驗** | 有對照組（DiD／PSM／合成控制／RDD）**且**平行趨勢或平衡性檢查通過 | 估計增量約 X（95% CI [a, b]） | 造成（未附不確定性描述時） |
| **實驗** | 隨機分派 + 事前登記主要指標 + 功效分析（MDE） | 造成、因果效果為 X | — |

**最高頻的誤標明寫在這裡：`pre-post 無對照組 = 相關，不是準實驗`。** 實例：促銷期（11/1–11/15）營收 +18%，對比前 15 天，分析師以為「有時間先後 + 有對照期」就是準實驗，寫「本次促銷**帶來** 18% 的營收增量」。實際同期有雙十一大盤（類目 +14%）、兩支新品上架、一次 KOL 曝光，真實增量做 DiD 約 +3%。**明年促銷預算從 800 萬加倍到 1,600 萬，多花的 800 萬換來約 240 萬增量營收、約 43 萬毛利，淨損 757 萬**（BT-04）。呼應 18-G6。

```text
《專案核心.md》三個宣告的固定寫法
─────────────────────────────────────────────
產業定位：消費者 / 極多 / 多樣 / 高頻 / 多樣 → 分析深度：全開
成熟度目標：CI（做到情境化係數，不做模擬）  → M9 做、M12 不做
證據等級目標：準實驗（對照組 + 平行趨勢檢查）→ 允許用「估計增量約 X」
```

## 八、產業知識由使用者提供

**不預先架構產業知識。** 這個 skill 不內建「零售業通常怎樣」「金融業通常怎樣」的假設庫——那類假設在單一客戶身上錯得很有把握，而且錯了不會報錯，只會讓整份分析悄悄偏掉。做法是 M0 就把該問的問完，答案原樣寫進《專案核心.md》§6，之後所有模組引用它而不是引用通用常識。

| # | 要問的問題 | 不問會怎樣 | 用在哪 |
|:--:|---|---|---|
| 1 | **產業特性與自然購買週期**：一個正常客人多久買一次？淡旺季在什麼時候？ | 切不出合理觀察窗。汽車業用「90 天沒買 = 流失」會把 100% 的客人標成流失 | M0 時間窗、M8-1 流失定義、M8-3 季節性 |
| 2 | **既有客群分類**：現在內部怎麼分客人？誰在用、用在哪？ | 丟一套全新分群給行銷團隊，他們的系統、話術、KPI 全對不上，最後不會被用 | M5 標籤、M6 分群後對照表 |
| 3 | **行銷團隊能同時操作幾個客群**：一季能同時跑幾檔差異化活動？ | 這是 k 的上限。**分出 8 群但團隊只能跑 3 檔 = 5 群沒有對應行動**，等於白分。答案通常是 3–5 | M6 的 k 決定（與 elbow／silhouette 並列理由）、M11 排優先序 |
| 4 | **歷史活動反應率基準**：過去同類活動反應率多少？最好的一次多少？ | 沒有這個數字，M11 的 sizing 只能靠外部基準或估算，損益兩平反應率無法被反駁。**這是對 ROI 影響最大的一題** | M11 sizing、損益兩平反應率、假設來源標籤 |
| 5 | **絕對不能做的事**：有沒有法遵、品牌或高層明確禁止的？ | 交出技術上正確、但踩到合規線的建議，成本遠大於分析價值。金融、醫療、教育業尤其 | M11 建議過濾、名單檔的排除規則 |

第 5 題要問得具體，客戶想不到要主動講：

```text
「絕對不能做的事」追問腳本
──────────────────────────────────────────────────────
□ 敏感屬性：可以用性別、年齡、教育程度、婚姻、居住地做「差別待遇」嗎？
   預設答案應為否。這類屬性只准做事後輪廓描述與卡方檢定，
   不准作為 targeting 條件、定價/折扣的分群鍵、風險評分輸入。
   有商業訊號時改用行為代理變數：
   「低學歷高客單」→ 改用「單筆金額 P90 以上 × 品類集中度高」
□ 接觸頻率：同一人一個月最多能被接觸幾次？（frequency cap，預設 2 次/月）
□ 通路限制：哪些通路不能用？（如不做電話外撥、不發簡訊）
□ 折扣底線：折扣率上限？哪些商品絕不打折？→ 寫進 metric_tree 的 guardrails
□ 名單外流：名單檔能不能離開你們的系統？要不要去識別化？
```
