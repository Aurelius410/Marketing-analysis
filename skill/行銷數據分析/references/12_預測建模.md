# 預測建模（M9）

這份文件管的是**預測型專案**：流失預測、下期購買傾向、回應率預測、CLV 預測、詐騙評論偵測。它只在包子明確要「預測」時才走 —— 不是每個行銷分析都需要模型，把 M8 的 RFM 排序拿去發 DM 常常就夠了，而且免費。

**演算法只佔這份文件的一小部分，方法論才是重點。** 換掉 XGBoost 改用 LightGBM 通常只動 AUC 的第三位小數；而時間切分切錯、機率沒校準、用 tree importance 當解釋，這三件事任何一件都會讓整套結論反向。素材裡的實證很直白：一份用 14 個特徵、跑完 backward elimination 的 logistic 拿到 in-sample AUC 0.89，看起來可以上線；但「只用 R 單變數排序」的 baseline 是 0.86，整套工程只多 0.03，而 80 萬喚回預算就這樣花在一件一行 SQL 就能做到的事情上（出處：`research/gap-statistical-inference.md` S9）。**沒有 baseline 對照的模型不是模型，是裝飾。**

更貴的失敗是機率沒校準。XGBoost 吐出來的 0.7 不是「這位顧客有 70% 會買」，拿它去乘客單價算期望營收，會系統性高估，而且高估的方向剛好是「模型最有信心的那批人」—— 也就是你最捨得花錢的那批。這個錯誤不會報錯、不會出現在 AUC 上，只會出現在半年後的實際回收數字裡。

M9 的證據等級**天花板是「預測」**，而且要拿到「預測」等級必須同時有 out-of-time 驗證與 naive baseline 對照（見 `00_通則與紀律.md` §1.5）。任何「模型顯示 A 造成 B」的句子在這個模組一律不准出現。

## 一、演算法選擇

先講結論：**表格型行銷資料，先跑 baseline，再跑一個梯度提升樹，就夠了。** 剩下的力氣花在切分、校準與 profit curve 上，投資報酬率高一個數量級。

資料量門檻是教材直接給的硬判準，不是感覺：

| 資料量 | 建議 | 明確避免 | 出處 |
|---|---|---|---|
| 標註 < 100 筆 | 不做模型。寫規則做 MVP，邊跑邊蒐集標籤 | 全部 | 【實測】`notion/大數據與商業分析/02_classification.md` §19.1「一旦有 100+ 個標籤，就可以考慮機器學習」 |
| 100 – 1,000 筆 | Naive Bayes 首選；淺樹（**必剪枝**）；Logistic Regression | **NN、Random Forest、Boosting 全部避免**（多樹集成對小資料不划算、Boosting 容易過擬合小資料） | 【實測】同上 §19.2 |
| 1K – 100K 筆 | Random Forest 或 SVM；**梯度提升樹（GBDT）是這一段的實務主力** | — | 【實測】同上 §26 母頁流程圖；GBDT 一項為【推導，待驗證】，教材只在 ICDM Top10 提了一句「現代的 Gradient Boosting（如 XGBoost）是基於這個思想」 |
| > 100K 筆 | RF（可並行）或 Logistic Regression（速度）；LightGBM | **避免 SVM**（訓練 $O(n^2)$–$O(n^3)$）、**避免 kNN**（預測 $O(n)$，每次預測要比 100K 個距離） | 【實測】同上 §19.3 |

**這是「筆數」不是「顧客數」。** 顧客層預測（每人一列）的行銷資料，2 萬名會員就是 2 萬筆 —— 落在 1K–100K 這一段，這是絕大多數行銷專案的位置。

四個樹家族的選擇：

| 演算法 | 什麼時候選它 | 代價 | 出處 |
|---|---|---|---|
| **Random Forest** | 想要穩、調參少（只有 $m_{try}$ 與 $N_{trees}$）、可並行。**當作 GBDT 的對照組永遠值得跑** | 通常略輸調好的 GBDT；預測機率往中間縮（見 §三） | 【實測】§18.4、§24.1 |
| **XGBoost** | 表格資料的預設起手。生態成熟、`scale_pos_weight` 直接處理不平衡 | 類別特徵要自己編碼；序列訓練，比 RF 慢 | 【推導，待驗證】教材未涵蓋 |
| **LightGBM** | 資料量大（> 10 萬列）或特徵多時，訓練明顯更快（leaf-wise 生長 + 直方圖分箱） | 小資料上 leaf-wise 容易過擬合，要壓 `num_leaves` / 設 `min_data_in_leaf` | 【推導，待驗證】 |
| **CatBoost** | **類別特徵多、且基數高時最省事** —— 通路、品類、地區、門市、品牌這些欄位不用自己做 target encoding，它內建 ordered target statistics 且自帶防洩漏 | 訓練較慢；預設參數下模型檔較大 | 【推導，待驗證】 |

> **行銷資料為什麼常常直接指向 CatBoost**：一份典型的會員特徵表裡，`通路`（8 類）、`主力品類`（16 類）、`居住縣市`（22 類）、`來源活動代碼`（可能 200+ 類）全是類別型。One-hot 之後維度爆炸且每個 dummy 都稀疏；自己做 target encoding 又極容易把標籤洩漏進特徵（用了全期的目標平均去編碼）。CatBoost 把這一段做掉，是**省時間也省一個常見錯誤**。但注意：**高基數不等於可以用**，會員編號、訂單號這種接近唯一的欄位無論用什麼演算法都要先踢掉（見 §七）。

```
選演算法（表格型行銷資料）
   │
   ├─ 標註 < 1,000 筆 ──► Naive Bayes / 剪枝過的淺樹 / Logistic Regression
   │                        （避免 NN、RF、Boosting）
   │
   ├─ 需要向主管逐條解釋規則、或要進監管/稽核 ──► 單棵決策樹（深度 ≤4）+ RF 做對照
   │
   ├─ 類別特徵佔一半以上，且有 >50 類的欄位 ──► CatBoost
   │
   ├─ 列數 > 10 萬、要在幾分鐘內重跑 ──► LightGBM
   │
   └─ 其他 ──► XGBoost，並同時跑 RF 與 Logistic Regression 當對照
                 └─ 三者 AUC 差 <0.01 ──► 用最好解釋的那個（通常是 LR）
```

**環境警語（誠實標記）**：`18_分析陷阱清單.md` 的 T1/T2 只實測過 dowhy／EconML／meridian 在 Python 3.14.1 的狀況，**本模組要用的四個套件本專案尚未實測**。第一次用之前先跑 `python scripts/setup_check.py`：

| 套件 | 3.14.1 狀態 | 裝不起來的替代 |
|---|---|---|
| `xgboost` | **未實測** | `sklearn.ensemble.HistGradientBoostingClassifier`（sklearn 內建，無額外相依，演算法同族） |
| `lightgbm` | **未實測** | 同上；或退 `.venv-causal`（3.12） |
| `catboost` | **未實測**（相依較重，風險最高） | 自己做 target encoding（**必須用 as_of 之前的資料算**，否則就是 18-G4） |

## 二、時間切分驗證

★ 這一節是 case by case，判準必須寫清楚，因為「隨機切 8:2」是所有行銷預測專案的預設錯誤。

隨機切列在有時間結構或有顧客重複的資料上，會讓驗證分數系統性樂觀。素材給的實證後果：驗證集 AUC 0.95、上線崩盤（`18_分析陷阱清單.md` G4）。而 out-of-time 的正確做法是**用更晚的 `as_of` 重建特徵與標籤再評估，不可用隨機切列**（出處：【實測】`research/gap-statistical-inference.md` S9 修補動作 2）。

**判準表（照這張表決定，不要憑感覺）：**

| 觸發條件 | 切分方式 | 為什麼 | 額外要求 |
|---|---|---|---|
| 目標本身與時間有關（流失、下期購買、下季 CLV） | **必須時間切分** | 標籤定義裡就含「未來 N 天」，隨機切等於讓模型看過未來 | 特徵窗與標籤窗**不可重疊**（見下方程式碼） |
| 有明顯季節性（檔期、換季、年節） | **必須時間切分，且測試集要涵蓋完整季節週期** | 只用 3–5 月當測試集，模型學到的是淡季規律，雙十一就失效 | 測試集長度 ≥ 一個完整週期（多數零售＝12 個月） |
| 資料期間短（< 2 個完整週期） | **時間切分 + rolling origin** | 單一測試切面只有一次觀測，運氣成分太大 | 至少 3 折；報告要列每折分數與**全距**，不能只報平均 |
| 目標與時間無關（顧客屬性分類、商品歸類、評論情感） | 隨機分層可以 | 沒有時間結構就沒有時間洩漏 | 仍要分層（`stratify=y`），否則稀有正類可能整批落在同一邊 |
| **同一顧客有多筆列**（每次交易一列、每月一列、每張卡一列） | **必須 `GroupKFold(groups=customer_id)`，不能按列切** | 同一人的兩筆會分別落進訓練與測試，模型等於考過的題目再考一次 | 這是行銷資料**最常見的隱藏洩漏**；同時存在時間結構就用 `GroupTimeSeriesSplit`（先按時間切，再檢查 group 不跨邊） |

> **為什麼「同一顧客多筆」這麼危險**：假設 2,000 位顧客、每人 12 個月共 24,000 列。隨機 8:2 切列之後，幾乎每一位顧客都同時出現在訓練集與測試集裡 —— 模型只要記住「顧客 #87 這個人的消費水位」就能在測試集拿高分，但它對**新顧客**零預測力。這與 §七 的高基數 ID 是同一個病的兩種長相。實務徵狀：加入顧客層彙總特徵後 AUC 跳升 0.05 以上，且 SHAP 顯示前三名全是顧客層均值類特徵 —— 這時先懷疑切分，不要先高興。

rolling origin（滾動原點）長這樣，每一折的訓練集只用切點以前的資料：

```
時間軸 ────────────────────────────────────────────────────►
折 1  [====== train ======][gap][= label =]
折 2  [========= train =========][gap][= label =]
折 3  [============ train ============][gap][= label =]
折 4  [=============== train ===============][gap][= label =]
                                              └─ 最後一折 = 正式 out-of-time 測試集

gap = 特徵窗與標籤窗之間的緩衝，長度 ≥ 資料入庫延遲
     （POS 資料 T+1、廣告平台回填 T+3、退貨認列 T+30 → gap 取最長的那個）
```

`gap` 不是選配。沒有 gap 的話，標籤期第一天的交易可能已經被算進特徵（尤其是「最近 7 天消費金額」這種滾動特徵），這是最隱蔽的洩漏形態。

```python
# 三種切法的最小實作（scripts/split_time.py）
from sklearn.model_selection import StratifiedKFold, GroupKFold, TimeSeriesSplit

# ① 目標與時間無關 → 隨機分層
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

# ② 同一顧客多筆 → 依 customer_id 分組，不按列切
cv = GroupKFold(n_splits=5)          # split(X, y, groups=df["cust_id"])

# ③ 有時間結構 → rolling origin；gap 用「列數」表達，先確認資料已按時間排序
cv = TimeSeriesSplit(n_splits=4, gap=gap_rows, test_size=test_rows)

# 標籤與特徵的時間窗必須由兩支獨立函式產生，且簽章強制寫明 horizon
#   build_features(as_of)                 → 只讀 txn_date <= as_of
#   make_label(as_of, horizon_days)       → 只讀 as_of < txn_date <= as_of + horizon
# 出處：research/gap-statistical-inference.md S9 修補動作 1；洩漏條目見 18-G4
assert features["as_of"].max() < labels["window_start"].min(), "特徵窗與標籤窗重疊 = 洩漏"
```

## 三、機率校準

★ 這一節是 M9 與 M11（決策轉譯）之間的橋。不做它，M11 的所有 sizing 都是錯的。

**XGBoost 的原始輸出不是校準過的機率。** 教材對這件事只講了 Naive Bayes 的版本 ——「NB 輸出的機率其實只是未歸一化的分數……不能直接當成『這位客戶有 73% 會買』拿去算期望營收」（【實測】`02_classification.md` §8.5 評註），並在缺漏清單裡明寫「機率校準（calibration）：教材自己說機率估不準卻沒給對策，需另尋來源：Platt scaling / isotonic」（§27）。樹模型的版本是同一個病：**early stopping、正則化、`scale_pos_weight`、以及任何重抽樣都會把輸出從機率推開**；RF 因為是多棵樹的平均投票，輸出會系統性往中間縮（極端機率被稀釋）。以上機制說明為【推導，待驗證】。

**錯在哪裡，用數字講**（示意數字，【推導，待驗證】）：

> 模型把 10,000 位顧客的回應機率排序，最高的那一箱平均輸出 **0.70**。M11 照這個數字算：期望回應 = 0.70 × 1,000 人 = 700 人，毛利 600 元／人 → 預期收益 **420,000 元**，於是核了 30 萬的活動預算。
> 校準曲線一畫才發現，這一箱的**實際回應率是 0.42**，真實收益 252,000 元。**高估 168,000 元（40%）**，而預算已經照 42 萬批出去了。
> 注意 AUC 完全看不出這件事 —— 排序沒錯，錯的是刻度。**AUC 管排序，校準管刻度，兩者互相看不見對方的錯。**

**Platt scaling vs Isotonic regression：**

| | Platt scaling（sigmoid） | Isotonic regression（保序） |
|---|---|---|
| 形式 | 對 logit 套一條兩參數 sigmoid | 非參數階梯函數 |
| 假設 | 校準誤差呈 **sigmoid 形狀**，平滑且單調 | 只假設**單調**，形狀不限 |
| 校準集樣本量 | 數百筆即可（參數只有 2 個） | **建議 ≥ 1,000 筆**；更少會過擬合成鋸齒 |
| 修得了什麼 | 整體過度自信／過度保守 | 上面那些 **＋ 局部的非 sigmoid 扭曲** |
| 修不了什麼 | 曲線在中段反轉、多段不同方向 | 校準集外的區間（會外推成常數） |
| 輸出長相 | 平滑連續 | 階梯狀，相鄰分數可能被壓成同一值 |
| 行銷上的選擇 | **正類稀有（<5%）或校準集 <1,000 筆時選它** | 校準集夠大、且校準曲線明顯不是 sigmoid 形狀時選它 |

> 樣本量門檻 1,000 為【推導，待驗證】—— 這是常見經驗值，本專案**尚未在自己的資料上驗過**。實際做法：兩種都跑，比 Brier score 與校準斜率，把兩組數字寫進表 11.1，選贏的那個並記錄理由（這是 `00_通則與紀律.md` §1.4「參數必附理由」的要求）。

**校準必須在獨立的校準集上做。** 用訓練集校準等於用模型已經記住的樣本去修正模型的自信 —— 修完看起來完美，上線照樣高估。切法固定為三份：

```python
# scripts/calibrate.py —— 三切分，calib 只做校準，test 只評估，兩者都不參與訓練
# 有時間結構時，三份必須依時間先後排列：train 最早、calib 次之、test 最晚
from sklearn.calibration import CalibratedClassifierCV
from sklearn.metrics import brier_score_loss
from sklearn.linear_model import LinearRegression
import numpy as np

base = XGBClassifier(...).fit(X_train, y_train)          # 只用 train
cal_p = CalibratedClassifierCV(base, method="sigmoid", cv="prefit").fit(X_calib, y_calib)
cal_i = CalibratedClassifierCV(base, method="isotonic", cv="prefit").fit(X_calib, y_calib)

def calib_report(model, X, y, n_bins=10):
    p = model.predict_proba(X)[:, 1]
    bins = np.quantile(p, np.linspace(0, 1, n_bins + 1))      # 等頻分箱，不用等寬
    obs, pred, cnt = [], [], []
    for lo, hi in zip(bins[:-1], bins[1:]):
        m = (p >= lo) & (p <= hi)
        if m.sum() < 30:                                       # 樣本 <30 的箱不畫、標 N/A
            obs.append(np.nan); pred.append(np.nan); cnt.append(int(m.sum())); continue
        obs.append(y[m].mean()); pred.append(p[m].mean()); cnt.append(int(m.sum()))
    ok = ~np.isnan(obs)
    slope = LinearRegression().fit(np.array(pred)[ok].reshape(-1, 1),
                                   np.array(obs)[ok]).coef_[0]   # 理想 = 1.0
    return {"brier": brier_score_loss(y, p), "calib_slope": slope,
            "bins": list(zip(cnt, pred, obs))}
# 表 11.1 的「Brier／校準斜率」兩欄就是這支的輸出；圖檔命名 M9_<主題>_calibration.png（ref 19 §1.7）
```

**校準曲線怎麼讀**（橫軸＝預測機率分箱均值，縱軸＝該箱實際發生率，45 度線＝完美）：

| 曲線長相 | 意思 | 該做什麼 |
|---|---|---|
| 貼著 45 度線，斜率 ≈ 1 | 已校準 | 可以拿去乘金額算期望值（M11 放行） |
| 整條在對角線**下方** | 系統性**高估** —— 最貴的錯誤 | 必須校準。同時檢查訓練集是否做過重抽樣（§四） |
| 整條在對角線**上方** | 系統性低估 | 校準；名單會比預期好，但預算會編不足 |
| S 形（低機率端偏低、高機率端偏高） | 過度自信 | Platt 通常修得動 |
| 反 S（往中間縮，兩端都被拉回 0.5） | 過度保守，**RF 的典型長相** | Platt 或 Isotonic 都可，比 Brier 決定 |
| 中段反轉、上上下下 | 非單調扭曲 | Platt 修不動，改 Isotonic；若仍不動，特徵或切分有問題，回 §二 |
| 0.6 以上完全沒有點 | 高分區根本沒有樣本 | 高分區機率標 `N/A`，該區**只准用排序不准用機率**，並在圖下標註 |
| 每箱樣本 <30，點在跳 | 校準集太小 | 該箱標 `N/A`（有樣本但算不出可信值，見 `00_通則與紀律.md` §四）；考慮改 Platt |

## 四、類別不平衡

行銷的正類幾乎永遠稀有：轉換率 1%、流失率 3%、詐騙評論 0.1%。教材給的四點應對是：不用 Accuracy 當主指標 → 逐類看 P/R → 用 macro／weighted → 訓練時類別加權或 over/under-sampling（【實測】`02_classification.md` §12.1）。教材對第四點只有一行，**沒有 SMOTE**（digest 的 `material_gaps_confirmed` 明確記載）。

**硬規則：`class_weight` / `scale_pos_weight` 優先於 SMOTE。**

| 手段 | 怎麼做 | 什麼時候用 | 風險 |
|---|---|---|---|
| **類別加權**（首選） | `class_weight="balanced"`；XGBoost/LightGBM 用 `scale_pos_weight = n_neg / n_pos` | 預設就用這個 | 會把預測機率整體推高 → **必接 §三 的校準** |
| **調整決策門檻** | 不動訓練，只在 §八 用 profit curve 找切點 | 只要模型能輸出分數就適用 | 幾乎無風險。**這才是行銷最該用的手段** |
| undersampling | 丟掉多數類 | 資料量大到訓練跑不動時 | 丟掉的是真實資訊（【實測】§12.1 評註） |
| 純複製 oversampling | 複製少數類 | 幾乎不用 | 模型過擬合到被複製的那幾筆 |
| **SMOTE** | 在少數類的 k 近鄰之間線性內插造點 | **低維表格資料不建議** | 見下方 |

> **SMOTE 在低維表格資料上會製造不存在的模式**（【推導，待驗證】，教材無此內容）：假設兩位流失者，A 是 `R=5, F=1`（買過一次就消失的新客），B 是 `R=400, F=30`（老客戶終於停了）。SMOTE 在兩者之間內插，會造出 `R=200, F=15` 這種「合成流失者」—— 但這個組合在真實資料裡**根本不存在**（買了 15 次的老客不會恰好卡在 200 天）。模型學到一條穿過空白區的邊界，交叉驗證分數變好（因為驗證集裡也有合成點，如果你不小心在切分前做了 SMOTE），上線後那個區間根本沒有人。RFM 這種只有 3–5 維、且各維有強烈聯合結構的空間，內插的「中間點」通常不是真實顧客。
>
> 高維稀疏文本（TF-IDF 上萬維）反而沒這麼嚴重，因為維度高到內插點附近本來就沒有真實樣本可比對 —— 但行銷的主戰場是前者。

**任何重抽樣只能在訓練集上做，測試集與校準集保持原始分布**（【實測】§12.1 評註：否則就是 data leakage，評估數字虛高）。

```python
# 正確順序：先切，再在訓練折內重抽樣；用 Pipeline 綁死，避免手滑
# ❌ 錯：SMOTE 之後才 train_test_split —— 合成點會同時出現在兩邊
# ✅ 對：
clf = XGBClassifier(scale_pos_weight=(y_train == 0).sum() / (y_train == 1).sum())

# 若堅持要用重抽樣，必須包進 imblearn Pipeline，讓它只在每個 CV 訓練折內執行
from imblearn.pipeline import Pipeline
from imblearn.over_sampling import SMOTE
pipe = Pipeline([("smote", SMOTE(random_state=42)), ("clf", XGBClassifier())])
# 並且：校準集(X_calib) 與測試集(X_test) 絕不進 SMOTE，正類比例維持母體原值
assert abs(y_test.mean() - y_pop_rate) < 0.005, "測試集分布已被動過，評估無效"
```

## 五、評估指標

★ 這一節照大數據商業分析的 Lift／Gain 走。

**AUC 不夠。** AUC 是全域指標 —— 它問的是「隨機抽一正一負，模型給正類更高分的機率」（【實測】§11.8）。但行銷部門的決策不是全域的，是「這次只發 1 萬封 DM，該發給誰」。AUC 0.82 完全不告訴你前 10% 名單的命中率，而後者才是要花錢的那個數字。

**Lift 與 Gain 的定義：**

$$\text{Lift}_k = \frac{\text{前 } k\% \text{ 名單中的實際回應率}}{\text{母體整體回應率}}, \qquad \text{Gain}_k = \frac{\text{前 } k\% \text{ 名單抓到的回應者數}}{\text{全部回應者數}}$$

**Top decile lift**（$k=10$）是行銷最常引用的單一數字：前 10% 名單的命中率是隨機亂發的幾倍。

**十分位 Lift 表範例**（對應 ref 19 表 11.2；下列為構造的示意數字，【推導，待驗證】。母體 10,000 人，整體回應率 4.0%，共 400 位回應者）：

| 十分位 | 人數 | 回應數 | 該箱回應率 | **Lift** | 累積回應數 | **累積 Gain** |
|---|---:|---:|---:|---:|---:|---:|
| D1（最高分 10%） | 1,000 | 132 | 13.2% | **3.30** | 132 | 33.0% |
| D2 | 1,000 | 88 | 8.8% | 2.20 | 220 | 55.0% |
| D3 | 1,000 | 60 | 6.0% | 1.50 | 280 | 70.0% |
| D4 | 1,000 | 40 | 4.0% | 1.00 | 320 | 80.0% |
| D5 | 1,000 | 28 | 2.8% | 0.70 | 348 | 87.0% |
| D6 | 1,000 | 20 | 2.0% | 0.50 | 368 | 92.0% |
| D7 | 1,000 | 12 | 1.2% | 0.30 | 380 | 95.0% |
| D8 | 1,000 | 8 | 0.8% | 0.20 | 388 | 97.0% |
| D9 | 1,000 | 8 | 0.8% | 0.20 | 396 | 99.0% |
| D10 | 1,000 | 4 | 0.4% | 0.10 | 400 | 100.0% |

這張表一眼可讀的三件事：top decile lift = 3.30（前 10% 命中率是亂發的 3.3 倍）；前 30% 就撈到 70% 的回應者；D4 之後 lift < 1，**發給後 60% 的人比亂發還糟**（因為模型已經明確告訴你他們不會回應）。這三句話都可以直接寫進報告，AUC 一句都寫不出來。

**其他指標的使用規則：**

> **主管最愛問的那句「你的模型準嗎」有一個標準答案**：教材算過，**base rate 1% 的事件，即使模型的敏感度與特異度都做到 99%，陽性預測值也只有 50%**（【實測】`02_classification.md` §8.4）—— 也就是名單上每兩個人有一個是錯的，而這已經是接近完美的模型。行銷的稀有事件本來就是這個結構，**所以要報的是 Lift 不是準確率**：「名單命中率是亂發的 3.3 倍」是真話也是好消息，「準確率 99%」是真話但會讓主管做出錯誤預期。

| 情況 | 主指標 | 理由與出處 |
|---|---|---|
| 正類佔比 < 10% | **PR curve / Average Precision**，ROC 只當輔助 | 【實測】§25.6：ROC 的 FPR 分母含大量 TN，FP 再多 FPR 仍很小 → **AUC 虛高**；PR 完全不用 TN，忠實反映名單品質。PR 的隨機基準線是水平線 $y=$ 正類佔比 |
| 類別不平衡 | **禁用 Accuracy 當主指標** | 【實測】§11.7：A 類 800、B 類 200，全猜 A 得 Accuracy 80%，但**對 B 類的 Precision／Recall／F1 全部是 0%**（多數類陷阱） |
| 多類別（客訴分派、商品歸類） | **同時報 macro 與 micro，並看差距** | 【實測】§12.4/§12.6：教材例 macro 66.67% vs micro 76%，**差 9.3 個百分點就是小類失效的診斷訊號**。單標籤多類別下 micro-F1 = Accuracy |
| 每次動作有成本（電話、實體 DM、贈品、折扣碼） | 主看 **Precision** | 【實測】§11.3、§25.2：FP = 白花錢 + 侵蝕毛利 |
| 漏掉的代價高、動作近乎免費（App push、EDM、站內推薦） | 主看 **Recall** | 【實測】§11.4、§25.2：漏掉一位即將流失的高價值客 = 損失整個 LTV |
| 在比模型（選演算法／選特徵組） | AUC（正類 <10% 改 AP） | 【實測】§11.8：不受閾值影響，適合比較 |
| 在定門檻（發幾封） | **不用統計指標，用 §八 的 profit curve** | 行銷的真正約束是預算能接觸幾人，不是某個統計指標 |

```
評估指標的決策順序（行銷版，改寫自 02_classification.md §25.7）
Step 1  正類佔比？
        ├─ ≥10% ──► ROC/AUC 可當主指標，仍須附逐類 P/R
        └─ <10% ──► 主看 PR/AP；AUC 只當模型間比較的輔助
Step 2  這次要交的是「名單」還是「分類結果」？
        ├─ 名單（發 DM、打電話、推播）──► **Lift / Gain 是主指標**，AUC 是配角
        └─ 分類結果（自動歸類、自動分派）──► 逐類 P/R/F1 + macro & micro 並報
Step 3  FP 與 FN 哪個貴？
        ├─ FP 貴 ──► Precision（且門檻由 profit curve 決定，不是 0.5）
        ├─ FN 貴 ──► Recall
        └─ 相當 ──► F1
Step 4  要拿去乘金額算期望值嗎？
        ├─ 要 ──► **先過 §三 的校準，沒校準不准算**
        └─ 不要（只排序）──► 校準可省，但報告要寫明「本模型輸出僅供排序」
Step 5  上線後 ──► §十 的監控
```

## 六、SHAP 而非 tree importance

★ 硬規則：**報告用 SHAP，不用 tree importance 條形圖**（ref 19 §1.7 已把 SHAP summary 列為八張圖之一，並註明「取代單一 importance 條形圖」）。

理由有兩層。第一層是偏誤：**tree importance 對高基數特徵有偏**。教材講的是 ID3 的 Information Gain 版本 —— IG「偏好選擇取值多的特徵」，因為用顧客 ID 分裂會產生很多子集合、每個子集合純度 100%、IG 最高，但「顧客 ID 對新顧客完全沒有預測力」（【實測】§15.10）。RF／GBDT 的 `feature_importances_`（gain 或 split count）繼承同一個結構性偏誤：一個有 200 個水準的 `來源活動代碼` 會得到比二元的 `是否曾退貨` 更多的分裂機會，因此累積更多 gain —— **即使後者才是真正的訊號**。

第二層是可用性：**SHAP 能給單一顧客層級的解釋，可以直接寫進行銷話術。**

| 方法 | 給什麼 | 對高基數的偏誤 | 個體層級解釋 | 建議用途 |
|---|---|---|---|---|
| tree importance（gain／split） | 全域排序 | **有偏，會偏愛 ID 類與高基數類別欄** | 無 | 只當開發期的快速掃描，**不進報告** |
| permutation importance | 全域排序，直接對應「打亂它模型掉多少」 | 偏誤較小，但**共線特徵會互相掩護**（兩個高度相關的特徵各自打亂都不掉分） | 無 | 當 SHAP 的對照，兩者排序差很多時要查共線 |
| **SHAP** | 全域（beeswarm）＋ **每位顧客每個特徵的貢獻值** | 較小；仍受特徵相關性影響（TreeSHAP 的路徑相依） | **有** | **報告主力** |

```python
# scripts/explain_model.py
import shap
explainer  = shap.TreeExplainer(model)
sv         = explainer(X_test)                 # (n_samples, n_features)

shap.plots.beeswarm(sv, max_display=15)        # → M9_<主題>_shap_summary.png
for f in top_features[:5]:
    shap.plots.scatter(sv[:, f], color=sv)     # → M9_<主題>_shap_dep.png（標交互著色變數）

# 個體解釋 → 直接生成行銷話術的素材（這是 SHAP 相對 importance 的真正價值）
import pandas as pd
row = 0
contrib = (pd.Series(sv.values[row], index=X_test.columns)
             .sort_values(key=abs, ascending=False).head(3))
# 例：cust_id=A0871，流失機率 0.68
#   R_days_since_last_sale = 96      → +0.21
#   cai                    = -18.4   → +0.14   （購買節奏在變慢，見 17 §4.2）
#   主力品類_烘焙_金額佔比  = 0.62    → -0.05
# 話術：「這位顧客三個月沒回、且回購節奏連續三期在拉長，但仍集中在烘焙品類
#        → 用烘焙品類的限期券喚回，不要發全店通用券。」
```

**兩條警語，寫成可檢查的形式：**

| 警語 | 錯誤的寫法 | 正確的寫法 | 依據 |
|---|---|---|---|
| **SHAP 值不是因果效果** | 「R 驅動流失，把 R 降下來就能降低流失」 | 「在本模型中，R=96 天使這位顧客的流失分數上升 0.21」 | `00_通則與紀律.md` §1.5 措辭白名單（預測級禁用任何 intervention 語句）；18-G6 |
| **單一特徵獨大 = 先懷疑洩漏** | 直接寫進報告：「最重要的特徵是 X」 | 兩件事都查：① `m_try` 是不是設太大（太大時所有樹都選同一強特徵）② 那個變數是不是洩漏（教材原例：用「已成交金額」預測「是否成交」）。查完沒問題才寫 | 【實測】`02_classification.md` §28.3 診斷順序；18-G4 |

## 七、建模前的欄位掃描

這一步在切分之前做，五分鐘，抵掉整個專案最常見的返工。

**高基數 ID 欄位必須排除。** 教材的原話是：用「顧客 ID」分裂會讓每個子集合都只含一個類別 → 高純度 → 高 IG，「但『顧客 ID』對新顧客完全沒有預測力」（【實測】§15.10）。digest 給的實務規則：「建模前先掃描每個欄位的 unique 值數量，接近樣本數的欄位一律先排除」（同節）。

**排除清單（四類，觸發即踢或改造）：**

| 類型 | 例 | 判定 | 處理 |
|---|---|---|---|
| **高基數 ID** | 會員編號、訂單號、交易序號、Email、手機、卡號、門市代碼 | `nunique / n_rows > 0.5`，或欄名符合 `(id|no|code|mail|phone|uuid)$` | **直接排除**。門市／通路這種「高基數但有語意」的，改為聚合特徵（該門市歷史回應率，且**必須用 as_of 之前的資料算**） |
| **標籤衍生／事後欄位** | `是否已喚回`、`本期回購金額`、`退貨次數`（若退貨發生在標籤窗內）、`最後一次登入`（若晚於 as_of） | 欄位的更新時間戳晚於 `as_of`，或語意上「只有在結果發生後才會有值」 | **直接排除**。這是 18-G4 最常見的長相 |
| **常數與近常數** | 全表同值、或最大類別佔比 >99% | `top1_share > 0.99` | 排除（不帶資訊，但會拖慢訓練並污染 SHAP 排序） |
| **覆蓋率過低** | CAI（需 ≥3 次購買）、CRI（需分群層） | 有值的顧客佔比 < **30%** | 【實測】`00_通則與紀律.md` §五：低於門檻不准進報告，或必須在圖表下標覆蓋率。素材案例：某汽車專案 CAI 覆蓋率只有 3.0%，交出 18 人名單，被理解成「全庫只有 18 人有流失風險」，2,329 位（97%）沒被納入喚回設計（出處：`research/gap-business-translation.md` BT-07） |

> `nunique / n_rows > 0.5` 這個門檻為【推導，待驗證】—— 教材只說「接近樣本數」。行銷資料的實際狀況：真實類別欄位（縣市 22、品類 16、通路 8）的比值都在 0.01 以下，ID 類則接近 1.0，中間是一大片空白，門檻放在 0.5 或 0.3 結果一樣。**但要跑一次敏感度並記錄**（`00_通則與紀律.md` §1.4）。

**一個容易混淆的點**：18-E2 規定**分群（M6）的輸入變數白名單裡不准有人口統計變數**，理由是行為分群的定義才穩定。**這條不適用於 M9。** 預測模型可以用年齡、性別、地區當特徵（它們對預測有貢獻就用），只是**不能拿模型輸出回頭當分群依據**，也不能把「女性流失機率較高」寫成因果。兩個模組的規則不同，不要互相套用。

```python
# scripts/scan_columns.py —— 建模前必跑，輸出直接進表 11.4
import re, pandas as pd
ID_PAT = re.compile(r"(_id|_no|_code|mail|phone|uuid)$", re.I)

def scan(df, as_of, label_cols, n_min_coverage=0.30):
    rows = []
    for c in df.columns:
        if c in label_cols:
            continue
        nu, n = df[c].nunique(dropna=True), len(df)
        cov   = df[c].notna().mean()
        top1  = df[c].value_counts(normalize=True).iloc[0] if nu else float("nan")
        flags = []
        if nu / n > 0.5 or ID_PAT.search(c): flags.append("高基數ID→排除")
        if top1 > 0.99:                      flags.append("近常數→排除")
        if cov < n_min_coverage:             flags.append(f"覆蓋率{cov:.1%}<30%→標註或排除")
        rows.append({"欄位": c, "unique": nu, "unique_ratio": round(nu / n, 4),
                     "覆蓋率": round(cov, 4), "as_of": as_of,
                     "判定": "；".join(flags) or "保留"})
    return pd.DataFrame(rows)
# 人工複核「事後欄位」那一類 —— 機器判不出語意，必須逐欄問「這個值在 as_of 當天真的存在嗎？」
```

## 八、profit curve 與最佳切點

★ 這一節是 M9 交給 M11 的成果，也是唯一一個**必須有人類簽字**的步驟。

模型輸出 → 十分位 Lift 表 → profit curve → 最佳切點。公式：

$$\text{Profit}(k) = \underbrace{N_k \cdot r_k \cdot m}_{\text{毛利}} - \underbrace{N_k \cdot c}_{\text{接觸成本}}, \qquad \text{損益兩平反應率} = \frac{c}{m}$$

其中 $N_k$＝發給前 $k$ 分位的人數、$r_k$＝該區間的累積回應率、$m$＝每個回應的毛利、$c$＝每人接觸成本。

**邊際規則：往下多發一個十分位，只要「該十分位的回應率 > 損益兩平反應率」就繼續發，一旦低於就停在前一格。**

沿用 §五 的示意數字（$m=600$ 元、$c=25$ 元 → 損益兩平反應率 $=25/600=4.17\%$）：

| 切點 | 發送人數 | 累積回應數 | 毛利 | 成本 | **淨利** | 該十分位回應率 vs 4.17% |
|---|---:|---:|---:|---:|---:|---|
| 前 10% | 1,000 | 132 | 79,200 | 25,000 | 54,200 | 13.2% ✅ |
| 前 20% | 2,000 | 220 | 132,000 | 50,000 | 82,000 | 8.8% ✅ |
| **前 30%** | 3,000 | 280 | 168,000 | 75,000 | **93,000 ← 最佳** | 6.0% ✅ |
| 前 40% | 4,000 | 320 | 192,000 | 100,000 | 92,000 | 4.0% ❌（<4.17%，停） |
| 前 50% | 5,000 | 348 | 208,800 | 125,000 | 83,800 | 2.8% ❌ |
| 全發 | 10,000 | 400 | 240,000 | 250,000 | **−10,000** | — |

三個要寫進報告的結論：最佳切點是**前 30%（3,000 人）不是前 10%**（只發 D1 少賺 38,800）；**全發會虧 1 萬**；D4 的邊際淨利已經是負的（92,000 − 93,000 = −1,000），與「該十分位回應率 4.0% < 損益兩平 4.17%」互相對上 —— **這是一組免費的雙路徑交叉驗算**（`00_通則與紀律.md` §1.3），兩邊對不上就是算錯了。

**這一步在模擬階段做，而且必須與現場／有經驗的人確認結果是否與經驗一致。** 現場的人腦子裡有一份沒寫下來的先驗：他們知道去年同樣的券發了多少、大概回收多少、哪一區的店長會擋。模型算出「前 30%」而業務說「我們一向只發前 5%」，這個落差不是誰對誰錯的問題，是**兩個假說**。

```
profit curve 結果 vs 現場經驗
   │
   ├─ 一致 ──► 照結果做，並把現場的確認寫進 _log（誰、什麼時候、確認了什麼）
   │
   └─ 不一致 ──► ① 先查是不是資料品質造成的假象（照下表逐項查）
                 │
                 ├─ 查到問題 ──► 修完重跑 profit curve，回到上一格重新確認
                 │
                 └─ 查完沒問題 ──► ② **記錄分歧，兩個假說並存**
                                    ③ 兩者都寫進 M11 的提案（模型版 / 經驗版各自的預期損益）
                                    ④ 交給 M12 設計實驗去裁決
                                       └─ **分歧本身就是最有價值的實驗題目**
```

**「先查資料品質」要查什麼**（不要含糊地說「檢查一下資料」）：

| 懷疑 | 具體查法 | 會怎麼造成假象 |
|---|---|---|
| 回應定義不對 | `dim_metric_definition` 裡的「回應」是點擊、開信、還是實際下單？時間窗多長？ | 用開信當回應會讓回應率虛高 5–10 倍，profit curve 整條上移 |
| 毛利 $m$ 用錯口徑 | 用營業額還是毛利？有沒有扣券的成本、退貨、金流手續費？ | 用營業額當 $m$ 會讓損益兩平反應率被低估數倍，切點被推得太深 |
| 成本 $c$ 漏項 | 只算簡訊費 0.8 元，漏掉折抵金額、印製、物流、客服工時 | 同上，且方向一致 —— 兩個錯都讓「多發」看起來划算 |
| 歷史回應率被污染 | 過去的名單是不是本來就只發給高價值客？ | 訓練標籤帶著舊策略的選擇性，模型只是在複製舊規則（**這常常正是現場經驗的來源，所以兩邊會一致地錯**） |
| 退貨未扣 | 18-G2：買 50 萬退 48 萬的人被算成高價值 | 高分箱的毛利虛胖 |
| 覆蓋率 | §七 的 30% 門檻 | 名單只涵蓋一小群人，現場看到的是「怎麼都是同一批熟客」 |

## 九、模型跑不出來的降級

沿用 `00_通則與紀律.md` §1.6 的通用降級模式：**沒跑出來不是理由，沒有備案才是。** M9 的特殊之處在於，「跑得出來但沒有用」比「跑不出來」更常見，而且更難承認。

**硬門檻：候選模型相對 naive baseline 的提升 < 0.03 AUC 時，強制寫「不建議上線，用 baseline 排序即可」**（【實測】`research/gap-statistical-inference.md` S9 修補動作 3；同一條也寫在 `00_通則與紀律.md` §1.5 的證據等級決策樹裡）。表 11.1 必須至少三列：

| 模型 | in-sample | **out-of-time** | 相對 baseline |
|---|---|---|---|
| naive baseline（單一 R 排序） | | | — |
| naive baseline（RFM Score 排序） | | | — |
| 候選模型 | | | |

**表現不比 baseline 好的時候，老實說「這批特徵預測不了這個目標」，並列出可能原因：**

| 可能原因 | 怎麼判斷 | 下一步 |
|---|---|---|
| 訊號太弱 | 所有模型、所有特徵組的 out-of-time AUC 都在 0.55–0.60 徘徊 | 停。報告寫「本批特徵對此目標無預測力」，並列出**缺哪一域的資料**才可能有訊號（六域缺口見 M1） |
| 目標定義不對 | 標籤與某個特徵幾乎是同一件事的兩個切法（例：「未來 6 個月是否再購買」對低頻顧客 ≈ R） | 重新定義標籤（換 horizon、換事件），回 M0 與包子確認 |
| 觀察期太短 | 資料期間 < 2 個購買週期；$n_i \le 2$ 的顧客佔多數，$\lambda$ 不可估 | 降級為 §五 的排序交付（只給名單順序、不給機率），或列入 M12 的資料需求 |
| 標籤太稀有 | 正類 < 200 筆 | 不建模。改用業務規則 + 敘述統計，並說明需要多少筆才值得建模 |
| 切分本來就有洩漏（反向） | in-sample 極高、out-of-time 崩掉 | 回 §二 與 §七，這不是模型問題 |

**不要調參調到過擬合。** 具體規則：

```
超參數搜尋的紀律
  1. 搜尋範圍與次數**事前寫進 params.yml**（含 reason／source／sensitivity 四欄，見 00 §1.4）
  2. 搜尋只在 **CV 的訓練折內**進行，測試集在整個搜尋過程中不可被讀取一次
  3. 上限：隨機搜尋 ≤ 50 組（樹模型的效果曲線在 30 組後幾乎持平）—— 此數為【推導，待驗證】
  4. 若「換一組超參數 AUC 就跳動 >0.02」，代表樣本量不足以支撐調參，**停止調參**，
     退回預設參數並在報告寫明「本模型未調參，理由：驗證分數對超參數不穩定」
  5. 禁止動作：反覆看測試集分數再回頭改特徵或參數（這叫用測試集訓練，
     做過幾輪之後 out-of-time 就不再是 out-of-time）
  6. 每一次降級都寫進 _log/degradation_log.md，七欄照 00 §1.6 的格式
```

## 十、Concept drift 與監控

模型不是訓練完就一勞永逸（【實測】`02_classification.md` §21）。**行銷環境的漂移速度遠高於一般領域** —— 教材自己給的例子就是行銷例：「聖誕節前『50% off!』是正常行銷郵件，平時是垃圾郵件」。

教材給的四點應對：持續監控新鮮資料的 P/R → **設定告警閾值（準確率跌 5% 以上）** → 定期重訓（如每月）→ 資料洗淨（移除過時特徵、新增新興特徵）（【實測】§21）。

**行銷特有的漂移來源**（每一條都要在監控時對得上一個可查的事件）：

| 來源 | 徵狀 | 對策 |
|---|---|---|
| 季節與檔期 | 每年同期分數規律性下滑 | 特徵加 `month` / `week_of_year`；重訓時確保訓練窗涵蓋完整週期 |
| 公司政策改變 | 分數在某個日期斷崖式改變 | 例：免運門檻從 599 拉到 899（`gap-business-translation.md` 的案例）。政策上線日必須進 `dim_event`，重訓前先切齊 |
| 產品／品類改版 | 某些特徵突然大量 `—`（無樣本） | 商品下架、品類重編。重訓前清掉過期特徵 |
| 外部事件 | 全體特徵分布同時位移 | 疫情、競品大促、平台演算法改版 |
| 量測變更 | 某天起某欄位口徑不同 | 18-G10：口徑進 `dim_metric_definition`；橫跨量測變更日的時間窗要切開（`00_通則與紀律.md` §1.4） |
| **標籤反饋迴路** | 模型上線後，被模型挑中的人才收到 DM → 下一輪的訓練標籤只反映舊模型的選擇 | 保留 **5–10% 的隨機對照名單不受模型影響**（此比例為【推導，待驗證】），當作下一輪的乾淨訓練資料。這同時也是 M12 的地基 |

```python
# scripts/model_monitor.py —— 對應 18-G15，輸出寫進 07_report/預測追蹤.md
MONITOR = {
    "頻率":     "每月（與重訓同週期）；檔期前後加跑一次",
    "監控對象": ["precision@門檻", "recall@門檻", "top_decile_lift",
                 "calib_slope", "brier", "正類實際發生率", "各特徵的 PSI"],
    "告警規則": [

    "留痕":     "每次重訓在 _log/ 留下：訓練窗、樣本數、out-of-time 分數、與前一版的名單重疊率",
```
