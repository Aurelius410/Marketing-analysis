# 交付物產製

分析做完不等於交付完成。這份文件管的是**最後一哩：把同一批計算結果，變成四種給不同人看的東西**。它的存在理由很現實 —— IB5082 的評分標準逐字寫著「主體內容與整體文書排版**各占 50% 與 50%**」（`local/大數據行銷IB5082/04_期末報告樣本與報告文體.md` §1.1，【實測，逐字全文】）。也就是說，分析全對但交付物做壞，最高只能拿一半的分。真實職場更狠：主管不會給你 50 分，他會直接不採用。

漏掉這份規格的代價分三種，都有實證。**看不到**：32 頁完整報告直接寄給行銷總監，他翻到第 3 頁就停，你在第 19 頁寫的「建議 C 損益兩平需 9.1% 兌換率、歷史上限 8%，打不平」他沒看到，下一季預算照樣編了 C。**用不了**：Excel 名單把 `48.6%` 存成字串，行銷專員想樞紐分析重算加權平均只能重打一次，打成 `4.86%`，名單規模估錯 10 倍。**打不開**：Altair 圖忘了 `inline=True`，收件人在公司防火牆後面開啟，整份報告的圖全是空白框（`research/03_dashboard_and_delivery.md` §11.3，【材料原文，Altair 官方文件】）。三種失敗都不會報錯，全部在對方手上才爆。

本文與既有規格的邊界：**19 管「圖表與表格長什麼樣」，本文管「它們怎麼被包成交付物送出去」**；**18 管「錯了會怎樣」，本文遇到具體坑一律寫「見 18-Exx」不重抄**；**00 管「姿勢」，本文的每個 gate 都是 00 §1.6 降級紀律與 §四 空值紀律的下游執行點**。空值符號沿用 00 §四的權威定義（`N/A` 有樣本算不出來／`-` 無樣本／`n.s.` 不顯著且必附 MDE／`0` 真的是零），本文不自創。

## 一、四種交付物：依聽眾分層，不依格式分層

**這是本文的第一條硬規則，也是最容易做錯的一條。** 直覺會想「一份報告，導出成 PDF、PPT、Excel 三種格式」—— 那是**依格式分層**，結果是三份內容一樣、深淺一樣、都不好用的東西。正確作法是先問「誰要拿它做什麼決策」，四種聽眾要的深度差三個數量級。

| 聽眾 | 他要做的決策 | 交付物 | 形式 | 規模 | 通路 | 完成判準 |
|---|---|---|---|---|---|---|
| **決策者**（行銷總監／總經理） | 要不要批這筆預算 | **決策摘要** | 單頁 HTML（A4 可列印） | **1 頁** | email 內文 + 附件 | 三條建議各附 sizing、損益兩平反應率、證據等級 |
| **行銷執行**（企劃／CRM 專員） | 這週推播給誰、推什麼 | **名單檔 + 活動規格** | `.xlsx` 多工作表（+ `.csv` utf-8-sig） | 名單不限列數，規格 1 頁 | 檔案傳輸／共享碟 | 名單能直接匯進 CRM，欄位對得上、數值是數值型別 |
| **分析同儕／稽核／助教** | 這個結論站不站得住、能不能複現 | **完整報告** | 單檔 HTML（可列印） | **25–35 頁**【實測門檻，見下】 | 附件 | 11 章 gate 全綠、每個數字可追回結果物件 |
| **自己探索** | 下一個假說是什麼 | **儀表板** | L1／L2／L3（見 §五） | 依層級 | 依層級 | 能回答「還有哪些切法我沒看過」 |

**篇幅門檻的出處**（全部【實測】，`04_期末報告樣本與報告文體.md` §9.1 與 §2.1）：目標 25–35 頁、<20 頁警告、<15 頁不得輸出。實證是 **5 份 <10 頁的報告全部拿不到 A+**；另有 3 份被評語點名「報告完整但篇幅精簡（約 8／9／11 頁），各節內容較簡略」全部降到 A-。決策摘要的「1 頁」則是包子確認的規格，不是引用值【設計決定】。

**分層的判斷**：

```
這份東西要送到誰手上？                          判準
├─ 要簽預算的人 ────► 決策摘要 1 頁（§四）      能不能當場說「批」或「不批」
├─ 明天要執行的人 ──► 名單 .xlsx + 規格（§七）  不用回頭問任何一個欄位是什麼意思
├─ 要挑戰你方法的人 ► 完整報告 25–35 頁（§三）  能重跑出同一組數字（§十）
└─ 你自己 ──────────► 儀表板（§五）             能生出下一輪假說

★ 兩種以上聽眾 → 產兩份，不要產折衷版。
  折衷版的失敗模式很固定：對決策者太長、對稽核太淺，兩邊都不採用。
```

## 二、單一來源原則（★ 全文最重要的一節）

四種交付物**必須從同一份計算結果物件產生**。這不是整潔問題，是 18-E7 的直接預防 —— 那個「圖例標女 75.20%、內文寫女性佔 24.8%」的實證案例，根源就是圖和文字有兩個數字來源。SKILL.md 的負面清單也明列「內文數字用手打」為禁止項。

### 2.1 兩個唯一入口

| 東西 | 唯一入口 | 規格在哪 | 違反的徵狀 |
|---|---|---|---|
| **所有圖** | `build_chart(df, ...) -> alt.Chart` 純函式 | **19 §7.2**（七條硬規則，本文不重抄） | 報告的圖和儀表板的圖顏色不一樣 |
| **所有數字** | `Result` 結果物件，鍵值取用 | 本節 2.2 | 改了口徑之後，摘要還是舊數字 |

`build_chart()` 的四種下游呼叫方式（引自 19 §7.2，此處只列對照，細節回去看）：

```python
build_chart(df, ...).save(out, inline=True)                        # 1 報告／決策摘要（單檔 HTML）
png = vlc.vegalite_to_png(build_chart(df, ...).to_dict(), scale=2) # 2 投影片（先跑 check_fonts.py）
mo.ui.altair_chart(build_chart(df, ...))                           # 3 儀表板 L2／L3
# 4 圖表/ 實作：同 2 的 PNG，分析當下就存；報告階段只 copy 不重畫（19 §6.2、03 §1.3）
```

### 2.2 `Result`：數字的單一來源

```python
# scripts/result_bundle.py —— 所有交付物取數字的唯一介面
@dataclass(frozen=True)
class Result:
    value: float | int | str
    fmt: str        # 格式代號，對應 19 §5.3（"pct2" / "money" / "corr4" / "pval" …）
    source: str     # 產出它的腳本 + 結果檔路徑，用來回答「這數字哪來的」
    as_of: str      # 特徵基準日（見 18-G4）
    evidence: str   # 相關 / 預測 / 準實驗 / 實驗（判定樹見 00 §1.5）
    n: int | None = None   # 樣本數；None 代表不適用（不是 0）

class Bundle(dict):                        # 鍵是 metric_id，如 'rfm.champions.share'
    def fmt(self, key: str) -> str:        # 唯一允許把數字變成字串的地方
        return FORMATTERS[self[key].fmt](self[key].value)   # KeyError = 你手打了

# 模板裡只准：  共 {{ R.fmt("cluster.c2.n") }} 人，占營收 {{ R.fmt("cluster.c2.rev_share") }}
# 絕對不准：    共 1,240 人，占營收 48.6%          ← 18-E7 的溫床
```

**空值走 00 §四的符號**：`FORMATTERS` 遇到 `value is None` 且 `n == 0` 輸出 `-`（無樣本）；`value is None` 且 `n > 0` 輸出 `N/A`（有樣本算不出來，且 `degradation_log.md` 必有對應紀錄）。**永遠不輸出空字串** —— 空白格有「沒算」與「算出來是零」兩種讀法，會導向完全不同的行動。

### 2.3 一個具體的錯誤行動

M8-1 算完 RFM，報告第 6 章寫「Champions 20 人、營收占比 48.6%」。兩週後補載了兩天遲到的 POS 資料重跑，結果物件變成 19 人、47.2%，報告 HTML 也重生成了 —— **但決策摘要和投影片是上一輪手打的，還停在 20 人 48.6%**。會議上主管同時看到兩份，問哪個對，你答不出來。此後這套系統產出的每個數字都要被重新質疑。這正是 03 §6.3 記錄的 D20 情境（【實測，`gap-data-engineering.md` D20】），解法是本節 + §十的版本三件套，兩者缺一不可。

```python
# verify_outputs.py 的對應檢查（完整清單見 §九）
"交付檔中每個數字 token 都能在 Bundle 中找到對應鍵"        # 18-E7
"同一個 metric_id 在四種交付物中格式化後的字串完全一致"
"Bundle 中每個 Result 的 evidence 欄非空且在四級白名單內"   # 00 §1.5
```


**體積預算**：base64 的膨脹率是 4/3 ≈ **+33.3%**（編碼定義，可直接算，非引用值），故單檔 ≈ 圖檔總 bytes × 1.34 + Vega runtime + 本體。Vega inline runtime 的實際體積**本機未實測【待補】**，只知道對照組 plotly.js 約 3 MB【實測】。上限訂 **10 MB**【設計決定，非引用值；企業信箱附件上限多落在 10–25 MB 帶，確切值依收件方而定，交付前要問】。超過的處置順序：① 互動圖降 PNG ② 明細表改前 20 列 + 附 CSV ③ 拆附件 —— **不要壓縮圖質**。

```python
# scripts/build_report.py 的實作 gate

assert out.stat().st_size < SIZE_LIMIT_MB * 1024**2, (
```

## 四、決策摘要 1 頁：產製規格

**內容結構不在這裡定，在 14 §六**（報告定位宣告 → 三欄表 → Key Insights 4 條 → 建議優先序表，四塊順序不可換）。本節只管**怎麼把那四塊塞進一頁並送出去** —— 兩份文件的分工線是：14 決定寫什麼，20 決定怎麼排、怎麼渲染、什麼情況不准出。

先釐清一個常見誤用：**決策摘要不是完整報告的「摘要章」**。摘要章是給分析同儕的（寫方法與範圍），決策摘要是給要簽預算的人的（寫要他決定什麼）。兩者讀者不同，不能共用一段文字。

| 版位（A4 直式，由上而下） | 對應 14 §六 | 產製硬規則 |
|---|---|---|
| ① 標題列：專案名、資料期間、`as_of_date` | — | 期間中文全寫（19 §5.3）：`2026 年 1 月 1 日至 6 月 30 日` |
| ② 報告定位宣告（一格小表） | （1） | 讀者要寫**具名職位**，不是「管理者」 |
| ③ 三個 KPI 卡 | 三欄表的濃縮 | 主數字 30pt（19 §3.1）；變化必附 `+`/`−` 符號與顏色（19 C-05，deutan 下紅綠 ΔE 僅 10.3【實測】） |
| ④ 一張圖 | — | **只放一張**，標題是結論句；從 `圖表/報告用/` 複製，禁重畫（19 §6.2） |
| ⑤ Key Insights 4 條 | （3） | 每條「數字 + 所以呢」，一行一條 |
| ⑥ 建議優先序表 | （4） | **「不做」那幾列要留在表裡**，不准移到附錄消失 |
| ⑦ 頁尾 | — | 版本三件套（§十），9.5pt |

**排不下時的處置順序**（不准用縮字級硬塞）：① 併掉三欄表，只留 KPI 卡 ② 圖改成 sparkline 進 KPI 卡 ③ Key Insights 減到 3 條 —— **絕不砍建議優先序表的任何一列**，那是這頁存在的理由。

```
templates/exec_onepager.html.j2   ← 唯一的決策摘要範本（14 §六已指定此檔名，勿另建）

禁止出現在這一頁（給決策者的版本）：
  p 值 / VIF / RMSEA / Deviance / FDR / 任何統計軟體輸出   （14 §六）
```

## 五、儀表板三層（★ 交付形式決定層級）

選型已定案，不翻案。出處：`research/03_dashboard_and_delivery.md` §7、§10、§11.1（GitHub API 與 PyPI 於 2026-07-26 實測、marimo CLI 原始碼實查）。

**第一個問題不是「哪個框架好」，是「這份東西怎麼送到對方手上」**（規則 D9）。

| 層 | 技術 | 產出形態 | 互動能力 | 交付方式 | 什麼時候用 |
|---|---|---|---|---|---|
| **L1 預設** | Altair `selection` + `transform_filter` + Jinja2 | **真正的單一 `.html`**（必須 `inline=True`） | 圖內篩選、跨圖聯動、hover、legend 篩選；資料已內嵌，無 Python | ✅ **email 附件，雙擊開啟** | **多數下鑽需求這層就夠**。零新框架、可直接嵌進報告 |
| **L2 需要時** | `marimo export html-wasm` | 一個**目錄**：`.html` + `assets/`（+ `public/` 放 Parquet） | 完整 Python + DuckDB 跑在瀏覽器，可重跑 SQL、任意下鑽 | 🟡 **需靜態 host 給 URL**。⚠️ **不能雙擊開啟** | 要在瀏覽器端重跑 SQL／使用者上傳自己的資料／要跑 Python 計算 |
| **L3 少數** | `marimo run app.py` | 長駐 Python process | 完整能力 + 即時資料源 | ❌ 需自架服務 | 資料 >200 MB【估計值，素材明載未實測】／資料機密不可外流／要連即時資料源 |

### 5.1 L2 的那個坑（v1 調研自己踩過，必須明講）

marimo 原始碼中 `html-wasm` 的 help 字串【材料原文】：

> "In order for this file to be able to run, it must be served over HTTP, and cannot be opened directly from the file system (e.g. `file://`)."

也就是說 **L1 → L2 的真正跨越點不是「靜態 vs 動態」，是「附件 vs URL」**。L2 仍是靜態託管（不跑後端 Python），但收件人必須連得到一個網址。寄 zip 請對方跑 `python -m http.server` 對非技術收件人不可行。交付 L3 時要**明確告知「這份不能寄」**。

### 5.2 升級決策樹

```
需求是什麼？
├─ 圖表內篩選 / 跨圖聯動 / hover 看細節
│    └─► L1。不要開新框架。★ 一定要 chart.save(..., inline=True)
│          漏了 → 預設走 CDN → 收件人斷網或防火牆擋 CDN → 圖全空白
├─ 任一成立：瀏覽器端重跑 SQL（維度事前未知）／使用者上傳資料／要跑 Python
│    └─► L2。先回答：對方能不能收 URL？
│          不能 ► 退回 L1，把「常用的 5 種切法」預先做成 selection
│          能   ► GitHub Pages / Cloudflare Pages（皆免費）
└─ 任一成立：資料 >200 MB／機密不外流／即時資料源
     └─► L3。明確告知「這份不能寄，只能自己看或架內網」
```

### 7.2 數值型別：這一條錯了整份檔案就廢了

```python
# XlsxWriter 負責寫（格式碼最完整）、openpyxl 負責讀改
# 格式碼出處：04_design_system.md §4.4【本機實測 XlsxWriter 3.2.9 / openpyxl 3.1.5】
NUMFMT = {"int": '#,##0', "money": '#,##0;[Red]-#,##0', "ratio2": '0.00',
          "pct1": '0.0%;[Red]-0.0%', "pct_delta": '+0.0%;-0.0%;0.0%',  # 正號強制（19 C-05）
          "coef3": '0.000', "pval": '[<0.001]"<0.001";0.000', "date": 'yyyy-mm-dd',
          "missing": '#,##0;-#,##0;"-";@'}   # 無樣本落到 "-"，符號口徑見 00 §四

ws.write_number(r, c, 0.486, wb.add_format({"num_format": NUMFMT["pct1"]}))  # ✅ 存 0.486
ws.write_string(r, c, "48.6%")                                              # ❌ 從此無法計算
ws.freeze_panes("A2")   # 凍結表頭（04_design_system §4.3）
ws.repeat_rows(0)       # 列印每頁重標表頭（對應 18-E14）
```

**具體錯誤行動**：把 `48.6%` 存成字串，行銷專員要按通路重算加權平均只能重打，打成 `4.86%`，名單規模估錯 10 倍 —— 簡訊發了 96 人而不是 967 人，活動當週回報「兌換率 0%」，結論變成「這個名單沒用」。**分析沒錯，交付格式錯，結論被推翻。**

**CSV 一律 `utf-8-sig`**（帶 BOM，讓 Excel 雙擊開不亂碼）。這是 03 §1.4 已定的慣例（統計表 csv 存 utf-8-sig），名單檔沿用 —— 純 `utf-8` 在繁體中文 Windows 上會被 Excel 當成 CP950 解析。

| 情境 | 編碼 | 為什麼 |
|---|---|---|
| 交給人用 Excel 雙擊開的 CSV | **`utf-8-sig`** | 無 BOM 會被當 CP950，中文全亂 |
| 程式間交換（DuckDB 讀回、pipeline 中繼） | `utf-8` 或直接用 Parquet | BOM 會變成第一個欄名的一部分 |
| 讀進來的台灣舊系統匯出檔 | 先 `INSTALL encodings; LOAD encodings;` | 18-T9（Big5/CP950 亂碼） |

## 八、字型：交付時序上的三個關卡

字型規格本身在 19 §3（字級階梯、法務判斷流程、可變字型與 `tnum` 的實測限制），**本節不重抄**，只寫交付流程上什麼時候該卡住。三條渲染路徑的機制不同，處置也不同。

| 路徑 | 字型從哪來 | 失敗長什麼樣 | 卡在哪一步 |
|---|---|---|---|
| **HTML 互動圖／報告** | **收件人的機器** | 靜默 fallback → 行高變、標籤重疊、版面跑掉 | `build_report.py` 渲染前：對外一律 `@font-face` 內嵌 Noto Sans TC subset |
| **PNG → pptx** | **產圖的機器（我們自己）** | **豆腐字 □□□，靜默失敗** —— 圖產出來了、檔案大小正常、無 warning | `check_fonts.py` 退出碼非 0 就**不准產圖**；產完抽驗一張肉眼看 |
| **marimo 介面** | 收件人的機器 | 同 HTML | 只設官方保證跨版本穩定的三個 CSS 變數（19 §3.3） |

vl-convert 官方原文【材料原文】：「SVG text placement and PNG text rendering require that the fonts referenced by the exported chart are installed on the system that VlConvert is running on.」

**法務關卡**：微軟正黑體與 Times New Roman 是 Windows／Office 隨附授權，**本機產出沒問題，對外散布且需嵌入字型時不被授權**。判定流程完整版在 19 §3.2，交付端只要記住這條分岔：

```
產出物要離開這台機器嗎？
├─ 否 → JhengHei + Times New Roman ✅ 直接用
└─ 是 → 需要嵌入字型嗎？（PDF/PPTX 嵌入、Web @font-face、送印）
        ├─ 否（PNG、已點陣化）→ 維持，但提醒對方機器可能 fallback
        └─ 是 → 自動切 Noto Sans TC（SIL OFL 1.1，可嵌可再散布）
                 ⚠️ 必須主動告知使用者，不要默默換：
                 「這份要對外，字型已從微軟正黑體換成 Noto Sans TC
                   （授權原因），版面寬度會有微幅變化」
                 ⚠️ 數字欄禁用 Noto Serif TC（實測數字有 6 種寬度，非等寬）
```

更新時要注意三件事：

1. **每個新加的門檻都要標出處。** 本文的數字分三類：【實測】（素材裡有實際量測或 API 查證）、【估計值／設計決定】（沒有引用依據，明說是決定）、【推導，待驗證】（我推的，等第一個真實案例校準）。**不准出現第四類「看起來合理的數字」。**
