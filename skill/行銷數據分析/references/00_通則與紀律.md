# 通則與紀律

這份文件是整套 skill 的**地基**。其他 20 份 reference 都假設你已經讀過它 —— `04_資料體檢` 假設你知道什麼叫「留成果」，`08_迴歸建模` 假設你知道降級要怎麼記，`14_決策轉譯` 假設你知道證據等級的措辭白名單長什麼樣。跳過這份直接進模組，你會做出一份**每個步驟單看都對、合起來卻不可稽核也不可反駁**的分析：數字追不回計算過程、相關被寫成因果、參數說不出理由、跑不出來的地方留白。這種報告最貴的地方不是被退件，是它會被採用 —— 主管照著它花掉預算，半年後沒有人能回答「當初那個 30% 是怎麼算的」。

`18_分析陷阱清單.md` 管的是**具體會踩到的坑**（E/G/T 三系列，每條都有實證）；這份管的是**每次開工都要維持的姿勢**。兩份互補，不重疊：本文遇到具體坑一律用「見 18-Exx」交叉引用，不重抄。

## 一、六條貫穿全流程的紀律

`SKILL.md` 的六條是速記，這裡是可執行版本。每一條都寫成「怎麼做到 → 什麼情況算違反」。

### 1.1 決策驅動欄位

**怎麼做到。** 每個進入分析的欄位、每個要跑的分析動作，都要能填完這句話：

> 「這個欄位／這項分析服務的決策是 ______；管理者拿到結果之後會做 ______ 這個動作；這個動作要花 ______。」

填不完 = 這不是一項分析，是好奇心。做法上落在兩個地方：M0 的 Check List 矩陣（列＝分析動作，欄＝決策 A–E）與 M0 的假說登錄表。矩陣裡任一列在**所有**決策欄都填不出「會影響哪個動作」，這一列直接刪掉，不要因為「反正順手」就做。

**唯一的例外**是 M1 資料體檢 —— 它是全流程中唯一允許「先看資料」的模組。但它的輸出必須是**「因此建議做／不做哪些分析」**，不是「這批資料很有趣」。體檢報告不給出排除清單，等於沒做體檢。

**什麼情況算違反。** 出現以下任一項，就是已經違反了，不是「有點偏離」：

| 徵狀 | 為什麼是違反 |
|---|---|
| 先打開資料、看完欄位才想題目 | 題目被資料的可得性綁架，不是被決策綁架 |
| 分析清單裡任何一項的理由是「資料裡剛好有這個欄位」 | 典型的資料驅動 |
| 某章小結只寫得出統計事實，寫不出行動 | 執行脈絡 §0 的成因 1：章節由方法驅動不由決策驅動 |
| 有人問「這個發現要幹嘛」而你答不出來 | 這一章從一開始就不該存在 |
| 11 個發現無法排序 | 沒有北極星指標樹（成因 2），S6.5 的優先序無從生成 |
| 產出了指標但沒有人是它的使用者 | 報表不是分析 |

### 1.2 每階段都留成果

沿用包子在 Excel 上已經跑通的三段式（出處：`00_source_archive/gdrive/own/02_包子自己的計算檔逐步拆解.md` §5.1、§5.2）。Excel 的 `Step 1 → Step 2 → Step 3` 換成 parquet，規則一模一樣：**每一個可獨立驗證的計算階段 = 一個檔**，不把兩步併在同一個檔裡。

| 段 | 規則 | 具體要求 |
|---|---|---|
| **① 原始檔原名不動** | `01_raw/` 下保留來源檔名與副檔名，**唯讀** | 只准加兩個欄：`_source_file`、`_ingested_at`。連欄名的空白與全形字都不要清 —— 清理是下一段的事 |
| **② 一步一檔絕不覆寫** | `02_staging/` 用 `s{階段}_{序號}_{動作}.parquet` | 對應 Excel 的 `Step 1` / `Step 2-1-1`。同一個檔名寫第二次 = 違反。要改參數就換序號，舊檔留著 |
| **③ 結果檔有意義命名** | 進 `03_mart/`、`04_features/` 之後改語意命名 | 特徵檔一律帶 `as_of`：`customer_features__as_of_2026-06-30.parquet`（見 18-G4） |

**刪列要先顯性化再刪**（02 §5.2）：不直接 `WHERE` 掉，先加一欄 `_keep_flag` 寫 `保留`／`刪除`，檢查完再產生下一個檔。**列數差本身就是稽核軌跡** —— 包子 HW2 的 1815 → 1743 → 1593、HW5 的 1815 → 1615，每一步差多少都查得到。這同時直接滿足 18-E22（樣本數變化必須交代）。

### 1.3 雙路徑交叉驗算（招牌手法）

這是包子自己的做法，不是外來規範。HW4 的階層貝氏在同一張表裡並排放了兩條數學等價的公式：

$$\hat\theta_i \;=\; W_1\bar x_i + W_2\mu_g, \qquad W_1=\frac{\tau^2_g}{\tau^2_g+s^2_i/n_i},\;\; W_2=1-W_1$$

$$\hat\theta_i \;=\; \frac{\bar x_i n_i/s^2_i \;+\; \mu_g/\tau^2_g}{n_i/s^2_i \;+\; 1/\tau^2_g}$$

實測（02 §3.2）：客戶 #62（$n=18$）兩式皆得 **465.44504311117777**，一位不差；客戶 #92 得 `2638.3931801302433` vs `2638.3931801302438`，只差在浮點尾數。第三重檢查是 $\text{CRI} \equiv W_2 \times 100$，實測 `I2=0.0011339478248075215` 對上 `L2=0.1133947824807567`。

**為什麼值得照做**：這是**免費的斷言**。兩條路徑用的是不同的中間量（一條走權重、一條走精確度），任何一邊的分母寫錯、絕對參照拖曳漂移、或誤用總額當平均，兩邊就不會相等。它抓的正是 18-E8（公式抄錯）與 18-E9（數值異常沒察覺）這類**不會報錯的錯**。跑一次的成本是三行程式，不跑的成本是一份數字全錯但格式完美的報告。

**哪些指標有兩條路徑：**

| 指標 | 路徑 A | 路徑 B | 應相符到 | 出處 |
|---|---|---|---|---|
| 顧客交易筆數 F | SQL `GROUP BY … COUNT` | 樞紐／`pivot` 計數 | **完全相等**（整數） | 02 §5.3（HW1） |
| 顧客金額 M | 交易明細層 `SUM` | 訂單層 `SUM` 再彙總 | **完全相等** | 六域模型粒度檢查 |
| HB 收縮估計 | 加權平均式 | 精確度加權式 | $<10^{-6}$ | 02 §3.2 |
| CRI | $(\bar x-\hat\theta)/(\bar x-\mu)\times100$ | $W_2\times100$ | $<10^{-9}$ | 02 §3.2 |
| RFM 分位分數 | `rank` 百分位切 | `NTILE(5)` | 各組大小差 ≤1 | 17 §3.1 |
| 購物籃關聯 | 0/1 矩陣的 Pearson | $\phi=(ad-bc)/\sqrt{\cdot}$ | $<10^{-9}$ | 17 §6.1 |
| 轉移矩陣 | 明細 `GROUP BY` 展開 | 矩陣行列總計 | 總數相等（如 1,615） | 02 §4 |
| 分群人數 | $\sum$ 各群 $n$ | 母體 $n$ | **完全相等** | 不變量 |
| ANOVA 平方和 | `stats_utils.anova3()` | $SS_{between}+SS_{within}=SS_{total}$ | $<10^{-6}$ | 18-T3 |

容差用相對誤差，不用絕對誤差（金額與比例的量級差太多）：

$$\Delta_{\text{rel}}=\frac{|A-B|}{\max(|A|,|B|,\varepsilon)},\qquad \varepsilon=10^{-12}$$

門檻的理由：**代數等價**（同一個式子的重排）應到 $10^{-9}$，這是 float64 在十來次四則運算後的累積尾差量級；**含迭代或最佳化**（EM、MLE、k-means）放寬到 $10^{-6}$；**整數計數**要求完全相等，差一列就是 join 掉了東西。

不一致時怎麼辦 —— 不要挑一個看起來合理的用：

```
兩路徑不一致
   │
   ├─ 差在 1e-9 ~ 1e-6 之間，且屬迭代法 ──► 記在 _log，照常往下（標註容差）
   │
   ├─ 整數計數不相等
   │     ├─ A > B ──► 通常是 B 端 join 掉了列（外鍵孤兒、日期型別不一致）
   │     └─ A < B ──► 通常是 A 端重複（粒度不對／未去重／一對多 join）
   │            └─► 兩邊都輸出「差集」的實際列，點名 ID，不要只報筆數
   │
   ├─ 相對誤差 > 1e-6 且屬代數等價
   │     └─► 停。這是實作錯誤，不是數值問題。
   │         逐項印出中間量（分子、分母、權重）比對，找出第一個分岔的量
   │
   └─ 任何一條路徑跑不出來（除以 0、缺參數）
         └─► 不算「驗算通過」。依 1.6 降級，並在報告註明「本指標未經雙路徑驗算」
```

**硬規則**：`tests/` 裡每個有兩條路徑的指標都要有對應的 `assert`，且雙路徑結果與 `max_abs_diff` 一併寫進 `_log/`。驗算沒過而照樣出報告，等同 18-E7（圖文數字矛盾）的上游版本。

### 1.4 參數必附理由

**為什麼要有這條**：包子自己的檔案就是反例。02 §2.4（HW2）盤點了 7 個參數 —— 樣本門檻「≤2 筆剔除」、權重函數「線性序位」、活躍門檻「前 20%」、不活躍門檻「後 20%」…… **「有無理由」欄七格全部是「無明文」**；§4.5（HW5）的 8 個參數同樣全部「無明文」。這條紀律就是為了補這個洞。半年後沒有人記得 20% 是怎麼來的，換一批資料要不要沿用也沒人敢決定。

**代價有多具體**：執行脈絡 §S2 的哨兵案例 —— `int` 欄有 100 個 `9999`（數量恰等於客戶數）。沒排除就算平均購買間隔得 **199.46 天**，真值是 **10.79 天**，差 18.5 倍。流失門檻因此被設成 200 天，100 人裡只標出 3 人流失（真實 28 人），**漏掉的 25 人合計營收占 6.4%**。這是一個「沒有寫理由的門檻」直接造成的營收漏接。

**需要理由的參數種類（全部）：**

| 種類 | 例 | 理由必須交代什麼 | 呼應 |
|---|---|---|---|
| **k（群數）** | `k=4` | elbow／silhouette／gap 的實際數值 + bootstrap ARI + **行銷團隊同時經營得了幾群** | 18-G7 |
| **切點／分位** | 20/60/20、五等分 | 為什麼是這個比例；換成 25/50/25 結論會不會翻（要真的跑） | — |
| **權重** | Bob Stone `m_rate=0.0025`、`cap=10` | 來源是教材原版還是自訂；自訂要寫商業理由，不是「調到好看」 | 18-E8 |
| **閾值** | 共現 $n\ge5$、覆蓋率 30%、VIF<5、AUC 提升 0.03 | 出處 + 沒過的代價 | 18-E10 |
| **α** | 0.05 → 0.20 | 為什麼放寬（通常是分群後 n 小）+ 是否已做 FDR | 18-E18、18-G8 |
| **時間窗** | `as_of_date`、回看 90 天、留存窗 | 為什麼這個長度；有沒有橫跨量測變更日 | 18-G4 |
| **樣本門檻** | 交易筆數 ≤2 剔除 | 剔了幾人 + **剔除者的營收占比** | 18-E22 |
| **哨兵值** | 9999、8888 | 是誰放的、掃描結果、排除前後的指標對照 | 執行脈絡 §S2 |
| **折現率／存活假設** | CLV 的 r、留存曲線形式 | 用公司資金成本還是慣例值 | 09 |
| **排除規則** | 剔除手續費／贈品／卡務品項 | 剔了幾列、占營收多少 | 18-E22 |

**落地方式**（沿用 02 §5.4 的參數集中化）：參數不散在程式碼裡，集中在一個 `params.yml`／一張參數表，每個參數四欄 —— `值`、`理由`、`出處`、`敏感度（換成 X 結論會不會變）`。報告的附錄直接貼這張表。

```yaml
# projects/<代號>/params.yml
churn_window_days:
  value: 90
  reason: "λ 中位數 10.79 天，90 天 ≈ 8.3 個購買週期；用 3σ 上界會落在 74 天，取整到 90"
  source: "M8-1 購買間隔分布；哨兵 9999 已於 s2_01 排除"
  sensitivity: "60 天 → 流失名單 41 人；90 天 → 28 人；120 天 → 19 人。結論方向不變"
alpha:
  value: 0.20
  reason: "群 3 僅 47 人，α=0.05 下 MDE 超過群間實際差距"
  source: "18-E18；已對同一族檢定做 BH 校正（18-G8）"
  sensitivity: "α=0.05 時 5 個顯著剩 2 個，被降的 3 個已列表並附 MDE"
```

### 1.5 證據等級標籤

四級：**相關 → 預測 → 準實驗 → 實驗**。SKILL.md 已經規定每條建議都要標，但**標籤本身不值錢，判定規則才值錢**。素材裡的診斷很直接：這個標籤目前是自由填寫的，「任何人跑一次 DiD 就可以標準實驗」（`research/gap-statistical-inference.md` S11）。

**代價有多具體**（同上 S11）：A 區上新版落地頁、B 區沒上，DiD 得到「提升轉換 1.8pp」，標「準實驗」，全站上線預算 300 萬。但 A 區同期在辦門市週年慶，且事前 6 期兩區趨勢本來就在分岔（A +0.15pp/期、B +0.02pp/期），1.8pp 裡至少 $0.13\times6\approx0.8$pp 是既有趨勢。實際只升 0.6pp，300 萬回收不到一半 —— 而且因為標了「準實驗」，主管把它當已驗證的因果寫進下一季策略。

**判定規則（決策樹）：**

```
這條結論想主張什麼？
 │
 ├─「A 與 B 一起動」──────────────────────────────────────► 相關
 │    需要：抽樣設計已登錄（是不是 case-control？回溯性只能估 OR）
 │
 ├─「給定 X 能猜出 Y」
 │    ├─ 有 out-of-time 驗證（用更晚的 as_of 重建特徵，不可隨機切列）？
 │    │    └─ 否 ──────────────────────────────────────► 降回「相關」
 │    ├─ 有 naive baseline 對照（單一 R 排序／RFM Score 排序）？
 │    │    └─ 否 ──────────────────────────────────────► 降回「相關」
 │    └─ 相對 baseline 提升 ≥ 0.03 AUC ─────────────────► 預測
 │         提升 < 0.03 AUC ──► 寫「不建議上線，用 baseline 排序即可」
 │
 ├─「X 造成 Y 改變」且無隨機分派
 │    ├─ DiD：①事前≥4期 placebo 檢定不顯著 ②事前趨勢平行圖
 │    │        ③對照組選擇的書面說明 ④同期其他干擾活動盤點
 │    ├─ PSM／uplift：①overlap 圖＋修剪規則 ②配對後 SMD<0.1 平衡表
 │    │        ③未觀測混淆敏感度分析（E-value 或 Rosenbaum bounds）
 │    │    ├─ 任一項缺 ─────────────────────────────────► 降回「相關」＋寫降級原因
 │    │    └─ 全過 ───────────────────────────────────► 準實驗
 │
 └─「X 造成 Y 改變」且有隨機分派
      ├─ ①分流前共變數平衡 ②**事前**樣本量／MDE 計算
      │  ③汙染與溢出檢查 ④分流單位＝分析單位
      │    ├─ 任一項缺 ─────────────────────────────────► 降為「準實驗」或「相關」
      │    └─ 全過 ───────────────────────────────────► 實驗
```

**硬規則**：等級標成「準實驗」或「實驗」時，對應的檢查結果物件必須實際存在於 `05_models/`。不存在 → **自動降級為「相關」，並在報告顯示降級原因**（不是靜默通過，也不是報錯停住 —— 沿用 1.6 的降級精神）。這條進 `verify_outputs.py`。

**措辭白名單**（這是最容易滑掉的一關）。教材的示範值得原樣搬：MBA5045 的養鳥／肺癌案例，控制了性別、社經地位、年齡、抽菸年數四個共變數、$p=0.0008$、odds 3.80 倍，**全篇仍然只寫「存在關聯」，一次都沒寫「造成」**（出處：`notion/商管統計資料分析/02_logistic_glm_categorical.md` §2.6 評註）。

| 等級 | **准用**動詞／句型 | **禁用**動詞 | 範例句 |
|---|---|---|---|
| **相關** | 同時、伴隨、與…同期上升、與…相關（r=）、在…之中佔、較高／較低、出現在 62% 的路徑裡 | **造成、帶動、驅動、導致、提升了、貢獻了、增量、因為…所以** | 「Facebook 投入與營收同期上升（r=0.42），但無法排除旺季共同驅動」 |
| **預測** | 可預測、可辨識出、模型排序下前 N% 的…、命中、優於 baseline | 造成、只要做…就會、帶來 | 「out-of-time 樣本上，模型前 10% 名單命中 34% 的流失者，RFM 排序為 21%」 |
| **準實驗** | 在…識別假設下估計為、模型下的移除效應、估計增量約為（**必附假設**） | 證實、確定、必然、就是 | 「在平行趨勢假設下估計提升 1.0pp（95% CI 0.3–1.7）；事前 6 期 placebo 不顯著」 |
| **實驗** | 造成、帶動、提升了、增量為 | （無禁用，但仍須附 CI 與事前 MDE） | 「實驗組較對照組轉換率高 1.8pp（95% CI 1.1–2.5，n=24,000／組）」 |

**沒有實驗時絕對不能說的三句話**（`gap-statistical-inference.md` 深挖(3)）：「廣告使購買率提升 X%」、「這檔活動帶來 X 筆增量訂單」、「ROAS = 6.0 所以應該加碼」。

歸因分析特別容易越級 —— Markov removal effect 是**模型內的移除效應**，不是「停投會少 18%」。四層能說的話見同一份素材的分層表。

### 1.6 降級不留空

原則一句話：**沒跑出來不是理由，沒有備案才是。**（藍圖裁決 1：IB5082 說「只檢查步驟」、MBA5045 說「假設不成立結論就無效」，兩者都要 —— 同時輸出計算軌跡與假設檢查結果，假設不成立就降級並說明。）

**通用模式**（不論是哪個模組）：

```
方法 A 跑不出來 / 前提不成立
   │
   ▼ ① 點名哪一條前提壞了 —— 要帶檢定名稱與數值，不准寫「資料不符合假設」
   │     ✗「殘差不符合常態」
   │     ✓「Shapiro-Wilk W=0.913, p<0.001；群 3 變異數是群 1 的 11.4 倍（Levene p=0.003）」
   │
   ▼ ② 沿階梯往「前提更少」的方向退**一格**
   │     不是往旁邊換一個等難度的方法（換 LSD 為 SNK 不叫降級）
   │
   ▼ ③ 退到底就退到敘述統計 + 明說「本節無法主張 X」
   │     章節**保留**，不准整章刪掉（見 18-E11）
   │
   ▼ ④ 寫四件事：原本要做什麼 → 為什麼不能做 → 改成做什麼 → 結論因此弱在哪
```

**紀錄格式**（每次降級都在 `_log/degradation_log.md` 加一列，並在該章小結複述前四欄）：

| 欄位 | 範例內容 |
|---|---|
| 原方法 | 單因子 ANOVA（客單價 ~ 群別） |
| 失效證據 | Levene $p=0.003$；群 3（$n=47$）變異數為群 1 的 11.4 倍 |
| 降級路徑 | ANOVA → Welch ANOVA → **Kruskal-Wallis** |
| 實際採用 | Kruskal-Wallis + Dunn 事後檢定（BH 校正） |
| 結論弱在哪 | 只能主張中位數排序差異，**不能報「平均差 X 元」** |
| 影響哪幾章 | §6.2 的結論措辭；§9.1 的 sizing 改用中位數客單價 |
| 證據等級變動 | 無（本來就是相關級） |

**常用降級階梯**（各模組的完整階梯見對應 reference）：

| 情境 | 階梯（左 → 右 = 前提由多到少） |
|---|---|
| 事後檢定（18-E1 綁定，不可分離） | LSD → Tukey HSD → Games-Howell → 手動獨立樣本 t（BH 校正）→ 敘述統計對照表 |
| 組間差異 | ANOVA → Welch ANOVA → Kruskal-Wallis → 中位數與 IQR 對照 |
| 因素分析適配不佳 | 保留章節 + 報告 KMO/RMSEA → 改用相關矩陣 → 品類共現次數表（**不准刪章**，18-E11） |
| 因果主張 | 實驗 → 準實驗（含識別假設檢查）→ 條件關聯（控制共變數的 logistic）→ 相關 |
| CLV | BG/NBD + Gamma-Gamma → 留存曲線外推 → 歷史加總（明寫「非預測值」） |
| 分群 | 兩階段（Ward + k-means）→ k-means → 分位切割 → 業務規則標籤 |

## 二、階梯式否定：方法升級的通用規則

這是包子報告的核心引擎，也是報告章節接縫的**生成器**：**做了 A → 指出 A 在這批資料上的具體失效 → 所以做 B**。不是「A 比較簡單、B 比較厲害」，而是「A 在**這一批**資料上壞在哪裡，我有證據」。

### 2.1 三條必須交代的事

每上一層，都要回答三個問題。少任何一個，這一層就是在炫技：

| 要交代 | 寫成什麼樣 | 反例（不算） |
|---|---|---|
| **先做它的理由** | 「前提最少：只需要 顧客ID + 交易日期 + 金額 三欄」 | 「這是課本第一個教的」 |
| **需要什麼前提** | 「每人 ≥3 筆交易才有 ≥2 個間隔可算 CAI」 | 「資料要乾淨」 |
| **什麼具體現象代表要升級** | 「客戶 #87 只有 16 筆交易，個人平均客單價的標準誤約 1,282 元」 | 「個人平均不夠穩健」 |

### 2.2 升級的觸發必須點名

**這是整節最重要的一條**：證明前一層失效時，要**點名具體的 ID 或數字**，不用抽象說詞。抽象說詞（「樣本量不足」「不夠穩健」「容易受離群值影響」）在任何資料上都成立，因此在這一批資料上什麼都沒證明 —— 讀者無從反駁，也就無從相信。

實例（02 §3、階層貝氏那一層的真實數字）：

```
✗ 抽象版（不合格）
   「個人平均客單價對交易筆數少的顧客不穩健，因此改用階層貝氏收縮估計。」

✓ 點名版（合格）
   「客戶 #87 有 16 筆交易，個人平均客單價 1,827.19 元，個人變異數
    2.63e7 —— 平均值的標準誤約 √(2.63e7/16) ≈ 1,282 元，也就是說
    這個 1,827 元本身的不確定範圍比它與群平均（1,542.60 元）的差距
    還大 1.6 倍。用它排 VIP 名單等於在排噪音。
    收縮後為 1,799.52 元，CRI = 9.72%（被拉回 9.72%）；
    對照客戶 #62（n=18、個人變異數小）僅被收縮 0.11%，
    從 464.22 元變成 465.45 元 —— 收縮量隨樣本量與變異自動調整，
    這正是我們要的性質。
    因此第 N+1 節改用階層貝氏收縮估計。」
```

點名的三種合法形式，任選其一即可：**具名 ID**（客戶 #87、品類「麵包吐司」）、**具體統計量與門檻的比較**（Levene $p=0.003$、VIF=8.4 > 5）、**兩個方法在同一批資料上的實際差距**（門檻設 200 天 vs 90 天，流失名單 3 人 vs 28 人）。

### 2.3 章節接縫的生成模板

報告每一章的小結不是「本章分析了 XX」（18-E19 明令禁止），而是這個模板的填空。這樣寫出來的報告，**目錄本身就是論證鏈**，而不是分析師的工作日誌：

```
§N 小結（150–400 字）
  ① 我們先做了 <方法 A>，因為 <A 的前提最少：只需要 X、Y 兩欄>。
  ② 結果是 <A 的具體數字，帶單位>。
  ③ 但 <點名的具體失效：ID / 統計量 / 兩法差距>。
  ④ 這代表 <失效的商業後果：會把誰放進哪個名單、會多花多少錢>。
  ⑤ 因此 §N+1 改用 <方法 B>，它多要求 <B 的額外前提>。
  ⑥ 若 B 也失效，備案是 <降級路徑>（見 1.6）。
```

### 2.4 什麼時候**不要**升級

階梯不是越高越好。以下三種情況停在原地，並把「為什麼不往上」寫進報告 —— 這比硬升上去有價值：

| 情況 | 判定 | 處理 |
|---|---|---|
| 前一層沒有失效 | 找不到可點名的失效證據 | 停。寫「A 在本批資料上未觀察到失效，因此不升級」 |
| 升級後不改變任何決策 | B 的結果與 A 的名單重疊 > 90% | 停。用 A，並在附錄放重疊率 |
| 升級要的前提這批資料沒有 | 如 uplift 需要處理／對照的重疊區 | 停，並列入 M12 的實驗設計需求 |

```
                  ┌──────────────────────────────┐
   方法 A ───────►│ 在這批資料上有可點名的失效？   │
   （前提最少）    └──────┬───────────────┬───────┘
                        否│             是│
                          ▼               ▼
                   停在 A，寫理由    ┌─────────────────────┐
                                    │ B 的前提這批資料有嗎？│
                                    └──┬──────────────┬───┘
                                     否│            是│
                                       ▼              ▼
                              列入 M12 實驗需求   ┌────────────────────┐
                                                 │ B 的結論會改變決策嗎？│
                                                 └──┬─────────────┬───┘
                                                  否│           是│
                                                    ▼             ▼
                                            用 A，附錄放重疊率   升級到 B
                                                                （寫進章節接縫）
```

## 四、空值與缺漏的表示紀律

包子的既有慣例：**從不留空白格**。空白格有兩種讀法（「沒算」與「算出來是零」），而兩種讀法會導向完全不同的行動 —— 這正是 18-E7（圖文數字矛盾）在表格層的孿生兄弟。

**兩種符號代表兩種不同情況，不可混用：**

| 符號 | 意思 | 什麼時候用 | 讀者該做什麼 |
|---|---|---|---|
| `N/A` | **有樣本，但算不出來** | 公式在此處無定義（分母為 0、log 負值）、前提不成立、方法失敗、指標對這個對象無意義 | 去看 `_log/degradation_log.md` 找原因 |
| `-` | **無樣本** | 這一格根本沒有觀測值（該群沒有女性、該品類該月無交易） | 不要解讀，這不是「零」 |
| `0` | **真的是零** | 有樣本、算得出來、值就是 0 | 正常解讀 |
| `n.s.` | 有算出來但不顯著 | 檢定跑完 $p>\alpha$ | **同列必須附 MDE**（見下） |
| `<5`（或遮蔽） | 樣本數過小不揭露 | 個資或商業敏感的小格 | 只看方向不看數值 |

**與 18-E17 的口徑統一**：18-E17 寫「不顯著標『—』」。本 skill 把「不顯著」統一寫成 `n.s.`，因為 `-` 已被「無樣本」佔用，兩者混用會讓讀者把「這群沒有人」誤讀成「這群沒差異」。18-E17 的精神（所有群 × 所有人口變數都要出現在表中）完全不變。

**`n.s.` 必須附 MDE**（出處：`gap-statistical-inference.md` S12）。「沒差異」與「看不出差異」是兩件事，混為一談會直接造成錯誤行動：群 3（$n=21$）與群 4（$n=12$）比平均客單價，$t=1.12$、$p=0.27$，報告老實寫「兩群無顯著差異，可沿用同一套定價」。但 SD ≈ 3,000 元時：

$$\text{MDE}=(z_{1-\alpha/2}+z_{1-\beta})\cdot s\cdot\sqrt{\tfrac{1}{n_1}+\tfrac{1}{n_2}}=(1.96+0.84)\times3{,}000\times\sqrt{\tfrac{1}{21}+\tfrac{1}{12}}\approx 3{,}010$$

也就是說即使真實差異有 2,500 元（約 40% 的客單價落差），這個樣本大概率也看不出來。正確的翻譯是「**這個樣本量看不出 3,000 元以內的差異**」，而不是「兩群一樣」。錯誤行動：兩群被合併成一套定價，放棄了一個實際存在的價差機會。

**機械化檢查**（併入 `verify_outputs.py`，與 18 §八 同一支腳本）：

```python
CELL_RULES = [
    "交付檔中不存在空白格（None / '' / 純空白字串）",
    "NaN / inf / #DIV/0! / #NAME? 一律不得出現，須已轉為 N/A",
    "凡出現 'N/A' 的欄，degradation_log.md 中必有對應紀錄",
    "凡出現 'n.s.' 的列，必有同列的 mde 欄位且非空",
    "'-' 只出現在樣本數欄為 0 或缺席的列",
    "'0' 不得出現在樣本數為 0 的格（該用 '-'）",
    "遮蔽格的門檻寫在表註，且全表一致",
]
```

## 五、模組的必做／選做判定

SKILL.md 的表格是骨架，這裡補上**什麼資料條件下某模組不可用**。不可用不等於跳過 —— 不可用要在 M1 的「因此建議做／不做」明確列出並說明理由，這是 18-E3（報告中途結束）的預防。

| 模組 | 必做？ | 最低資料條件 | 不可用的判定（觸發即改走右欄） | 不可用時做什麼 |
|:--:|:--:|---|---|---|
| **M0** 開案 | **必做** | 不碰資料 | 無（永遠可做） | — |
| **M1** 體檢 | **必做** | 至少一個檔 | 無 | — |
| **M2** 特徵檢驗 | **必做** | 有數值欄 | 全部欄位皆為類別 → 只跑類別檢查 | 卡方前提檢查（$E_{ij}\ge5$） |
| **M3** 前處理 | **必做** | 承 M2 | 不轉換也是一種決定 | **明寫「不轉換」及其理由**，不准留白 |
| **M4** 複檢 | **必做** | 承 M3 | 無 | — |
| **M5** 業務標籤 | 選做 | 有業務規則文件 | 沒有成文規則 | 跳過並註明，不要自創規則 |
| **M6** 分群 | **必做** | ≥2 個行為指標欄；顧客數 ≥ 50 | 可用行為指標只有 1 欄；或顧客 <50（k=4 時每群約 12 人，依 §四 的 MDE 算式已無檢定力） | 降級為分位切割／業務規則標籤，並說明 |
| **M7** 迴歸 | 選做 | 有明確的 y、$n\ge 10p$ | 沒有可辯護的應變數 | 停在描述與分群 |
| **M8-1** 顧客價值 | 行銷專案**必做** | 顧客ID + 交易日期 + 金額 | 無顧客ID → 全模組不可用；每人 <3 筆 → CAI 不可用（無 ≥2 個間隔）；無分群層 → CRI 不可用 | RFM 可做、CAI/CRI 標 `N/A` 並寫原因 |
| **M8-2** 購物籃 | 行銷專案**必做** | 籃子鍵 + 品項／品類欄 | 品類數 <10（因素分析在品類層需 15–16 類，見 18-E12）；共現 $n<5$（見 18-E10） | 只出共現次數表 + 條件機率，不做因素分析 |
| **M8-3** 成長促銷 | 行銷專案**必做** | 時間軸 + 營收 | **無 `fact_marketing_spend` → 不可談 ROI／歸因**（18-G5） | 只做成長分解，報告明寫「本分析無法歸因至行銷投入」 |
| **M9** 預測 | 預測型才做 | ≥2 個可用的 `as_of` 窗口 | 只有一個時間切面 → 無法 out-of-time，證據等級升不到「預測」 | 降回「相關」；或列入 M12 的資料需求 |
| **M10** 文本 | 有文本才做 | 有自由文字欄 | 無文本欄 | 跳過（**不做文字雲**，見 SKILL.md 負面清單） |
| **M11** 決策轉譯 | **必做** | 承前 | 無（永遠可做） | 即使全是「不建議做」，也要交出排除理由 |
| **M12** 實驗設計 | 第二輪才用 | 有第一輪假說 + 可分流的單位 | 分流單位與分析單位無法一致 | 改設計（改成地理實驗／switchback），不要硬做 |

**跨模組的共同否決條件**（任一成立，該指標不准進報告）：

| 條件 | 門檻 | 出處／理由 |
|---|---|---|
| 覆蓋率過低 | 算得出來的顧客占比 < **30%** | 執行脈絡 §S2。低於門檻不准進報告，或必須在圖表下標覆蓋率 |
| 目標洩漏 | 特徵未帶 `as_of_date` | 18-G4。驗證集 AUC 0.95 上線崩盤 |
| 分群輸入違規 | 出現人口統計變數 | 18-E2。白名單：R/F/M/RFM Score/CAI/CRI/因素分數/LN_F/LN_M |
| 環境不符 | 在主環境跑 dowhy／EconML／meridian | 18-T1、18-T2。切 `.venv-causal`（Python 3.12） |
| 口徑未定義 | 指標不在 `dim_metric_definition` | 18-G10 |

## 六、與使用者互動的節奏

包子的口氣直接、條列式，不喜歡被堆一大坨 bullet。互動的節奏規則如下：

| 時機 | 做什麼 | 具體到什麼程度 |
|---|---|---|
| **開工** | 先讀本文 + 18，再讀該模組的 reference。不要三份一起讀完才動 | 走到哪讀哪 |
| **發現資料有問題** | **立刻講**，不要做完才說 | 帶列數與 ID，例：「spend 欄 12% 無法 cast，其中 8 成集中在 3 月」 |
| **硬卡點（M0/M1/M4/M11）** | 用 §三 的四段格式回報，然後**真的停** | 不要在同一則訊息裡先問再自己往下跑 |
| **一般模組完成** | 同樣四段，第四段寫「無，繼續」，然後繼續 | — |
| **要問問題** | **一次最多三題**，每題附選項 + 各自後果 + 你的預設值 | 「1) 排除（預設，會少 6 人）／2) 保留（RFM 會偏）」 |
| **改了任何口徑或假設** | 列**異動清單**，不要默默改掉 | 改了什麼、為什麼、影響哪些既有數字 |
| **要說「不」的五個地方** | M0「這還不是分析問題」／M1「這份資料回答不了」／M6「這群 47 人檢定力不足」／驗證「只能到相關」／M11「損益兩平打不平」 | 出處：執行脈絡 §4 |
| **交付** | 跑 `verify_outputs.py` → 用 `[View 檔名](computer://...)` 給連結 | — |

**節奏上的三個反模式：**

| 反模式 | 為什麼壞 | 改成 |
|---|---|---|
| 一次丟 15 個問題 | 包子會挑三個回，剩下 12 個你就自己決定了 —— 那 12 個決定沒有人審過 | 一次三題，其餘用預設值並在異動清單列出 |
| 做完一整條 pipeline 才回報 | 中間錯了要全部重跑；而且硬卡點的意義就是「還來得及轉向」 | 按模組回報 |
| 「跑不出來」就空著等問 | 違反 1.6。而且包子會以為你還在跑 | 降級 + 記錄 + 在回報第二段講 |

```
包子丟資料 + 一句話
   │
   ▼ 先問決策，不碰資料 ─────────────► M0 ▣ 停
   │
   ▼ 體檢，壞消息先講 ───────────────► M1 ▣ 停
   │
   ▼ M2 → M3 → M4 ▣ 停（每步留檔、雙路徑驗算）
   │
   ▼ M5/M6/M7/M8… 每個模組四段回報，預設繼續
   │      └─ 任何時候發現資料問題 → 立刻插播，不等模組做完
   │
   ▼ M11 ▣ 停（sizing + 損益兩平 + 證據等級）
   │
   ▼ verify_outputs.py 全綠 → 交付 → 連結
```

## 七、維護條款

這份文件是所有 reference 的地基，因此**改它的成本最高、也最需要留痕**。

**什麼情況要更新：**

| 觸發事件 | 要動哪一節 | 注意什麼 |
|---|---|---|
| 包子改了工作習慣（命名、回報格式、互動偏好） | 1.2、三、六 | 保留舊寫法作為向後相容說明，不要直接覆蓋 |
| 新增一個有兩條等價算法的指標 | 1.3 的表 | 同時在 `tests/` 加 `assert`，否則這一列是空頭支票 |
| 某條降級階梯被證明有更好的中間層 | 1.6 的階梯表 | 階梯只能在「前提由多到少」的軸上插入，不可平移 |
| 證據等級的門檻被實務證明過嚴／過鬆 | 1.5 的決策樹與白名單 | 措辭白名單改動要同步 `verify_outputs.py` 的字串檢查 |
| 新增模組或某模組的資料條件變了 | 五 | 同步 SKILL.md 的模組表，兩處不可分岔 |
| 18 新增了 E/G/T 條目而本文有相關規則 | 對應節 | **只加交叉引用，不要抄內容**——重複的規則遲早會分岔 |
| 某個門檻數字改了（30% 覆蓋率、0.03 AUC、$10^{-9}$ 容差） | 對應節 | **必須同時改出處說明**，否則下一個人不知道能不能再改 |

**更新時要注意的三件事：**

1. **本文與 SKILL.md 的六條速記必須一致。** SKILL.md 是速記、本文是展開，展開版改了語意就要回頭改速記。兩邊分岔比兩邊都錯還糟 —— 讀者會以為自己讀到的是權威版。
2. **不要把 18 的內容搬過來。** 本文寫「姿勢」，18 寫「坑」。判斷準則：**有具體樣本實證的進 18，沒有的進本文**。本文引用 18 一律用 `見 18-Exx` 的形式。
3. **每個新加的門檻都要附出處或理由。** 這是 1.4 的紀律，對這份文件自己同樣適用 —— 一份要求別人寫理由卻自己有無出處門檻的文件，沒有權威可言。
