# 文本分析（M10）

M10 只在「手上真的有自由文字欄」時才做，而且它是全流程裡**最容易產出一堆好看但沒有決策價值的東西**的模組。理由很簡單：文字分析的中間產物（詞頻表、關鍵詞清單、主題分布）本身看起來就很像結論，讀者不會追問「所以要改哪個動作」。這正是 00 §1.1 講的資料驅動陷阱在文本上的變形 —— 沒有人會質疑一張 Top 20 詞頻表，但也沒有人會因為它做任何事。

比「沒有價值」更貴的是**第四節那個坑**：把「出現在高 CTR 廣告裡的詞」講成「這個詞會提高 CTR」。這不是文本問題，是因果推論問題，而且它會直接花掉錢 —— 文案團隊照著關鍵詞清單改寫全部素材，成效沒動，半年後沒人說得出當初那份清單是怎麼來的。本文把這件事獨立成一節，並規定它的結論只能標到「控制了 X Y Z 之後的關聯」（措辭白名單見 00 §1.5）。

本文假設你已讀過 `00_通則與紀律.md` 與 `18_分析陷阱清單.md`。公式一律引用 `17_指標公式庫.md`，不重寫；具體會踩到的坑用「見 18-Exx」交叉引用，不重抄。**不要把這一份寫成 NLP 教科書** —— 這裡只放「做行銷分析時真的會用到、而且會出錯」的部分。

空值符號沿用 00 §四：`—` = 無樣本、`N/A` = 有樣本但算不出來、`n.s.` = 有算出來但不顯著。

## 一、進場條件與中文處理

### 1.1 三個子模組的資料條件完全不同

M10 底下有三個彼此獨立的子模組，**它們要的資料不一樣，不可以互相代替**。最常見的誤會是「我有評論文字，所以可以做 SEO 關鍵字」—— 不行，SEO 要的是語料裡根本沒有的東西（見第五節）。

| 子模組 | 最低資料條件 | 缺什麼就不可用 | 不可用時做什麼 |
|---|---|---|---|
| **M10-A 關鍵詞抽取**（第二節） | 自由文字欄 + 文件的類別標籤（客群／通路／評分區間／時間段） | 無類別標籤 → MI／χ²／Lift 全部 `N/A`（三者都需要 class $c$） | 只做 TF-IDF 的篇內代表詞，並在報告明寫「本批文本無類別欄，無法做類別富集分析」 |
| **M10-B 吸睛字詞**（第四節） | 廣告文本 + 廣告成效 + **控制變數**（版位／受眾／時段／素材類型／預算／曝光量） | 缺控制變數 → 只能做描述性交叉表，**不可寫任何「哪些詞比較好」的建議** | 降級為「高 CTR 組 vs 低 CTR 組的詞頻對照表」，證據等級標「相關」，並列入 M12 的實驗需求 |
| **M10-C SEO 字詞**（第五節） | **外部搜尋量資料**（關鍵字規劃工具）+ 競爭度 + 自家相關性 | 沒有外部搜尋量 → **整個子模組不可用**，語料本身推不出來 | 明寫「這需要 Google Keyword Planner／Ahrefs／Semrush 類工具的外部資料，本批資料無法回答」 |

三者共同的否決條件沿用 00 §五：文本欄覆蓋率 < 30% 的指標不准進報告（例如 8.6 萬筆訂單只有 2,100 筆有評論，覆蓋率 2.4% → 這批評論可以讀、可以引述，但**不可以拿去代表整體顧客**）。

### 1.2 中文一定要先斷詞，而且斷完要用空白 join

材料原文的警告值得原樣搬：中文語法結構中沒有空白，直接把語料丟給 vectorizer 會變成「單字元」或亂切，keyword 會整個崩掉（【實測／教材原文】`notion/大數據與商業分析/01_text_web_mining.md` §15.7）。第二個坑同樣致命而且更隱形：**斷完詞如果沒有用空白 join 回去，vectorizer 仍然不知道怎麼切**，它會安靜地跑完、給你一張看起來正常的矩陣，只是每個「詞」都是單字。這是不會報錯的錯，性質同 18-E9。

### 1.3 jieba 是課程用的起點，繁中要升級到 CKIP

課程用 jieba（【實測／教材原文】同上 §15.1），它裝得起來、跑得動、純 Python 沒有相依地獄。但 **jieba 的內建詞庫偏簡體中文語境**，台灣的專有名詞（品牌、產品型號、通路名、網路用語）常被切壞。升級路徑照 00 §二的階梯式否定走 —— **升級的理由必須是「jieba 在這批資料上的具體失效」，不是「CKIP 比較厲害」**：

```
斷詞工具階梯（前提最少的先做）
  │
  ├─ ① jieba + 自訂詞典
  │      前提：只要 pip install jieba，無 GPU、無大型模型
  │      什麼算失效（要點名，不准抽象）：
  │        · 抽 200 句人工標，錯切率 > ?%（門檻自訂，須寫進 params.yml）
  │        · 品牌／型號被切壞且加了 add_word 仍無法解（例：切成「原/萃/精華/露」）
  │        · 需要 POS 詞性過濾（只留名詞／形容詞）而 jieba 的詞性標註不夠準
  │        · 需要 NER（抓人名、品牌、地點）—— jieba 本身不做 NER
  │
  ├─ ② ckiptagger（中研院，BiLSTM 世代）
  │      前提：需下載模型檔（數百 MB 級），CPU 可跑
  │
  └─ ③ CKIP Transformers（中研院，BERT 世代；繁中斷詞與 NER 目前最準）
         前提：transformers + torch。**主環境（Python 3.14.1）能不能裝要先實測**
         【推導，待驗證】截至本文撰寫，torch 對 cp314 的 wheel 支援情況未在本機驗證。
         若主環境裝不起來 → 另開 `.venv-nlp`（Python 3.12），
         與主環境用 Parquet 交換「斷好詞的語料」，不要跨環境傳模型物件。
         驗證指令見本節末的程式碼區塊。
```

**不要為了升級而升級。** 若 jieba + 自訂詞典後的人工抽檢已可接受，就停在 ① 並把「為什麼不升級」寫進報告（00 §2.4）。

### 1.4 自訂詞典不能省，而且它是一個要維護的資產

品牌名、產品型號、行銷術語、通路名、台灣網路用語，這些詞在任何通用詞庫裡都不會有。材料只給了 `jieba.add_word("郭台銘")` 這一招（【實測／教材原文】§15.7），但真實專案要把它當成一張**版控的字典檔**，而不是散在程式碼裡的幾行 `add_word` —— 這是 00 §1.4「參數必附理由」在文本上的對應：詞典裡每一個詞都是一個參數。

| 詞類 | 例（示意） | 來源 | 不加的後果 |
|---|---|---|---|
| 品牌／子品牌 | 自家與競品的中英文寫法、常見錯字 | 品牌手冊 + 語料高頻 n-gram 人工掃 | 品牌被切成單字，share-of-voice 全錯 |
| 產品型號 | `A7 Pro`、`SE 第三代` | 商品主檔 `dim_product` | 型號散成碎片，無法對到銷售資料 |
| 通路／門市名 | 蝦皮、momo、全家、7-11 | `dim_channel` | 通路聲量無法比較 |
| 行銷術語 | 回購、開箱、鬥內、業配、免運門檻 | 語料人工掃 + 團隊補 | 這些正是最有商業意義的詞，切壞等於沒做 |
| 台灣網路用語／注音文 | 洗版、雷、CP值、太雷了 | 語料人工掃 | 情感訊號漏掉 |
| **停用詞（反向）** | 的、了、真的、覺得、就是；平台自動文字（「此則評論已編輯」） | 通用繁中停用詞表 + 本專案自訂 | 詞頻表全是廢話（英文用 `stop_words="english"`，中文**沒有內建表，一定要自己給**） |

教材對中文處理的深度確實不足 —— digest 自己的評註就寫了：全部中文處理就是「用 jieba、記得 add_word」，沒有繁簡處理、全半形正規化、表情符號處理（【實測／教材評註】§17.3）。所以下面這段正規化是本 skill 補的，**順序不可調換**（正規化要在斷詞之前，否則同一個詞會因全半形不同被切成兩個 type）：

```python
# scripts/text_prep.py —— 中文語料標準前處理（順序不可調換）
import re, unicodedata, jieba, pandas as pd

def normalize(s: str) -> str:
    s = unicodedata.normalize("NFKC", s)   # ① 全形→半形、相容字元統一
    s = re.sub(r"https?://\S+", " ", s)    # ② URL 移除（否則變成超高 IDF 的怪詞）
    s = re.sub(r"[\U0001F300-\U0001FAFF]", " ", s)  # ③ emoji：先抽出另存欄再移除
    s = re.sub(r"\s+", " ", s).strip()
    return s

jieba.load_userdict("dict/custom_terms.txt")   # ④ 自訂詞典（版控檔，不寫在程式碼裡）
STOP = set(open("dict/stopwords_zh_tw.txt", encoding="utf-8").read().split())

def segment(s: str) -> str:
    toks = [t for t in jieba.cut(normalize(s)) if t.strip() and t not in STOP]
    return " ".join(toks)          # ⑤ 空白 join —— 漏掉這行 vectorizer 會逐字切

# 留成果：斷詞結果一步一檔（00 §1.2），不要只留在記憶體
df["seg"] = df["review_text"].map(segment)
df.to_parquet("清理後資料/s6_01_segmented.parquet")   # 含原文與斷詞兩欄，可回查

# 環境實測（新機器第一件事，把結果貼進 執行紀錄/）
# python -c "import torch, transformers; print(torch.__version__, transformers.__version__)"
# 裝不起來 → 走 .venv-nlp (3.12)，只交換 s6_01_segmented.parquet
```

## 二、關鍵詞抽取的三層流程

這一節是包子 HW1 已經做過並跑通的東西，把它固化成標準流程。**核心規則一句話：永不從全表直接選最終答案，先建一個「有證據支持」的候選池**（【實測】`notion/大數據與商業分析/04_homework_and_textbook.md` §5 Step 3、§10.3）。

### 2.1 三層流程

```
全部詞表（斷詞後的 1-gram / 2-gram / 3-gram）
   │
   ▼ 第一層：TF-IDF 篩候選（top 200）
   │     為什麼是 TF-IDF：它只需要語料本身，前提最少（不需要類別標籤）
   │     為什麼是 200：教材原文給的量級【實測】01 §8.7；
   │     實務上取 max(200, 10×最終要的詞數)【推導，待驗證】
   │
   ▼ 第二層：MI / χ² / Lift 重排（需要類別標籤 c）
   │     四個指標問的是四個不同問題，見 2.2 的分工表 —— 不是四個版本的同一件事
   │     量尺不可比 → 一律先轉 0~1 百分位 rank 再加權，絕不直接加總原始分數
   │     （【實測】04 §5 Step 4.2、§10.2）
   │
   ▼ 第三層：人工 sanity check
   │     自動化選出來的詞會有「不好看、切得怪、太泛」的
   │     → 額外輸出第 N+1 ~ N+10 名候補供人工替換（【實測】04 §7、§10.3）
   │
   ▼ 最終清單 + diagnostics 漏斗表（每一關剩幾個，進報告方法論章）
```

**第三層不是可選的。** HW1 的作者自己把它寫進設計裡：自動選出的詞可能不合語感，所以預留候補（【實測】04 §8.2 坑 #15）。跳過這一層等於把切詞錯誤直接印在老闆的簡報上。

### 2.2 四個指標的分工（這是本節最重要的一張表）

四個指標**不是精度高低的關係，是問題不同**。選錯的代價是答非所問：你要的是「這個客群的特有說法」，卻用了 TF-IDF，結果拿到一堆「能區分文件」但每群看起來都差不多的詞。

| 指標 | 它在回答什麼 | 行銷上的對應 | 什麼時候用 | 什麼時候不要用 |
|---|---|---|---|---|
| **TF-IDF** | 哪些詞能**區分文件** | 內容摘要、報告標題、篇內代表用語 | 沒有類別標籤時的唯一選擇；要找「這篇在講什麼」 | 單一主題語料（全都是自家品牌評論）→ 品牌名的 $df$ 極大、$idf \approx 0$，會**被自己壓掉**。這是正常行為不是 bug（見 3.1 第 5 條） |
| **MI** | 這個詞和**主題／類別**是不是真的綁在一起 | 「跟客訴主題特別相關的詞」「跟高價值客群特別相關的描述詞」 | 已有明確類別，要確認關聯而非只是稀有 | $f(x,y)=0$ 時 $\log 0 \to$ `inf`，**要先做規則處理**（見 3.1 第 7 條）。另見 2.4 的同構陷阱 |
| **χ²（保留正負號）** | 這個詞在該類別是否**顯著突出**，以及**方向** | over/under-index 分析：品牌被過度討論／被迴避的話題 | 要更貼近人類閱讀的 keyword；要方向性 | expected count < 5 的格子統計上要小心解讀（【實測】01 §15.6）。**TF 卡方易被單篇高頻重複污染，用 DF 卡方**（【實測】04 §4.4） |
| **Lift** | 在該類別的**相對豐富程度**（富集倍數） | segment index（>1 = 該客群偏好），與消費者研究的 index=130 完全同構 | 要挑「某主題／類別的代表詞」 | 分母 $P(t)$ 極小時倍數會爆掉 → 必須配 support penalty（2.3） |

**χ² 保留正負號是一個常被跳過但很值錢的動作。** 一般卡方只有「偏離程度」，看不出是高於還是低於期望（【實測】04 §4.4）。保留正負號之後，同一份計算同時給你兩件事：正值 = 這個客群特有的說法；**負值 = 這個客群明顯不講的話**。後者在做品牌區隔與 messaging 時同樣有價值 —— 例如「免運」在高價值客群是強負值，代表這群人根本不談運費，那把運費優惠當成對他們的主打就是浪費預算。

公式一律引用 `17_指標公式庫.md`；本節只補文本情境專用的兩條（來源：教材與 HW1，非本文自創）：

$$\chi^2_{\text{signed}}(t,c)=\frac{(O-E)^2}{E}\times\operatorname{sgn}(O-E),\qquad E_{DF}=\frac{df_t^{\text{全體}}}{N}\times N_c$$

$$\text{Lift}(t,c)=\frac{P(t\mid c)}{P(t)}=\frac{df_{t,c}/N_c}{df_t/N}$$

### 2.3 硬性篩選與融合排序的參數（全部標出處）

下表的每一個數字都來自 HW1 的實作，**照抄可用；要改就改，但必須依 00 §1.4 寫進 `params.yml` 的四欄（值／理由／出處／敏感度）**。

| 參數 | 值 | 出處 | 沒過的代價 |
|---|---|---|---|
| 本地 DF 門檻 | ≥ 2 | 【實測】04 §5 Step 4.1 | 偶發詞、切詞錯誤混進最終清單 |
| 全體 DF 門檻 | ≥ 2 | 同上 | 同上 |
| 方向性（富集） | Lift > 1 | 同上 | 選到「反而不偏向這類別」的詞 |
| 方向性（超越期望） | DF 卡方 > 0 | 同上 | 同上 |
| 3-gram 放寬 | 存活 < 目標 N 時，本地 DF 降為 ≥ 1，**且必須在 diagnostics 標記「條件放寬 = Y」** | 【實測】04 §8.2 坑 #9 | 放寬而不留痕 = 18-E22 的文本版 |
| Composite 權重 | TF-IDF 0.25／Lift 0.30／DF 卡方 0.30／MI 0.15 | 【實測】04 §5 Step 4.3、§6（權重理由原文完整） | — |
| Support penalty | $\min(1,\frac{DF}{3})\times\min(1,\frac{DF_{\text{全體}}}{5})$ | 【實測】04 §5 Step 4.4 | 低 DF 詞靠單一指標衝上榜 |
| Agreement bonus | $0.05\times(\text{入選方法數}-1)$ | 【實測】04 §5 Step 4.5 | — |
| 最終輸出 | Top 20 + 候補 10 | 【實測】04 §7；教材作業要求每張表 20 個【實測】01 §8.8 | 沒有候補 = 沒有人工覆核的餘地 |

$$\text{FinalScore}=\underbrace{\left(\sum_m w_m \cdot \text{rank}^{01}_m\right)}_{\text{Composite}}\times \text{SupportPenalty}+\text{AgreementBonus}$$

**三段分數要分別輸出**（Composite / Penalty / Bonus），這樣任何一個詞的名次都可以逐項拆解回來源 —— 這是可解釋性設計，也是 00 §1.2「每個數字都要能追回計算過程」在這裡的落地（【實測】04 §8.2 評註）。

### 2.4 一個真實的方法論瑕疵：MI 與 Lift 可能是同一個東西

這條必須寫進來，因為它是 HW1 裡**尚未被作者發現的問題**，而且會在任何「多指標融合」的專案重演。

HW1 的 workbook 版 MI 定義為 $\log_{10}\frac{df_{t,c}}{df_t \times N_c}$，展開後：

$$\text{MI}_{\text{workbook}}=\log_{10}(\text{Lift})-\log_{10}(N)$$

$N$ 在同一 gram 下是常數，所以 **MI 只是 Lift 取 log 再平移，兩者排序完全相同**（【實測】04 §4.5 評註）。後果有三個，都是實質的：

1. `rank_mi` 與 `rank_lift` 逐位相同 → Lift 的實際權重是 $0.30+0.15=0.45$，不是宣稱的 0.30。四方法融合實際上只有三方法。
2. 候選池裡 MI 與 Lift 的 Top-20 是同一批詞 → 這些詞的「入選方法數」自動 +2，AgreementBonus 被系統性放大 0.05，**共識是假共識**。
3. 原文說「MI 只給 15% 比較穩健」，這個防衛在數學上失效了。

修法**不是**把 MI 換成標準 PMI（$\log\frac{P(t,c)}{P(t)P(c)}$ 仍與 Lift 同單調，換了等於沒換），而是換一個**不同族**的指標，或直接移除 MI 把權重併回。

```python
# 融合排序前的必跑檢查 —— 三行，抓的是「不會報錯的錯」（同 00 §1.3 的免費斷言精神）
from scipy.stats import spearmanr
for a, b in itertools.combinations(METHOD_COLUMNS, 2):
    rho = spearmanr(df[a], df[b], nan_policy="omit").statistic
    if abs(rho) > 0.99:                      # 【推導，待驗證】0.99 是「疑似代數同構」門檻
        raise ValueError(f"{a} 與 {b} 的 Spearman ρ={rho:.4f}，疑似單調同構，"
                         f"權重會被重複計算；請確認公式或移除其中一個")
    if abs(rho) > 0.90:                      # 【推導，待驗證】高相關但未必同構
        print(f"⚠ {a} 與 {b} ρ={rho:.4f}，共識加分可能被高估，請在報告註明")
```

## 三、診斷順序：「keyword 結果看起來很怪」

這是一條**按順序排查**的清單，不是一堆並列的可能性。順序是照「多久能查完 × 多常是真兇」排的，前六條全部來自教材與 HW1 的實際踩坑紀錄。

| # | 症狀 | 檢查 | 判定與處理 | 出處 |
|:--:|---|---|---|---|
| 1 | 詞表全是單字（「的」「好」「不」） | 中文語料有沒有先斷詞？ | 沒斷 → 會變成單字元或亂切，keyword 整個崩掉。回 §1.2 | 【實測】01 §15.7 |
| 2 | 斷詞跑了但詞表還是單字 | 斷完有沒有**用空白 join**？ | 沒 join → vectorizer 仍不知道怎麼切。**這是不會報錯的錯** | 【實測】01 §15.7 |
| 3 | 品牌／型號變成碎片 | 專有名詞有沒有被切壞？ | → 補自訂詞典（§1.4）。補完**要重跑整條 pipeline**，不是只改詞表 | 【實測】01 §15.7 |
| 4 | 英文詞表全是 the / of / and | 有沒有加 `stop_words="english"`？中文有沒有給停用詞表？ | 中文**沒有內建停用詞表**，一定要自己給 | 【實測】01 §15.5 |
| 5 | **品牌名不見了** | 語料是不是單一主題（全是自家品牌）？ | **這是 IDF 的正常行為，不是 bug**：$df$ 大 → $idf \approx 0$。要「代表詞」就別只信 TF-IDF，改用 Lift／χ²，或把品牌名列為 must-keep | 【實測】01 §8.2 |
| 6 | 大量只出現 1 篇的怪詞排在前面 | IDF 被極端稀有詞衝高？ | 改用 χ² / Lift 修正，並套 support penalty（2.3） | 【實測】01 §8.3、04 §5 Step 4.4 |
| 7 | MI 欄出現 `inf` 或 `-inf` | 是不是 $f(x,y)=0$ 造成 $\log 0$？ | **先做規則處理**：設 MI=0，或做 smoothing。不可以留 `inf` 進排序（`inf` 會霸榜） | 【實測】01 §15.4 |

| 9 | 兩個指標的 Top 20 幾乎一樣 | 跑 2.4 的 Spearman 檢查 | ρ > 0.99 → 疑似代數同構，權重被重複計算 | 【實測】04 §4.5 評註 |
| 10 | 換一組權重結論就翻 | 做權重敏感度：Top 20 重疊率 | 重疊率低 → 結論靠權重撐著，不是靠資料。必須在報告揭露（00 §1.4 的 `sensitivity` 欄） | 【推導，待驗證】教材未做敏感度分析，04 §11 已列為缺口 |

## 四、吸睛字詞分析（M10-B）

### 4.1 這是因果問題，不是文本問題

先講結論：**「出現在高 CTR 廣告裡的詞」不等於「這個詞造成高 CTR」。**

高 CTR 的廣告通常不只是文案不同。它可能同時佔了更好的版位、投給更精準的受眾、用了更好的圖、跑在更好的時段、拿到更多預算所以演算法給它更多優質曝光。這些東西**和文案高度相關** —— 團隊會把最好的文案配給最重要的檔期與最好的版位，這是理性的操作，但它讓「詞 → CTR」的單變量比較徹底失效。

【示例，假想數字，非實測】假設「限時」出現在 40 則廣告，平均 CTR 3.2%；沒有「限時」的 160 則平均 CTR 1.8%。單變量看差 1.4pp，看起來「限時」很威。但把版位拆開之後：帶「限時」的 40 則裡有 32 則跑在動態消息（該版位整體 CTR 3.0%），沒帶的 160 則只有 48 則在動態消息（其餘在版面右側，該版位整體 CTR 1.5%）。控制版位後「限時」的邊際效果可能只剩 0.2pp 甚至反向。**錯誤行動**：文案團隊把 200 則素材全部加上「限時」，同時把預算配置維持不動 —— 成效不會動，因為真正在起作用的是版位。

這正是 18-G6（相關性直接寫成行銷建議）在文本上的版本，也是 00 §1.5 措辭白名單要擋的東西。

### 4.2 正確做法：把詞特徵放進控制了其他變數的模型

$$\text{CTR}_i \sim \text{詞特徵}_i + \text{版位}_i + \text{受眾}_i + \text{時段}_i + \text{素材類型}_i + \log(\text{預算}_i) + \log(\text{曝光量}_i)$$

詞的係數才是「控制了這些之後的邊際效果」。幾個實作上必須注意的點：

| 項目 | 規則 | 理由 |
|---|---|---|
| 應變數形式 | CTR 是比例，**不要直接對 CTR 跑 OLS**。用二項式 GLM（logit link），`freq_weights = 曝光量`；或對 (點擊, 未點擊) 建模 | 曝光 100 的 3% 與曝光 100 萬的 3% 精確度差幾個數量級，OLS 會等權對待。詳見 `08_迴歸建模.md` |
| 詞特徵編碼 | 廣告層級的 **0/1 出現與否**，不用 TF | 一則廣告文案只有幾十字，TF 幾乎都是 1，且長文案天生佔優 |
| 詞特徵數量 | 先用第二節的流程篩到可管理的量；候選詞要求「出現在 ≥ 30 則廣告」【推導，待驗證】 | 出現在 3 則廣告的詞，係數的信賴區間會寬到沒有意義。門檻要寫進 `params.yml` 並做敏感度 |
| 共線性 | 詞之間高度共現（「限時」常和「優惠」同框）→ 查 VIF，或改用 group lasso / ridge | VIF > 5 的處理見 18-E10 精神與 `08_迴歸建模.md` |
| 多重比較 | 幾十到幾百個詞係數 → **一律做 BH FDR 校正**，同時列原始 p 與校正後 p | 18-G8 |
| 不顯著的詞 | 要列表、要寫商業意涵，**同列必附 MDE**（00 §四） | 18-E16、18-E17 |
| 樣本切分 | 廣告層級的觀測值不獨立（同一 campaign 下的廣告共享受眾與預算池）→ 用 cluster-robust SE，cluster = campaign | 忽略會讓 SE 低估、p 值虛假顯著 |

### 4.3 結論只能標到哪裡

| 你做了什麼 | 能說的話 | **禁止說的話** | 證據等級 |
|---|---|---|---|
| 高 CTR 組 vs 低 CTR 組的詞頻對照 | 「『限時』出現在高 CTR 組 62% 的文案、低 CTR 組 18%」 | 任何含「提升／帶動／造成」的句子 | 相關 |
| 控制了版位／受眾／時段／素材／預算／曝光的 GLM | 「**在控制版位、受眾、時段、素材類型、預算與曝光量之後**，含『限時』的廣告 CTR 高 0.2pp（95% CI 0.05–0.35，BH 校正後 q=0.03）」 | 「加上『限時』會讓 CTR 提高 0.2pp」 | 相關（條件關聯） |
| 同素材同受眾，只改文案的 A/B | 「實驗組 CTR 高 0.2pp（95% CI …，n=…／組）」 | —（此時可用因果動詞） | 實驗 |

**要到因果只有一條路：A/B 測試 —— 同素材、同受眾、同版位、同時段，只改文案。** 這正好就是 M12 的題目，把它寫成需求交出去（`15_實驗設計.md`），不要在 M10 硬拗。

### 4.4 常見的三個附加陷阱

```
① 倖存者偏誤：被關掉的廣告不在報表裡
   投手會把跑不動的素材提早關掉 → 低 CTR 的文案曝光量小、甚至整筆消失
   → 分析前先確認資料是「所有曾上線的廣告」還是「目前還在跑的廣告」
   → 只有後者 = 樣本已被成效篩選過，任何詞的係數都被污染

② 學習期與時間趨勢：新素材前 3 天的 CTR 不是穩態
   → 加 campaign 固定效果 + 素材上線後天數，或直接排除學習期
   → 排除幾則、占曝光多少，要寫進 _log（18-E22）

③ 文案長度是隱形共變數
   長文案天生含更多詞 → 「含某詞」與「文案較長」混在一起
   → 模型一定要放 log(字數)，否則你測到的是長度不是詞
```

## 五、SEO 字詞分析（M10-C）

### 5.1 這個子模組的資料需求和前面完全不同

SEO 關鍵字選擇要回答的是「**多少人在搜這個詞**」。這個數字**不在你的語料裡** —— 評論、客服逐字稿、廣告文案，全都只告訴你「已經接觸到你的人怎麼講話」，不告訴你「還沒接觸你的人在 Google 打什麼」。這是資料缺口，不是分析技巧問題，**必須在 M1 的「因此建議做／不做」明確講出來**。

唯一內部可得的近似是**站內搜尋 log**（使用者在你的網站搜尋框打了什麼）。它有價值，但它的母體是「已經到站的人」，天生漏掉整個獲客漏斗上游 —— 拿它當 SEO 依據等於只研究已經進門的客人要買什麼，卻不知道路過的人在找什麼。

| 需要的欄位 | 從哪來 | 語料能不能替代 |
|---|---|---|
| 月搜尋量 | Google Keyword Planner／Ahrefs／Semrush／Similarweb | **不能** |
| 關鍵字難度／競爭度 | 同上（或自行以 SERP 前 10 名的網域權重估） | **不能** |
| CPC（付費競價成本，商業意圖的代理變數） | Keyword Planner／廣告帳戶 | **不能** |
| 自家相關性（這個詞對應到哪個商品／頁面） | 內部：`dim_product`、站內內容盤點 | **可以**，這是語料唯一的貢獻 |
| 目前排名 | Search Console／排名追蹤工具 | 不能 |
| 站內搜尋量（近似訊號） | 站內搜尋 log | 部分，但母體不同 |

### 5.2 這是三維排序，不是文本分析

$$\text{Priority}(k)=\underbrace{f(\text{搜尋量}_k)}_{\text{有多少人在找}}\times\underbrace{g(1-\text{競爭度}_k)}_{\text{打得贏嗎}}\times\underbrace{h(\text{相關性}_k)}_{\text{找來的人會買嗎}}$$

三個維度必須都有，缺一個就會做出典型的錯誤決定：

| 缺哪一維 | 會做出什麼錯誤決定 |
|---|---|
| 缺搜尋量 | 主打一個沒人搜的詞，內容寫完沒有流量 |
| 缺競爭度 | 主打「保養品」這種頭部詞，和一整排大品牌硬碰，投入半年排不進前 3 頁 |
| 缺相關性 | 搶到高流量詞但和商品無關，跳出率高、轉換是 0，等於買了假流量 |

**權重與函數形式一律標【推導，待驗證】**：本 skill 不給預設權重，因為它高度依賴產業與網站現況（新站要偏長尾、老站可以搶頭部）。落地方式沿用 00 §1.4 —— 寫進 `params.yml` 四欄，並做敏感度（換權重後 Top 30 的重疊率是多少）。

### 5.3 語料在 SEO 裡真正的角色

語料不能給搜尋量，但它能給**別的工具給不了的東西：你的顧客實際用的詞**。關鍵字工具給的是通用詞，顧客講的可能完全不一樣（工具說「精華液」，評論裡都在講「小棕瓶」）。所以正確的接法是：

```
第二節的關鍵詞抽取（自家語料）
   │  產出：顧客真正在用的說法（含口語、俗名、錯字、台灣在地用語）
   ▼
丟進關鍵字規劃工具，取回 搜尋量 / 競爭度 / CPC
   │  這一步是外部資料，M10 做不到，要先確認工具權限
   ▼
三維排序（5.2）
   │
   ▼
交付：關鍵字優先序表（詞／月搜尋量／競爭度／相關性／目前排名／建議動作）
       每個詞都要寫「對應哪個頁面、要做什麼」（18-E20：建議不可空泛）
```

**沒有外部資料時的正確回應**（不是硬做，是說「不」，見 00 §六）：

| 情況 | 回報怎麼寫 |
|---|---|
| 完全沒有外部搜尋量 | 「M10-C 不可用。SEO 需要外部搜尋量資料（Keyword Planner／Ahrefs／Semrush），本批資料無法回答『多少人在搜這個詞』。可先交付『顧客用語清單』作為關鍵字工具的輸入。」 |
| 只有站內搜尋 log | 「可做站內搜尋詞分析，但母體是**已到站訪客**，不可外推到自然搜尋流量。搜尋量欄標 `N/A`。」 |
| 有工具但沒有台灣區資料 | 「地區設定必須是台灣＋繁中，否則搜尋量是別的市場的。設定值寫進 `params.yml`。」 |

## 六、新技術：什麼時候值得升級

一樣照 00 §二的階梯走：**前提最少的先做，升級的理由必須是前一層在這批資料上的具體失效**。下面每一項都只給「什麼時候用、什麼時候不用」，不展開原理 —— 需要展開時再去查套件文件。

| 技術 | 取代誰 | 升級的觸發條件（要點名） | 額外前提 | 不要用的時候 |
|---|---|---|---|---|
| **KeyBERT** | TF-IDF 關鍵詞抽取 | 診斷順序第 8 條成立：語意相近詞被拆成互不相干的維度（點名詞組，例：「便宜／CP值高／划算／不貴」四個詞各自進不了 Top 20，合起來卻是最大主題） | embedding 模型；文件數多時要算 embedding，比 TF-IDF 慢一到兩個量級 | 只有幾百篇短文本、TF-IDF 已經給出可用清單時 |
| **BERTopic** | LDA | LDA 主題不可解讀（同一主題混了兩件事）、或主題數 k 換一個值結論就翻 | embedding + UMAP + HDBSCAN；**隨機性大，必須固定 random_state 並跑穩定性檢查**（同 18-G7 對 k 的要求） | 文件數 < 幾百篇（HDBSCAN 會把大部分文件丟進 outlier） |
| **繁中 embedding 模型**：BGE-M3／multilingual-e5／jina-embeddings-v3 | TF-IDF 向量 | 上面兩項的前提 | **三者的繁中支援度不同，一定要在自己的語料上實測再選**【推導，待驗證：本文不給排名，因為未在本專案語料上比較過】 | — |
| **Aspect-based 情感（ABSA）** | 整篇正負分類 | 整篇情感無法行動：一則 3 星評論同時誇物流、罵包裝，整篇標「中性」等於沒有資訊 | 需要定義面向清單（物流／包裝／客服／價格／品質…），並人工標一批驗證 | 只要知道整體滿意度趨勢時 |
| **few-shot LLM 標註 + 小模型蒸餾** | 通用情感詞典 | **繁中電商語境特殊，通用情感詞典表現差**（「雷」「地雷」「踩雷」是負面、「毒」在美妝是正面、「盤」是貴） | 要有人工標註的驗證集才知道 LLM 標得準不準 | 沒有驗證集時 —— 不然你只是把不知道準不準的詞典換成不知道準不準的 LLM |

**升級前後一定要做的一件事**：新方法的結果和舊方法的名單重疊率。00 §2.4 講得很清楚 —— 重疊率 > 90% 就停在舊方法，把重疊率放進附錄。升級要花時間、要多一個環境、要多一組參數，不改變決策就不值得。

```python
# 升級前的必要對照：三行，決定要不要升級
old = set(tfidf_top_terms[:30])
new = set(keybert_top_terms[:30])
overlap = len(old & new) / 30
print(f"Top30 重疊率 {overlap:.1%}｜只有新方法抓到：{sorted(new - old)}")
# 【推導，待驗證】沿用 00 §2.4 的 90% 門檻：
#   overlap > 0.90 → 停在 TF-IDF，把重疊率與差集寫進附錄
#   overlap ≤ 0.90 → 升級，並在章節接縫點名「新方法多抓到哪幾個詞、那些詞為什麼重要」
```

## 七、不做文字雲，以及其他負面清單

文字雲在 `SKILL.md` 的負面清單裡，`19_圖表與統計表規格.md` §1.8 也明令禁用。理由不是「不好看」，是它**在統計上不成立**：

| 問題 | 具體是什麼 |
|---|---|
| 字級只編碼頻率 | 頻率是第二節四個指標裡**最沒有鑑別力**的那一個。整張圖等於只用了最差的排序依據 |
| 面積非線性 | 字級加倍、面積變四倍，讀者接收到的是面積 → 系統性誇大高頻詞 |
| 排版隨機 | 位置與角度不編碼任何資訊，卻會影響讀者的注意力分配 |
| 兩張圖無法比較 | 換一批資料重畫，佈局全變 → 無法做「本群 vs 全體」或「本季 vs 上季」 |
| 長詞天生佔優 | 中文 4 字詞比 2 字詞面積大一倍，與重要性無關 |
| 會被高頻無意義詞主導 | 停用詞沒清乾淨時，整張圖就是「真的／覺得／很／好」 |

**替代方案就是第二節那套四指標排序**：要看「講最多」用詞頻長條；要看「這群特別在講」用 Lift 或 signed χ² 的差異長條。後者比前者有價值得多，19 §1.8 要求**兩張都要出**。

| 也不要做的 | 為什麼 | 改成 |
|---|---|---|
| 雷達圖比較主題分布 | 19 §4.3 禁用清單（軸順序任意、面積誤導） | 分組水平長條 |
| 只報詞頻不報區辨力 | 詞頻表看起來像結論但不能行動（00 §1.1） | 詞頻 + Lift/χ² 並列，並排序 |
| 用整篇情感分數直接下行銷建議 | BOW 丟掉語序與否定，「不好吃」含「好吃」（【實測】01 §4.2 的直接推論） | ABSA，或至少人工抽驗一批確認方向沒反 |
| 把 LLM 產出的主題名當結論 | 沒有樣本支持的命名 = 幻覺風險 | 主題名旁邊一律附「該主題文件數 + 代表文件 3 則原文」 |
| 對 `inf` / `NaN` 直接排序 | `inf` 會霸榜（見 3.1 第 7 條） | 先做規則處理，並在表格標 `N/A` |
