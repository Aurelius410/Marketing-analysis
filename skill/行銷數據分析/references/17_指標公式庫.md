# 指標公式庫

這份文件是所有顧客指標的**單一真相**。E8（公式抄錯）就是因為公式散在各處被逐份手寫 —— 一旦某個地方寫成 `BE = w1·GE × w2·IE`（應為加號），錯誤就會一路傳到結論。

**規則：任何指標都不准在分析腳本裡就地手寫公式，一律呼叫 `scripts/build_features.py` 的實作。** 這份文件是那些實作的規格書。

最重要的是 §八 的驗證基準值 —— 那是用 IB5082 課程資料集（Excel 手工做出來的答案）逐位比對過的 ground truth。**任何指標實作改動後，都要重跑一次 `tests/test_metrics.py`。**

## 一、前置：粒度與去重（做錯這步後面全錯）

行銷交易資料的分析單位是**天**，不是筆。同一顧客同一天多筆交易要壓成一筆，否則購買間隔會出現大量 0，把 MLE/WMLE/CAI 全部拉歪。

```sql
-- Step 0：只留分析必要欄位
-- Step 1：以「客戶ID + 日期」去重，壓成一天一列
CREATE OR REPLACE TABLE stg_customer_day AS
SELECT DISTINCT
    cust_id,
    CAST(txn_datetime AS DATE) AS txn_date
FROM raw_transaction;

-- 排序是後續 LAG/LEAD 正確的前提，不可省
```

**實測數字（課程資料集）**：7,764 筆原始交易 → 去重後 **5,294 筆**（同客戶同日整併）→ 再刪每人最後一筆 → **5,194 筆**（可算間隔的列數）。

## 二、RFM 三指標

$$R_i = D_{\text{base}} - \max_{t \in T_i}(\text{date}_t), \qquad F_i = |T_i|, \qquad M_i = \sum_{t \in T_i}\text{amount}_t$$

- $D_{\text{base}}$ = 基準日。**必須明確指定，不可預設用「今天」**（會讓歷史報告每次重跑數字都變）。課程資料集用 `2012-12-01`。
- $F_i$ 的口徑：預設**交易筆數**（去重前的原始筆數），若改用「購買天數」或「品項數」必須寫進指標字典。
- $M_i$ 的口徑：預設**淨額**（扣退貨）。同時輸出毛額版供對照（見 G2）。

```sql
CREATE OR REPLACE TABLE feat_rfm AS
SELECT
    cust_id,
    DATE_DIFF('day', MAX(txn_date), DATE '2012-12-01') AS r_days_since_last_sale,
    COUNT(*)                                            AS f_txn_cnt,
    COUNT(DISTINCT txn_date)                            AS f_active_days,
    SUM(amount)                                         AS m_net_twd
FROM fact_transaction
WHERE txn_date <= DATE '2012-12-01'      -- as_of_date 防洩漏，不可省
  AND txn_type = 'sale'                  -- 排除 return/void/exchange，不可省
GROUP BY cust_id;
```

**這段 SQL 有兩個「不可省」，兩者漏掉的後果完全不同：**

> ⚠️ **`WHERE txn_date <= as_of_date`** —— 防目標洩漏（G4）。任何特徵計算都要有它。
>
> ⚠️ **`AND txn_type = 'sale'`** —— 沒有它，**退貨列會污染 R**，而且是沉默的。一位顧客最後購買是 2025-08-10、2026-07-20 辦退貨，退貨在系統裡是一筆交易列 → `R = 基準日 − MAX(txn_date)` = 6 天 → 這位一年沒買的顧客被算成「最近極活躍」→ 落進 `R_score=5` → 進了冠軍客戶名單、收到 VIP 禮。F 也會被換貨（一退一買）重複計算。
>
> **課程資料集測不出這組 bug** —— 它實測無負值、無零值、不含退貨。所以這條過濾必須由 dirty fixture 驗證（見 §八）。

**欄名一律帶口徑後綴，禁止裸 `F` / `M`。** 因為 `F` 有三種粒度（筆數 / 消費天數 / 品項數）而數字差很多：客戶 89 的 `f_txn_cnt = 85`、`f_active_days = 68`，用前者算客單價得 1,773、用後者得 2,216，**差 25%**。三個恆成立的不等式可以當免費的正確性檢查：

$$\texttt{f\_active\_days} \le \texttt{f\_txn\_cnt} \le \texttt{f\_item\_cnt}$$

## 三、RFM 計分：三種方法（要並排比較）

### 3.1 五等分法（無母數分位）

```sql
-- R：越小越高分；F/M：越大越高分
SELECT cust_id,
    6 - NTILE(5) OVER (ORDER BY R ASC)  AS R_score,   -- R 小 → 分數高
    NTILE(5) OVER (ORDER BY F ASC)      AS F_score,
    NTILE(5) OVER (ORDER BY M ASC)      AS M_score
FROM feat_rfm;
```

原 Excel 版用 `PERCENTRANK.INC` + 五級對照，等價於 NTILE(5)。原範本回傳文字 `"5"`，實作時一律用數值。

### 3.2 原版 Bob Stone

$$R\text{-score} = \begin{cases}24 & 0 \le R \le 90 \\ 12 & 91 \le R \le 180 \\ 6 & 181 \le R \le 270 \\ 3 & 271 \le R \le 360 \\ 0 & R > 360\end{cases}
\qquad F\text{-score} = 4F \qquad M\text{-score} = \min(\lfloor c \cdot M \rfloor,\ 9),\ c = 0.0025$$

原文的自訂 R-score 變體：`=INT(2^(4-INT(B3/90)))`（值域 1~16）。

### 3.3 自訂 Bob Stone（權重要寫理由）

**硬規則：自訂權重必須說明「為什麼這個產業要這樣訂」。只給權重不給理由 = 核心致命傷。**

範本表格（四欄，缺一不可）：

| 構面 | 給分機制 | 權重 | 原因（產業特性論證） |
|---|---|---|---|
| Recency | 級距與分數 | 高/中/低 | |
| Frequency | 換算式 | 高/中/低 | |
| Monetary | 換算式與上限 | 高/中/低 | |

### 3.4 三法比較（作業硬性要求）

取三種方法排名的**前 20~30% 與後 20~30%** 樣本，做特徵描述與差異比較。只列排名不做特徵比較會被扣分。

## 四、動態指標：λ、MLE、WMLE、CAI

### 4.1 購買間隔與顧客層參數

$$\lambda_i = \frac{1}{n_i-1}\sum_{j=2}^{n_i}\left(t_{ij}-t_{i,j-1}\right) \quad\text{(平均購買間隔，天)}$$

$$\mu_i = \frac{1}{n_i}\sum_{j=1}^{n_i}\text{Amount}_{ij}, \qquad \text{Recency}_i = T_{\text{obs}} - t_{i,n_i}$$

**標準化流失訊號**（衍生，非教材原文，但實務上比裸 Recency 有用得多）：

$$\text{Churn Signal}_i = \frac{\text{Recency}_i}{\lambda_i} \qquad (\gg 1 \Rightarrow \text{異常沉睡})$$

> 為什麼要標準化：「30 天沒買」對月買一次的人是正常，對週買一次的人是流失警訊。裸 Recency 分不出這兩種人。

### 4.2 CAI（Customer Activity Index）完整六步

令顧客 $i$ 有 $n_i$ 次購買日（**已去重後**），則間隔數 $m_i = n_i - 1$。

$$\text{int}_{ij} = t_{i,j+1} - t_{i,j}\ (j = 1 \dots m_i), \qquad w_{ij} = j$$

$$\text{MLE}_i = \frac{1}{m_i}\sum_{j=1}^{m_i} \text{int}_{ij}, \qquad
\text{WMLE}_i = \frac{\sum_{j=1}^{m_i} j \cdot \text{int}_{ij}}{\sum_{j=1}^{m_i} j}$$

> ⚠️ **分母是間隔數 $m_i = n_i - 1$，不是購買次數 $n_i$。** 這與 §4.1 的 $\lambda_i$ 是同一個量（$\text{MLE}_i \equiv \lambda_i$），也與已驗證的 SQL `AVG(interval_days)` 一致 —— `AVG` 的分母正是間隔列數。
> 本文件曾把 §4.2 的分母誤寫為 $n_i$（2026-07-26 由缺口審查抓出並更正）。這正是 E8「公式抄錯」發生在號稱單一真相的公式庫裡的實例 —— 記錄下來提醒：**同一個量在同一份文件出現兩次時，一定要交叉檢查。**

$$\boxed{\ \text{CAI}_i = \frac{\text{MLE}_i - \text{WMLE}_i}{\text{MLE}_i} \times 100\ }$$

```sql
-- Step 1-2：去重後排序，算間隔（跨客戶的那筆自動為 NULL）
WITH d AS (
    SELECT cust_id, txn_date,
           ROW_NUMBER() OVER (PARTITION BY cust_id ORDER BY txn_date) AS seq,
           LEAD(txn_date) OVER (PARTITION BY cust_id ORDER BY txn_date) AS next_date
    FROM stg_customer_day
),
-- Step 3：權重 = 交易序位；刪掉每位客戶最後一筆（next_date IS NULL）
w AS (
    SELECT cust_id, seq AS weight,
           DATE_DIFF('day', txn_date, next_date) AS interval_days
    FROM d WHERE next_date IS NOT NULL
)
-- Step 4-5：彙總 → WMLE → CAI
SELECT cust_id,
       AVG(interval_days)                                        AS mle,
       SUM(weight * interval_days) / SUM(weight)                 AS wmle,
       (AVG(interval_days) - SUM(weight * interval_days) / SUM(weight))
           / AVG(interval_days) * 100                            AS cai
FROM w GROUP BY cust_id;
```

**執行順序不可跳步**（漏一步評分標準明列會降等）：
1. 只留 `客戶ID` + `日期` 兩欄
2. 串接去重 → **同客戶同日壓成一筆**
3. **依客戶ID + 日期排序**（否則 offset 全錯）
4. 算 `int`
5. **刪除每位客戶的最後一筆**
6. 算 `weight`（序位）與 `int × weight`
7. 彙總三個量
8. 算 WMLE、CAI
9. 常態累積分佈 → 切「非常活躍群／非常不活躍群」→ 用人口統計比較兩群

**CAI 解讀方向**：`CAI > 0` = 節奏加快 = 越來越活躍；`CAI < 0` = 節奏變慢 = 走向流失。

**分佈機率化**：`NORM.DIST(x, mean, sd, 1)`，課程範本用 `mean=0, sd=15`。

## 五、貝氏收縮平均（處理小樣本個體不穩定）

$$\hat{\theta}_i = \lambda_i \bar{x}_i + (1-\lambda_i)\mu, \qquad \lambda_i = \frac{n_i \tau^2}{n_i \tau^2 + s^2}$$

其中 $\bar{x}_i$ 為個體均數、$\mu$ 為區隔總體均數、$n_i$ 為個體樣本數。買 2 次的人平均金額不該和買 200 次的人等同視之 —— 收縮估計把前者往總體均數拉。

## 六、購物籃分析：兩條路線

### 6.1 相關矩陣路線（對稱、無方向）

```sql
-- Step 1：客戶 × 品類的 0/1 矩陣（注意：在品類層級，不是 SKU —— 見 E12）
-- Step 2：對 0/1 矩陣求 Pearson 相關
-- Step 3：unpivot 成長表 → 降冪 → Top 20
```

⚠️ **必須設最低共現次數門檻（n≥5）**。在稀疏二元資料上，只要兩商品恰好被同一人買過就會得到 `r=1`（E10 的實證：有份報告 Top 12 組合的 r 全部是 1）。`|r|=1` 一律標記「樣本不足，不可解讀」。

### 6.2 條件機率路線（非對稱、有方向）

$$P(B \mid A) = \frac{N(A \to B)}{\sum_{B'} N(A \to B')}$$

```sql
-- Step 1：依「客戶ID + 日期」排序，用 LEAD 取「下次購買產品」
-- Step 2：轉移次數矩陣（本次品類 × 下次品類）
-- Step 3：條件機率 —— 分母是「列總計」，不是「全表總計」
```

> ⚠️ 課程範本裡有一個**錯誤寫法**：`=轉移矩陣!B4/轉移矩陣!$Q$19`（用全表總計當分母）。這會退化成聯合機率、**失去方向性**。正確是除以列總計 `$Q4`。

### 6.3 兩法比較（報告必備）

| 比較維度 | 相關係數矩陣 | 條件機率矩陣 |
|---|---|---|
| 數學本質 | 兩者變動趨勢的線性同步性 | 已知 A 發生下 B 發生的條件機率 |
| 方向性 | 無方向（對稱），A→B = B→A | 有方向（非對稱），A→B ≠ B→A |
| 商業解讀 | 哪些產品屬於「同一個消費生活圈」 | 「買了 A 之後有多大機率買 B」 |
| 數據敏感度 | 容易放大低頻但趨勢一致的組合 | 反映真實交易量基數與信心度 |
| 核心應用 | 產品促銷與包裝設計；整體行銷規劃 | 動態即時推薦；個體、有時間先後的系統觸發 |

**加上因素分析（第三法）**：籃子少但每籃品項多，能降維看見整體商業結構、描繪消費者輪廓；額外產出**因素分數**（每位消費者對每個購物籃的偏好強度）。整合策略是**先用因素分析做大方向輪廓分群，再對各客群用相關係數找具體搭售組合**。

## 七、ARFM 十六分類

| 維度 | 資料庫欄位名 | 二分水準 | 標籤用詞 |
|---|---|---|---|
| A | `活躍性_Activity` | 低活躍性 / 高活躍性 | 不活躍 / 隨機 |
| R | `最近購買日期_Recency` | 近 / 遠 | （流失，或省略） |
| F | `購買頻率_Frequency` | 低 / 高 | 游離 / 忠誠 |
| M | `購買金額_Monetary` | 低 / 高 | 低價值 / 高價值 |

交叉後 2⁴ = **16 類**。標籤串接規則：`A-[R]-F-M`，R 僅在「流失」時出現於字串中（未流失則省略該段），所以標籤長度不固定。

A 這一維是 ARFM 比傳統 RFM 多出來的，原料就是 §四 的 $\lambda_i$ 與其分散程度（規律 vs 隨機）。
