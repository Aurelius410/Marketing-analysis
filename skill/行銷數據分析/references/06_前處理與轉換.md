# 前處理與轉換（M3）

這個模組的核心不是「有哪些轉換方法」，而是**在一個具體的資料情境下，第一順位該做什麼、為什麼不做第二順位**。方法目錄網路上到處都有，但沒有一份會告訴你「右偏的客單價要拿去做預測」和「右偏的客單價只是要畫圖」應該走完全不同的路。

漏掉這一節的代價是可量化的：一份右偏的交易金額資料，取 log 建模再 `exp` 回去，會把 1,909 元的平均客單價報成 688 元 —— **系統性少算 64%**，而且模型的 R² 看起來完全正常，殘差圖也漂亮。這種錯誤不會在任何診斷裡跳出來，它會一路走到營收預測、預算編列、庫存備貨，最後在缺貨的時候才被發現。同一份資料如果先 winsorize 再轉換，會砍掉一位單筆 20 萬保險交易的大客戶，讓他掉出 VIP 名單。

M3 的產出是**轉換後的新欄位 + 一份可審計的轉換紀錄**，不是一個標準化好的矩陣。標準化屬於各方法族自己的第一步（見 §五），在這裡統一做會讓監督式那條路直接洩漏。

進來之前先確認 M2（`05_資料特徵檢驗.md`）已經發過通行證或禁行令；出去之後 M4 要複檢三個門檻：**偏度 <1、變異數同質、排序相關 >0.95**。

## 一、七種資料情境的轉換順位表

### 1.1 先分流，再選方法

情境判定的順序是固定的：**先看值域（有沒有負值、是不是 [0,1]）→ 再看零的比例 → 最後才看偏度**。順序搞反會選錯整條路徑，例如把零膨脹的品類金額當成「右偏含 0」去做 Yeo-Johnson，偏度指標會過關，但分布是雙峰的。

```
                        ┌─ 值域在 [0,1] 且是連續比例 ──────────→ 情境 5（比率）
                        │      ※ 若有整數分子/分母（點擊/曝光）
                        │        不要先算成比率，直接 binomial GLM
                        │
   欄位進來 ─ 檢查值域 ──┼─ 有負值 ────────────────────────────→ 情境 4（含負值）
                        │
                        └─ 全部 ≥ 0 ─┐
                                      │
              零佔比 = (x == 0 的列數) / 非空列數
                                      │
        ┌─────────────────────────────┼──────────────────────────┐
        │                             │                          │
   零佔比 ≥ 30%                  10% ≤ 零佔比 < 30%          零佔比 < 10%
   或為「結構性零」                    │                          │
        │                     零是結構性還是隨機？                 │
        ▼                             │                          ▼
   情境 3（零膨脹）          結構性 → 情境 3          ┌─ 有 0 → 情境 2（右偏含 0）
   ★ 不要轉換，改模型        隨機   → 情境 2          └─ 無 0 ─┐
                                                              │
                                              skew > 1  ──────┴──→ 情境 1（右偏全正）
                                              skew < -1 ─────────→ 情境 6（左偏）
                                              |skew| ≤ 1 ────────→ 不轉換

   ※ 以上都通過之後，若各欄量級差 10^3 以上 ────────────────────→ 情境 7（尺度問題）
     這是尺度問題不是分布問題，不要用 log 去「解決」它
```

**`|skew| ≤ 1` 就不轉換**這條門檻直接沿用 SKILL.md 的 M4 三門檻，不是我另訂的。教材本身只給了方向性規則（「高度偏態的變數，常先取自然對數再分析」，素材：`notion/商管統計資料分析/01_eda_regression_anova.md` §6.3），沒有給數字門檻。

**零佔比 30% 這個切點是我的判斷**〔判斷〕，理由是：零佔比 30% 時，`log(x+c)` 之後有近三分之一的觀測堆在 `log(c)` 這同一個值上，Q-Q plot 會出現一段明顯的水平線，任何常態性檢定都會拒絕 —— 這時再調 c 也沒用，因為問題是機率質量點，不是尺度。低於 10% 時 Yeo-Johnson 通常可以吸收掉。10–30% 是灰帶，改看零的性質。

### 1.2 順位表

| # | 情境 | 判定 | ① 第一順位 | ② 第二順位 | ③ 第三順位 | 絕對不要 |
|---:|---|---|---|---|---|---|
| 1 | **右偏全正值** | `min > 0`、`skew > 1` | **Gamma GLM + log link**（要預測時）| `log(x)`（只做描述／分群輸入時）| Box-Cox（λ 從訓練集學）| 取 log 建模後 `exp` 回去報平均（見 §二）|

| 4 | **含負值** | `min < 0` | **Yeo-Johnson** | `arcsinh(x/θ)` | 水平平移後 log（**平移量必須報告**）| 把負值當缺失刪掉（那是退貨，見 18-G2）|

| 6 | **左偏** | `skew < -1` | `x²` | `x³` | Yeo-Johnson（λ>1 自動處理）| 忽略天花板效應硬轉（見下）|
| 7 | **尺度差異大** | 各欄量級差 ≥ 10³ | **z-score**（在各方法族內做，見 §五）| 有離群 → RobustScaler（中位數 + IQR）| — | 用 log 當作「壓量級」的手段就以為解決了 |

### 1.3 每個情境的關鍵細節

**情境 1 — 為什麼 Gamma GLM 排在 log 前面。** 因為 GLM 建模的是 $\log(\mathrm{E}[Y]) = X\beta$，而 log 迴歸建模的是 $\mathrm{E}[\log Y] = X\beta$。**這兩件事根本不同**，前者 `exp` 回去就是 $\mathrm{E}[Y]$ 的估計，不需要任何修正。家族的判準不是看 Y 長什麼樣，而是看 Var 與 Mean 的關係：常數 → Normal、線性上升 → Poisson、倒 U → Binomial、**超線性上升 → Gamma**（素材：`notion/商管統計資料分析/02_logistic_glm_categorical.md` §1118「不同資料類型中平均值與變異數之間的關係」與 §6.2 家族／連結函數選擇規則表）。客單價、LTV、營收都是「大客戶的變異也大」，屬於超線性。

只有在**不需要預測、只做描述**（EDA 直方圖、分群輸入、相關矩陣）時，才降到 `log(x)`。教材的 Bakery 範例 `lm(log(revenue) ~ county_district)` 就是這一類（素材：同上 01 §11.5）—— 它做的是市場區隔檢定，要的是各行政區的相對差異，不是營收預測值。

**情境 2 — arcsinh 的 θ 一定要報。**

$$\operatorname{arcsinh}\!\left(\frac{x}{\theta}\right) = \ln\!\left(\frac{x}{\theta} + \sqrt{\frac{x^{2}}{\theta^{2}} + 1}\right)$$

θ 決定「線性區到對數區的轉折點」：在 $x \ll \theta$ 時它接近線性，在 $x \gg \theta$ 時它接近 $\ln(2x/\theta)$。**改 θ 不只是改截距，會改係數的大小**，所以彈性解讀會跟著變〔判斷，這是文獻上已知的爭議，非素材內容〕。敏感度做法：θ 取 `p25 / p50 / p75` 三個值各跑一次，把係數並排；若正負號或量級改變，arcsinh 不能用，降級回 Yeo-Johnson，或直接承認這是情境 3 改走 Hurdle。

`log(x+c)` 的 c 更麻煩，因為 c 決定「0 與最小正值之間的距離」，而這個距離是你憑空造的。教材的 0930 腳本用 `eps_y = 0.001`、`eps_pf = 1e-6`（素材：01 §6.5），**那是避免 `log(0)` 的工程保護，不是統計上的 c**。直接把 `1e-6` 當 c 用在金額欄上會製造 `log(1e-6) = −13.8` 的假離群值，把整條左尾拉出去 —— 原本零消費的顧客會變成分布裡最極端的那群，跑 K-means 時他們自己會被切成一群，報告寫成「發現一個特徵鮮明的沉睡客群」，其實只是 c 造出來的。若非用不可，c 取「最小正值的一半」或 `p1`，並寫進轉換紀錄。

**情境 3 — 轉換不能改變機率質量點，只有模型可以。** Hurdle 是兩段：第一段用 logit 建模「買不買」，第二段用截斷 Gamma／lognormal 建模「買了的人買多少」。這兩段的係數可以方向相反，而且**這正是它的價值**：折扣往往提高購買率但降低客單價，轉換做不到這件事，它只會給你一個混合了兩種效應的平均係數。

具體情境：超市資料的 30 個品類中，`會員補卡` 觸及 106/200 = 53% 的客戶（滲透率排名第 1），但總金額只有 780 元；其餘多數品類的滲透率遠低於此（素材：`gdrive/own/03_新資料集剖析_3C與超市.md` §2.4）。對「顧客 × 品類金額」矩陣的任一欄做 `log(x+1)`，有 50–90% 的列會落在 `log(1) = 0` 這個點上。跑迴歸「品類金額 ~ DM 曝光」得到係數 0.8、p < 0.01，結論寫「DM 曝光讓該品類消費提升 80%」，據此把 DM 預算往這個品類加倍。實際上係數被那根零柱子主導，量的是「有沒有被觸及」而不是「觸及後買多少」，加倍預算後金額毫無變化。

結構性零與隨機零要分開：**結構性零**（沒訂閱該服務、該門市根本不賣這個品類）→ 必須 Hurdle，因為那些列不該進第二段；**隨機零**（有機會但這期沒發生）→ Tweedie 可以，$\mathrm{Var}(Y) = \phi\mu^{p}$，`1 < p < 2` 是複合 Poisson-Gamma，天生同時有零的質量點與正值的連續部分，很適合「總金額 = 次數 × 單價」這種行銷資料。

**情境 4 — 負值在行銷資料裡是常態，不是髒資料。** 超市資料的 `數量` 欄實際值域是 `[-25, ..., 10]`，負值是退貨；還有「空瓶回收，金額歸零」這種數量 −6、金額 0 的列（素材：同上 §3.4）。CAI 本身也是可正可負的欄（`CAI > 0` = 購買節奏加快，見 18 §四）。把負值當缺失刪掉會直接違反 18-G2（退貨未處理）。

水平平移 `log(x - min(x) + c)` 排第三順位，因為平移量是從**這一批資料**的 min 學來的：新資料出現更小的值就會產生負數進 log。若非用不可，平移量存進 `transform_spec.json`，並定義 clip 規則。**平移量會影響係數大小，必須在報告寫出來。**

**情境 5 — 比率的第一順位是換模型不是換尺度。** 教材原文已經講死：「Continuous Proportion（連續型比例）⋯ **這不能用 Binomial GLM**（可能要用 Beta Regression 或轉換後用 Normal）」（素材：02 §1125 §3.1）。Beta regression 要求開區間 (0,1)，端點用 $\frac{y(n-1)+0.5}{n}$ 壓縮，或改用 zero-one-inflated beta。

有一個更常見的錯誤在表格外面：**有整數分子分母的比例不屬於這個情境**。點擊/曝光、開信/寄送、轉換/到站，這些應該直接用 binomial GLM 的分組形式（`cbind(成功, 失敗)`），不要先除成比率再轉換 —— 除完之後 1,000 次曝光的 5% 和 20 次曝光的 5% 變成同一筆資料，權重全部丟掉。

**情境 6 — 看到左偏先懷疑天花板。** 行銷資料的左偏幾乎都來自上界：滿意度 1–10 分多數打 9、10；高滲透品類的購買率；折扣後價格佔原價比例。如果是天花板效應（大量觀測堆在最大值），轉換無效 —— 平方、立方只會把中段拉開，不會把天花板那根柱子拆掉。這種要改 ordinal logistic 或 censored（Tobit）模型。先看「最大值的重複次數佔比」，超過 15% 就當天花板處理〔判斷〕。

**情境 7 — log 不是尺度解法。** 課程資料集的 RFM 三維量級：`R ∈ [8, 401]`、`F ∈ [16, 85]`、`M ∈ [約 2 萬, 150,681]`，M 的樣本變異數約為 F 的 $10^{6}$ 倍（素材：`research/gap-statistical-inference.md` S2）。直接跑 Euclidean K-means，WGSS 的 99.99% 以上來自 M，分群結果實質上就是 M 的四分位切法，然後報告寫「群 1 是高頻高額忠誠客」—— F 對這個切法幾乎沒有貢獻。**取 log 之後 M 與 F 的量級仍然不同**（`ln(150681) = 11.9` vs `ln(85) = 4.4`，還是 2.7 倍），M 依然支配。log 治的是偏態，z-score 治的是尺度，兩件事。

```python
# scripts/pick_transform.py — 情境路由（決策順位的程式化，不是自動執行）
# 這支只「建議」不「執行」，輸出要進 §六 的轉換紀錄由人確認
import numpy as np
from scipy import stats

def route(x: np.ndarray, is_ratio: bool = False, has_int_denominator: bool = False) -> dict:
    x = x[~np.isnan(x)]
    if has_int_denominator:
        return {"situation": 0, "rec": "binomial GLM (cbind)", "note": "不要先算成比率"}
    if is_ratio and x.min() >= 0 and x.max() <= 1:
        return {"situation": 5, "rec": ["beta_reg", "logit", "arcsine_sqrt"]}
    if x.min() < 0:
        return {"situation": 4, "rec": ["yeo_johnson", "arcsinh", "shift_log"]}

    zero_ratio = float((x == 0).mean())
    skew = float(stats.skew(x))
    tie_top = float((x == x.max()).mean())

    if zero_ratio >= 0.30:
        return {"situation": 3, "rec": ["hurdle", "zinb", "tweedie"],
                "note": f"零佔比 {zero_ratio:.1%} ≥ 30%，不要轉換，改模型"}
    if zero_ratio >= 0.10:
        return {"situation": "3 or 2", "rec": "先判定零是結構性還是隨機",
                "zero_ratio": zero_ratio}
    if zero_ratio > 0:
        return {"situation": 2, "rec": ["yeo_johnson", "arcsinh(theta)", "log(x+c)"],
                "note": "arcsinh 必須報 θ 並做敏感度；c 不可用 1e-6"}
    if skew > 1:
        return {"situation": 1, "rec": ["gamma_glm_log", "log", "boxcox"],
                "note": "要預測 → GLM；只做描述 → log"}
    if skew < -1:
        return {"situation": 6, "rec": ["square", "cube", "yeo_johnson"],
                "note": f"最大值重複佔比 {tie_top:.1%}，>15% 視為天花板，改 ordinal/Tobit"}
    return {"situation": None, "rec": "不轉換", "skew": skew}
```

## 二、反轉換偏誤（retransformation bias）★

### 2.1 問題本身

$$\mathrm{E}[Y] \;=\; \mathrm{E}\!\left[e^{\log Y}\right] \;\neq\; e^{\mathrm{E}[\log Y]}$$

`exp` 是凸函數，由 Jensen 不等式，$\mathrm{E}[e^{Z}] \ge e^{\mathrm{E}[Z]}$，**等號只在 Z 沒有變異時成立**。你 `exp` 回去拿到的是**幾何平均**，不是算術平均。右偏資料的幾何平均恆小於算術平均，所以這個偏誤**必然是低估**，而且偏度越大低估越多。

若 $\log Y \sim N(\mu, \sigma^{2})$：

$$\mathrm{E}[Y] = e^{\mu + \sigma^{2}/2}, \qquad e^{\mathrm{E}[\log Y]} = e^{\mu}, \qquad \frac{\mathrm{E}[Y]}{e^{\mu}} = e^{\sigma^{2}/2}$$

**低估倍數就是 $e^{\sigma^{2}/2}$，只跟殘差變異有關，跟你模型配得好不好完全無關。** 這是它最陰險的地方：R² 高、殘差圖漂亮、Q-Q plot 直，偏誤照樣在那裡。

### 2.2 用真實數字算一次

課程資料集的交易金額（素材：`local/資料集剖析/marketing_datasets_profile.md` §2.5.4）：

```
n = 7,764   min = 2   max = 202,200   avg = 1,909.73   p50 = 688   p95 = 6,114.45   p99 = 27,253.7
```

以 lognormal 近似：幾何平均 ≈ 中位數 = 688，算術平均 = 1,909.73，比值 $= 2.776$，回推 $\sigma^{2} = 2\ln(2.776) = 2.042$（$\sigma = 1.43$）。

| 口徑 | 每筆金額 | 7,764 筆總額 | 相對實際 |
|---|---:|---:|---|
| 實際（算術平均）| 1,909.73 | 14,827,176 | — |
| `exp(平均的 log)` | 688 | 5,341,632 | **少算 9,485,544（−64.0%）** |

錯誤的行動長這樣：年度促銷預算按營收 3% 編列 → 用正確數字編 **44.5 萬**，用 `exp` 回去的數字編 **16.0 萬**，差 28.5 萬。同一組數字拿去做庫存備貨，備到需求的三分之一。而報告裡的模型診斷全部是綠燈，沒有任何一個檢定會告訴你這件事。

這也是 18-E7（圖文數字矛盾）的變形：數字確實來自同一份計算結果物件，但**口徑錯了** —— 幾何平均被當成算術平均報出去。

### 2.3 三個解法

**① GLM with log link（預設走這條）。** 因為它建模的是 $\log(\mathrm{E}[Y]) = X\beta$，$\exp(X\hat\beta)$ 直接就是 $\mathrm{E}[Y]$ 的估計，沒有偏誤要修。係數解讀是乘法效果：$e^{\hat\beta}$ 倍（素材：02 §6.2 家族與連結函數選擇規則表）。**只要交付物含「預測金額／營收／客單價」，一律走這條。**

注意：GLM 的信賴區間要在 link scale 算好再轉換，**不能直接轉換上下界的中點**（素材：`research/02_marketing_models_and_stats.md` 對 emmeans 替代實作的警告）。同樣地，GLM 的診斷圖第 1 張要改用 deviance residual vs linear predictor，套 OLS 那一套會誤導（素材：同上）。

**② Duan smearing estimator。** 已經配了 log-OLS、不想重配 GLM 時用：

$$\hat{\mathrm{E}}[Y_i] \;=\; e^{X_i\hat\beta} \cdot \underbrace{\frac{1}{n}\sum_{j=1}^{n} e^{\hat\varepsilon_j}}_{\text{smearing factor}}$$

它不假設殘差常態，只用經驗殘差。若殘差近似常態，smearing factor 會收斂到 $e^{\hat\sigma^{2}/2}$ —— 在上面那組數字就是 2.78，正好把 688 拉回 1,910。**前提是殘差同質變異**；有異質變異時要分組算 smearing factor（例如按預測值分位分成 5 組各算一個），否則低估只是從整體搬到某幾段。

**③ 只要排序就不用管。** 單調轉換不改變排序，`exp` 回去也不改變。分群、RFM 分數、Top-N 名單、Spearman 相關、滲透率排名，這些交付物完全不受影響。

| 交付物是什麼 | 需要處理反轉換偏誤嗎 | 走哪條 |
|---|:--:|---|
| 預測營收／客單價／CLV 金額 | **要** | ① GLM + log link |
| 已配好 log-OLS，要出金額 | **要** | ② Duan smearing |
| 報「中位數客單價」 | 不用 | `exp` 合法，但**必須在報告寫明這是中位數不是平均** |
| 分群、Top-N 名單、排序 | 不用 | ③ 直接用 |
| 相關係數、Spearman | 不用 | ③ 直接用 |
| 效果量的相對比較（誰比誰大） | 不用 | ③ 直接用 |
| 貝氏收縮平均後回報金額 | **要** | 在 `log(M)` 尺度收縮，回報時註明幾何平均意義（素材：`gap-statistical-inference.md` S16）|

```python
# scripts/retransform.py
import numpy as np
import statsmodels.api as sm

# ① 預設路線：Gamma GLM + log link，exp(Xb) 直接就是 E[Y]
g = sm.GLM(y, X, family=sm.families.Gamma(sm.families.links.Log())).fit()
pred_mean = g.predict(X_new)          # 已經是 E[Y]，不要再乘任何東西

# ② 已有 log-OLS 時的補救：Duan smearing
m = sm.OLS(np.log(y), X).fit()
smear = np.exp(m.resid).mean()        # 這組資料實測應接近 exp(sigma^2/2)
pred_mean_duan = np.exp(m.predict(X_new)) * smear

# 異質變異時要分組算，不能只用一個 smear
grp = np.digitize(m.fittedvalues, np.quantile(m.fittedvalues, [.2, .4, .6, .8]))
smear_by_grp = {k: np.exp(m.resid[grp == k]).mean() for k in np.unique(grp)}

# 交付前的硬檢查：模型平均必須對得上樣本平均
assert abs(pred_mean.mean() / y.mean() - 1) < 0.05, "反轉換偏誤未處理"
```

## 三、winsorize 與轉換的嚴格順序 ★

### 3.1 鐵則

> **先轉換 → 再看還有沒有離群 → 才 winsorize。**

SKILL.md 已把「先 winsorize 再轉換」列進「絕對不要出現的東西」。理由只有一句：**轉換會壓縮尾端，先 winsorize 等於在壓縮之前砍掉真實長尾，而行銷資料的長尾就是大客戶。**

用課程資料集算一次。若先用 p99 = 27,253.7 做上尾 winsorize：

| 交易 | 客戶 | 原金額 | winsorize 後 | 損失 |
|---|---|---:|---:|---:|
| 3924（03_保險）| 5425 | 202,200 | 27,253.7 | 174,946 |
| 9335（11_3C居家電信）| 5425 | 110,164 | 27,253.7 | 82,910 |

客戶 5425 一個人被砍掉約 **25.8 萬**。他從 M 最高的族群掉出去，不進 VIP 名單，該給的高資產客戶服務沒給。而 202,200 那筆是保險，`刷卡類型` 是「一般消費」、地點國內、日期正常 —— **它不是資料錯誤，它是這個人真的刷了 20 萬保費**。素材本身也確認這批資料「無負值、無零值、不含退貨」（素材：`marketing_datasets_profile.md` §2.5.4），沒有髒資料的藉口。

先轉換之後尾端長什麼樣：

$$\frac{202{,}200}{688} = 293.9\ \text{倍} \quad\xrightarrow{\ \ln\ }\quad \frac{\ln(202{,}200)}{\ln(688)} = \frac{12.22}{6.53} = 1.87\ \text{倍}$$

原尺度上是中位數的 294 倍，log 尺度上剩 1.87 倍 —— **多數情況下轉換完就不構成離群了，根本不需要 winsorize**。這就是順序不能反的實質理由。

順帶一提：**不要用 3σ 當離群門檻**。右偏資料的 sd 本身被右尾撐大，門檻是被離群值自己決定的。以上面那組 lognormal 近似推算〔以 lognormal 近似，非素材實測〕：$\text{sd} = \mu\sqrt{e^{\sigma^{2}}-1} = 4{,}943$，`mean + 3sd = 16,739`，**比 p99 = 27,253.7 還低**，會砍掉約 1.3% 的資料，比 p99 多砍 30%。教材對離群值的處方也是分位／穩健路線，不是 σ 規則（素材：01 §11.3 表第 3 項、§13.4 離群值四類成因）。

## 四、五個實務條件

### 4.1 轉換參數只能從訓練集學

Box-Cox / Yeo-Johnson 的 λ、winsorize 的分位點、arcsinh 的 θ、平移量、scaler 的 mean/sd —— **全部都是從資料估出來的參數，全部都會洩漏**。這是 18-G4（目標洩漏）的一個常被漏掉的入口：大家都記得特徵計算要切 `as_of_date`，卻用全資料 `fit` 了一個 PowerTransformer。

$$\lambda^{(\text{Box-Cox})}:\quad y^{(\lambda)} = \begin{cases} \dfrac{y^{\lambda}-1}{\lambda}, & \lambda \neq 0\\[4pt] \ln y, & \lambda = 0\end{cases} \qquad (y>0)$$

$$\lambda^{(\text{Yeo-Johnson})}:\quad y^{(\lambda)} = \begin{cases}
\dfrac{(y+1)^{\lambda}-1}{\lambda}, & \lambda \neq 0,\ y \ge 0\\[4pt]
\ln(y+1), & \lambda = 0,\ y \ge 0\\[4pt]
-\dfrac{(1-y)^{2-\lambda}-1}{2-\lambda}, & \lambda \neq 2,\ y < 0\\[4pt]
-\ln(1-y), & \lambda = 2,\ y < 0
\end{cases}$$

規則：**所有轉換參數存進 `04_features/transform_spec.json`，換一批資料重跑時載入同一份，不重新 fit。** 監督式路線的轉換直接放進 sklearn Pipeline，讓交叉驗證自己在每個 fold 內 fit。

### 4.2 保留原始欄位，不覆寫

沿用 SKILL.md 紀律 2（每階段都留成果、絕不覆寫）與 17 的欄名慣例（禁止裸 `F` / `M`）。命名規則：**原欄名 + 雙底線 + 轉換代號**。

| 轉換 | 後綴 | 範例 |
|---|---|---|
| 自然對數 | `__log` | `m_net_twd__log` |
| log(x+c) | `__log_c<值>` | `m_net_twd__log_c344` |
| Yeo-Johnson | `__yj` | `profit_twd__yj` |
| Box-Cox | `__bc` | `m_net_twd__bc` |
| arcsinh | `__ihs_t<θ>` | `spend_twd__ihs_t688` |
| logit | `__logit` | `ctr_ratio__logit` |
| winsorize | `__w<下><上>` | `m_net_twd__w0199` |

參數寫進欄名不是為了好看，是為了讓 18-E7（每個數字都要能追回計算過程）在**欄名層級**就成立 —— 報告裡出現 `m_net_twd__log_c344`，讀者立刻知道 c = 344。

### 4.3 係數解讀口徑會變

這是轉換最容易在**報告階段**出錯的地方：模型跑對了，話講錯了。

| 模型形式 | 數學 | 係數意義 | 行銷講法 |
|---|---|---|---|
| level-level | $Y = \beta X$ | X +1 單位 → Y +β 單位 | 「每多投 1 元廣告，營收多 β 元」|
| **log-level（半彈性）** | $\ln Y = \beta X$ | X +1 單位 → Y 變動 $(e^{\beta}-1)\times 100\%$ | 「多發一次 EDM，客單價提升 X%」|
| level-log | $Y = \beta \ln X$ | X +1% → Y +β/100 單位 | 「廣告費多 1%，營收多 β/100 元」|
| **log-log（彈性）** | $\ln Y = \beta \ln X$ | X +1% → Y +β% | 「廣告彈性 β」，遞減報酬看 β<1 |
| GLM + log link | $\ln \mathrm{E}[Y] = \beta X$ | X +1 單位 → $\mathrm{E}[Y]$ **乘** $e^{\beta}$ 倍 | 「該族群消費是基準組的 $e^{\beta}$ 倍」|

取 log 後係數變成百分比效果，正好是行銷人習慣的「提升 X%」語言（素材：01 §6.5 評註）。但**半彈性不等於 100β%**：β = 0.5 時真值是 $e^{0.5}-1 = 64.9\%$，不是 50%，差 15 個百分點。廣告係數報成「+50%」而實際是 +64.9%，ROAS 目標會訂錯，而且錯在保守方向 —— 你會以為某個渠道不划算而砍掉它。**β 的絕對值超過 0.1 就不准用線性近似，一律用 $e^{\beta}-1$。**

### 4.4 比率型不要用 log

log 假設沒有上界，比率有。同樣是「翻倍」：

| 變化 | log 尺度差 | logit 尺度差 | 現實上做得到嗎 |
|---|---:|---:|---|
| CTR 3% → 6% | +0.693 | +0.712 | 做得到 |
| CTR 45% → 90% | +0.693 | +2.001 | 幾乎不可能 |

log 說這兩件事一樣難，**logit 才反映「越接近天花板越難再提升」**。具體錯誤行動：迴歸「CTR ~ 素材類型」用 log(CTR)，得到「影片素材讓 CTR 提升 69%」，套到一個原本 CTR 已經 45% 的高意圖再行銷受眾上，預期會到 76%，據此把該受眾的預算調高三倍。實際上該受眾的 CTR 只從 45% 動到 52%，因為模型從來沒有被告知上界存在。

同理，比率欄的離群判定也不要用 log 尺度的 z 分數。

### 4.5 時間型欄位要想清楚再轉

$$\ln 60 - \ln 30 = \ln 2 = 0.693, \qquad \ln 600 - \ln 300 = \ln 2 = 0.693$$

**log 把「30 天 vs 60 天」和「300 天 vs 600 天」變成完全一樣的差距。** 但行銷上這是兩件毫不相干的事：30→60 天是「該發喚回券了」，300→600 天是「兩個都已經死了，發券只是燒錢」。用 `log(R)` 跑分群，這兩群顧客會被拉到相近的位置。

Recency 的正確處理是**分位數分箱**不是 log。實測：R 的 median = 12 天但 max = 516 天，std = 129 > mean = 74，等寬分箱會把 90% 的客戶塞進第一箱，必須用 `NTILE` / quantile（素材：`marketing_datasets_profile.md` RFM 分位表，五分位切點 R = 3.0 / 5.0 / 22.4 / 113.8）。要連續尺度時走存活分析的 `P(alive)`，見 `09_行銷_顧客價值.md`。

另外兩條：**tenure / 帳齡不要轉**（cohort 比較要的是絕對時間，見 18-G3）；**日期不要當數值轉**（要的是 year/month/dow/節慶旗標這類衍生欄，見 `04_資料體檢.md`）。

## 五、標準化不在這個模組做

### 5.1 為什麼不能統一做

四個方法族對資料形態的要求**互相矛盾**，沒有一個統一的標準化能同時滿足：

- **非監督**要的是「所有輸入在同一個距離尺度上」，而且沒有訓練/測試的概念，必須在整個分析集上 fit。
- **監督**要的是「參數只從訓練 fold 學」。在 M3 統一 z-score 就是用了測試集的 mean/sd，**這條路直接洩漏**（18-G4）。
- **時間序列**用全期 z-score 等於用到未來資訊，且它真正需要的是差分／季節調整，不是 z-score。
- **因果推論**的處理與結果變數一般**不標準化** —— ATE 要保留原單位才能換算成金額，標準化完的「效果 0.3 個標準差」沒辦法拿去算損益兩平。

教材對這塊是零覆蓋：`03_clustering_sequence.md §15` 明文寫「**標準化 / 尺度處理：完全沒有提及**」，並自己註明「這是行銷分群最常見的踩雷點（RFM 的 M 尺度遠大於 F），教材零覆蓋，Skill 必須自己加」（素材：同檔 §15）。所以下面這張表是本 skill 自訂的規則，不是教材規則。

### 5.2 各方法族怎麼做

| 方法族 | 對應模組 | 標準化怎麼做 | fit 在哪 | 存在哪 | 不做會怎樣 |
|---|---|---|---|---|---|
| **非監督**（K-means / HAC / DBSCAN / PCA / 因素分析）| M6、M8-2 | 一律 z-score；有離群且已走完 §三 → RobustScaler | 整個分析集 | `05_models/scaler.json` | M 的變異數是 F 的 $10^6$ 倍，WGSS 99.99% 來自 M，分群 = M 的四分位切法（18-G7 的前置條款）|
| **監督**（迴歸 / 分類 / 預測）| M7、M9 | 放進 `sklearn.Pipeline`，跟模型綁在一起 | **每個訓練 fold 內** | Pipeline 物件本身 | 洩漏，驗證分數虛高、上線崩盤（18-G4）|
| **時間序列**（趨勢分解 / 季節性 / MMM）| M8-3 | 不做全期 z-score；要縮放用 expanding window | 只用 t 以前 | `05_models/ts_spec.json` | 用到未來資訊，回測看起來完美 |
| **因果**（DiD / uplift / Meridian）| M12、`.venv-causal` | 處理與結果變數**不標準化**；共變量可標準化 | 由估計器內部處理 | 估計器設定檔 | 效果量無法換算金額，M11 的損益兩平算不出來 |

補一條共通規則：**距離型方法若尺度決策不同，要輸出「標準化前 vs 標準化後」的群成員 ARI 對照**。ARI 低代表尺度決策改變了整個分群結論，必須在報告寫明選擇理由（素材：`gap-statistical-inference.md` S2 修補動作 Step 4）。教材的距離選擇表也呼應這件事：「含極端值的金額（未做 log、未 winsorize）→ Manhattan（對異常值相對不敏感）」（素材：`03_clustering_sequence.md` 距離選擇表）。

## 六、轉換紀錄的六欄格式

每一個被轉換的欄位在 `04_features/transform_log.csv` 佔一列，**六欄缺一不可**。第四欄（為什麼是它）是這份紀錄存在的理由 —— 沿用 SKILL.md 紀律 4「參數必附理由」，也是品質檢查清單裡「每個轉換都寫了理由（第幾順位、前面的為什麼不行）」那一條的實作。

下表是**填寫範例**：`r_days_since_last_sale` 的分布數字與五分位切點是課程資料集實測值（素材：`marketing_datasets_profile.md` RFM 分位表），`m_net_twd` 的 min/p50/max 同樣來自該表；其餘欄位（偏度、`profit_twd__yj`、`cat_amt_bakery`）是為了示範六欄怎麼填而虛構的，**不要當基準值引用**。

| 欄名 | 原分布特性 | 選了哪個轉換 | 為什麼是它（第幾順位、前面的為什麼不行）| 參數值 | 轉換後偏度與排序相關 |
|---|---|---|---|---|---|
| `m_net_twd` | n=100, min=583, max=1,153,973, p50=76,432, skew=3.87, zero=0% | **不轉換**，改 Gamma GLM + log link | 情境 1 第 ① 順位。交付物含「預測年度營收」，走 log-OLS 再 exp 會低估（§二）| `family=Gamma, link=log` | 原欄不變；GLM deviance residual 已檢查 |
| `m_net_twd__log` | 同上 | `ln(x)` | 情境 1 第 ② 順位。**僅供分群輸入與 EDA 直方圖**，① 是建模路線不產生欄位 | — | skew 0.31；Spearman(原,轉) = 1.000 |
| `r_days_since_last_sale` | min=1, max=516, p50=12, mean=74, std=129, skew=2.1 | **不做 log**，改 `NTILE(5)` 分位分箱 | 時間型欄位，log 會讓 30vs60 與 300vs600 變成同樣差距（§4.5）。等寬分箱會把 90% 塞進第一箱 | 切點 3.0 / 5.0 / 22.4 / 113.8 | 分箱後為序數；Spearman(原,箱) = 0.997 |
| `profit_twd__yj` | min=−12,400, max=88,200, skew=1.9, 負值 6.2% | Yeo-Johnson | 情境 4 第 ① 順位。log 不吃負值；平移後 log 的平移量會隨新資料改變（第 ③ 順位）| `λ = −0.3142`（fit on train）| skew 0.44；Spearman = 1.000 |
| `cat_amt_bakery` | zero = 61%, 正值部分 skew=2.7 | **不轉換**，改 Hurdle（logit + 截斷 Gamma）| 情境 3。零佔比 61% ≫ 30%，且為結構性零（該門市不賣）。`log(x+c)` 只會把 61% 的列堆到 `log(c)` 一根柱子 | 兩段模型，見 `08_迴歸建模.md` | 不適用（未產生轉換欄）|

### 6.1 第六欄的兩個數字各自在抓什麼

**轉換後偏度**抓的是統計目的有沒有達成，門檻 `|skew| < 1`（M4 三門檻之一）。

**排序相關**（Spearman，原欄 vs 轉換後欄）抓的是**實作有沒有寫錯**，不是統計訊號。任何單調轉換的 Spearman 理論上都是 1.000；掉下來只有四種可能：

| Spearman | 代表什麼 | 該做什麼 |
|---:|---|---|
| 1.000 | 正常 | 通過 |
| 0.95 ~ 0.999 | winsorize 或 clip 製造了並列 | 檢查並列數，與 §3.3 的 `n_rows_clipped` 對得起來就通過 |
| < 0.95 | **M4 門檻不過** | winsorize 砍太多，或 clip 範圍設錯 |
| 有 NaN | 轉換產生了 NaN（`log` 吃到 0 或負值）| **Bug，不是統計問題**，回去修 §一 的情境判定 |
| 非單調下降 | 用了非單調轉換（如未取絕對值的平方）| 情境 6 的平方轉換對含負值的欄是非單調的，重新分流 |

```python
# scripts/write_transform_log.py — 六欄格式的 schema，欄位順序不可改
SCHEMA = [
    "col_name",        # 1. 欄名（含轉換後綴，見 §4.2）
    "src_profile",     # 2. 原分布特性：n / min / max / p50 / skew / zero_ratio / neg_ratio
    "method",          # 3. 選了哪個轉換（或 "none + <模型族>"）
    "rationale",       # 4. ★ 為什麼是它：情境編號 + 第幾順位 + 前面順位為什麼不行
    "params",          # 5. 參數值 + fit_on（train / full）
    "post_skew",       # 6a. 轉換後偏度，門檻 |skew| < 1
    "spearman_vs_src", # 6b. 排序相關，門檻 > 0.95
]

# verify_outputs.py 要加的三條 CHECK
CHECKS_M3 = [
    "transform_log.csv 的每一列 rationale 欄非空，且含情境編號與順位",
    "每個進入 05_models 的特徵欄都能在 transform_log.csv 找到對應列",
    "transform_spec.json 的 fit_on='full' 只出現在 purpose='descriptive_only' 或非監督路線",
]
```

## 七、單位統一

單位問題不會讓程式報錯，它只會讓數字安靜地錯掉，所以它屬於 M3 而不是 M1 —— **M1 檢查的是有沒有髒值，M3 檢查的是同一欄裡的數字講的是不是同一件事**。這一節的三項全部對應 18-G10（指標口徑沒有單一真相）。

### 7.1 幣別：`dim_fx_rate` 是維度資料，不是常數

匯率**隨日期變動**，把它寫成程式裡的一個常數是最常見的做法，也是最錯的。它必須是一張維度表，並且要指定用哪一天的匯率。

實測案例：課程信用卡檔**沒有任何幣別欄位**，從金額量級（中位數 688、最大 202,200）與台灣地名判斷單位是 TWD，且 216 筆國外交易的平均金額是國內的 3.6 倍，符合「國外刷卡以旅遊/大額為主」，代表國外交易已折算為台幣而非原幣別（素材：`marketing_datasets_profile.md` §2.5.4）。**ingest 在缺幣別欄時要強制產生 `WARNING: currency column absent`**，不能靜默假設。

錯誤行動：日本站營收記 JPY、台灣站記 TWD，直接 `SUM(amount) GROUP BY market`。1 TWD ≈ 4.5 JPY，日本站被當成 4.5 倍大的市場，年度預算往日本配 —— 這種錯誤在報表上完全看不出來，因為每個數字自己都是對的。

第二個錯誤：用「今天的匯率」重算歷史營收 → 每次重跑報告數字都不一樣，正好違反 17 §二對基準日的規定（「必須明確指定，不可預設用今天」）。

```sql
-- 02_資料模型規格.md 的維度表，M3 之前必須建好
CREATE TABLE IF NOT EXISTS dim_fx_rate (
    from_ccy   VARCHAR NOT NULL,      -- 'JPY'
    to_ccy     VARCHAR NOT NULL,      -- 'TWD'（報告幣別，寫進專案核心.md）
    rate_date  DATE    NOT NULL,      -- 匯率日，不是載入日
    rate       DECIMAL(18,8) NOT NULL,
    rate_type  VARCHAR NOT NULL,      -- 'daily_close' | 'month_avg' | 'budget_fixed'
    src        VARCHAR NOT NULL,      -- 來源（央行/財務部門/供應商）
    PRIMARY KEY (from_ccy, to_ccy, rate_date, rate_type)
);

-- 換算一律用交易日匯率；要改用期間平均必須在指標字典寫明（18-G10）
CREATE OR REPLACE VIEW stg_transaction_twd AS
SELECT t.*,
       t.amount * COALESCE(fx.rate, 1.0) AS amount_twd,
       CASE WHEN t.currency <> 'TWD' AND fx.rate IS NULL
            THEN 'ERROR: fx rate missing' END AS fx_flag   -- 缺匯率要擋，不可靜默補 1.0
FROM fact_transaction t
LEFT JOIN dim_fx_rate fx
       ON fx.from_ccy = t.currency AND fx.to_ccy = 'TWD'
      AND fx.rate_date = t.txn_date AND fx.rate_type = 'daily_close';
```

### 7.2 率 vs 百分比：契約檔必填 `unit`，staging 一律存 ratio

| 規則 | 內容 |
|---|---|
| 契約檔 | 每個比率欄必填 `unit: ratio \| percent`，**沒填的欄不准進 staging**（18-G11 的品質關卡）|
| staging 儲存 | **一律 ratio**（0.032），percent 在 ingest 時就除以 100 |
| 欄名 | 帶單位後綴：`ctr_ratio`、`discount_pct_display`。**禁止裸 `ctr`** |
| 顯示層 | 只在報告/儀表板渲染時乘 100，不在資料層做 |
| 檢查 | ratio 欄的值域必須落在 `[0, 1]`；出現 > 1 的值一律擋下人工確認 |

錯誤行動：Google Ads 匯出的 CTR 是 `3.2`（percent），內部資料倉的 CTR 是 `0.032`（ratio），兩張表 `UNION` 後算平均得 1.616，報告寫「整體 CTR 161.6%」—— 這個還算好，因為荒謬到有人會發現。真正危險的是**只有部分渠道混單位**：三個渠道 ratio、一個渠道 percent，平均變成 0.83，看起來像 83% 也像 0.83%，取決於讀者怎麼猜。18-E9 的自動離群掃描（同欄數量級差 >100 倍）能抓到同欄混用，**但抓不到「A 欄全是 ratio、B 欄全是 percent」的跨欄不一致** —— 那只能靠契約檔。

### 7.3 時間單位

| 項目 | 規則 | 不遵守會怎樣 |
|---|---|---|
| Recency / 間隔 / tenure | 一律**天**，欄名帶 `_days` | 月與天混用，CAI 的 λ 差 30 倍 |
| 月營收比較 | 用**日均**或做天數校正 | 2 月 28 天 vs 3 月 31 天 = 10.7% 的差，被讀成「3 月成長 10%」並據此加碼 |
| 週定義 | 明訂週起始日（ISO 週一 / 商業週日），寫進專案核心.md | 跨系統 join 時週次錯位一天，週對週比較全錯 |
| 時區 | 一律存 UTC + 明確標示分析時區（`Asia/Taipei`）| 切日界線錯 → 17 §一「同顧客同日壓成一筆」的去重口徑跟著錯 → 購買間隔出現大量 0 → MLE/WMLE/CAI 全歪 |
| 基準日 | 必須明確指定，不可用「今天」（17 §二）| 歷史報告每次重跑數字都變，無法對帳 |

```sql
-- 單位統一的三條 gate，放在 staging → mart 之間，不通過就擋
-- 1) ratio 欄值域
SELECT 'ctr_ratio' AS col, COUNT(*) AS bad FROM stg_ad_daily WHERE ctr_ratio > 1.0
UNION ALL
-- 2) 非 TWD 交易必須有匯率
SELECT 'fx_missing', COUNT(*) FROM stg_transaction_twd WHERE fx_flag IS NOT NULL
UNION ALL
-- 3) 時間欄必須帶單位後綴（掃 information_schema）
SELECT 'time_col_no_unit', COUNT(*) FROM information_schema.columns
WHERE table_schema = 'mart'
  AND (column_name LIKE '%recency%' OR column_name LIKE '%interval%' OR column_name LIKE '%tenure%')
  AND column_name NOT LIKE '%\_days' ESCAPE '\';
```
